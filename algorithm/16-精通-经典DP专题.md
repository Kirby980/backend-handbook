# 精通经典 DP 专题

> 掌握了 DP 四步法（[15](./15-精通-动态规划基础.md)），还要熟悉几类经典 DP 题型的"套路状态定义"——背包、子序列、编辑距离、区间、树形、状态机。每类都有固定的状态设计，认出类型就能套。本篇是 DP 的"题型字典"。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

## 一、背包问题

**背包**是 DP 最经典的模型：给定容量和物品（重量+价值），求最大价值。

**0-1 背包**（每个物品只能选一次）：

```go
// 0-1 背包：weights/values 是物品重量/价值，cap 是容量
func knapsack01(weights, values []int, cap int) int {
    dp := make([]int, cap+1) // dp[j] = 容量 j 的最大价值
    for i := 0; i < len(weights); i++ {
        for j := cap; j >= weights[i]; j-- { // ⚠️ 倒序遍历容量
            dp[j] = max(dp[j], dp[j-weights[i]]+values[i]) // 不选 or 选第 i 个
        }
    }
    return dp[cap]
}
```

**完全背包**（每个物品可选无限次）——只是容量**正序**遍历：

```go
for i := 0; i < len(weights); i++ {
    for j := weights[i]; j <= cap; j++ { // ⚠️ 正序（可重复选）
        dp[j] = max(dp[j], dp[j-weights[i]]+values[i])
    }
}
```

**关键区别（高频考点）**：一维 DP 下，**0-1 背包容量倒序**（保证每个物品只用一次——倒序时 dp[j-w] 还是上一轮的值），**完全背包容量正序**（允许重复用——正序时 dp[j-w] 是本轮更新过的值）。背包变体：分割等和子集（能否装满 cap/2）、目标和、零钱兑换（完全背包求最少硬币数）、组合总和。

## 二、子序列问题

**最长递增子序列（LIS）**：

```go
// LIS：dp[i] = 以 nums[i] 结尾的最长递增子序列长度
func lengthOfLIS(nums []int) int {
    n := len(nums)
    dp := make([]int, n)
    ans := 0
    for i := 0; i < n; i++ {
        dp[i] = 1 // 至少自己
        for j := 0; j < i; j++ {
            if nums[j] < nums[i] { // 能接在 j 后面
                dp[i] = max(dp[i], dp[j]+1)
            }
        }
        ans = max(ans, dp[i])
    }
    return ans // O(n²)；二分优化可到 O(n log n)
}
```

**最长公共子序列（LCS）**（两个字符串）：

```go
// LCS：dp[i][j] = text1 前 i 个 和 text2 前 j 个 的最长公共子序列长度
func longestCommonSubsequence(text1, text2 string) int {
    m, n := len(text1), len(text2)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if text1[i-1] == text2[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1 // 字符相同，从对角线 +1
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1]) // 不同，取上/左较大
            }
        }
    }
    return dp[m][n]
}
```

子序列 DP 套路：**"以 i 结尾"（LIS）** 或 **"前 i 个 vs 前 j 个"（LCS 两序列用二维）**。注意子序列（可不连续）≠ 子串/子数组（连续，子串问题状态定义略不同）。

## 三、编辑距离

**编辑距离（Edit Distance）**：把 word1 变成 word2 的最少操作数（插入/删除/替换）。两个字符串 → 二维 DP：

```go
// dp[i][j] = word1 前 i 个 变成 word2 前 j 个 的最少操作数
func minDistance(word1, word2 string) int {
    m, n := len(word1), len(word2)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
        dp[i][0] = i // word1 前 i 个变空串：删 i 次
    }
    for j := 0; j <= n; j++ {
        dp[0][j] = j // 空串变 word2 前 j 个：插 j 次
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if word1[i-1] == word2[j-1] {
                dp[i][j] = dp[i-1][j-1] // 字符相同，不操作
            } else {
                dp[i][j] = min(
                    dp[i-1][j-1], // 替换
                    min(dp[i-1][j], // 删除
                        dp[i][j-1]), // 插入
                ) + 1
            }
        }
    }
    return dp[m][n]
}
```

编辑距离是"两序列对比"二维 DP 的代表：`dp[i][j]` 由 `dp[i-1][j-1]`（替换/匹配）、`dp[i-1][j]`（删）、`dp[i][j-1]`（插）转移。是文本 diff、拼写纠错（[Java 字符串](../java/J03-精通-String与不可变设计.md)、[系统设计 S12 搜索纠错](../system-design/S12-精通-设计搜索与自动补全.md)）的底层算法。

## 四、区间 DP

**区间 DP**：状态是一个区间 `dp[i][j]`（i 到 j 这段的解），通常**按区间长度从小到大**遍历。典型：最长回文子串/子序列、戳气球、合并石头。

```go
// 最长回文子序列：dp[i][j] = s[i..j] 的最长回文子序列长度
func longestPalindromeSubseq(s string) int {
    n := len(s)
    dp := make([][]int, n)
    for i := range dp {
        dp[i] = make([]int, n)
        dp[i][i] = 1 // 单字符是长度 1 的回文
    }
    for length := 2; length <= n; length++ { // 按区间长度从小到大
        for i := 0; i+length-1 < n; i++ {
            j := i + length - 1
            if s[i] == s[j] {
                dp[i][j] = dp[i+1][j-1] + 2 // 两端相同，内部 +2
            } else {
                dp[i][j] = max(dp[i+1][j], dp[i][j-1]) // 取去掉一端的较大
            }
        }
    }
    return dp[0][n-1]
}
```

区间 DP 特点：**dp[i][j] 由更小的区间（dp[i+1][j-1]、dp[i+1][j]、dp[i][j-1]）转移**，所以**遍历顺序按区间长度递增**（保证小区间先算）。这是区间 DP 的标志。

## 五、树形 DP

**树形 DP**：在树上做 DP，状态是"以某节点为根的子树"，**后序遍历**（先算子节点再算父节点，[12](./12-精通-二叉树.md)）。典型：打家劫舍 III（树形）、二叉树最大路径和。

```go
// 打家劫舍 III：树形，不能偷相邻（父子）节点
// 每个节点返回 [不偷该节点的最大值, 偷该节点的最大值]
func rob(root *TreeNode) int {
    var dfs func(*TreeNode) [2]int
    dfs = func(node *TreeNode) [2]int {
        if node == nil {
            return [2]int{0, 0}
        }
        left := dfs(node.Left)   // 后序：先算左子树
        right := dfs(node.Right) // 再算右子树
        notRob := max(left[0], left[1]) + max(right[0], right[1]) // 不偷当前：左右随意
        rob := node.Val + left[0] + right[0]                     // 偷当前：左右都不能偷
        return [2]int{notRob, rob}
    }
    res := dfs(root)
    return max(res[0], res[1])
}
```

树形 DP 套路：**递归（后序）返回子树的 DP 状态（常是个数组/多个值），父节点据此合并**。这是 DP 和树递归（[12](./12-精通-二叉树.md)）的结合。

## 六、状态机 DP

**状态机 DP**：状态包含"当前处于哪个状态"，在状态间转移。典型：**股票买卖系列**（持有/不持有/冷冻期等状态）。

```go
// 买卖股票最佳时机 II（可多次交易）：两个状态——持有/不持有
func maxProfit(prices []int) int {
    hold, cash := -prices[0], 0 // hold:持有股票的最大收益, cash:不持有的最大收益
    for i := 1; i < len(prices); i++ {
        hold = max(hold, cash-prices[i])  // 持有：保持 or 今天买入
        cash = max(cash, hold+prices[i])  // 不持有：保持 or 今天卖出
    }
    return cash // 最后不持有收益最大
}
```

状态机 DP 套路：**枚举所有"状态"，写出状态之间的转移**。股票系列（限次数、含手续费、含冷冻期）都是加状态/维度。状态定义要做到"无后效性"（当前状态包含决策所需全部信息，[15](./15-精通-动态规划基础.md)）。

## 七、DP 题型速查

| 题型 | 状态定义套路 | 例题 |
|---|---|---|
| **背包** | dp[j] = 容量 j 的最优 | 0-1/完全背包、零钱、分割等和、目标和 |
| **线性 DP** | dp[i] = 到 i 的最优 | 爬楼梯、打家劫舍、最大子数组 |
| **子序列** | dp[i] 以 i 结尾 / dp[i][j] 两序列 | LIS、LCS |
| **字符串双序列** | dp[i][j] = 前 i vs 前 j | 编辑距离、LCS、正则匹配 |
| **区间** | dp[i][j] = 区间 i..j | 回文、戳气球、合并石头 |
| **树形** | 后序返回子树状态 | 打家劫舍 III、树的最大路径和 |
| **状态机** | dp[i][状态] | 股票买卖系列 |

认出题型 → 套对应的状态定义 → 推转移方程。这是攻克 DP 难题的捷径。

## 陷阱清单

- **0-1 背包正序遍历容量**：会导致物品被重复选（变成完全背包）。0-1 必须**倒序**，完全背包正序。
- **子序列和子串混淆**：子序列可不连续（dp[i] 以 i 结尾或二维），子串/子数组要连续（状态定义不同）。
- **二维 DP 初始化漏边界**：编辑距离/LCS 的 dp[i][0]、dp[0][j] 要正确初始化（删/插次数）。
- **区间 DP 遍历顺序错**：必须按区间长度从小到大（或 i 倒序、j 正序），保证小区间先算。
- **树形 DP 不用后序**：必须先算子树再算父，用后序递归返回子树状态。
- **状态机 DP 状态没枚举全**：漏了某个状态（如股票冷冻期），转移就不对。
- **LIS 暴力 O(n²) 没想到二分优化**：进阶可用"贪心 + 二分"到 O(n log n)。
- **状态定义有后效性**：当前状态不足以决策后续，需增加维度。

## 2026 现状

- **DP 题型化**：面试 DP 大多能归到这几类经典模型，认出类型 + 套状态定义是高效解法，比每题从零推快得多。
- **背包和子序列最高频**：0-1/完全背包、LIS、LCS、编辑距离是 DP 必考，股票系列（状态机）也常见。
- **DP 的工程价值**：编辑距离 → 文本 diff/拼写纠错（[S12](../system-design/S12-精通-设计搜索与自动补全.md)）、背包 → 资源分配、LCS → 版本控制 diff、Floyd → 路由。
- **配合刷题**：按"入门线性 DP → 背包 → 子序列 → 区间/树形/状态机"循序渐进刷，配合本篇题型速查（见 [20](./20-精通-高频题型与刷题路线.md)）。

## 练习题

1. 0-1 背包和完全背包在一维 DP 实现上有什么区别？为什么遍历方向不同？

<details><summary>参考答案</summary>

0-1 背包（每个物品最多选 1 次）和完全背包（每个物品可选无限次）用一维 dp 数组（dp[j] 表示容量为 j 时的最大价值）实现时，转移方程相同：`dp[j] = max(dp[j], dp[j-w[i]] + v[i])`（不选第 i 个物品 vs 选第 i 个物品），但**遍历容量 j 的方向相反**：**0-1 背包必须倒序遍历容量**（j 从 cap 到 w[i]），**完全背包必须正序遍历容量**（j 从 w[i] 到 cap）。**为什么方向不同**：关键在于"在计算 dp[j] 时，dp[j-w[i]] 用的是上一轮（不含当前物品 i）的值还是本轮（已含物品 i）的值"。①**0-1 背包要倒序**：因为每个物品只能用一次，计算 dp[j] 时引用的 dp[j-w[i]] 应该是"还没考虑物品 i 时"的状态（即上一轮的值），这样才保证物品 i 只被加入一次。倒序遍历（从大 j 到小 j）时，dp[j-w[i]]（更小的下标）在本轮**还没有被更新过**、仍是上一轮的值，所以引用到的是"不含物品 i"的状态，物品 i 不会被重复计入。如果正序，dp[j-w[i]] 会在本轮先被更新（已经包含了物品 i），再用它更新 dp[j] 就相当于物品 i 被用了多次——这就错误地变成了完全背包。②**完全背包要正序**：因为每个物品可以用无限次，我们**希望** dp[j-w[i]] 是"已经考虑过物品 i（可能已选若干个 i）"的本轮最新状态，这样用它更新 dp[j] 就允许物品 i 被再次选入、实现"重复使用"。正序遍历时，dp[j-w[i]]（更小下标）在本轮已被更新过、包含了物品 i 的贡献，符合完全背包的需求。一句话：**倒序保证物品只用一次（0-1），正序允许物品重复使用（完全）**——这是背包问题一维优化最经典、最易错的考点。理解它需要想清楚"一维数组原地滚动更新时，被引用的更小下标的值是本轮新值还是上轮旧值"。

</details>

2. 最长递增子序列（LIS）的 DP 状态怎么定义？转移方程是什么？

<details><summary>参考答案</summary>

**状态定义**：`dp[i]` 表示**以 nums[i] 结尾的最长递增子序列的长度**（注意是"以 i 结尾"，必须包含 nums[i]，这样才能方便地通过"前面哪个元素能接到 nums[i] 前面"来转移）。**转移方程**：对每个 i，考察它前面所有的 j（0 ≤ j < i），如果 **nums[j] < nums[i]**（说明 nums[i] 可以接在以 nums[j] 结尾的递增子序列后面，构成更长的递增子序列），则 dp[i] 可以由 dp[j] + 1 更新；取所有这样的 j 中的最大值：`dp[i] = max(dp[j] + 1)，其中 0 ≤ j < i 且 nums[j] < nums[i]`。如果前面没有比 nums[i] 小的元素，dp[i] = 1（自己单独成一个长度为 1 的子序列）。**初始化**：每个 dp[i] 初始为 1（至少包含自己）。**最终答案**：LIS 的长度是 **max(dp[i])（所有 i 中的最大值）**——注意不是 dp[n-1]，因为最长递增子序列不一定以最后一个元素结尾，要在所有"以 i 结尾"的结果里取最大。**复杂度**：这个 DP 是双重循环 O(n²) 时间、O(n) 空间。**进阶优化到 O(n log n)**：维护一个数组 tails，tails[k] 表示长度为 k+1 的递增子序列的**最小可能结尾值**；遍历每个数，用**二分查找**在 tails 中找到第一个 ≥ 当前数的位置替换（或追加到末尾），tails 的长度就是 LIS 长度。这个"贪心 + 二分"的优化把复杂度降到 O(n log n)（利用了 tails 始终有序的性质，见二分查找 06）。面试中能写出 O(n²) 的标准 DP（讲清"以 i 结尾"的状态定义和转移），并知道有 O(n log n) 的二分优化，是完整的回答。LIS 是子序列类 DP 的代表，"以 i 结尾"是子序列 DP 常用的状态设计。

</details>

3. 编辑距离的 dp[i][j] 表示什么？三种操作如何对应到状态转移？

<details><summary>参考答案</summary>

**状态定义**：`dp[i][j]` 表示**把 word1 的前 i 个字符转换成 word2 的前 j 个字符所需的最少操作次数**（操作包括插入、删除、替换一个字符）。**初始化（边界）**：`dp[i][0] = i`（把 word1 的前 i 个字符变成空串，需要删除 i 次）；`dp[0][j] = j`（把空串变成 word2 的前 j 个字符，需要插入 j 次）；dp[0][0]=0。**转移方程**：考察 word1 的第 i 个字符（word1[i-1]）和 word2 的第 j 个字符（word2[j-1]）：①如果**两个字符相同**（word1[i-1] == word2[j-1]），则这个字符不需要任何操作，`dp[i][j] = dp[i-1][j-1]`（直接继承"前 i-1 变前 j-1"的结果）。②如果**两个字符不同**，则需要一次操作，取以下三种方式的**最小值再 +1**：**dp[i-1][j-1] + 1（替换）**——把 word1 的第 i 个字符替换成 word2 的第 j 个字符，于是问题变成"前 i-1 变前 j-1"；**dp[i-1][j] + 1（删除）**——删除 word1 的第 i 个字符，问题变成"前 i-1 变前 j"；**dp[i][j-1] + 1（插入）**——在 word1 末尾插入 word2 的第 j 个字符，问题变成"前 i 变前 j-1"。即 `dp[i][j] = min(替换 dp[i-1][j-1], 删除 dp[i-1][j], 插入 dp[i][j-1]) + 1`。**三种操作对应转移**的直观理解：删除对应"少看 word1 一个字符"（从 dp[i-1][j] 来）、插入对应"少看 word2 一个字符"（从 dp[i][j-1] 来）、替换对应"两个都少看一个字符并花一次替换"（从 dp[i-1][j-1] 来）；字符相同则免费从对角线 dp[i-1][j-1] 继承。最终答案是 dp[m][n]（m、n 是两串长度）。复杂度 O(m×n) 时间和空间（空间可用滚动数组优化到 O(n)）。编辑距离是"两个字符串对比"型二维 DP 的经典代表，是文本 diff、拼写纠错、DNA 序列比对等的基础算法。

</details>

4. 区间 DP 的特点是什么？为什么遍历顺序通常按"区间长度从小到大"？

<details><summary>参考答案</summary>

**区间 DP 的特点**：它的状态是定义在一个**区间**上的，通常写作 `dp[i][j]`，表示"原序列中从下标 i 到下标 j 这一段（子区间）"的某个最优解/结果（如这段的最长回文子序列长度、合并这段石头的最小代价、戳爆这段气球的最大收益等）。它的转移通常是**把大区间 [i, j] 分解为更小的子区间**来求解——要么是收缩两端（由 dp[i+1][j-1]、dp[i+1][j]、dp[i][j-1] 转移，如回文问题），要么是枚举一个分割点 k 把 [i,j] 分成 [i,k] 和 [k+1,j]（如合并石头、戳气球，dp[i][j] = 最优的 dp[i][k] + dp[k+1][j] + 合并代价）。基准情况通常是长度为 1 的区间（dp[i][i]）或空区间。**为什么遍历顺序按区间长度从小到大**：因为根据转移方程，**计算一个大区间 dp[i][j] 时，它依赖的都是比它更短的子区间的结果**（如 dp[i+1][j-1] 比 [i,j] 短 2、dp[i][k] 和 dp[k+1][j] 都是 [i,j] 的真子区间，长度更短）。动态规划要求"计算某状态时它依赖的状态都已经算好"，所以必须**先把所有更短的区间算完，再算更长的区间**——这就要求按区间长度递增的顺序遍历：先算所有长度为 1 的区间（base case），再算长度为 2 的，再长度为 3……最后算长度为 n 的整个区间 dp[0][n-1]。如果不按长度从小到大（比如简单地按 i 从小到大、j 从小到大的常规双重循环），就可能在计算 dp[i][j] 时它依赖的某个更短区间（如 dp[i+1][j-1]）还没被计算，导致用到未初始化的错误值。实现上常见两种等价写法：①外层循环区间长度 length 从 2 到 n、内层枚举起点 i（j = i+length-1）；②外层 i 从 n-1 倒序到 0、内层 j 从 i+1 正序到 n-1（这样也能保证算 dp[i][j] 时 dp[i+1][...] 和 dp[i][j-1] 已算好）。核心都是保证"短区间先于长区间被计算"。这个"按区间长度递增遍历"是区间 DP 区别于线性 DP 的标志性特征。

</details>

5. 树形 DP 和普通线性 DP 有什么不同？以打家劫舍 III 为例说明。

<details><summary>参考答案</summary>

**不同点**：①**结构载体不同**——普通线性 DP 的状态定义在线性序列（数组/字符串）的下标上（dp[i]、dp[i][j]），按下标顺序递推；**树形 DP 的状态定义在树的节点上**，表示"以某个节点为根的子树"的最优解，依赖的是该节点的**子节点的状态**。②**遍历方式不同**——线性 DP 用循环按下标顺序填表；树形 DP 用**递归 + 后序遍历**（先递归计算左右子树的状态、再合并到当前节点），因为父节点的结果依赖子节点的结果，必须"自底向上"先算子树（这与二叉树的后序递归套路一致，见 12）。③**状态的返回形式**——树形 DP 中，递归函数通常对每个节点**返回一组状态值（如一个数组/元组），表示该节点在不同"决策状态"下的最优解**，父节点根据子节点返回的这组值来计算自己的各状态值。**以打家劫舍 III 为例**（在二叉树上偷钱、不能偷直接相连的父子节点，求能偷到的最大金额）：对每个节点定义两个状态——"**不偷该节点时，以它为根的子树能偷到的最大金额**"和"**偷该节点时的最大金额**"，递归函数返回 [不偷, 偷] 这一对值。转移（在后序合并时）：①**偷当前节点**：那么它的左右孩子都不能偷，所以 `偷 = 当前节点值 + 左孩子的"不偷" + 右孩子的"不偷"`；②**不偷当前节点**：左右孩子可偷可不偷，各取其较大者，所以 `不偷 = max(左孩子偷, 左孩子不偷) + max(右孩子偷, 右孩子不偷)`。递归到空节点返回 [0, 0]。最终答案是根节点的 max(偷, 不偷)。可以看到：它的"状态"是定义在每个子树根节点上的、用递归后序自底向上计算、每个节点返回多个状态值供父节点合并——这些都体现了树形 DP 与线性 DP 的区别。本质上树形 DP 就是"在树的递归遍历中携带并合并 DP 状态"，是 DP 思想（状态 + 转移）与树形递归（分治、后序）的结合，常见于树上的最优选择问题（打家劫舍 III、二叉树最大路径和、树的最小覆盖等）。

</details>

6. 什么是"状态机 DP"？股票买卖问题为什么适合用它？

<details><summary>参考答案</summary>

**状态机 DP** 是指：当问题在每个阶段（如每一天、每个位置）可以处于**几种明确的、互斥的"状态"**之中，且这些状态之间按一定规则相互转移时，把这些状态及其转移建模成一个"状态机"，DP 的状态里就包含"当前处于哪个状态"这一维度（如 dp[i][状态]），转移方程描述"从前一阶段的各状态如何转移到当前阶段的各状态、取最优"。它适合那些"每一步要在若干种持有/进行中的状态间做选择"的问题。**股票买卖问题为什么适合用它**：股票买卖类问题（在给定每天价格下买卖股票求最大利润，有多种变体：只能交易一次、可多次交易、最多 k 次、含冷冻期、含手续费等）的本质，是**每一天你都处于某种"持仓状态"**——最基本的有两种状态：**"持有股票（手上有一支股票）"** 和 **"不持有股票（手上没有股票，持币观望）"**；更复杂的变体会增加状态，如"处于冷冻期"、"已用第 j 次交易且持有/不持有"等。每天你的状态会基于前一天的状态发生转移：例如"今天不持有"可以来自"昨天就不持有（保持）"或"昨天持有、今天卖出"；"今天持有"可以来自"昨天就持有（保持）"或"昨天不持有、今天买入"。这种"状态 + 状态间的转移 + 在每个状态上取最大利润"的结构，正好是状态机 DP 的形式。所以股票问题用状态机 DP 极其自然：**定义 dp[i][状态] = 第 i 天处于某状态时的最大利润**，写出各状态的转移方程（买入会减去当天价格、卖出会加上当天价格、保持则不变），递推到最后一天、取"不持有"状态的最大利润即为答案。它的优势是：面对各种变体（限制交易次数 → 多加一维 k；含冷冻期 → 多加一个冷冻状态；含手续费 → 在卖出转移里减手续费），只需相应地增加状态或修改转移方程，框架统一、思路清晰，而不必为每个变体单独想一套复杂逻辑。这也是为什么"股票买卖系列"是状态机 DP 的经典教学例题——它完美展示了"识别状态、画状态转移、写 DP"的思路。状态定义要满足无后效性（当前状态包含决策所需的全部信息，见 15）。

</details>
