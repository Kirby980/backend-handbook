# 精通滑动窗口

> 滑动窗口是同向双指针（[04](./04-精通-双指针.md)）的核心应用，专治"连续子数组/子串 + 最长/最短/满足条件"这类题。掌握通用模板，一类题全部拿下。本篇讲清可变长 / 定长两种模板。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、滑动窗口是什么

**滑动窗口（Sliding Window）**：用左右两个指针维护一个**连续区间 [left, right]**（窗口），通过 right 扩大、left 收缩，在数组/字符串上滑动这个窗口来求解。

适用特征（看到就想滑窗）：
- 数据是**连续的**子数组 / 子串（不是子序列）。
- 求**最长 / 最短 / 满足某条件**的窗口，或**定长窗口**的某种统计。

为什么高效：每个元素被 right 加入一次、被 left 移出一次，**整体 O(n)**（见 [04](./04-精通-双指针.md) 的摊还分析），把暴力枚举所有子串的 O(n²)/O(n³) 降到 O(n)。

---

## 二、通用模板

可变长滑动窗口的通用骨架（**最重要，背下来**）：

```go
func slidingWindow(s string) int {
    window := make(map[byte]int) // 窗口内的状态（按题意：计数/和/...）
    left, ans := 0, 0
    for right := 0; right < len(s); right++ {
        c := s[right]
        window[c]++ // 1. 扩大窗口：把 right 元素加入

        for /* 窗口不满足条件（需要收缩） */ {
            d := s[left]
            window[d]-- // 2. 收缩窗口：把 left 元素移出
            left++
        }

        // 3. 此时窗口满足条件，更新答案（求最长在收缩后更新）
        ans = max(ans, right-left+1)
    }
    return ans
}
```

三步：**扩窗（right 加入）→ 按条件收窗（left 移出）→ 更新答案**。关键是想清楚：
- 窗口里维护**什么状态**（字符计数、和、不同元素个数）。
- **什么时候收缩**（收缩条件）。
- **什么时候更新答案**（求最长 vs 求最短，更新时机不同）。

## 三、可变长窗口

可变长窗口的两个方向——**求最长**和**求最短**，更新答案的时机相反：

**求最长**（窗口尽量大，不满足才收缩）：

```go
// 无重复字符的最长子串
func lengthOfLongestSubstring(s string) int {
    window := make(map[byte]int)
    left, ans := 0, 0
    for right := 0; right < len(s); right++ {
        c := s[right]
        window[c]++
        for window[c] > 1 { // 出现重复，收缩到无重复
            window[s[left]]--
            left++
        }
        ans = max(ans, right-left+1) // 收缩后窗口合法，更新最长
    }
    return ans
}
```

**求最短**（窗口满足条件就尽量收缩，收缩时更新）：

```go
// 长度最小的子数组（和 >= target 的最短连续子数组）
func minSubArrayLen(target int, nums []int) int {
    left, sum, ans := 0, 0, len(nums)+1
    for right := 0; right < len(nums); right++ {
        sum += nums[right]
        for sum >= target { // 满足条件，尽量收缩并更新最短
            ans = min(ans, right-left+1)
            sum -= nums[left]
            left++
        }
    }
    if ans == len(nums)+1 {
        return 0
    }
    return ans
}
```

区别：**求最长在收缩之后更新答案**（窗口合法时尽量大）；**求最短在收缩之中更新答案**（满足时尽量小）。

## 四、定长窗口

**定长窗口**（窗口大小固定为 k）：right 和 left 保持 k 的距离，窗口滑动时一进一出：

```go
// 大小为 k 的窗口的最大平均值（求定长窗口的和的最大值）
func maxSumSubarray(nums []int, k int) int {
    sum := 0
    for i := 0; i < k; i++ { // 先填满第一个窗口
        sum += nums[i]
    }
    ans := sum
    for right := k; right < len(nums); right++ {
        sum += nums[right] - nums[right-k] // 进一个、出一个
        ans = max(ans, sum)
    }
    return ans
}
```

定长窗口更简单：**滑动时加入新进的、减去移出的**，维护窗口状态。求定长窗口最值时，若要 O(1) 取窗口最值，用**单调队列**（见 [10 栈与队列](./10-精通-栈与队列.md)）。

## 五、经典题

| 题 | 窗口状态 | 收缩条件 | 求 |
|---|---|---|---|
| 无重复字符最长子串 | 字符计数 | 有字符 count>1 | 最长 |
| 最小覆盖子串 | 字符计数 + 已覆盖数 | 已覆盖所有目标字符 | 最短 |
| 长度最小子数组 | 窗口和 | 和 ≥ target | 最短 |
| 找所有字母异位词 | 字符计数 | 窗口=定长 | 定长匹配 |
| 至多 K 个不同字符 | 不同字符数 | 不同字符 > K | 最长 |

**最小覆盖子串**是滑窗难题代表：维护"还需多少个目标字符"，窗口覆盖全部目标时收缩求最短。这类题的关键是设计好"窗口状态"和"满足条件的判定"。

## 六、窗口内状态维护

滑窗的难点在**高效维护窗口状态**（O(1) 更新）：
- **字符/数字计数**：用哈希表或定长数组（`[26]int`/`[128]int`，见 [02](./02-精通-数组与字符串技巧.md)）。
- **窗口和**：加入时 +、移出时 -。
- **不同元素个数**：计数从 0→1 时 +1，从 1→0 时 -1。
- **窗口最值**：用**单调队列**（[10](./10-精通-栈与队列.md)）维持 O(1) 取最值（普通方法取最值是 O(k)）。

状态维护要做到**进出窗口都 O(1)**，整体才是 O(n)。

---

## 七、识别与复杂度

**识别滑窗**：题目有"连续子数组/子串" + "最长/最短/恰好/至多/至少满足某条件"，且**移动窗口时状态可增量更新**（单调性：窗口扩大时某指标单调变化）。

**复杂度**：O(n)（每个元素进出窗口各一次），空间 O(窗口内不同元素数)（哈希表/计数数组）。

注意：如果窗口**没有单调性**（如"和恰好等于 k"且有负数，扩窗和不单调），滑窗不适用，要用**前缀和 + 哈希表**（见 [02](./02-精通-数组与字符串技巧.md)）。

## 陷阱清单

- **用滑窗解非连续子序列**：滑窗只适用连续子数组/子串，子序列要用 DP（[16](./16-精通-经典DP专题.md)）。
- **求最长/最短更新时机搞反**：求最长在收缩后更新（窗口合法时尽量大）；求最短在收缩中更新（满足时尽量小）。
- **窗口状态更新不对称**：进窗口加什么，出窗口必须减什么，否则状态错乱。
- **有负数还用滑窗求"和=k"**：负数破坏单调性，滑窗失效，用前缀和+哈希。
- **收缩条件写错导致死循环或漏解**：想清"什么时候必须收缩"。
- **定长窗口边界**：先填满前 k 个再滑动，注意 right-k 的下标。
- **窗口最值用暴力 O(k)**：定长窗口求最值用单调队列降到 O(1)（[10](./10-精通-栈与队列.md)）。

## 练习题

1. 滑动窗口适合解决什么类型的问题？看到什么特征就应该想到它？

<details><summary>参考答案</summary>

滑动窗口适合解决**连续子数组 / 子串**相关的问题，特别是求"满足某条件的最长 / 最短窗口"或"定长窗口的某种统计"。看到以下特征就应该想到滑动窗口：①问题针对的是**连续的**一段（子数组、子串），而**不是**可以跳着选的子序列（子序列要用 DP）；②要求的是**最长、最短、恰好、至多 K 个、至少 K 个**等满足某条件的连续区间，或者固定长度 k 的窗口的最大/最小和/平均等；③随着窗口的扩大或缩小，所关心的指标（如窗口和、不同字符数、某字符出现次数）能够**增量地、单调地更新**（窗口扩大时该指标单调变大或某种性质单调变化，使得"何时该收缩"有明确依据）。典型题：无重复字符的最长子串、长度最小的子数组（和≥target）、最小覆盖子串、找所有字母异位词、至多包含 K 个不同字符的最长子串等。识别口诀："连续子数组/子串 + 最长/最短/满足条件 + 状态可增量维护"。反例（不适用滑窗）：求子序列（非连续，用 DP）、或窗口指标没有单调性的情况（如数组含负数还要求"和恰好等于 k"，扩窗时和不单调，应改用前缀和+哈希表）。

</details>

2. 写出可变长滑动窗口的通用模板，并说明"求最长"和"求最短"更新答案的时机为什么不同。

<details><summary>参考答案</summary>

通用模板（三步）：用 left、right 维护窗口 [left, right]，外层 for 让 right 从 0 到 n-1：①**扩窗**——把 nums[right]/s[right] 加入窗口，更新窗口状态（计数、和等）；②**收窗**——用一个 while 循环：当窗口"不满足条件（求最长时）"或"满足条件可继续缩小（求最短时）"时，把 nums[left] 移出窗口、更新状态、left++；③**更新答案**——在恰当时机用 right-left+1 更新答案。骨架：
```
left, ans := 0, init
for right := 0; right < n; right++ {
    加入 nums[right] 更新状态
    for 需要收缩 { 移出 nums[left]; left++ }
    更新 ans
}
```
**"求最长"和"求最短"更新时机不同的原因**：①**求最长**——我们希望窗口尽可能大，所以让窗口不断扩大，只有当窗口**违反条件**时才收缩（把它缩回合法状态）。收缩完成后，窗口一定是"合法且尽可能大"的，此时（**收缩之后**、循环体末尾）用 right-left+1 更新最大长度。也就是"先扩到不能扩、缩回合法、再记录最长"。②**求最短**——我们希望找到满足条件的最小窗口，所以一旦窗口**满足条件**，就应该尝试不断收缩 left 让它更小，并在**收缩的过程中（while 循环内、满足条件时）**就更新最小长度（因为每次缩小后只要还满足条件就是更短的候选，缩到不满足为止）。也就是"满足条件就尽量缩、边缩边记录最短"。一句话：求最长是"窗口合法时取最大"（收缩后更新），求最短是"窗口满足时尽量缩并取最小"（收缩中更新）——本质是因为最长要的是"合法的最大窗口"、最短要的是"满足条件的最小窗口"，两者对"何时窗口处于我们想记录的状态"判断相反。

</details>

3. 用滑动窗口求"无重复字符的最长子串"，窗口里维护什么状态？收缩条件是什么？

<details><summary>参考答案</summary>

窗口里维护**当前窗口内每个字符的出现次数**（用哈希表 map[byte]int 或定长数组 [128]int 计数）。算法流程：right 从左到右扩窗，每次把字符 s[right] 加入窗口、其计数 +1；**收缩条件是"当前加入的字符在窗口内出现次数 > 1"**（即出现了重复字符）——此时用 while 循环不断从左边收缩：把 s[left] 移出窗口（计数 -1）、left++，直到刚才那个重复字符的计数回到 1（窗口内不再有重复）。收缩完成后，窗口 [left, right] 内保证所有字符都不重复，此时用 right-left+1 更新最长长度 ans。这样每个字符进窗口一次、出窗口一次，O(n)。**为什么这样设计**：题目要求子串内无重复字符，所以窗口的"合法状态"就是"窗口内无重复字符"；用计数维护每个字符的出现次数，新加入字符后若它的计数变成 2 就说明产生了重复，必须从左收缩把前面那个相同字符移出去（连同中间的字符），直到窗口重新无重复。这是"求最长"型滑窗，所以在收缩到合法之后才更新答案。窗口状态用字符计数是因为它能 O(1) 地在字符进/出窗口时更新、并 O(1) 判断是否有重复（看刚加入字符的计数是否 >1）。也可以用一个哈希表记录字符最近出现的下标来直接跳转 left（优化版），但用计数 + 逐步收缩是最通用、最契合模板的写法。

</details>

4. 滑动窗口的时间复杂度为什么是 O(n)？

<details><summary>参考答案</summary>

滑动窗口虽然代码里有"外层 for（right）+ 内层 while（left 收缩）"的嵌套结构，但整体时间复杂度是 O(n)，不是 O(n²)。原因是**两个指针 left 和 right 都只单调向右移动、从不回退，各自移动的总步数都不超过 n**。具体来说：外层循环让 right 从 0 走到 n-1，right 总共移动 n 次（每个元素被加入窗口恰好一次）；内层 while 循环让 left 向右收缩，但 left 同样**只增不减、单调右移**，所以在**整个算法的全过程中**，left 累计移动的总次数也最多是 n（每个元素被移出窗口至多一次）。关键点在于：内层 while 的执行次数不是"每次外层迭代都执行 O(n) 次"，而是"在所有外层迭代之间总共执行不超过 n 次"——left 的移动被摊销到了整个过程中。因此总的操作次数 = right 移动约 n 次 + left 移动至多 n 次 + 每次常数时间的窗口状态更新 = O(2n) = **O(n)**。这是一种摊还（amortized）分析的思想：不能只看循环嵌套的层数来判断复杂度，而要统计指针/操作的**总执行次数**。因为每个元素最多被 right 加入窗口一次、被 left 移出窗口一次，总共线性次操作，所以滑动窗口是 O(n)，这也正是它能把暴力枚举所有子串的 O(n²) 优化到线性的根本原因。空间复杂度为 O(窗口内不同元素数)（哈希表/计数数组）。

</details>

5. 定长滑动窗口和可变长滑动窗口在实现上有什么区别？

<details><summary>参考答案</summary>

**可变长滑动窗口**：窗口大小不固定，由"是否满足某条件"动态决定。实现上 right 不断扩窗，然后用一个内层 while 根据条件**动态地收缩 left**（窗口大小随条件变化而伸缩），并在恰当时机（求最长在收缩后、求最短在收缩中）更新答案。它的难点在于设计"窗口状态"和"收缩条件"，以及更新答案的时机。适合"最长/最短满足条件的子串/子数组"类问题。**定长滑动窗口**：窗口大小固定为 k，left 和 right 始终保持 k 的距离同步移动。实现上更简单：先用前 k 个元素填满第一个窗口、计算初始状态（如窗口和）；然后让窗口整体向右滑动——每滑一步就"**加入新进入窗口的元素 nums[right]、减去离开窗口的元素 nums[right-k]**"（一进一出，O(1) 更新窗口状态），并在每个位置更新答案。不需要内层 while 动态收缩，因为窗口大小恒定。适合"固定长度 k 的窗口的最大/最小和、平均值、是否匹配（如找定长的字母异位词）"类问题。区别小结：可变长用"扩窗 + 条件收缩"两个指针独立移动、窗口大小动态变化、需要内层 while；定长是两个指针同步移动保持距离 k、每步一进一出、无需内层收缩循环、实现更直接。共同点是都靠增量维护窗口状态做到 O(n)。补充：定长窗口若要 O(1) 求窗口内最大/最小值，需要配合单调队列（见 10）。

</details>

6. 什么情况下"连续子数组求和"问题不能用滑动窗口？应该用什么？

<details><summary>参考答案</summary>

当数组中**含有负数**（或窗口指标不具有单调性）时，"连续子数组求和"类问题（尤其是"和恰好等于 k"或"和等于某值的子数组个数/最长子数组"）**不能用滑动窗口**。原因：滑动窗口能工作的前提是窗口指标随窗口扩大/收缩**单调变化**——例如全是正数时，窗口越大和越大、移出元素和一定减小，所以可以根据"和与 target 的大小关系"确定性地决定扩窗还是收窗（这正是"长度最小子数组、和≥target"能用滑窗的原因）。但如果数组有负数，扩大窗口时和**不再单调递增**（加入一个负数和会变小），收缩时和也不单调，于是"该扩还是该缩"失去了确定的依据，滑窗逻辑崩溃——你无法通过移动指针单调地逼近目标。**应该用前缀和 + 哈希表**：先求前缀和 prefix（prefix[i] 表示前 i 个元素之和，见 02），那么子数组 [l, r] 的和 = prefix[r+1] - prefix[l]；要找"和等于 k 的子数组"，就是找满足 prefix[r+1] - prefix[l] = k 即 prefix[l] = prefix[r+1] - k 的配对。遍历过程中用哈希表记录已出现的前缀和（及其出现次数或最早下标），对每个 prefix[r+1] 查哈希表里有没有 prefix[r+1]-k，即可 O(n) 求"和为 k 的子数组个数/是否存在"等。这种"前缀和 + 哈希表"不依赖单调性，能处理含负数的情况，是和为 k 子数组、连续子数组和的众数等问题的标准解法。一句话：和恒为正/单调 → 滑动窗口；含负数/无单调性 → 前缀和 + 哈希表。

</details>
