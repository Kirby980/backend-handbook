# 精通二叉树

> 二叉树是面试出现频率最高的数据结构之一，而且它是**分治/递归思想的最佳载体**——绝大多数树题都能用"递归解左子树 + 递归解右子树 + 合并"的套路解决。本篇讲透遍历、递归套路、BST 和高频题。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、二叉树基础

```go
type TreeNode struct {
    Val         int
    Left, Right *TreeNode
}
```

几个概念：
- **满二叉树**：每个非叶节点都有两个子节点。
- **完全二叉树**：除最后一层外都满，最后一层节点靠左连续（堆的底层结构，[13](./13-精通-堆与TopK.md)）。
- **二叉搜索树（BST）**：左子树所有值 < 根 < 右子树所有值（见第四节）。
- **平衡二叉树**：任意节点左右子树高度差 ≤ 1（AVL、红黑树）。

二叉树天然递归——每个节点的左右子树又是二叉树，这是树题套路的根基。

## 二、遍历

**深度优先（DFS）三种序** + **广度优先（BFS）层序**：

| 遍历 | 顺序 | 用途 |
|---|---|---|
| 前序 | 根 → 左 → 右 | 复制树、序列化 |
| 中序 | 左 → 根 → 右 | **BST 中序得有序序列** |
| 后序 | 左 → 右 → 根 | 释放树、自底向上算 |
| 层序 | 一层一层 | 按层处理、最短路径 |

递归遍历（简洁）：

```go
func inorder(root *TreeNode, res *[]int) {
    if root == nil {
        return
    }
    inorder(root.Left, res)       // 左
    *res = append(*res, root.Val) // 根（中序：根在中间）
    inorder(root.Right, res)      // 右
}
```

层序遍历（BFS，用队列）：

```go
func levelOrder(root *TreeNode) [][]int {
    var res [][]int
    if root == nil {
        return res
    }
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        size := len(queue) // 当前层节点数（关键：固定这一层的数量）
        var level []int
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            level = append(level, node.Val)
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        res = append(res, level)
    }
    return res
}
```

层序的关键：**每轮循环前记录当前层节点数 size**，只处理这 size 个，就能分层。迭代版 DFS 用栈（前序好写，中序后序稍复杂），面试递归为主。

## 三、递归解题套路

**这是二叉树的精髓。** 几乎所有树题都能套这个思路：**把问题分解成"左子树的解 + 右子树的解 + 当前节点的处理"**（分治，见 [09](./09-精通-分治与归并思想.md)）。

两种递归方向：

**自底向上（后序，最常用）**：先递归算出左右子树的结果，再合并到当前节点：

```go
// 最大深度：左右子树深度的最大值 + 1
func maxDepth(root *TreeNode) int {
    if root == nil { // base case
        return 0
    }
    left := maxDepth(root.Left)   // 左子树深度
    right := maxDepth(root.Right) // 右子树深度
    return max(left, right) + 1   // 合并：取大的 + 当前节点
}
```

**自顶向下（前序）**：从根把信息传递给子节点：

```go
// 路径总和：从根传递剩余目标值
func hasPathSum(root *TreeNode, target int) bool {
    if root == nil {
        return false
    }
    if root.Left == nil && root.Right == nil { // 叶节点
        return target == root.Val
    }
    remain := target - root.Val // 向下传递剩余目标
    return hasPathSum(root.Left, remain) || hasPathSum(root.Right, remain)
}
```

写树的递归三问（同 [递归三要素](./08-精通-递归回溯与DFS.md)）：
1. **base case**：通常是 `root == nil`（或叶节点）。
2. **递归子问题**：递归处理 `root.Left` 和 `root.Right`。
3. **合并**：用左右子树的结果 + 当前节点算出答案。

掌握这个套路，最大深度、对称树、翻转树、路径和、直径等题都迎刃而解。

## 四、BST（二叉搜索树）

**二叉搜索树（BST）** 的核心性质：**左子树 < 根 < 右子树**（对每个节点都成立）。由此：

- **中序遍历得到升序序列**（最重要的性质，验证 BST、找第 K 小都靠它）。
- **查找/插入/删除平均 O(log n)**（树平衡时），最坏 O(n)（退化成链表）。

```go
// BST 查找：利用有序性，每次走一边
func searchBST(root *TreeNode, val int) *TreeNode {
    for root != nil {
        if val == root.Val {
            return root
        } else if val < root.Val {
            root = root.Left  // 目标更小，走左
        } else {
            root = root.Right // 目标更大，走右
        }
    }
    return nil
}

// 验证 BST：中序遍历应严格递增
func isValidBST(root *TreeNode) bool {
    var prev *TreeNode
    var inorder func(*TreeNode) bool
    inorder = func(node *TreeNode) bool {
        if node == nil {
            return true
        }
        if !inorder(node.Left) {
            return false
        }
        if prev != nil && prev.Val >= node.Val { // 中序非递增 → 非 BST
            return false
        }
        prev = node
        return inorder(node.Right)
    }
    return inorder(root)
}
```

BST 题套路：**利用"中序有序"和"左小右大"的性质**——验证 BST、BST 第 K 小、范围查询、最近公共祖先（BST 版可用值比较）都基于此。BST 是平衡树（红黑树，[Java TreeMap](../java/J01-精通-集合框架与List源码.md)）和数据库索引（[B 树](../backend/B08-精通数据库索引.md)）的基础。

## 五、常见题

| 题 | 套路 |
|---|---|
| 最大深度 | 自底向上，max(左,右)+1 |
| 是否平衡 | 自底向上算高度，顺便判左右差≤1 |
| 翻转二叉树 | 递归交换左右子树 |
| 对称二叉树 | 递归比较左子树和右子树的镜像 |
| 路径总和 | 自顶向下传递剩余目标 |
| **最近公共祖先（LCA）** | 后序，左右子树各找一个则当前是 LCA |
| 二叉树直径 | 后序，左高+右高更新全局最大 |

**最近公共祖先（LCA）** 是经典：

```go
func lowestCommonAncestor(root, p, q *TreeNode) *TreeNode {
    if root == nil || root == p || root == q {
        return root // 找到 p 或 q（或到底），返回
    }
    left := lowestCommonAncestor(root.Left, p, q)   // 左子树找
    right := lowestCommonAncestor(root.Right, p, q) // 右子树找
    if left != nil && right != nil {
        return root // p、q 分别在左右两侧 → 当前节点是 LCA
    }
    if left != nil { // 都在左子树
        return left
    }
    return right // 都在右子树（或都没找到）
}
```

LCA 的精髓：后序遍历，**如果 p 和 q 分别在当前节点的左右子树里，当前节点就是它们的最近公共祖先**。

## 六、构造二叉树

由遍历序列重建二叉树（经典）：**前序 + 中序** 或 **后序 + 中序** 能唯一确定一棵树。

原理：
- **前序的第一个**是根；在**中序**里找到根的位置，左边是左子树的中序、右边是右子树的中序，由此知道左右子树的节点数。
- 递归构造左右子树。

```go
func buildTree(preorder, inorder []int) *TreeNode {
    if len(preorder) == 0 {
        return nil
    }
    rootVal := preorder[0]        // 前序首个是根
    root := &TreeNode{Val: rootVal}
    i := 0
    for inorder[i] != rootVal {   // 在中序找根的位置
        i++
    }
    // i 个节点在左子树
    root.Left = buildTree(preorder[1:i+1], inorder[:i])
    root.Right = buildTree(preorder[i+1:], inorder[i+1:])
    return root
}
```

为什么需要中序 + 另一序：**中序确定左右子树的划分**，前序/后序确定根。两个前序无法确定树（不知左右边界）。

## 七、识别与套路

- **几乎所有树题** → 递归（分治）：base case（nil）+ 递归左右 + 合并。
- **算高度/深度/直径/平衡/路径** → 自底向上（后序）。
- **从根传信息** → 自顶向下（前序）。
- **按层处理 / 最短路径** → BFS 层序（队列 + 记录层 size）。
- **BST 相关** → 利用"中序有序"和"左小右大"。
- **重建树** → 前/后序定根 + 中序定左右。

---

## 陷阱清单

- **忘记 base case（nil 判断）**：空指针 panic 或无限递归。树递归第一行通常判 `root == nil`。
- **层序遍历不记录层 size**：无法分层；要在每轮循环前固定当前层节点数。
- **验证 BST 只比较父子**：必须保证整个左子树都小于根（用中序或传上下界），只比直接子节点是错的。
- **混淆完全二叉树和满二叉树**：完全是"最后一层靠左连续"，满是"每层都满"。
- **递归方向选错**：算高度类用自底向上（后序），传递目标类用自顶向下（前序）。
- **构造树缺中序**：两个前序/后序无法唯一确定树，必须有中序划分左右。
- **递归过深栈溢出**：极度不平衡的树（退化成链）递归深度 O(n)。
- **LCA 没考虑节点本身是祖先**：p 是 q 的祖先时 LCA 是 p，base case 要 `root==p||root==q` 就返回。

## 练习题

1. 二叉树的前序、中序、后序、层序遍历分别是什么顺序？各有什么用途？

<details><summary>参考答案</summary>

四种遍历：①**前序遍历（Pre-order）**——访问顺序是"**根 → 左子树 → 右子树**"，即先处理当前节点、再递归左、再递归右。用途：**复制/克隆一棵树**（先建根再建左右）、**序列化二叉树**（前序能记录树的结构）、需要"先处理父节点再处理子节点"的场景。②**中序遍历（In-order）**——顺序是"**左子树 → 根 → 右子树**"。最重要的用途是：**对二叉搜索树（BST）做中序遍历会得到一个升序排列的有序序列**（因为 BST 左 < 根 < 右）——所以验证一棵树是否是 BST、求 BST 中第 K 小的元素、BST 范围查询等都靠中序遍历。③**后序遍历（Post-order）**——顺序是"**左子树 → 右子树 → 根**"，即先处理完两个子树再处理当前节点。用途：需要**先得到子节点信息再处理父节点**的场景，如计算树的高度/深度、判断平衡、计算节点占用、**释放/删除整棵树**（先删子树再删根）、以及大量"自底向上"的树形递归（如二叉树直径、最大路径和、LCA）。④**层序遍历（Level-order / BFS）**——按层从上到下、每层从左到右逐层访问。用法是借助**队列**实现（广度优先），关键技巧是每轮循环前记录当前层的节点数 size 以便分层。用途：**按层处理节点**（如返回每层的值、找每层最大值、之字形遍历）、**求最短路径/最小深度**（BFS 第一次到达即最短）、按层级的各种统计。简记：前序根在前（复制/序列化），中序根在中（BST 有序），后序根在后（自底向上/释放），层序按层（BFS/最短）。前中后序是 DFS（深度优先），层序是 BFS（广度优先）。

</details>

2. 二叉树递归解题的通用套路是什么？以"求最大深度"为例说明。

<details><summary>参考答案</summary>

通用套路是把二叉树问题**分解成"左子树的解 + 右子树的解 + 当前节点的处理"**（分治思想）——因为每个节点的左右子树本身又是规模更小的二叉树，可以递归求解，再在当前节点合并子树的结果。写树递归要想清三件事（同递归三要素）：①**base case（递归终止）**——通常是 `root == nil`（空节点）返回一个边界值，有时是叶节点；②**递归子问题**——递归地处理 root.Left 和 root.Right，得到左右子树的结果；③**合并**——用左右子树的结果加上当前节点的信息，计算出当前（以 root 为根的子树）的答案并返回。**以"求最大深度"为例**：定义"以 root 为根的树的最大深度"。①base case：如果 root 为 nil，深度是 0（空树没有节点）；②递归子问题：分别递归求左子树的最大深度 `left = maxDepth(root.Left)` 和右子树的最大深度 `right = maxDepth(root.Right)`；③合并：当前树的最大深度 = 左右子树深度的较大者再加上当前这一层（根节点）的 1，即 `return max(left, right) + 1`。这就是典型的**自底向上（后序）**递归——先得到子树结果，再合并到根。整个过程每个节点访问一次，时间 O(n)、空间 O(树高)（递归栈）。这个"base case 判空 → 递归左右子树 → 合并结果"的三段式套路适用于绝大多数树题：求高度、判断平衡、翻转树、对称树、路径和、二叉树直径、最近公共祖先等，差别只在于"合并逻辑"和"递归是自底向上还是自顶向下"。掌握它，二叉树题就有了统一的思考框架。

</details>

3. 二叉搜索树（BST）有什么核心性质？如何利用它高效解题？

<details><summary>参考答案</summary>

BST 的核心性质是：**对树中每一个节点，它的左子树中所有节点的值都小于它，右子树中所有节点的值都大于它**（通常假设无重复值），且这个性质对每个节点递归成立。由此衍生出两个最有用的推论：①**中序遍历 BST 会得到一个严格递增（升序）的有序序列**——这是 BST 最重要的性质；②**从根开始可以像二分一样查找**——比较目标值与当前节点：相等则找到，小于就去左子树、大于就去右子树，每次排除一半，平均 O(log n)。**如何利用它高效解题**：①**查找/插入/删除**——利用"左小右大"每次只走一个分支，平均 O(log n)（树平衡时），比普通二叉树的 O(n) 快；②**验证是否是 BST**——做中序遍历，检查结果是否严格递增（或递归时传入每个节点允许的取值上下界 [min, max] 来校验，注意不能只比较父子两个节点，必须保证整个左子树都小于根）；③**求 BST 中第 K 小/大的元素**——中序遍历到第 K 个就是第 K 小（中序有序），无需排序；④**范围查询**（找 [low, high] 内的所有值）——利用有序性剪枝，小于 low 不必看左、大于 high 不必看右；⑤**BST 的最近公共祖先**——可以直接用值比较：从根开始，若 p、q 都小于当前节点就去左、都大于就去右、否则当前节点就是 LCA（比普通二叉树 LCA 更简单）；⑥**找前驱/后继、最近值**等也靠有序性。一句话：**凡是 BST 题，先想"中序有序"和"左小右大可二分"这两个性质**，往往能把问题简化或降低复杂度。BST 也是工程中有序映射（红黑树/TreeMap）和数据库索引（B/B+ 树）的理论基础。注意 BST 最坏情况（插入有序数据）会退化成链表、操作变 O(n)，所以工程上用自平衡 BST（红黑树、AVL）保证 O(log n)。

</details>

4. 如何用递归求二叉树的最近公共祖先（LCA）？

<details><summary>参考答案</summary>

求两个节点 p、q 的最近公共祖先（LCA）用**后序遍历的递归**，思路是"在以 root 为根的树中寻找 p 和 q，并向上汇报找到的情况"。递归函数 lca(root, p, q) 的逻辑：①**base case**——如果 root 为 nil，返回 nil（没找到）；如果 root 等于 p 或等于 q，就返回 root（找到了其中一个，向上汇报"我这棵子树里有 p 或 q"，注意这也处理了"p 是 q 的祖先"的情况）。②**递归左右子树**——left = lca(root.Left, p, q) 在左子树里找，right = lca(root.Right, p, q) 在右子树里找。③**根据左右结果判断**：如果 **left 和 right 都非空**，说明 p 和 q 分别位于当前 root 的左右两侧子树中，那么**当前 root 就是它们的最近公共祖先**，返回 root；如果**只有 left 非空**（right 为 nil），说明 p 和 q 都在左子树里（或只在左边找到了相关节点），返回 left（把左子树找到的结果继续向上传）；如果**只有 right 非空**，返回 right；如果**都为空**，返回 nil。**核心洞察**：LCA 的判定就是"**p 和 q 第一次分处某节点的左右两侧的那个节点**"——当一个节点的左子树里找到了一个目标、右子树里找到了另一个目标时，这个节点就是它们分叉的最近公共祖先。而 base case 里"遇到 p 或 q 就返回它自己"保证了：若 p 本身就是 q 的祖先（q 在 p 的子树里），递归到 p 时就返回 p，p 即为 LCA。时间复杂度 O(n)（每个节点访问一次），空间 O(树高)。补充：如果是**二叉搜索树**的 LCA，可以更简单——利用 BST 有序性，从根开始，若 p、q 都小于当前节点值就往左走、都大于就往右走、否则当前节点就是 LCA，O(树高) 且无需遍历整棵树。

</details>

5. 为什么"前序 + 中序"可以唯一构造一棵二叉树，而"前序 + 后序"通常不能？

<details><summary>参考答案</summary>

关键在于**中序遍历能确定左右子树的分界，而前序/后序只能确定根**。**前序 + 中序能唯一构造的原因**：前序遍历的**第一个元素一定是根节点**（前序是"根→左→右"）。拿到根之后，到**中序遍历**（"左→根→右"）里找到这个根的位置——根左边的所有元素就是**左子树的中序序列**、根右边的就是**右子树的中序序列**，由此就**确定了左子树和右子树各有多少个节点、分别是哪些**。再根据这个数量，把前序剩余部分也切成"左子树的前序"和"右子树的前序"，然后递归地对左、右子树重复这个过程，就能唯一地重建整棵树。即：**前序定根、中序借根的位置定左右子树的划分**，两者配合信息完整、能唯一确定。**前序 + 后序通常不能唯一确定的原因**：前序的第一个是根、后序的最后一个也是根，它们都能告诉你"根是谁"，但**都无法告诉你左右子树的分界点在哪**——缺少中序提供的"根的左边是左子树、右边是右子树"这个划分信息。特别是当某个节点**只有一个子节点**（只有左孩子或只有右孩子）时，光看前序和后序无法区分这个唯一的孩子到底是左孩子还是右孩子（两种情况的前序和后序序列完全相同），于是会有多棵不同的树对应同一对前序+后序序列，无法唯一确定。（只有当树是"满二叉树"——每个节点要么有两个孩子要么没有孩子时，前序+后序才能唯一确定，因为不存在"只有一个孩子"的歧义。）所以构造二叉树必须有**中序**来划分左右子树，配上前序或后序（用来定根）即可唯一重建：前序+中序、或后序+中序都行，但前序+后序一般不行。

</details>

6. 层序遍历（BFS）为什么要记录"当前层的节点数"？

<details><summary>参考答案</summary>

记录"当前层的节点数 size"是为了**把队列里的节点按层分隔开**，从而能区分每个节点属于哪一层、实现"逐层处理"。层序遍历用队列实现 BFS：把根入队，然后不断从队头取节点、把它的左右孩子入队。如果只是简单地一个个出队，**所有层的节点是混在队列里连续处理的**，你无法知道"哪些节点属于同一层""一层到哪里结束、下一层从哪里开始"。而很多题目需要按层输出或按层统计——比如"返回每一层的节点值列表"（每层一个数组）、"求每层的最大值/平均值"、"之字形（锯齿）层序遍历"、"二叉树的右视图（每层最后一个节点）"、"判断完全二叉树"等，这些都必须知道每一层的边界。**做法**：在每一轮（处理一层）开始时，先记录下此刻**队列的长度 size**——因为这个时刻队列里恰好装的就是"当前这一层的全部节点"（上一层已全部出队、它们的孩子即当前层已全部入队）。然后只**循环 size 次**，把这 size 个节点出队处理（同时把它们的孩子入队，作为下一层），这一轮结束就正好处理完了一整层；下一轮再重新读取队列长度作为下一层的 size。这样每一轮循环精确对应一层，就能把节点按层分组。如果**不记录 size**、写成普通的 while(队列非空) 一个个处理，虽然也能完成遍历，但无法分层（不知道层边界），只能得到一个所有节点混在一起的序列，做不了上述按层的题目。所以"每轮固定当前层节点数 size、只处理这 size 个"是 BFS 层序遍历分层的关键技巧。

</details>
