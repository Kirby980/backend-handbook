# 精通双指针

> 双指针是性价比最高的算法技巧之一——用两个指针的协同移动，把很多 O(n²) 的暴力解降到 O(n)。它分对撞、快慢、同向三类，覆盖大量数组/字符串/链表题。本篇讲清三类模板和识别方法。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、双指针总览

双指针 = 用两个指针在数据上移动，通过它们的**相对位置/速度**减少重复扫描。三大类：

| 类型 | 指针怎么动 | 典型题 |
|---|---|---|
| **对撞指针** | 一头一尾，向中间靠拢 | 两数之和 II、盛水容器、反转 |
| **快慢指针** | 同起点，不同速度 | 原地去重、移动零、链表判环（[03](./03-精通-链表技巧.md)） |
| **同向指针** | 同向移动，一前一后 | 滑动窗口（[05](./05-精通-滑动窗口.md)）、删除重复 |

核心思想：**利用数据的某种性质（有序、单调）让两个指针只朝一个方向走，每个元素最多被访问常数次，从而 O(n)**。

---

## 二、对撞指针

**对撞指针（左右指针）**：left 从头、right 从尾，向中间移动。**前提常是数组有序**：

```go
// 两数之和 II（输入有序数组，找两数之和=target）
func twoSum(numbers []int, target int) []int {
    l, r := 0, len(numbers)-1
    for l < r {
        sum := numbers[l] + numbers[r]
        switch {
        case sum == target:
            return []int{l + 1, r + 1}
        case sum < target:
            l++ // 和小了，左指针右移（变大）
        default:
            r-- // 和大了，右指针左移（变小）
        }
    }
    return nil
}
```

为什么 O(n)：利用**有序性**，sum 小就移左（增大）、大就移右（减小），每步排除一个不可能的元素，左右指针总共移动 n 次。暴力是 O(n²)，对撞降到 O(n)。

盛水最多的容器、有效回文判断、反转数组（[02](./02-精通-数组与字符串技巧.md)）都是对撞指针。

---

## 三、快慢指针

**快慢指针**：两个指针同向但速度/角色不同，常用于**原地处理**（slow 维护结果边界，fast 探索）：

```go
// 移动零：把所有 0 移到末尾，非零保持相对顺序（原地）
func moveZeroes(nums []int) {
    slow := 0 // slow 指向下一个非零该放的位置
    for fast := 0; fast < len(nums); fast++ {
        if nums[fast] != 0 {
            nums[slow], nums[fast] = nums[fast], nums[slow] // 非零换到前面
            slow++
        }
    }
}

// 删除有序数组重复项（原地）
func removeDuplicates(nums []int) int {
    if len(nums) == 0 {
        return 0
    }
    slow := 0
    for fast := 1; fast < len(nums); fast++ {
        if nums[fast] != nums[slow] { // 遇到新值
            slow++
            nums[slow] = nums[fast]
        }
    }
    return slow + 1 // 新长度
}
```

模式：**slow 指向"已处理好的部分"的边界，fast 向前探索**，满足条件才把元素放到 slow 处。这是原地去重/移除类题的通用套路（链表版见 [03](./03-精通-链表技巧.md)）。

---

## 四、同向双指针

**同向双指针**：两指针都从左向右，一前一后，维护一个"区间/窗口"。这是**滑动窗口的本质**（见 [05](./05-精通-滑动窗口.md)）：

```go
// 同向指针维护窗口的骨架（滑窗）
left := 0
for right := 0; right < n; right++ {
    // 1. right 扩大窗口（加入 nums[right]）
    for /* 窗口不满足条件 */ {
        // 2. left 收缩窗口（移出 nums[left]）
        left++
    }
    // 3. 此时 [left, right] 是满足条件的窗口，更新答案
}
```

每个元素被 right 加入一次、被 left 移出一次，所以**整体 O(n)**（不是 O(n²)，虽然有嵌套循环）。这是同向双指针/滑窗高效的关键。

## 五、三数之和

**三数之和**（找所有和为 0 的三元组）是"排序 + 双指针"的经典，也是去重的难点：

```go
import "sort"

func threeSum(nums []int) [][]int {
    sort.Ints(nums) // 1. 先排序，才能用双指针 + 去重
    var res [][]int
    for i := 0; i < len(nums)-2; i++ {
        if nums[i] > 0 {
            break // 最小的已 >0，不可能和为 0
        }
        if i > 0 && nums[i] == nums[i-1] {
            continue // 跳过重复的第一个数（去重）
        }
        l, r := i+1, len(nums)-1
        for l < r { // 2. 对撞指针找另外两个数
            sum := nums[i] + nums[l] + nums[r]
            switch {
            case sum == 0:
                res = append(res, []int{nums[i], nums[l], nums[r]})
                for l < r && nums[l] == nums[l+1] { // 去重
                    l++
                }
                for l < r && nums[r] == nums[r-1] { // 去重
                    r--
                }
                l++
                r--
            case sum < 0:
                l++
            default:
                r--
            }
        }
    }
    return res
}
```

套路：**排序后固定一个数，对剩余部分用对撞双指针**，O(n²)（外层 n × 内层双指针 n）。难点在**去重**（三处：固定数、左指针、右指针都要跳过重复值）。四数之和同理（再套一层）。

## 六、合并类

合并两个有序数组/链表也是双指针（各一个指针）：

```go
// 合并两个有序数组到 nums1（从后往前填，避免覆盖）
func mergeSorted(nums1 []int, m int, nums2 []int, n int) {
    i, j, k := m-1, n-1, m+n-1 // 三指针从后往前
    for j >= 0 {
        if i >= 0 && nums1[i] > nums2[j] {
            nums1[k] = nums1[i]
            i--
        } else {
            nums1[k] = nums2[j]
            j--
        }
        k--
    }
}
```

技巧：**从后往前填**，避免覆盖 nums1 还没处理的元素（原地合并的常见技巧）。链表合并见 [03](./03-精通-链表技巧.md)，归并排序的 merge 见 [09](./09-精通-分治与归并思想.md)。

## 七、模板与识别

**怎么识别该用双指针**：
- 数组/字符串**有序** + 找配对/区间 → 对撞指针。
- **原地**修改、去重、移除、分区 → 快慢指针。
- 连续**子数组/子串** + 最长/最短/满足条件 → 同向指针（滑窗，[05](./05-精通-滑动窗口.md)）。
- 两个有序序列**合并** → 各一指针。

**关键前提**：对撞指针通常需要**有序**（无序先排序）；移动方向要有**单调依据**（移哪个指针能让结果朝目标变化）。

---

## 陷阱清单

- **对撞指针用在无序数组**：对撞指针的移动依赖有序性，无序要先排序（排序后下标会变，注意题目要不要原下标）。
- **三数之和不去重**：会有重复三元组。三处去重（固定数、左、右指针跳过相邻相同值）。
- **同向双指针误判为 O(n²)**：虽有嵌套循环，但每个元素只进出窗口一次，整体 O(n)。
- **合并有序数组从前往后填**：会覆盖未处理元素。原地合并从后往前填。
- **指针越界**：`l < r` 边界、`fast < len`、三数之和里 `nums[l+1]` 要先判 `l < r`。
- **移动错指针**：对撞时该移左移成右，导致死循环或漏解。想清"移哪个能逼近目标"。
- **快慢指针 slow 含义不清**：明确 slow 是"结果边界"还是"待填位置"，逻辑才不乱。

## 练习题

1. 双指针分哪三类？分别适合什么场景？

<details><summary>参考答案</summary>

双指针主要分三类：①**对撞指针（左右指针）**——两个指针一个从头（left）、一个从尾（right），向中间靠拢移动。适合**有序数组上找配对/满足条件的两个元素**（如有序数组的两数之和、盛最多水的容器）、以及**首尾对称处理**（如判断回文、反转数组）。它的高效依赖数据的有序性——根据当前结果与目标的大小关系，决定移动左指针（让值变大）还是右指针（让值变小），每步排除一个元素，O(n)。②**快慢指针（同向不同速/不同角色）**——两个指针同向移动，速度或职责不同。适合**链表问题**（找中点、判环、找倒数第 k 个，见 03）和**数组原地操作**（原地去重、移除元素、移动零——slow 维护已处理结果的边界、fast 向前探索）。③**同向双指针（滑动窗口）**——两个指针都从左向右、一前一后维护一个连续区间/窗口。适合**连续子数组/子串**且求"最长/最短/满足某条件"的问题（如无重复字符的最长子串、最小覆盖子串），right 扩窗、left 收窗，每个元素进出窗口各一次、O(n)（见 05）。识别要点：有序数组找配对用对撞；原地修改/链表用快慢；连续子数组/子串求极值用同向滑窗。三类的共同本质都是利用数据的某种性质（有序、单调、连续）让指针只朝一个方向走，把暴力的 O(n²) 降到 O(n)。

</details>

2. 为什么"有序数组两数之和"用对撞指针是 O(n)？移动指针的依据是什么？

<details><summary>参考答案</summary>

在有序数组中找两个数之和等于 target，对撞指针做法：left 从 0、right 从末尾开始，计算 sum = nums[left] + nums[right]，然后：若 sum == target 找到答案；若 **sum < target**（和太小），就 **left++**（左指针右移，因为数组有序、右移会让 nums[left] 变大，从而 sum 增大、逼近 target）；若 **sum > target**（和太大），就 **right--**（右指针左移，nums[right] 变小，sum 减小）。**为什么是 O(n)**：left 只会单调右移、right 只会单调左移，两个指针相向而行、永不回头，整个过程中两指针移动的总步数最多就是数组长度 n（每次循环至少移动一个指针一步，直到 left 和 right 相遇）。所以只需一趟、O(n) 时间、O(1) 空间，而暴力双重循环枚举所有数对是 O(n²)。**移动指针的依据（关键）**：依据是数组的**有序性**带来的单调关系——因为数组有序，移动 left 必然使 sum 单调增大、移动 right 必然使 sum 单调减小，所以可以根据"当前 sum 比 target 大还是小"确定性地决定移动哪个指针，每移动一步都安全地排除了一个不可能成为答案的元素（比如 sum < target 时，nums[right] 与比 left 更小的任何数配对都只会更小、不可能等于 target，所以可以放心地不再考虑当前 left，left++）。正是这种"移动方向有单调依据、每步排除一个元素"使得双指针只需线性时间。如果数组无序，就没有这个单调依据，对撞指针不成立（需先排序或改用哈希表）。

</details>

3. 快慢指针解决"原地"问题（如移动零、删除重复项）的通用模式是什么？

<details><summary>参考答案</summary>

通用模式是"**慢指针维护已处理好的结果边界，快指针向前扫描探索**"，从而在原数组上原地完成操作、O(1) 额外空间、O(n) 时间。具体：用 slow 指针标记"下一个应该放置（保留）的元素的位置"（即 [0, slow) 是已经处理好、符合要求的结果区域），用 fast 指针从头遍历整个数组逐个考察元素。对每个 nums[fast]，判断它是否应该被"保留/放入结果"：如果应该保留，就把它放到 slow 指向的位置（nums[slow] = nums[fast] 或交换），然后 slow 前移一位；如果不该保留（如等于要删除的值、或与前一个重复），就跳过它、只移动 fast、不动 slow。遍历结束后，[0, slow)（或 slow+1 个元素）就是处理后的结果，slow 即新长度。例子：**移动零**——fast 遇到非零元素就和 slow 位置交换并 slow++，零自然被留到后面；**删除有序数组重复项**——fast 遇到与 nums[slow] 不同的新值，就 slow++ 并把新值放过去；**移除指定元素**——fast 遇到不等于 val 的元素就放到 slow 处并 slow++。这种模式的精髓是：把"要保留的元素"依次往数组前面"压实"，要删除/跳过的元素被后面保留的元素覆盖掉，用一个快指针探索、一个慢指针记录结果边界，全程在原数组上原地操作、不需要额外空间。链表版的快慢指针删除/去重也是同样思想（03）。

</details>

4. 三数之和为什么要先排序？去重需要注意哪几处？

<details><summary>参考答案</summary>

**先排序的原因**：①排序后才能使用**对撞双指针**——固定第一个数 nums[i] 后，在它右边的区间用左右指针找另外两个数，利用有序性根据和与 target（0）的大小关系移动指针（和小左指针右移、和大右指针左移），把找两数之和从 O(n²) 降到 O(n)，整体三数之和从 O(n³) 暴力降到 O(n²)；②排序后**相同的元素相邻**，便于跳过重复值进行去重；③还能剪枝（如最小的 nums[i] 已 > 0 则后面不可能和为 0，直接 break）。**去重需要注意三处**：①**固定的第一个数 nums[i] 去重**——外层循环中，如果 `i > 0 && nums[i] == nums[i-1]`，说明这个值作为第一个数的所有组合在上一轮已经枚举过，直接 continue 跳过，避免重复三元组；②**左指针 nums[l] 去重**——找到一个有效三元组后，若 `nums[l] == nums[l+1]` 则不断 l++ 跳过相同的左值；③**右指针 nums[r] 去重**——同理若 `nums[r] == nums[r-1]` 则不断 r-- 跳过相同的右值。注意去重时要判 `l < r` 边界防越界。三处去重缺一不可：不对第一个数去重会产生第一个数相同的重复组、不对左右指针去重会在同一个 i 下产生重复组。这是三数之和（及四数之和等）最容易出错的地方——核心是"排序让重复值相邻，凡是值和上一个处理过的相同就跳过"。

</details>

5. 同向双指针（滑动窗口）有嵌套循环，为什么整体复杂度是 O(n) 而不是 O(n²)？

<details><summary>参考答案</summary>

虽然滑动窗口的代码结构是"外层 for（right 指针）里嵌套一个 while（left 指针收缩）"，看起来像双重循环、容易误判为 O(n²)，但实际整体是 O(n)。原因在于**两个指针都是单调向右移动、永不回退，各自移动的总步数都不超过 n**。具体分析：外层循环让 right 从 0 到 n-1，right 总共移动 n 次（每个元素被加入窗口恰好一次）；内层 while 让 left 收缩，但 left 也只会**单调右移、从不回头**，所以在整个算法过程中，left 累计移动的总次数也不超过 n（每个元素被移出窗口至多一次）。也就是说，内层 while 不是"每次外层循环都执行 n 次"，而是"在整个过程中总共执行不超过 n 次"——left 的移动次数是在所有外层迭代之间**摊销**的，而不是每次外层都重新走一遍。因此总操作次数 = right 移动 n 次 + left 移动至多 n 次 = O(2n) = O(n)。判断这类复杂度的关键不是看循环嵌套的层数，而是看**指针/操作的总次数**：每个元素最多被 right 加入一次、被 left 移出一次，所以是线性的。这是一种摊还分析的思想（类似动态数组 append 均摊 O(1)，见 01）。理解这一点能避免把"带内层 while 的滑窗"误判为 O(n²)，也是滑动窗口能高效解决子数组/子串问题的根本原因（05 会展开）。

</details>

6. 合并两个有序数组到第一个数组（nums1 有足够空间），为什么要"从后往前"填充？

<details><summary>参考答案</summary>

题目场景：nums1 的前 m 个是有效元素、后面预留了 n 个空位（总长 m+n），nums2 有 n 个元素，要把两者合并成有序的结果**原地放入 nums1**。**从后往前填充的原因是避免覆盖 nums1 中尚未处理的有效元素**。如果**从前往后**填：用一个指针 k 从 nums1 的下标 0 开始放合并结果，但合并时如果 nums2 的当前元素较小要放到前面，就会**覆盖掉 nums1 中还没被比较处理的原有元素**（因为 nums1 前段正是有效数据所在），导致数据丢失——除非额外开一个数组暂存，那就不是 O(1) 空间原地了。而**从后往前**填：用三个指针，i 指向 nums1 有效部分末尾（m-1）、j 指向 nums2 末尾（n-1）、k 指向 nums1 的最末尾（m+n-1，即整个数组的最后一个位置）。每次比较 nums1[i] 和 nums2[j]，把**较大者放到 k 位置**，然后对应指针和 k 都左移。因为我们总是从两个数组的最大元素开始、往 nums1 的最后空位填，而 nums1 末尾的位置恰好是预留的空位（还没被有效数据占用，或已经处理过的位置），所以**永远不会覆盖到 nums1 中还没比较的有效元素**（k 始终在 i 的右边或相等，写入位置不会冲掉待读位置）。这样就能 O(m+n) 时间、O(1) 额外空间地原地合并。这是"利用末尾空位、逆向填充避免覆盖"的经典技巧，本质是双指针（这里是三指针）+ 逆向遍历。

</details>
