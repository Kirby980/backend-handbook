# 精通图论

> 图论是算法里最"重"的一块，但面试常考的就那几样：DFS/BFS 遍历、拓扑排序、并查集、最短路。掌握这几个核心，图论题就能应付大半。本篇讲清图的表示和这些必会算法。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、图的表示

图 = 顶点 + 边。两种存储方式：

| 表示 | 结构 | 空间 | 适用 |
|---|---|---|---|
| **邻接矩阵** | `matrix[i][j]=1` 表示 i→j 有边 | O(V²) | 稠密图、快速判断两点是否相邻 |
| **邻接表** | 每个顶点存一个邻居列表 | O(V+E) | **稀疏图（更常用）** |

```go
// 邻接表（无权图）
graph := make([][]int, n) // graph[i] 是 i 的所有邻居
graph[u] = append(graph[u], v) // 加边 u→v（无向图再加 v→u）

// 带权图：存 [邻居, 权重]
type Edge struct{ to, weight int }
wgraph := make([][]Edge, n)
```

概念：**有向图 vs 无向图**、**带权 vs 无权**、**连通分量**、**环**、**DAG（有向无环图）**。大多数面试图题用邻接表。

## 二、图的遍历

图的 DFS 和 BFS（[08](./08-精通-递归回溯与DFS.md)、[10](./10-精通-栈与队列.md)）核心区别于树：**图可能有环，必须用 visited 标记防重复访问**。

```go
// DFS（递归）
func dfs(graph [][]int, u int, visited []bool) {
    visited[u] = true // 标记已访问（防环）
    // 处理 u
    for _, v := range graph[u] {
        if !visited[v] {
            dfs(graph, v, visited)
        }
    }
}

// BFS（队列）
func bfs(graph [][]int, start int) {
    visited := make([]bool, len(graph))
    queue := []int{start}
    visited[start] = true
    for len(queue) > 0 {
        u := queue[0]
        queue = queue[1:]
        // 处理 u
        for _, v := range graph[u] {
            if !visited[v] {
                visited[v] = true // 入队时就标记（防重复入队）
                queue = append(queue, v)
            }
        }
    }
}
```

- **DFS**：一条路走到底，用递归/栈，适合找连通分量、路径、环检测。
- **BFS**：一层层扩展，用队列，适合**最短路径（无权图）**、层级遍历。
- **关键**：必须 `visited` 标记，否则有环会死循环（树没环不用，但图必须）。

## 三、BFS 与最短路

**无权图的最短路径用 BFS**——因为 BFS 一层层扩展，**第一次到达某点时一定是最短路径**（步数最少）。

```go
// 无权图：start 到各点的最短距离（步数）
func shortestPath(graph [][]int, start int) []int {
    n := len(graph)
    dist := make([]int, n)
    for i := range dist {
        dist[i] = -1 // -1 表示不可达
    }
    dist[start] = 0
    queue := []int{start}
    for len(queue) > 0 {
        u := queue[0]
        queue = queue[1:]
        for _, v := range graph[u] {
            if dist[v] == -1 { // 第一次到达 = 最短
                dist[v] = dist[u] + 1
                queue = append(queue, v)
            }
        }
    }
    return dist
}
```

应用：迷宫最短路、单词接龙、最少步数到达、矩阵中的最短路径。**带权图最短路要用 Dijkstra**（见第六节），BFS 只适合无权（或权都相同）。

## 四、拓扑排序

**拓扑排序（Topological Sort）**：把**有向无环图（DAG）**的顶点排成线性序列，使每条边 u→v 都满足 u 在 v 前面。用于**有依赖关系的排序**（课程先修、任务调度、编译依赖）。

**Kahn 算法（BFS 入度法，最常用）**：

```go
// 课程表：能否完成所有课程（判断有无环 + 拓扑序）
func canFinish(numCourses int, prerequisites [][]int) bool {
    graph := make([][]int, numCourses)
    inDegree := make([]int, numCourses) // 入度：依赖它的前置课数
    for _, p := range prerequisites {
        graph[p[1]] = append(graph[p[1]], p[0]) // p[1] → p[0]（先修 p[1] 才能学 p[0]）
        inDegree[p[0]]++
    }
    queue := []int{}
    for i := 0; i < numCourses; i++ {
        if inDegree[i] == 0 { // 入度为 0 = 无前置依赖，可先学
            queue = append(queue, i)
        }
    }
    count := 0
    for len(queue) > 0 {
        u := queue[0]
        queue = queue[1:]
        count++ // 学完一门
        for _, v := range graph[u] {
            inDegree[v]-- // 它的后继课少了一个前置依赖
            if inDegree[v] == 0 {
                queue = append(queue, v)
            }
        }
    }
    return count == numCourses // 全部学完 = 无环；否则有环（剩下的都在环里）
}
```

Kahn 算法思路：**反复取入度为 0 的点（无依赖）输出，删掉它的出边**。如果最后没能输出所有点，说明**有环**（环上的点入度永远 > 0）。这也是**判断有向图是否有环**的方法。也可用 DFS（后序 + 三色标记）做拓扑排序。

## 五、并查集

**并查集（Union-Find / Disjoint Set）** 高效处理**连通性**问题——判断两点是否连通、合并集合。两个操作近似 O(1)：

- **find(x)**：找 x 所属集合的"代表"（根）。
- **union(x, y)**：合并 x 和 y 所在的集合。

```go
type UnionFind struct {
    parent []int
    rank   []int // 按秩合并用
}

func NewUnionFind(n int) *UnionFind {
    uf := &UnionFind{parent: make([]int, n), rank: make([]int, n)}
    for i := range uf.parent {
        uf.parent[i] = i // 初始每个点自成一组
    }
    return uf
}

// 找根 + 路径压缩（把路径上的点直接挂到根，扁平化）
func (uf *UnionFind) Find(x int) int {
    if uf.parent[x] != x {
        uf.parent[x] = uf.Find(uf.parent[x]) // 路径压缩
    }
    return uf.parent[x]
}

// 合并 + 按秩合并（矮树挂到高树下）
func (uf *UnionFind) Union(x, y int) {
    rx, ry := uf.Find(x), uf.Find(y)
    if rx == ry {
        return // 已在同一组
    }
    if uf.rank[rx] < uf.rank[ry] {
        rx, ry = ry, rx
    }
    uf.parent[ry] = rx // 小树挂大树
    if uf.rank[rx] == uf.rank[ry] {
        uf.rank[rx]++
    }
}
```

两大优化：**路径压缩**（find 时把路径上节点直接挂到根，树扁平化）+ **按秩合并**（矮树挂高树下，避免退化）。两者结合后单次操作近似 O(α(n)) ≈ O(1)（α 是反阿克曼函数，极慢增长）。

应用：**连通分量计数、判断图连通、朋友圈、冗余连接（找成环的边）、最小生成树（Kruskal）**。看到"动态合并 + 查询是否连通"就想并查集。

## 六、最短路（Dijkstra）

**Dijkstra**：带**非负权**的单源最短路。用**优先队列（小顶堆，[13](./13-精通-堆与TopK.md)）**每次取当前距离源点最近的点：

```go
import "container/heap"

func dijkstra(wgraph [][]Edge, start int) []int {
    n := len(wgraph)
    dist := make([]int, n)
    for i := range dist {
        dist[i] = 1 << 30 // 无穷大
    }
    dist[start] = 0
    pq := &PQ{{node: start, d: 0}} // 小顶堆，按距离排
    for pq.Len() > 0 {
        cur := heap.Pop(pq).(Item)
        if cur.d > dist[cur.node] {
            continue // 过期项，跳过
        }
        for _, e := range wgraph[cur.node] {
            if nd := cur.d + e.weight; nd < dist[e.to] {
                dist[e.to] = nd // 松弛：找到更短的路
                heap.Push(pq, Item{node: e.to, d: nd})
            }
        }
    }
    return dist
}
```

核心是**松弛（relax）**：如果经当前点到邻居更短，就更新邻居的距离。用堆每次贪心取最近的点，O((V+E) log V)。

- **Dijkstra**：非负权单源最短路。
- **负权**：要用 Bellman-Ford / SPFA。
- **所有点对最短路**：Floyd-Warshall（O(V³)，DP，[16](./16-精通-经典DP专题.md)）。
- 面试 Dijkstra 最常考，能说清"优先队列 + 松弛"即可。

## 七、识别与套路

| 题型信号 | 用什么 |
|---|---|
| 连通分量 / 是否连通 / 路径存在 | DFS / BFS / 并查集 |
| **无权图最短路 / 最少步数** | **BFS** |
| **带非负权最短路** | **Dijkstra（堆）** |
| **依赖关系排序 / 检测有向环** | **拓扑排序** |
| **动态合并集合 / 判断同组** | **并查集** |
| 矩阵连通块（岛屿） | DFS/BFS（[08](./08-精通-递归回溯与DFS.md)） |
| 最小生成树 | Kruskal（并查集）/ Prim（堆） |

## 陷阱清单

- **图遍历不用 visited**：图有环会死循环（树才不用）。DFS/BFS 必须标记已访问。
- **BFS 入队时不标记**：等出队才标记会导致同一点重复入队。**入队时就标记 visited**。
- **用 BFS 求带权最短路**：BFS 只适合无权（或等权）图，带权用 Dijkstra。
- **Dijkstra 处理负权**：Dijkstra 不支持负权边，负权用 Bellman-Ford/SPFA。
- **拓扑排序不判环**：有环则无拓扑序，Kahn 算法最后 count < n 即有环。
- **并查集不做路径压缩/按秩合并**：会退化成 O(n) 链，加上两个优化才近 O(1)。
- **有向图当无向图建边**（或反之）：加边方向错，结果全错。看清题目方向。
- **稠密图用邻接表 vs 稀疏图用邻接矩阵**：一般稀疏用邻接表（省空间），别用错浪费 O(V²)。

## 2026 现状

- **图论核心四件套**：DFS/BFS、拓扑排序、并查集、Dijkstra 是面试高频，掌握它们能解大多数图题。
- **并查集是热门**：连通性、冗余连接、账户合并、岛屿数量 II 等高频，路径压缩 + 按秩合并要会。
- **图算法的工程映射**：拓扑排序 → 任务/依赖调度（[系统设计 S14](../system-design/S14-精通-设计延迟队列与定时任务.md)、构建系统）、最短路 → 路由/导航、并查集 → 社交关系/连通性。

## 练习题

1. 图的两种存储方式（邻接矩阵、邻接表）有什么区别？各适合什么场景？

<details><summary>参考答案</summary>

**邻接矩阵**：用一个 V×V 的二维矩阵表示，matrix[i][j] 记录顶点 i 到顶点 j 是否有边（无权图用 0/1，带权图存权值）。优点：**O(1) 判断任意两点是否相邻、O(1) 查/改某条边的权值**，实现简单；缺点：**空间是 O(V²)**，无论实际边数多少都要占满整个矩阵，对边稀疏的图极其浪费内存；遍历一个顶点的所有邻居要扫一整行 O(V)。适合：**稠密图**（边数接近 V² ）、或需要频繁快速判断"两点之间是否直接相连/边权是多少"的场景、以及顶点数较少的图。**邻接表**：每个顶点维护一个列表，存放它的所有邻居（及边权）。优点：**空间是 O(V+E)**（只存实际存在的边），对稀疏图非常省空间；遍历某顶点的所有邻居很高效（直接遍历它的列表，与其度数成正比）。缺点：判断两个特定顶点是否相邻需要遍历某个顶点的邻居列表（最坏 O(度数)），不是 O(1)。适合：**稀疏图**（边数远小于 V²，现实中大多数图都是稀疏的）、需要遍历邻居的算法（DFS/BFS/Dijkstra 等都是遍历邻居）。**选择**：绝大多数算法面试题用**邻接表**（图通常稀疏、且 DFS/BFS/最短路都需要遍历邻居），它省空间、契合遍历操作；只有图很稠密、或需要频繁 O(1) 查询任意两点边关系、或顶点数很小时才考虑邻接矩阵。记忆：稀疏用邻接表（省空间）、稠密或频繁查边用邻接矩阵（查边 O(1) 但费空间）。

</details>

2. 图的 DFS/BFS 和树的遍历相比，最大的区别是什么？为什么必须用 visited 标记？

<details><summary>参考答案</summary>

最大的区别是：**图可能存在环（以及一个节点可以有多个前驱/被多条路径到达），而树没有环、每个节点只有一个父节点**。因此图的遍历**必须使用 visited（已访问）标记来记录哪些节点已经访问过，避免重复访问和无限循环**；而树的遍历不需要 visited（因为树无环、不会绕回已访问的节点，沿父→子方向走不会重复）。**为什么图必须用 visited**：①**防止死循环**——如果图中有环（如 A→B→C→A），不做标记的话，DFS/BFS 会沿着环一圈圈无限地访问下去（A 访问 B、B 访问 C、C 又访问 A……永不停止），程序陷入死循环或栈溢出。用 visited 标记后，访问到已标记的节点就跳过，自然终止。②**避免重复访问/重复处理**——即使没有环，图中一个节点也可能通过多条不同路径到达（如 A→B、A→C、B→D、C→D，D 能被 B 和 C 两条路径到达），不做标记会导致 D 被重复访问、重复处理，浪费时间甚至产生错误结果（如重复计数、重复入队）。用 visited 保证每个节点只被访问一次，整个遍历是 O(V+E)。**实现注意**：DFS 在进入节点时标记 visited；**BFS 要在节点入队时就标记**（而不是出队时才标记），否则同一个节点可能在出队前被多个邻居重复加入队列，导致重复处理。一句话：树是无环的特殊图所以不用 visited，而一般图有环、有多路径，必须用 visited 标记防止死循环和重复访问。

</details>

3. 为什么无权图的最短路径可以用 BFS 求？

<details><summary>参考答案</summary>

因为 **BFS 是按"距离起点的层数"逐层向外扩展的**，它先访问离起点 1 步的所有节点，再访问 2 步的所有节点，再 3 步……以此类推。在**无权图（或所有边权相等）**中，"经过的边数（步数）"就等于路径长度，所以 **BFS 第一次到达某个节点时，所走的步数一定是从起点到该节点的最少步数，即最短路径**。证明直觉：BFS 用队列保证了"先入队的节点先被扩展"，而节点是按距离从小到大入队的（距离为 d 的节点一定在距离为 d+1 的节点之前入队和处理）。因此当一个节点第一次被某条路径访问到时，不可能再有更短的路径后来才到达它（更短的路径会更早被 BFS 探索到、更早访问它）——第一次到达即最短。实现上：从起点开始 BFS，记录每个节点第一次被访问时的距离（dist[邻居] = dist[当前] + 1），第一次访问就确定了最短距离，并标记 visited 防止后续更长的路径再更新它。这就是为什么迷宫最少步数、单词接龙、最少操作次数到达目标、矩阵中的最短路径等"无权/等权最短路"问题用 BFS 解。**注意前提是无权或等权**：如果图的边带有**不同的权值**，BFS 就不成立了——因为"边数最少"不等于"权值和最小"（一条边多但权小的路径可能总权值更小），这时需要用 **Dijkstra**（非负权）等带权最短路算法（用优先队列按累计距离扩展，而非按层数）。一句话：无权图中"层数=距离"，BFS 逐层扩展保证第一次到达即最短；带权图要用 Dijkstra。

</details>

4. 什么是拓扑排序？如何用它判断有向图是否有环（以课程表为例）？

<details><summary>参考答案</summary>

**拓扑排序**是针对**有向无环图（DAG）**的一种线性排序：把所有顶点排成一个序列，使得对图中每一条有向边 u→v，u 都排在 v 的前面。它表达的是一种"依赖/先后顺序"——常用于有先后依赖关系的排序问题，如课程先修关系、任务调度、编译依赖、项目工序等（必须先完成 u 才能做 v）。一个有向图存在拓扑排序**当且仅当它无环**（有环则无法排出满足所有依赖的线性序，因为环上的节点互相依赖、谁都没法排在最前）。**用 Kahn 算法（BFS 入度法）判断有环**（以课程表"能否修完所有课程"为例）：①建图——把"先修 a 才能学 b"建成有向边 a→b，并统计每门课的**入度**（指向它的边数 = 它的前置课数量）；②初始化——把所有**入度为 0**（没有任何前置依赖、可以直接学）的课程加入队列；③不断从队列取出一门课 u（表示"学完它"），计数 +1，并把它指向的每门后继课 v 的入度减 1（因为 u 这个前置已满足），如果某门 v 的入度减到 0（所有前置都学完了），就把 v 加入队列；④重复直到队列空。**判断有环**：如果最终**成功"学完"的课程数 count 等于总课程数**，说明所有课都能按依赖顺序学完——**无环**（且出队顺序就是一个拓扑序）；如果 **count < 总数**，说明还有课程的入度始终 > 0、永远进不了队列——这些课处在一个**环**里（互相循环依赖，谁都等不到前置全部满足），即**有环**，无法完成。所以"课程表能否修完"本质就是判断先修关系图是否为 DAG（无环），用拓扑排序的 Kahn 算法即可：能拓扑排出全部节点则无环可完成，否则有环不可完成。（也可用 DFS + 三色标记检测环并得到拓扑序。）

</details>

5. 并查集是什么？路径压缩和按秩合并两个优化分别起什么作用？

<details><summary>参考答案</summary>

**并查集（Union-Find / 不相交集合）** 是一种高效处理"**动态连通性**"问题的数据结构，支持两个核心操作：**Find(x)**——查询元素 x 所属集合的代表元（根节点），用来判断两个元素是否在同一集合（连通）；**Union(x, y)**——把 x 和 y 所在的两个集合合并成一个。它用一个 parent 数组表示森林：每个元素指向它的父节点，同一棵树的元素属于同一集合，树根作为集合代表。初始每个元素自成一个集合（parent[i]=i）。它特别适合"不断合并集合、并查询两点是否连通"的场景（连通分量、朋友圈、冗余连接、Kruskal 最小生成树等）。**两个优化**：①**路径压缩（Path Compression）**——在执行 Find 查找根的过程中，把查找路径上经过的所有节点**直接挂到根节点下面**（让它们的 parent 直接指向根），从而把树"压扁"。作用：避免树变得又高又长，使后续对这些节点的 Find 几乎能一步到根，大幅降低查找深度。②**按秩合并（Union by Rank/Size）**——合并两个集合时，总是把**较矮（秩小）的树挂到较高（秩大）的树的根下**（而不是随意合并）。作用：避免把高树挂到矮树下导致树不断增高、退化成一条链（那样 Find 会变成 O(n)）；按秩合并保证树的高度增长缓慢、保持相对平衡。**效果**：单独用任一优化能显著改善，**两者结合后，每次 Find/Union 的均摊时间复杂度近似 O(α(n))**，其中 α 是反阿克曼函数，增长极其缓慢，对所有实际的 n 都可视为**近似 O(1)** 的常数级。没有这两个优化时，并查集最坏会退化到 O(n) 每次操作（树退化成链）。所以路径压缩（压扁查找路径）+ 按秩合并（控制树高）是让并查集高效的关键，二者配合使其成为处理连通性问题的近乎常数级利器。

</details>

6. Dijkstra 算法解决什么问题？它的核心思想是什么？为什么不能处理负权边？

<details><summary>参考答案</summary>

**Dijkstra 算法解决"单源最短路径"问题**：给定一个**边权非负**的（有向或无向）带权图和一个起点，求起点到图中所有其他顶点的最短路径（最小权值和）。**核心思想（贪心 + 松弛）**：维护每个顶点当前已知的最短距离估计 dist[]（起点为 0、其余为无穷大），用一个**优先队列（小顶堆）**反复取出"当前 dist 最小且尚未确定的顶点 u"——此时 u 的最短距离就被**确定**了（因为再没有更短的路径能到它）；然后对 u 的每条出边 u→v 做**松弛（relax）**：如果 dist[u] + 边权(u,v) < dist[v]，就更新 dist[v]（找到了一条经过 u 的更短路径）并把 v 以新距离入堆。重复直到堆空，所有顶点的最短距离就都确定了。用优先队列每次贪心地扩展最近的节点，复杂度约 O((V+E) log V)。它本质是"每次确定一个离源点最近的、距离已不可能再变小的节点，并用它去松弛邻居"。**为什么不能处理负权边**：Dijkstra 的正确性依赖一个关键前提——**当一个节点被从优先队列取出（其 dist 为当前最小）时，它的最短距离就已经最终确定、之后不会再变小**。这个前提在边权非负时成立：因为后续路径只会在当前最小距离基础上加上非负的边权、只会更大，不可能产生更短的路径回头更新已确定的节点。但**如果存在负权边，这个前提就被打破了**：一个节点可能先被以某个较小距离"确定"，但之后通过一条包含负权边的路径反而能得到更小的距离——而 Dijkstra 已经把它当作确定的、不会再更新，于是得出错误的最短距离。换言之，负权边会让"已确定的最短距离"后来还可能变得更小，违反了 Dijkstra 贪心选择的正确性基础。所以**带负权边的最短路要用 Bellman-Ford 或 SPFA**（它们通过多轮松弛允许反复更新，能处理负权，还能检测负权环）；所有点对最短路可用 **Floyd-Warshall**（O(V³) 的 DP，也能处理负权但不能有负环）。Dijkstra 仅适用于非负权图。

</details>
