# 精通排序算法

> 排序是算法基本功，面试常要求**手写快排、归并、堆排**，并讲清复杂度、稳定性、适用场景。本篇梳理主流排序，重点是三大 O(n log n) 比较排序和它们的取舍。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、排序算法全景

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 类别 |
|---|---|---|---|---|---|
| 冒泡/插入/选择 | O(n²) | O(n²) | O(1) | 冒泡/插入稳定 | 比较 |
| **快速排序** | O(n log n) | O(n²) | O(log n) | 不稳定 | 比较 |
| **归并排序** | O(n log n) | O(n log n) | O(n) | **稳定** | 比较 |
| **堆排序** | O(n log n) | O(n log n) | O(1) | 不稳定 | 比较 |
| 计数排序 | O(n+k) | O(n+k) | O(k) | 稳定 | 非比较 |
| 桶排序 | O(n+k) | O(n²) | O(n+k) | 稳定 | 非比较 |
| 基数排序 | O(d(n+k)) | 同 | O(n+k) | 稳定 | 非比较 |

- **比较排序下界 O(n log n)**：基于比较的排序，最坏情况下界是 O(n log n)（信息论证明，n! 种排列要 log(n!)≈n log n 次比较区分）。
- **非比较排序能 O(n)**：计数/桶/基数不靠比较，靠值域分布，但有适用限制（值域、整数等）。

## 二、快速排序

**快速排序（Quick Sort）**：分治——选一个 pivot，把比它小的放左、大的放右（partition），再递归排左右两半。

```go
func quickSort(nums []int, lo, hi int) {
    if lo >= hi {
        return
    }
    p := partition(nums, lo, hi) // 分区，p 是 pivot 最终位置
    quickSort(nums, lo, p-1)     // 递归左半
    quickSort(nums, p+1, hi)     // 递归右半
}

// Lomuto 分区：以 nums[hi] 为 pivot
func partition(nums []int, lo, hi int) int {
    pivot := nums[hi]
    i := lo // i 指向"小于 pivot 区"的下一个位置
    for j := lo; j < hi; j++ {
        if nums[j] < pivot {
            nums[i], nums[j] = nums[j], nums[i]
            i++
        }
    }
    nums[i], nums[hi] = nums[hi], nums[i] // pivot 放到正确位置
    return i
}
```

- **平均 O(n log n)**（每次大致均分），**最坏 O(n²)**（已排序 + 固定取端点为 pivot，每次只分出一个）。
- **优化**：随机选 pivot（避免最坏）、三数取中、小数组转插入排序、三路快排（处理大量重复）。
- **原地**（O(log n) 递归栈），**不稳定**。是实际最常用的内排序（Go 的 sort 包用 pdqsort——快排的优化变体）。

## 三、归并排序

**归并排序（Merge Sort）**：分治——把数组对半拆分到单元素，再两两**有序合并**。

```go
func mergeSort(nums []int) []int {
    if len(nums) <= 1 {
        return nums
    }
    mid := len(nums) / 2
    left := mergeSort(nums[:mid])  // 递归排左半
    right := mergeSort(nums[mid:]) // 递归排右半
    return merge(left, right)      // 合并两个有序数组
}

func merge(a, b []int) []int {
    res := make([]int, 0, len(a)+len(b))
    i, j := 0, 0
    for i < len(a) && j < len(b) {
        if a[i] <= b[j] { // <= 保证稳定
            res = append(res, a[i])
            i++
        } else {
            res = append(res, b[j])
            j++
        }
    }
    res = append(res, a[i:]...) // 接剩余
    res = append(res, b[j:]...)
    return res
}
```

- **稳定**（merge 时相等取左边，`<=`），**O(n log n) 最坏也保证**（不像快排会退化）。
- 代价：**O(n) 额外空间**（合并要辅助数组）。
- 适合**链表排序**（[03](./03-精通-链表技巧.md)，链表归并不需额外数组）、**外部排序**（大数据分块）、**求逆序对**（merge 时统计，见 [09 分治](./09-精通-分治与归并思想.md)）。

## 四、堆排序

**堆排序（Heap Sort）**：用大顶堆，每次取堆顶（最大）放到末尾，O(1) 额外空间。

```go
func heapSort(nums []int) {
    n := len(nums)
    // 1. 建堆（从最后一个非叶节点开始下沉）
    for i := n/2 - 1; i >= 0; i-- {
        siftDown(nums, i, n)
    }
    // 2. 反复取堆顶放末尾
    for end := n - 1; end > 0; end-- {
        nums[0], nums[end] = nums[end], nums[0] // 堆顶（最大）换到末尾
        siftDown(nums, 0, end)                  // 对剩余 [0, end) 重新下沉
    }
}

func siftDown(nums []int, i, n int) {
    for {
        largest, l, r := i, 2*i+1, 2*i+2
        if l < n && nums[l] > nums[largest] {
            largest = l
        }
        if r < n && nums[r] > nums[largest] {
            largest = r
        }
        if largest == i {
            break
        }
        nums[i], nums[largest] = nums[largest], nums[i]
        i = largest
    }
}
```

- **原地 O(1) 空间**、O(n log n) 最坏也保证，但**不稳定**、常数较大（缓存不友好）、实际比快排慢。
- 堆的更多用法（优先队列、Top K）见 [13 堆与 Top K](./13-精通-堆与TopK.md)。

## 五、非比较排序

不靠元素比较，靠**值的分布**，能突破 O(n log n) 下界达到 O(n)，但有限制：

- **计数排序**：统计每个值出现次数，按值域顺序输出。**适合值域小的整数**（值域 k 不能太大），O(n+k)。
- **桶排序**：分到若干桶，桶内排序再合并。适合**均匀分布**的数据。
- **基数排序**：按位（个十百位）依次排。适合**整数/定长字符串**，O(d(n+k))。

限制：只适用于特定数据（整数、值域有限、定长），不通用。值域巨大或浮点/任意对象就退回比较排序。

## 六、稳定性与选择

**稳定性**：相等元素排序后相对顺序不变。**为什么重要**——多关键字排序时（先按 A 排再按 B 排，要保持 A 的相对序），或对象排序要保序时，需要稳定排序。

| 稳定 | 不稳定 |
|---|---|
| 归并、计数、桶、基数、冒泡、插入 | 快排、堆排、选择 |

**怎么选**：
- **通用内排序**：快排（实际最快，Go/多数库默认快排变体）。
- **要稳定 / 最坏也要 O(n log n) / 链表 / 外部排序**：归并。
- **要 O(1) 空间且最坏 O(n log n)**：堆排。
- **值域小的整数**：计数排序（O(n)）。

## 七、面试高频

- **手写快排、归并、堆排**：必会，且能说复杂度、稳定性。
- **快排为什么最坏 O(n²)、怎么优化**：随机 pivot / 三数取中 / 三路快排。
- **Top K / 第 K 大用快速选择（QuickSelect）**：基于快排 partition，平均 O(n) 找第 K 大（不用全排序），见 [13](./13-精通-堆与TopK.md)。
- **为什么 Go/Java 标准库的排序是混合的**：小数组插入排序、大数组快排/归并、防退化（pdqsort/TimSort）。

## 陷阱清单

- **快排最坏 O(n²) 忽视**：固定取端点 pivot + 已排序数据会退化。随机化或三数取中。
- **归并忘了 O(n) 空间**：merge 需辅助数组，空间敏感时考虑堆排（O(1)）。
- **快排/堆排当稳定排序用**：它们不稳定，多关键字保序要用归并。
- **计数排序用于大值域**：值域 k 巨大时空间爆炸，只适合小值域整数。
- **递归快排栈溢出**：最坏退化时递归深度 O(n)，可对较小一侧递归、较大一侧迭代（尾递归优化）。
- **partition 写错**：边界、pivot 归位、i/j 指针逻辑易错，背熟一种（Lomuto/Hoare）。
- **全排序求 Top K**：只要 Top K 不必全排序，用堆 O(n log k) 或快选 O(n)。

## 2026 现状

- **Go 标准库 `sort` / `slices.Sort`**：用 **pdqsort**（pattern-defeating quicksort，快排的现代优化，防退化），实际很快；稳定排序用 `sort.Stable`/`slices.SortStableFunc`。
- **Java `Arrays.sort`**：基本类型用双轴快排，对象用 **TimSort**（归并+插入的混合，稳定）。
- **面试趋势**：手写快排/归并仍是基本功；更看重"为什么这么选""怎么优化防退化""Top K 用快选/堆"等理解。
- **配合刷题**：排序本身的题 + 排序作为子步骤（很多题先排序再双指针/贪心），见 [04](./04-精通-双指针.md)、[17](./17-精通-贪心算法.md)、[20](./20-精通-高频题型与刷题路线.md)。

## 练习题

1. 快速排序的平均和最坏复杂度分别是多少？最坏情况怎么产生，如何优化？

<details><summary>参考答案</summary>

快速排序**平均时间复杂度 O(n log n)**，**最坏 O(n²)**，空间 O(log n)（递归栈），原地、不稳定。**原理**：选一个基准 pivot，通过 partition 把数组分成"小于 pivot"和"大于 pivot"两部分（pivot 归到正确位置），再递归排序两部分。**平均 O(n log n)** 的来源：如果每次 partition 都能大致把数组**均匀分成两半**，递归深度是 log n、每层 partition 总共 O(n)，合计 O(n log n)。**最坏 O(n²) 怎么产生**：当每次选的 pivot 都是当前区间的最大或最小值时，partition 后一边为空、另一边是 n-1 个元素——划分极度不均，递归深度退化到 O(n)、每层仍 O(n)，总共 O(n²)。最典型的触发场景是：**对已经有序（或逆序）的数组、且固定选取区间的第一个或最后一个元素作为 pivot**——这样每次 pivot 都是极值，划分最不平衡。**优化方法**：①**随机选 pivot**——随机选择基准位置（或随机交换到端点），让"恰好每次都选到极值"的概率极低，避免针对有序输入的退化；②**三数取中**——取首、中、尾三个元素的中位数作 pivot，使划分更均衡；③**三路快排（荷兰国旗）**——把数组分成 <pivot、=pivot、>pivot 三段，能高效处理**大量重复元素**的情况（普通快排遇大量重复会退化）；④**小数组转插入排序**——当区间长度小于某阈值时改用插入排序（小数组插入排序常数更小）；⑤对较小的一侧递归、较大的一侧用循环（尾递归优化）控制递归栈深度防栈溢出。实际工程库（如 Go 的 pdqsort）综合运用了这些优化来防止退化、保证高性能。

</details>

2. 归并排序为什么是稳定的？它的主要代价是什么？适合哪些场景？

<details><summary>参考答案</summary>

**归并排序稳定的原因**：稳定性取决于合并（merge）两个有序子数组时，对**相等元素**的处理。归并的 merge 过程是用两个指针分别扫描左右两个有序子数组，比较当前两个元素、把较小的放入结果；当**两个元素相等**时，**优先取左边子数组的元素**（代码里写 `if a[i] <= b[j]` 取 a[i]，注意是 `<=` 而非 `<`）。由于左子数组里的元素在原数组中本来就排在右子数组元素的前面，优先取左边就保证了相等元素的相对顺序在排序后保持不变——这就是稳定。（如果写成 `a[i] < b[j]` 时取 a、相等时取 b，就会破坏稳定性。）**主要代价**：**O(n) 的额外空间**——合并两个有序部分时需要一个辅助数组来暂存合并结果，无法像快排那样原地划分，所以数组归并排序需要 O(n) 额外空间（加上 O(log n) 递归栈）。这是它相比快排（O(log n) 空间）、堆排（O(1) 空间）的主要劣势。**适合的场景**：①**需要稳定排序**时（如多关键字排序要保持前一关键字的相对序、对象排序要保序）；②**要求最坏情况也是 O(n log n)** 时（归并任何输入都是 O(n log n)，不像快排会退化到 O(n²)，对最坏性能有保证的场景更可靠）；③**链表排序**——链表归并通过改指针合并、不需要额外数组（O(1) 额外空间），且天然适配链表的拆分合并，是链表排序的首选（见 03）；④**外部排序**——数据量大到内存放不下时，把数据分成若干块分别排序再多路归并（归并天然适合分块、顺序读写磁盘）；⑤**求逆序对**等可以在 merge 过程中顺便统计的问题（见 09）。

</details>

3. 三大 O(n log n) 比较排序（快排、归并、堆排）如何选择？

<details><summary>参考答案</summary>

三者平均都是 O(n log n)，但在最坏复杂度、空间、稳定性、实际常数上各有特点，按需选择：①**快速排序**——平均最快（常数小、缓存友好、原地），空间 O(log n)，但**最坏 O(n²)**（可通过随机化/三数取中/三路快排优化避免）、**不稳定**。是**通用内排序的首选**，绝大多数标准库默认用它的优化变体（Go 的 pdqsort、Java 基本类型的双轴快排）。当：通用排序、追求实际速度、不要求稳定、能接受/已优化掉最坏情况时选快排。②**归并排序**——**稳定**、**最坏也保证 O(n log n)**（不会退化），但需要 **O(n) 额外空间**。当：需要稳定排序（多关键字保序）、需要最坏性能保证、**链表排序**（O(1) 空间且天然适配）、**外部排序**（大数据分块多路归并）时选归并。③**堆排序**——**原地 O(1) 空间**、最坏也是 O(n log n)、但**不稳定**且实际常数大（缓存不友好，比快排慢）。当：**严格要求 O(1) 额外空间且最坏也要 O(n log n)**（既要原地又怕快排退化）时选堆排；它的另一大价值是用堆结构解决 **Top K、优先队列、动态求最值**等问题（见 13），而非单纯整体排序。决策口诀：**通用最快 → 快排；要稳定/最坏保证/链表/外部 → 归并；要 O(1) 空间且防退化、或求 Top K → 堆**。实际工程里标准库往往是混合策略（如小数组插入排序、防退化机制），兼取各家之长。

</details>

4. 为什么基于比较的排序算法的时间复杂度下界是 O(n log n)？非比较排序如何突破？

<details><summary>参考答案</summary>

**比较排序 O(n log n) 下界的原因**（信息论/决策树论证）：基于比较的排序，每一步只能通过"比较两个元素的大小"来获取信息，每次比较有两种结果（大于或小于/等于），相当于一次二分决策。对 n 个元素，可能的排列（输入顺序）共有 **n! 种**，排序算法必须能区分出这 n! 种不同情况、给出正确的有序结果。把整个排序过程看成一棵**比较决策树**：每个内部节点是一次比较、每个叶子对应一种最终排列结果，树至少要有 n! 个叶子才能覆盖所有可能。一棵二叉树要有 n! 个叶子，其高度（最坏路径上的比较次数）至少是 **log₂(n!)**。根据斯特林近似，log₂(n!) ≈ n·log₂n - n·log₂e ≈ **O(n log n)**。所以任何比较排序在最坏情况下至少需要 Ω(n log n) 次比较——这是比较排序无法逾越的下界。**非比较排序如何突破**：计数排序、桶排序、基数排序**不通过元素之间的比较来确定顺序**，而是利用元素值本身的信息（值的大小、值域分布、各数位）直接定位元素的位置。例如**计数排序**统计每个值出现的次数，然后按值域从小到大依次输出，根本不做元素间比较，时间 O(n+k)（k 是值域大小）；**基数排序**按数位多轮分配收集，O(d(n+k))。因为它们不受"每次比较只能区分两种情况"的信息论限制，所以能达到线性 O(n)。**代价/限制**：非比较排序只适用于特定数据——计数/桶要求值域不能太大（否则空间爆炸）、基数要求是整数或定长字符串，且对任意对象、超大值域、浮点数等不通用。所以非比较排序是"用对数据分布的假设换取突破比较下界"，比较排序则是通用但有 O(n log n) 下界。

</details>

5. 排序的"稳定性"是什么意思？为什么它在某些场景下重要？

<details><summary>参考答案</summary>

**稳定性**指：排序后，**值相等的元素之间的相对顺序与排序前保持一致**。也就是说，如果排序前 A 元素在 B 元素前面、且 A 和 B 的排序关键字相等，那么排序后 A 仍然在 B 前面。稳定的排序算法有归并排序、计数排序、桶排序、基数排序、冒泡排序、插入排序；不稳定的有快速排序、堆排序、选择排序（它们在交换过程中可能改变相等元素的相对位置）。**为什么在某些场景下重要**：①**多关键字排序（二次排序）**——这是最典型的场景。比如要把一批订单"先按金额排序，金额相同的再按下单时间排序"。一种做法是：先按"下单时间"排一次，再用**稳定排序**按"金额"排一次——因为第二次排序是稳定的，金额相同的订单会保持第一次排序后（即按时间）的相对顺序，从而实现"金额优先、金额相同按时间"的效果。如果第二次用不稳定排序，金额相同的元素相对顺序会被打乱，时间的次序就丢失了。②**保留原始顺序的语义**——当元素除了排序关键字外还携带其他信息、且业务上要求"同等条件下保持输入顺序"时（如展示列表、保持插入序），必须用稳定排序，否则相等元素的顺序随机化会影响结果的可预测性和正确性。③**对象排序**——对复杂对象按某字段排序，往往希望相等字段的对象保持原有相对位置。所以：当排序只关心单一关键字、且相等元素顺序无所谓时，稳定性不重要（可用快排等）；但凡涉及多关键字组合排序、或要求保持相等元素的原始相对顺序，就必须选择稳定排序（如归并、TimSort）。这也是为什么 Java 对象排序默认用稳定的 TimSort、而很多场景需要 sort.Stable。

</details>

6. 求数组中"第 K 大的元素"或"Top K"，一定要先全排序吗？有什么更优的方法？

<details><summary>参考答案</summary>

**不需要先全排序**。全排序是 O(n log n)，但求第 K 大或 Top K 有更优的专门方法：①**快速选择（QuickSelect）——平均 O(n)**。它基于快速排序的 partition：随机选 pivot 做一次 partition 后，pivot 会落到它在有序数组中的最终位置 p；如果 p 正好是我们要找的第 K 大对应的下标，就直接返回；如果 p 偏大就只递归处理左半、偏小就只递归右半——**每次只递归一侧**（不像快排两侧都递归）。因此平均时间是 n + n/2 + n/4 + ... ≈ 2n = O(n)（最坏 O(n²)，可用随机 pivot 避免）。适合"只要找第 K 大/小的那个值"或"找出前 K 个但不要求 K 个之间有序"的场景。②**堆（优先队列）——O(n log k)**。维护一个大小为 K 的**小顶堆**（求第 K 大时）：遍历数组，堆未满就入堆，堆满后若当前元素大于堆顶就弹出堆顶、压入当前元素；遍历完，堆顶就是第 K 大、堆里就是 Top K。每个元素入堆/调整是 O(log k)，共 O(n log k)。当 **K 远小于 n** 时，O(n log k) 优于 O(n log n)，且**只需 O(k) 额外空间**、支持**数据流/海量数据**（不必把所有数据load进内存，见 13）。③对比与选择：快速选择平均最快 O(n)、适合静态数组一次性求解、原地；堆方法 O(n log k)、适合 K 小、数据流式或超大数据（外部 Top K）、且能动态维护。所以求第 K 大/Top K **不应该全排序**（O(n log n) 浪费），而应根据场景用快速选择（要最快、静态）或堆（K 小、流式、海量）。详见 13。

</details>
