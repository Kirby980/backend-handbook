# 精通分治与归并思想

> 分治（Divide and Conquer）是"大事化小"的通用范式——把问题拆成同类子问题，分别解决再合并。归并排序、快速选择、逆序对、快速幂都是它的实例。本篇讲清分治框架和它的复杂度分析，收尾"核心题型"模块。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、分治三步

**分治（Divide and Conquer）** 三步走：

1. **分（Divide）**：把原问题拆成若干**规模更小的同类子问题**。
2. **治（Conquer）**：递归解决每个子问题（小到 base case 直接解）。
3. **合（Combine）**：把子问题的解**合并**成原问题的解。

```go
func divideConquer(problem) result {
    if 问题足够小 { // base case
        return 直接解(problem)
    }
    子问题们 := 拆分(problem)        // 分
    var 子解 []result
    for _, sub := range 子问题们 {
        子解 = append(子解, divideConquer(sub)) // 治（递归）
    }
    return 合并(子解)               // 合
}
```

关键是**子问题与原问题同构**（能递归），且**合并步骤**要高效。归并排序、二叉树递归（[12](./12-精通-二叉树.md)）、二分（[06](./06-精通-二分查找.md)）本质都是分治。

## 二、分治的复杂度

分治的复杂度看**递归树**（见 [01](./01-精通-复杂度分析与算法面试方法论.md)）：

`T(n) = a·T(n/b) + f(n)`——a 个子问题、每个规模 n/b、合并代价 f(n)。

- **归并排序**：`T(n) = 2T(n/2) + O(n)`（分两半，合并 O(n)）→ **O(n log n)**。
- **二分查找**：`T(n) = T(n/2) + O(1)`（只递归一半，合并 O(1)）→ **O(log n)**。
- **快速幂**：`T(n) = T(n/2) + O(1)` → O(log n)。

**主定理**给出快速判断（不必背公式，会画递归树估算即可）：看"每层工作量 × 层数"。归并每层 O(n)、共 log n 层 = O(n log n)。

## 三、归并排序回顾

归并排序是分治的典范（详见 [07 排序](./07-精通-排序算法.md)）：

- **分**：从中点把数组拆成两半。
- **治**：递归排序两半。
- **合**：合并两个有序数组（双指针，O(n)）。

```go
func mergeSort(nums []int) []int {
    if len(nums) <= 1 { // base case
        return nums
    }
    mid := len(nums) / 2
    left := mergeSort(nums[:mid])  // 治
    right := mergeSort(nums[mid:]) // 治
    return merge(left, right)      // 合
}
```

合并步骤是分治的精髓——子问题（两个有序半区）的解，合并成原问题（整体有序）的解。

## 四、逆序对

**逆序对**（i<j 但 nums[i]>nums[j]）是归并的经典应用——在 merge 时**顺便统计**：

```go
// 求逆序对数量（归并过程中统计）
func reversePairs(nums []int) int {
    count := 0
    var mergeSort func(lo, hi int)
    tmp := make([]int, len(nums))
    mergeSort = func(lo, hi int) {
        if lo >= hi {
            return
        }
        mid := (lo + hi) / 2
        mergeSort(lo, mid)
        mergeSort(mid+1, hi)
        // 合并 + 统计逆序对
        i, j, k := lo, mid+1, lo
        for i <= mid && j <= hi {
            if nums[i] <= nums[j] {
                tmp[k] = nums[i]
                i++
            } else {
                tmp[k] = nums[j]
                j++
                count += mid - i + 1 // 关键：左半 [i, mid] 都比 nums[j] 大，都是逆序对
            }
            k++
        }
        for i <= mid {
            tmp[k] = nums[i]; i++; k++
        }
        for j <= hi {
            tmp[k] = nums[j]; j++; k++
        }
        copy(nums[lo:hi+1], tmp[lo:hi+1])
    }
    mergeSort(0, len(nums)-1)
    return count
}
```

精髓：合并两个**已排序**的半区时，若右半的 nums[j] 比左半的 nums[i] 小，则左半 [i, mid] 的所有元素都和 nums[j] 构成逆序对（因为左半已排序），一次性 `count += mid-i+1`。把暴力 O(n²) 降到 **O(n log n)**——这是"在分治合并步骤里附带计算"的典型。

## 五、快速选择

**快速选择（QuickSelect）**：基于快排 partition 的分治，平均 O(n) 找**第 K 大/小**（不用全排序，见 [07](./07-精通-排序算法.md)、[13](./13-精通-堆与TopK.md)）：

```go
// 找第 k 大（转成找第 len-k 小的下标）
func findKthLargest(nums []int, k int) int {
    target := len(nums) - k // 第 k 大 = 升序第 (n-k) 个
    lo, hi := 0, len(nums)-1
    for lo <= hi {
        p := partition(nums, lo, hi) // 同快排的 partition
        switch {
        case p == target:
            return nums[p]
        case p < target:
            lo = p + 1 // 只递归右半
        default:
            hi = p - 1 // 只递归左半
        }
    }
    return -1
}
```

和快排的区别：**每次只递归一侧**（包含目标的那侧），所以平均 O(n)（n + n/2 + n/4 + ... ≈ 2n），而快排两侧都递归是 O(n log n)。最坏 O(n²)（随机 pivot 避免）。

## 六、其他分治

- **快速幂**：求 aⁿ，`aⁿ = (a^(n/2))²`，每次问题减半，O(log n)（位运算/递归实现，见 [19 数学](./19-精通-位运算与数学.md)）。
- **最大子数组**：可用分治（左半最大 / 右半最大 / 跨中点最大，取三者），O(n log n)——但 DP/前缀和有 O(n) 更优解（见 [15](./15-精通-动态规划基础.md)）。
- **二分查找**：每次排除一半，是退化的分治（只治一侧、合并 O(1)），见 [06](./06-精通-二分查找.md)。
- **树的递归**：二叉树问题几乎都是分治（左子树解 + 右子树解 + 合并），见 [12](./12-精通-二叉树.md)。

---

## 七、分治 vs 其他

- **分治 vs 动态规划**：都拆子问题。**分治的子问题独立、不重叠**（如归并的左右半互不影响）；**DP 的子问题重叠**（同一子问题被多次用到，需缓存，见 [15](./15-精通-动态规划基础.md)）。子问题不重叠用分治，重叠用 DP。
- **分治 vs 回溯**：回溯（[08](./08-精通-递归回溯与DFS.md)）是分治在"搜索所有解"上的特例（试探 + 撤销）。
- 分治适合：能拆成独立同类子问题、且合并高效的问题（排序、第 K、逆序对、快速幂、树）。

---

## 陷阱清单

- **合并步骤写错/低效**：分治的关键在合并，merge/合并逻辑错或不是 O(合理) 会拖垮复杂度。
- **base case 缺失或错误**：递归不终止栈溢出，先写正确的最小情况。
- **把重叠子问题用分治**：重复计算（如朴素 fib），应识别重叠子问题改用 DP/记忆化。
- **快速选择两侧都递归**：那就成了快排 O(n log n)，快选只递归含目标的一侧才是 O(n)。
- **逆序对统计时机/数量错**：必须在两半都已排序后的 merge 中统计，且 `count += mid-i+1`。
- **递归深度过大栈溢出**：分治深度 O(log n) 通常安全，但退化（如快选最坏）要注意。
- **最大子数组只会分治**：知道有 O(n) 的 DP（Kadane）解更优。

## 2026 现状

- **分治是基础思维范式**：归并排序、快速选择、二分、树递归、快速幂都是它的体现，理解它能串起很多算法。
- **快速选择是 Top K 的利器**：平均 O(n) 找第 K 大/Top K，比全排序优（见 [13](./13-精通-堆与TopK.md)）。
- **分治在大数据/并行的价值**：分治天然适合**并行**（子问题独立可并发）和**外部排序**（分块归并），MapReduce 本质也是分治思想。
- **配合刷题**：归并排序、逆序对、第 K 大、快速幂、最大子数组（分治解）等，配合本篇（见 [20](./20-精通-高频题型与刷题路线.md)）。

## 练习题

1. 分治算法的三个步骤是什么？举一个典型例子说明。

<details><summary>参考答案</summary>

分治（Divide and Conquer）的三个步骤：①**分（Divide）**——把原问题分解成若干个**规模更小、结构相同（同类）的子问题**；②**治（Conquer）**——递归地解决这些子问题，当子问题小到足够简单（达到 base case 基准情况）时直接求解；③**合（Combine）**——把子问题的解**合并**起来，得到原问题的解。其核心前提是：子问题与原问题同构（能递归处理）、子问题相互独立、且存在高效的合并方式。**典型例子——归并排序**：①分：把待排序数组从中间分成左右两半；②治：递归地对左半和右半分别进行归并排序（数组长度为 1 时就是有序的，即 base case）；③合：把两个已经各自有序的子数组通过双指针"合并"成一个整体有序的数组（每次取两个子数组当前较小的元素放入结果，O(n) 完成合并）。整个过程把"排序 n 个元素"分解为"排序两个 n/2"再合并，递归下去，时间复杂度 T(n)=2T(n/2)+O(n)=O(n log n)。其他分治例子还有：二分查找（每次把搜索区间分成两半、只在一半中继续找）、快速排序（按 pivot 分区后递归两部分）、快速幂（aⁿ 拆成 a^(n/2) 的平方）、二叉树的递归（左子树 + 右子树 + 合并）。分治的精髓在于"大问题拆成同类小问题独立求解、再合并"。

</details>

2. 如何分析分治算法的时间复杂度？归并排序为什么是 O(n log n)？

<details><summary>参考答案</summary>

分析分治复杂度的通用方法是**递归式 + 递归树（或主定理）**。把分治的代价写成递归式 `T(n) = a·T(n/b) + f(n)`，其中 a 是分解出的子问题个数、n/b 是每个子问题的规模、f(n) 是"分"和"合"这两步在当前层的代价（不含递归）。然后用**递归树**直观分析：树的每一层代表一个递归深度，统计"每一层的总工作量"乘以"层数"。或用**主定理**直接套用公式判断（比较 f(n) 与 n^(log_b a) 的大小关系）。**归并排序为什么是 O(n log n)**：它的递归式是 `T(n) = 2T(n/2) + O(n)`——每次把数组分成 2 个规模为 n/2 的子问题（a=2, b=2），合并两个有序子数组的代价是 O(n)（f(n)=O(n)）。用递归树分析：第 0 层（根）合并代价 O(n)；第 1 层有 2 个子问题、每个合并 O(n/2)，合计仍是 O(n)；第 2 层 4 个子问题、每个 O(n/4)，合计还是 O(n)……可以看出**每一层的总合并工作量都是 O(n)**（因为这一层所有子问题规模加起来总是 n）。而数组每次对半分，从 n 分到 1 需要 **log₂n 层**。所以总时间 = 每层 O(n) × log n 层 = **O(n log n)**。直观理解：归并排序把"排序"的工作均摊在 log n 层、每层都对全部 n 个元素做一遍线性的合并。这个"每层 O(n)、共 log n 层"的结构是 O(n log n) 类分治的典型特征。对比二分查找 T(n)=T(n/2)+O(1)：每层 O(1)、共 log n 层 = O(log n)（因为它每次只递归一半、合并 O(1)）。

</details>

3. 如何用归并排序在 O(n log n) 时间内统计数组的逆序对数量？

<details><summary>参考答案</summary>

逆序对是指满足 i < j 但 nums[i] > nums[j] 的数对。暴力枚举所有数对是 O(n²)，而利用归并排序可以降到 O(n log n)，关键是**在归并（合并两个已排序子数组）的过程中顺便统计逆序对**。做法：在归并排序的合并步骤中，左半子数组 [lo, mid] 和右半子数组 [mid+1, hi] 此时都已各自有序，用双指针 i（指左半）、j（指右半）依次合并：当 `nums[i] <= nums[j]` 时把左边的 nums[i] 放入结果、i++；当 `nums[i] > nums[j]` 时（出现逆序），把右边的 nums[j] 放入结果、j++，**此时关键地统计：由于左半子数组是有序的，nums[i] 既然大于 nums[j]，那么左半中从 i 到 mid 的所有元素（共 mid - i + 1 个）都大于 nums[j]，它们都与 nums[j] 构成逆序对**，于是一次性 `count += mid - i + 1`。这样在每次合并时把"跨左右两半的逆序对"全部统计出来，而左半内部、右半内部的逆序对会在它们各自的递归归并中被统计。整个归并排序结束时，累计的 count 就是总逆序对数。复杂度：和归并排序一样 O(n log n)（统计只是在合并里加了 O(1) 的累加，不改变量级）。这是"分治的合并步骤中附带完成额外计算"的经典范例——逆序对、计算右侧更小元素的个数、区间和的某些统计问题都可以用类似的"归并时统计"技巧。核心洞察是：利用合并时两半已有序的性质，能批量地、O(1) 地数出跨两半的满足条件的对数。

</details>

4. 快速选择（QuickSelect）和快速排序有什么区别？为什么它能做到平均 O(n)？

<details><summary>参考答案</summary>

快速选择和快速排序都基于同样的 **partition（分区）**操作：选一个 pivot，把数组划分成"小于 pivot"和"大于 pivot"两部分，pivot 落到它在有序数组中的最终正确位置 p。**区别在于分区之后的处理**：①**快速排序**为了让整个数组有序，需要**递归处理 pivot 左右两边**（左半和右半都要继续排序）；②**快速选择**只是要找"第 K 个元素"（第 K 大/小），分区后 pivot 的位置 p 已经确定，于是：如果 p 正好等于目标下标，就直接返回 nums[p]；如果目标在 p 左边就**只递归（处理）左半**、在右边就**只递归右半**——**每次只处理包含目标的那一侧，另一侧直接丢弃不管**。**为什么平均 O(n)**：因为每次 partition 是 O(当前区间长度)，而快速选择每次只往一侧递归、问题规模平均减半。平均情况下总工作量是 n + n/2 + n/4 + n/8 + ... ≈ 2n = **O(n)**（一个收敛的等比数列，而不是快排那样每层都要处理全部 n 个元素的 O(n log n)）。直观对比：快排每层要处理所有元素（两侧都做）所以是 O(n log n)；快选每层只处理一侧、规模指数衰减，所以是 O(n)。**最坏情况** O(n²)（每次 pivot 都选到极值、每次只缩小 1），可以通过**随机选 pivot**（或三数取中）让最坏情况几乎不发生，保证平均 O(n)。快速选择是求第 K 大/小、Top K 的高效方法（不需要全排序），平均比基于堆的 O(n log k) 还快（静态数组场景），但堆方法更适合数据流/海量数据（见 13）。

</details>

5. 分治和动态规划都把问题拆成子问题，它们的本质区别是什么？

<details><summary>参考答案</summary>

本质区别在于**子问题之间是否重叠（是否会被重复求解）**。①**分治的子问题相互独立、不重叠**——把原问题分解出的各个子问题彼此没有交集、互不依赖，每个子问题只会被求解一次。例如归并排序，把数组分成左右两半，左半和右半的排序完全独立、各自的子问题也不会重复出现；快速排序、二分查找的子问题也都是独立的。所以分治直接递归求解、合并即可，不需要存储中间结果。②**动态规划的子问题重叠**——把问题分解后，**同一个子问题会在不同的分解路径中被反复需要、重复计算**。最典型的是斐波那契：fib(n) 依赖 fib(n-1) 和 fib(n-2)，而 fib(n-1) 又依赖 fib(n-2)……fib(n-2) 等子问题被反复计算，朴素递归（相当于分治式地展开）会导致指数级 O(2ⁿ) 的重复计算。DP 正是为了解决这种重叠——它**把每个子问题的解缓存/记录下来（记忆化或递推表），每个子问题只计算一次**，从而把指数级降到多项式级（如 fib 用 DP 是 O(n)）。**联系与判断**：当你用递归分解问题时，如果发现"会重复求解同一个子问题"（重叠子问题），并且问题具有最优子结构，就应该用 DP（加缓存）而不是纯分治（否则重复计算爆炸）；如果子问题互相独立、不重复，用分治即可、无需缓存。一句话：**子问题独立不重叠 → 分治；子问题重叠（会重复计算）→ 动态规划（缓存避免重复）**。此外 DP 还要求最优子结构。这也是为什么"朴素递归 + 记忆化 = DP"——记忆化正是把会重复的分治式递归的中间结果缓存起来。

</details>

6. 哪些常见算法/问题用到了分治思想？请举几例并说明。

<details><summary>参考答案</summary>

很多经典算法本质都是分治，举例：①**归并排序**——把数组分成两半分别排序、再合并两个有序数组，T(n)=2T(n/2)+O(n)=O(n log n)，是分治排序的典范；②**快速排序**——选 pivot 把数组分区成两部分、递归排序两边（分区是"分+合"的体现），平均 O(n log n)；③**二分查找**——每次把有序区间分成两半、判断目标在哪半、只在那一半继续查找（只递归一侧、合并 O(1)），O(log n)，是分治的"退化"形式；④**快速选择（QuickSelect）**——基于分区的分治，每次只递归含目标的一侧，平均 O(n) 求第 K 大/小；⑤**逆序对统计 / 计算右侧更小元素个数**——在归并的合并步骤中附带统计跨两半的对数，O(n log n)；⑥**快速幂**——aⁿ = (a^(n/2))²，每次把指数减半，O(log n) 求幂（见 19）；⑦**二叉树的递归处理**——求树高、判断平衡、最大路径和等几乎都是"递归求左子树的解 + 递归求右子树的解 + 在根节点合并"，是天然的分治（见 12）；⑧**最大子数组和**——可以分治成"左半最大子数组、右半最大子数组、跨中点的最大子数组"三者取最大，O(n log n)（不过有 O(n) 的 Kadane/DP 更优解）；⑨**矩阵快速幂、大整数乘法（Karatsuba）、最近点对**等更高级的算法也是分治。此外，分治思想还广泛用于**并行计算和大数据处理**——因为分治的子问题相互独立，可以并行求解（MapReduce 的 Map 阶段就是分而治之），以及**外部排序**（数据太大分块排序再多路归并）。理解分治这个"拆成独立同类子问题、分别解决再合并"的范式，能帮助识别和设计很多高效算法。

</details>
