# 精通二分查找

> 二分查找思想简单——每次排除一半，O(log n)——但**边界处理是出了名的难**，差一个 `+1`/`<=` 就死循环或漏解。本篇给出清晰的模板，并讲透二分的两个高级应用：查找边界、二分答案。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、二分的前提与本质

**二分查找（Binary Search）** 的本质：在一个**有序（或具单调性）**的区间里，每次比较中点、排除一半，O(log n) 找到目标。

- **前提**：数据**有序**，或问题具有**单调性**（满足条件的解连成一段，可二分判定边界）。
- **本质**：把搜索空间每次砍半。n 个元素最多 log₂n 次就定位。
- 适用：有序数组找值/找边界、旋转数组、二分答案（求最小/最大满足条件的值）。

二分的难点不在思想，在**边界**——区间开闭、mid 取值、指针更新、循环条件，错一处就死循环或越界。

---

## 二、基础二分

找精确值——**左闭右闭 [left, right]** 写法（推荐，最不易错）：

```go
// 在有序数组中找 target，返回下标，不存在返回 -1
func search(nums []int, target int) int {
    left, right := 0, len(nums)-1 // 闭区间 [left, right]
    for left <= right {           // 区间非空：<= （因为右闭）
        mid := left + (right-left)/2 // 防溢出，等价 (left+right)/2
        switch {
        case nums[mid] == target:
            return mid
        case nums[mid] < target:
            left = mid + 1  // target 在右半，排除 mid
        default:
            right = mid - 1 // target 在左半，排除 mid
        }
    }
    return -1
}
```

记住三个细节（左闭右闭）：
- `right = len-1`（闭区间）。
- `left <= right`（区间 [left,right] 含等于时仍非空）。
- `left = mid+1` / `right = mid-1`（mid 已比较过，排除它，**防死循环**）。

`mid := left + (right-left)/2` 而非 `(left+right)/2`——**防整数溢出**（大数相加越界）。

---

## 三、二分的边界处理

二分有两种主流区间写法，**保持一致**是不出错的关键：

| | 左闭右闭 [l, r] | 左闭右开 [l, r) |
|---|---|---|
| right 初值 | `len-1` | `len` |
| 循环条件 | `l <= r` | `l < r` |
| 命中后 | `r = mid-1` | `r = mid` |
| 未命中右移 | `l = mid+1` | `l = mid+1` |

**建议固定用一种**（如左闭右闭），把模板背熟。死循环的根源通常是：区间没缩小（如 `left = mid` 而非 `mid+1`，当区间剩两个元素时 mid 一直等于 left）。

---

## 四、查找左/右边界

比"找精确值"更常考的是**找边界**：第一个 ≥ target（左边界）、最后一个 ≤ target（右边界）。即使有重复元素也能定位。

```go
// 找第一个 >= target 的位置（左边界 / lower_bound）
func lowerBound(nums []int, target int) int {
    left, right := 0, len(nums) // 左闭右开 [left, right)
    for left < right {
        mid := left + (right-left)/2
        if nums[mid] < target {
            left = mid + 1 // mid 太小，左边界在右
        } else {
            right = mid // nums[mid] >= target，可能是答案，保留 mid，向左找
        }
    }
    return left // [0, left) 都 < target，left 是第一个 >= target 的位置
}
```

找边界的关键：**找到候选时不立即返回，而是继续向一侧收缩**，直到区间为空，最后 left 就是边界。`>= target`、`> target`、`< target`、`<= target` 四种边界，靠调整判断条件实现。Go 标准库 `sort.SearchInts` 就是 lower_bound。

很多"找精确值"也可以用 lowerBound 实现（找到位置再判断是否等于 target），统一成一个模板更省心。

## 五、旋转数组二分

**旋转排序数组**（如 [4,5,6,7,0,1,2]）虽整体无序，但**一分为二后必有一半是有序的**，仍可二分：

```go
// 搜索旋转排序数组（无重复）
func searchRotated(nums []int, target int) int {
    left, right := 0, len(nums)-1
    for left <= right {
        mid := left + (right-left)/2
        if nums[mid] == target {
            return mid
        }
        if nums[left] <= nums[mid] { // 左半 [left, mid] 有序
            if nums[left] <= target && target < nums[mid] {
                right = mid - 1 // target 在有序的左半
            } else {
                left = mid + 1
            }
        } else { // 右半 [mid, right] 有序
            if nums[mid] < target && target <= nums[right] {
                left = mid + 1 // target 在有序的右半
            } else {
                right = mid - 1
            }
        }
    }
    return -1
}
```

套路：**判断哪半有序 → 看 target 是否落在有序的那半 → 据此缩小区间**。这是"部分有序也能二分"的代表，体现二分的灵活性。

## 六、二分答案

**二分答案（二分查找答案）** 是二分的高级用法：当**答案具有单调性**（"答案越大越容易/越难满足"）时，把"求最优解"转化为"判定某个值是否可行"，对答案空间二分。

```go
// 例：分割数组的最大值最小（把数组分成 k 段，使各段和的最大值最小）
// 答案 = 最小的"最大段和"。给定一个候选 maxSum，能否分成 <= k 段？这是单调判定。
func splitArray(nums []int, k int) int {
    left, right := 0, 0
    for _, x := range nums {
        if x > left {
            left = x // 下界：最大单元素
        }
        right += x // 上界：全部和
    }
    for left < right {
        mid := left + (right-left)/2
        if canSplit(nums, k, mid) { // 判定：限制每段和 <= mid，能否 <= k 段
            right = mid // 可行，尝试更小
        } else {
            left = mid + 1 // 不可行，增大
        }
    }
    return left
}
// 贪心判定：每段和不超过 maxSum，最少需要几段
func canSplit(nums []int, k, maxSum int) bool {
    count, cur := 1, 0
    for _, x := range nums {
        if cur+x > maxSum {
            count++
            cur = 0
        }
        cur += x
    }
    return count <= k
}
```

识别二分答案：题目求"**最大值最小**""**最小值最大**""第 K 小/大"，且给定一个候选答案能 O(n) 判定是否可行（判定函数单调）。把"求解"变成"二分 + 判定"，复杂度 O(n log(答案范围))。这是二分最"高阶"的应用。

## 七、模板总结

| 场景 | 模板要点 |
|---|---|
| 找精确值 | 左闭右闭，`l<=r`，命中返回，`l=mid+1`/`r=mid-1` |
| 找左边界（第一个 ≥） | lower_bound，命中不返回继续向左缩 |
| 找右边界（最后一个 ≤） | upper_bound 变体 |
| 旋转数组 | 判断哪半有序，再定位 |
| 二分答案 | 二分答案空间 + 单调判定函数 |

**建议**：把"找精确值"和"lower_bound（找左边界）"两个模板背熟，覆盖绝大多数二分题。`mid` 永远用 `left+(right-left)/2` 防溢出。

---

## 陷阱清单

- **死循环**：区间没缩小（`left=mid` 而非 `mid+1`，或循环条件与区间开闭不匹配）。固定模板。
- **整数溢出**：`(left+right)/2` 大数溢出，用 `left+(right-left)/2`。
- **区间开闭混用**：左闭右闭和左闭右开的 right 初值、循环条件、更新不能混，固定一种。
- **有重复元素找边界用普通二分**：普通二分返回任意一个匹配，找第一个/最后一个要用 lower/upper_bound。
- **没确认有序就二分**：二分前提是有序或单调，无序先排序或换思路。
- **二分答案判定函数不单调**：二分答案要求判定函数单调，否则二分不成立。
- **mid 偏向问题**：求右边界时若 `mid=left+(right-left)/2` 可能死循环，需 `+1` 上取整（按模板）。

## 练习题

1. 二分查找的前提是什么？为什么 mid 要用 `left + (right-left)/2` 而不是 `(left+right)/2`？

<details><summary>参考答案</summary>

**前提**：二分查找要求搜索空间具有**有序性或单调性**——经典情况是数组已排序（升序或降序），更一般地是"满足条件的解连成一段、存在一个单调的判定边界"（这是二分答案的前提）。只有具备这种单调性，才能根据中点的比较结果确定性地排除掉一半搜索空间。如果数据无序又无单调性，二分无法判断目标在哪一半，就不适用（需先排序或换方法）。**mid 用 `left + (right-left)/2` 而非 `(left+right)/2` 的原因是防止整数溢出**：当 left 和 right 都很大时（接近整型最大值），`left + right` 可能超出 int 的表示范围而**溢出**（变成负数或错误值），导致 mid 计算错误、程序出 bug。而 `left + (right-left)/2` 在数学上完全等价于 `(left+right)/2`（right-left 是区间长度的一半加到 left 上），但它先算 `right-left`（这个差值不会溢出，因为它 ≤ right ≤ 最大值）、再除以 2、再加 left，整个过程不会产生超出范围的中间结果，因此避免了溢出。在 Go 里 int 通常是 64 位、一般数组规模下不会溢出，但这是一个跨语言通用的好习惯（尤其 Java/C++ 的 int 是 32 位，很容易溢出），面试写出 `left + (right-left)/2` 能体现严谨性。

</details>

2. 二分查找为什么容易写出死循环？如何避免？

<details><summary>参考答案</summary>

二分死循环的根本原因是**每次循环没有真正缩小搜索区间**，导致 left、right 卡在某个状态反复循环。最常见的两种情况：①**指针更新没有排除 mid**——比如写成 `left = mid`（而不是 `left = mid + 1`）或 `right = mid`（在左闭右闭模板里应是 `right = mid - 1`）。当区间缩小到只剩两个元素时，`mid = left + (right-left)/2` 会等于 left（向下取整），如果此时执行 `left = mid` 就等于 `left = left`，区间没变，无限循环。②**区间开闭约定与循环条件、更新方式不一致**——比如混用了左闭右闭和左闭右开的写法（right 初值、循环条件 `<=` 还是 `<`、命中后 right 怎么改没对应好）。**避免方法**：①**固定使用一套模板并背熟**——比如统一用"左闭右闭 [left, right]"：right 初值为 len-1、循环条件 `left <= right`、mid 比较后用 `left = mid + 1` 或 `right = mid - 1`（两者都排除了已比较的 mid），这样每次区间至少缩小 1，保证收敛、不会死循环；②确保区间约定（开闭）与三要素（right 初值、循环条件、指针更新）**严格一致**；③对于查找边界（lower/upper bound）的模板，注意 `right = mid`（不 -1）配合 `left < right`（不带等于）的左闭右开写法，且某些求右边界的场景 mid 要上取整 `left + (right-left+1)/2` 防止 `left = mid` 时不前进。核心原则：**每次循环必须让区间严格变小**（要么排除 mid，要么至少缩小一端），并保持开闭约定自洽。把一两个正确模板练到肌肉记忆，是避免二分边界 bug 的最有效办法。

</details>

3. 如何用二分查找"第一个大于等于 target 的位置"（左边界 / lower_bound）？关键点是什么？

<details><summary>参考答案</summary>

查找"第一个 >= target 的位置"（lower_bound）的做法（左闭右开 [left, right) 模板）：left=0、right=len(nums)，循环条件 left < right；每次 mid = left + (right-left)/2，比较 nums[mid] 与 target：如果 **nums[mid] < target**，说明 mid 及其左边都不可能是"第一个 >= target"的位置，令 **left = mid + 1**（排除 mid 和左边）；如果 **nums[mid] >= target**，说明 mid **可能就是答案**（它 >= target），但左边或许还有更靠前的也 >= target 的位置，所以**不能排除 mid**，令 **right = mid**（保留 mid，继续在 [left, mid) 里向左找更靠前的）。循环结束（left == right）时，left 就是第一个 >= target 的下标（若所有元素都 < target，则 left == len，表示不存在）。**关键点**：①**找到候选时不立即返回，而是继续向左收缩**——这是找边界与找精确值的本质区别。普通二分找到相等就返回（返回任意一个匹配位置），而找左边界必须在 nums[mid] >= target 时保留 mid（right = mid）继续向左，才能保证最终停在"第一个"满足条件的位置。②**指针更新要保证区间收敛**：left = mid+1（不满足时排除）、right = mid（满足时保留但缩小右界），配合 left < right 终止。③**循环不变量清晰**：始终维持"[0, left) 都 < target、[right, len) 都 >= target"，结束时 left 即分界点。这个模板稍作修改（把判断条件改成 <=、>、< 等）就能求"第一个 > target""最后一个 <= target"等各种边界，是处理有重复元素、找插入位置、统计某值出现次数（upper-lower）等问题的通用工具。Go 的 sort.Search/sort.SearchInts 就是这个语义。

</details>

4. 旋转排序数组（如 [4,5,6,7,0,1,2]）整体无序，为什么还能用二分？怎么做？

<details><summary>参考答案</summary>

虽然旋转排序数组整体不是有序的，但它有一个关键性质：**从任意中点把它一分为二，至少有一半（左半或右半）是完全有序的**。因为它是由一个有序数组旋转得到的（在某个点断开、前后两段各自有序），所以对任意 mid，[left, mid] 和 [mid, right] 中必有一段不跨越"断点"、是单调有序的。利用这个性质就能二分。做法：在 `left <= right` 的二分循环里，算出 mid，先判断 nums[mid] 是否等于 target（是则返回）；然后**判断哪一半有序**——比较 nums[left] 和 nums[mid]：①如果 `nums[left] <= nums[mid]`，说明**左半 [left, mid] 有序**，此时再看 target 是否落在这个有序区间内（`nums[left] <= target < nums[mid]`）：如果在，就 right = mid - 1 去左半找；不在就 left = mid + 1 去右半找。②否则（nums[left] > nums[mid]），说明**右半 [mid, right] 有序**，再看 target 是否落在 `nums[mid] < target <= nums[right]`：如果在，left = mid + 1 去右半；不在就 right = mid - 1 去左半。核心套路是：**先确定哪一半是有序的，再用有序那半的边界判断 target 在不在其中，从而决定往哪半收缩**——这样每次仍能排除一半，保持 O(log n)。关键点是不能直接用普通二分（因为整体无序、nums[mid] 与 target 的大小关系不能直接定位），而要借助"必有一半有序"这个性质，先判断有序的那一半、再利用其单调性判断 target 归属。这体现了二分的灵活性：只要能找到可利用的单调/有序结构，部分有序也能二分。（注意：若数组含重复元素，nums[left]==nums[mid] 时无法确定哪半有序，需要额外处理 left++ 退化。）

</details>

5. 什么是"二分答案"？什么样的题目适合用它？

<details><summary>参考答案</summary>

"二分答案"是二分查找的高级应用：当**最终答案本身具有单调性**时，不直接去"求解"，而是把问题转化为"**判定一个候选答案是否可行**"，然后在**答案的取值空间**上做二分查找，逐步逼近最优答案。具体套路：①确定答案的可能取值范围 [lo, hi]（下界和上界）；②设计一个**判定函数 check(x)**——判断"当答案取 x 时，是否满足题目约束/是否可行"，要求这个判定具有**单调性**（即存在一个临界值，x 比它大都可行、比它小都不可行，或反之）；③在 [lo, hi] 上二分：对中点 mid 调用 check(mid)，根据可行与否决定往左半还是右半收缩，最终二分出那个"恰好可行"的临界值，即为答案。复杂度 O(判定函数复杂度 × log(答案范围))。**适合用二分答案的题目特征**：①题目求的是"**最大值最小化**"或"**最小值最大化**"（如"使最大段和最小""使最小间距最大"）、"第 K 小/大"、"最少需要多少/最多能多少"等最优化问题；②直接求最优解很难，但**给定一个具体的候选答案 x，能比较容易地（通常 O(n) 用贪心或遍历）判定它是否可行**；③这个"可行性"关于 x 单调——比如"每段和不超过 x 时所需段数"随 x 增大而单调不增，于是"段数 <= k 是否成立"随 x 单调，可二分出最小的可行 x。典型例题：分割数组的最大值（最小化最大段和）、在 D 天内运送包裹的最低运载能力、爱吃香蕉的珂珂（最小吃速）、制作 m 束花所需最少天数等。识别口诀："最大值最小/最小值最大/第K个 + 给定答案能 O(n) 判定可行性 + 可行性单调" → 二分答案。它把"难以直接求解的最优化"变成"二分 + 简单判定"，是处理这类难题的利器。

</details>

6. 二分查找有重复元素时，普通二分有什么问题？应该怎么处理？

<details><summary>参考答案</summary>

当数组中有**重复元素**时，普通的二分查找（找到 nums[mid] == target 就立即返回 mid）的问题是：它返回的是**任意一个**等于 target 的位置（取决于二分路径，可能是中间某个），而**不能保证是第一个或最后一个**。但很多题目需要的恰恰是边界——比如"target 第一次出现的位置""最后一次出现的位置""target 出现的次数""第一个大于 target 的位置（插入位置）"等，普通二分无法直接给出这些。处理办法是改用**查找边界的二分（lower_bound / upper_bound）**：①**找第一个等于 target 的位置**——用 lower_bound 找"第一个 >= target 的位置"，再判断该位置元素是否真等于 target（等于则是首次出现，否则不存在）。lower_bound 的关键是：当 nums[mid] >= target 时不返回、而是 right = mid 继续向左收缩，直到定位到最左边的满足位置。②**找最后一个等于 target 的位置**——用类似思路找"第一个 > target 的位置"（upper_bound），其前一个位置就是最后一个等于 target 的（若存在）；或直接写"找最后一个 <= target"的变体，当 nums[mid] <= target 时 left = mid 向右收缩（注意此时 mid 要上取整防死循环）。③**统计 target 出现次数** = upper_bound(target) - lower_bound(target)。核心思想是：**找到匹配时不立即返回，而是继续朝目标边界的方向收缩区间**，把"找任意一个"变成"找第一个/最后一个"。所以遇到有重复元素且要求边界/计数的二分题，要用 lower_bound/upper_bound 这类边界二分模板，而不是找到就返回的普通二分。Go 的 sort.Search 实现的就是 lower_bound 语义，可直接用或作为模板。

</details>
