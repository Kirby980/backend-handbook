# 精通链表技巧

> 链表题是面试高频，套路也最固定：哑结点、反转、快慢指针、环检测。掌握这几个模板，链表题基本不慌。本篇用 Go 讲清链表的通用技巧。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、链表的特点

链表是**非连续内存**、靠指针串联的结构：

- **插入/删除 O(1)**（已知位置，改指针即可），但**访问第 i 个 O(n)**（要遍历）。
- 与数组相反：数组随机访问快、增删慢；链表增删快、访问慢（见 [02 数组](./02-精通-数组与字符串技巧.md)、[Java 集合](../java/J01-精通-集合框架与List源码.md)）。

Go 中定义单链表节点：

```go
type ListNode struct {
    Val  int
    Next *ListNode
}
```

链表题的核心是**指针操作**——画图理清指针指向，是不出错的关键。

## 二、哑结点（dummy node）

**哑结点（dummy/sentinel）** 是链表题第一大技巧：在头部前面放一个虚拟节点，**统一头结点和其他节点的处理逻辑**，避免对"头结点是否被删/被改"做特判。

```go
// 删除链表中所有值为 val 的节点：用 dummy 统一处理头结点
func removeElements(head *ListNode, val int) *ListNode {
    dummy := &ListNode{Next: head} // 哑结点指向头
    prev := dummy
    for cur := head; cur != nil; cur = cur.Next {
        if cur.Val == val {
            prev.Next = cur.Next // 删除 cur
        } else {
            prev = cur
        }
    }
    return dummy.Next // 返回真正的头（可能变了）
}
```

**什么时候用 dummy**：当**头结点可能被删除或改变**时（删除、合并、插入到头部）。有了 dummy，头结点和中间节点处理逻辑一致，代码更简洁、少 bug。`return dummy.Next` 拿到最终的头。

## 三、反转链表

**反转链表**是必会模板，迭代法（O(1) 空间）：

```go
// 迭代反转：三指针 prev/cur/next
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode // 新链表的头（初始 nil）
    cur := head
    for cur != nil {
        next := cur.Next // 1. 暂存下一个
        cur.Next = prev  // 2. 反转指针
        prev = cur       // 3. prev 前移
        cur = next       // 4. cur 前移
    }
    return prev // prev 是反转后的头
}
```

递归法（O(n) 栈空间）：

```go
func reverseListRec(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head
    }
    newHead := reverseListRec(head.Next)
    head.Next.Next = head // 让下一个节点指回自己
    head.Next = nil       // 断开自己原来的指向
    return newHead
}
```

反转的变体（反转前 k 个、反转区间、k 个一组反转）都基于这个模板，是高频题。

## 四、快慢指针

**快慢指针（fast & slow）**：两个指针不同速度移动，解决"找中点、找倒数第 k 个、判环"等：

```go
// 找链表中点（快指针走 2 步，慢指针走 1 步，快到尾时慢在中点）
func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next      // 慢走 1 步
        fast = fast.Next.Next // 快走 2 步
    }
    return slow // 偶数个节点时返回后中点
}

// 找倒数第 k 个：快指针先走 k 步，再一起走
func findKthFromEnd(head *ListNode, k int) *ListNode {
    fast := head
    for i := 0; i < k; i++ {
        fast = fast.Next // 快指针先走 k 步
    }
    slow := head
    for fast != nil {
        slow = slow.Next
        fast = fast.Next // 一起走，fast 到尾时 slow 在倒数第 k
    }
    return slow
}
```

核心思想：用**两个指针的速度差/起点差**，一次遍历就定位特殊位置，避免先求长度再遍历的两趟。

## 五、环检测

**Floyd 判圈算法（龟兔赛跑）**：快慢指针，有环则快指针会"套圈"追上慢指针。

```go
// 判断是否有环
func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast { // 相遇 = 有环
            return true
        }
    }
    return false // fast 到 nil = 无环
}

// 找环的入口：相遇后，一个指针回到头，两指针同速走，再次相遇即入口
func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast { // 第一次相遇
            p := head
            for p != slow {
                p = p.Next
                slow = slow.Next
            }
            return p // 环入口
        }
    }
    return nil
}
```

为什么"相遇后一个回头、同速走会在入口相遇"——是数学推导（设头到入口 a、入口到相遇点 b、环长 c，可推出 a = (n-1)c + (c-b)），面试能说出结论 + 大致推导即可。

## 六、合并与排序

**合并两个有序链表**（归并的基础）：

```go
func mergeTwoLists(l1, l2 *ListNode) *ListNode {
    dummy := &ListNode{} // 哑结点简化
    tail := dummy
    for l1 != nil && l2 != nil {
        if l1.Val <= l2.Val {
            tail.Next = l1
            l1 = l1.Next
        } else {
            tail.Next = l2
            l2 = l2.Next
        }
        tail = tail.Next
    }
    if l1 != nil { // 接上剩余
        tail.Next = l1
    } else {
        tail.Next = l2
    }
    return dummy.Next
}
```

**链表排序**首选**归并排序**（[09 分治](./09-精通-分治与归并思想.md)）：用快慢指针找中点拆两半，递归排序后合并。O(n log n) 时间、O(log n) 栈空间，链表归并不需要额外数组（数组归并要 O(n) 辅助空间），是链表排序的最优选择。

## 七、常见技巧

- **画图**：链表题一定画图，标出 prev/cur/next 指针，理清指向再写。
- **dummy 哑结点**：头结点可能变就用。
- **快慢指针**：找中点、倒数第 k、判环。
- **递归**：链表天然适合递归（反转、合并），但注意 O(n) 栈空间。
- **断开与连接顺序**：改指针时先暂存要用的节点，避免丢失（如反转里先存 next）。

## 陷阱清单

- **不用 dummy 导致头结点特判一堆**：头可能变（删除/合并/头插）就用 dummy，统一逻辑。
- **反转时丢失 next**：改 `cur.Next = prev` 前必须先存 `next := cur.Next`，否则链表断了找不回。
- **快慢指针判空不全**：循环条件 `fast != nil && fast.Next != nil`，少判一个会空指针 panic（fast.Next.Next 越界）。
- **环形链表无限循环**：处理可能有环的链表，遍历要有终止机制（判环或限步）。
- **返回错头结点**：用了 dummy 要 `return dummy.Next`，别返回 dummy 或原 head。
- **递归栈溢出**：超长链表递归（反转/排序）有 O(n) 栈深度风险，必要时改迭代。
- **修改指针顺序错**：连接新节点前丢了对后续的引用，画图理清顺序。

## 练习题

1. 哑结点（dummy node）解决什么问题？什么情况下应该用它？

<details><summary>参考答案</summary>

哑结点（dummy/sentinel node，哨兵节点）是在链表真正的头结点前面额外添加的一个虚拟节点（dummy.Next 指向原头结点），它解决的核心问题是：**统一头结点和其他节点的处理逻辑，避免对头结点做特殊判断**。在链表操作中，头结点常常是"特殊"的——它没有前驱节点，所以涉及"删除头结点""在头部插入""头结点可能改变"等操作时，如果不用 dummy，就必须单独写一段代码处理头结点的情况（判断是不是头、单独更新 head 等），代码冗长且容易出 bug。有了哑结点，头结点就有了一个"前驱"（dummy），于是删除/插入头结点和删除/插入中间节点的逻辑完全一样（都是改前驱的 Next），无需特判；最后返回 `dummy.Next` 即可拿到（可能已改变的）真正头结点。**应该用 dummy 的情况**：当操作可能**改变或删除头结点**时，典型场景包括——删除链表中的节点（尤其可能删头）、合并两个链表、在头部插入、链表重排/分区等。判断标准是"头结点会不会被动到、最终的头是否可能和原来不同"。如果操作完全不涉及头结点的增删改（如单纯遍历、原地改值），则不必用 dummy。哑结点是链表题的第一大通用技巧，能显著简化代码、减少边界错误。

</details>

2. 写出迭代反转链表的思路，关键步骤的顺序为什么不能乱？

<details><summary>参考答案</summary>

迭代反转链表用**三个指针 prev、cur、next**，从头到尾逐个把每个节点的指针方向反转。思路：prev 初始为 nil（它将成为反转后链表的尾、最终是新头的前驱），cur 从原头开始遍历。对每个 cur 节点，执行四步：①`next := cur.Next` 先暂存 cur 的下一个节点；②`cur.Next = prev` 把 cur 的指针反转，指向它前面的 prev；③`prev = cur` 把 prev 前移到 cur；④`cur = next` 把 cur 前移到刚才暂存的 next。循环直到 cur 为 nil，此时 prev 指向原链表的最后一个节点，即反转后的新头，返回 prev。**关键步骤顺序不能乱的原因**：核心在于第①步必须**先暂存 next**，再做第②步的反转。因为第②步 `cur.Next = prev` 会把 cur 原本指向后继的指针**覆盖**掉——一旦执行了这步，如果之前没有用 next 保存住 cur 原来的下一个节点，就再也找不到链表的后续部分了（链表从这里断开、丢失）。所以必须先 `next := cur.Next` 把后继存好，才能安全地修改 cur.Next。同理③④的前移也依赖前面已正确保存的引用。一句话：改一个指针之前，先保存好这个指针原本指向的、后面还要用到的节点，这是链表指针操作不丢失数据的通用原则。

</details>

3. 快慢指针能解决哪些链表问题？以"找中点"为例说明原理。

<details><summary>参考答案</summary>

快慢指针（fast & slow pointers）通过让两个指针以**不同的速度**或**不同的起点**移动，常用来一趟遍历就定位链表的特殊位置或检测结构，典型应用有：①**找链表中点**（快指针走两步、慢指针走一步）；②**判断链表是否有环**（Floyd 判圈，有环时快指针会追上慢指针）；③**找环的入口**；④**找倒数第 k 个节点**（快指针先走 k 步，再两指针同速走）；⑤判断回文链表（找中点 + 反转后半比较）等。**以"找中点"为例**：让 slow 和 fast 都从头开始，循环中 slow 每次走 1 步（slow = slow.Next）、fast 每次走 2 步（fast = fast.Next.Next）。由于 fast 的速度是 slow 的两倍，当 fast 走到链表末尾（fast 为 nil 或 fast.Next 为 nil）时，fast 走过的路程是 slow 的两倍，所以此时 slow 恰好走到了链表的**中间位置**。直观理解：fast 走完全程 n 步时，slow 只走了 n/2 步，正好在中点。这样**只需一趟遍历**就找到中点，而不用先遍历一遍求出长度 n、再遍历 n/2 步（两趟）。注意偶数个节点时有"返回前中点还是后中点"的差异，取决于循环条件的写法（fast!=nil 还是 fast.Next!=nil 作为终止），按题目要求调整。快慢指针的精髓就是用速度差/起点差，把"需要知道长度才能定位"的问题变成一趟遍历搞定。

</details>

4. 如何用快慢指针判断链表是否有环？如何进一步找到环的入口？

<details><summary>参考答案</summary>

**判断是否有环（Floyd 判圈/龟兔赛跑）**：用 slow（每次走 1 步）和 fast（每次走 2 步）从头同时出发。如果链表**无环**，fast 会先到达链表末尾（fast 或 fast.Next 为 nil），循环结束、返回无环；如果链表**有环**，fast 进入环后会一圈圈地转，slow 随后也进入环，由于 fast 比 slow 每次多走一步、相对速度为 1，fast 一定会在环内逐步追上并与 slow **相遇**（slow == fast），相遇即证明有环。**找环的入口**：在快慢指针第一次相遇后，让一个指针（设为 p）**重新回到链表头**，另一个指针（slow，停在相遇点）留在原地，然后两个指针都**以相同速度（每次 1 步）**一起前进，它们**再次相遇的节点就是环的入口**。原理（数学推导）：设链表头到环入口的距离为 a，环入口到首次相遇点的距离为 b，环的长度为 c。相遇时 slow 走了 a+b，fast 走了 a+b+kc（k 为 fast 在环里多转的圈数）；又因 fast 速度是 slow 两倍，fast 路程 = 2×slow 路程，即 a+b+kc = 2(a+b)，化简得 a = kc - b = (k-1)c + (c-b)。这意味着：从头走 a 步到达入口，恰好等于从相遇点再走 (c-b) 步（绕完剩余环段到入口）再加若干整圈——所以一个指针从头走 a、另一个从相遇点走同样步数，会同时到达环入口而相遇。面试中能说出"相遇后一个回头、同速再走、相遇点即入口"这个结论并给出大致的距离推导即可。

</details>

5. 链表排序为什么首选归并排序？相比数组归并有什么优势？

<details><summary>参考答案</summary>

链表排序首选归并排序，原因和它相比数组归并的优势主要在**空间**和**对链表结构的契合**上。①**O(n log n) 的稳定时间复杂度**——归并排序无论什么输入都是 O(n log n)，而快速排序在链表上不仅实现别扭、还有最坏 O(n²) 风险，且快排依赖随机访问（数组下标）而链表随机访问是 O(n)、不适合。②**归并对链表是"近乎原地"的，空间优势明显**——数组做归并排序时，合并两个有序部分需要一个 O(n) 的额外辅助数组来暂存合并结果（无法在原数组上原地高效合并），所以数组归并是 O(n) 额外空间；而链表归并**不需要额外数组**：合并两个有序链表只需通过改变节点的指针指向就能把它们串起来（见合并两个有序链表的模板，O(1) 额外指针操作），完全复用原有节点，不分配新空间。所以链表归并的额外空间只有递归调用栈的 O(log n)（自顶向下递归找中点拆分），比数组归并的 O(n) 更省。③**链表拆分和合并都很自然**——用快慢指针 O(n) 找中点把链表拆成两半，递归排序后用"合并两个有序链表"拼接，整个流程与链表的指针结构天然契合，实现清晰。综上，归并排序在时间最优、空间更省（无需 O(n) 辅助数组）、且天然适配链表的拆分/合并操作，是链表排序的最佳选择；而数组场景下快排（原地、常数小）往往更受青睐——这也体现了"数据结构决定算法选择"。

</details>

6. 链表操作中最容易出的 bug 有哪些？如何避免？

<details><summary>参考答案</summary>

链表操作常见 bug 及避免方法：①**修改指针时丢失后续节点**——在执行 `cur.Next = xxx` 改变指针前，没有先保存原来的 cur.Next，导致链表后半部分丢失、找不回。避免：改指针前先用临时变量暂存所有后面还要用到的节点引用（如反转里先 `next := cur.Next`）。②**空指针解引用（panic）**——访问 nil 节点的 Next，尤其快慢指针里 `fast.Next.Next` 没判空。避免：循环条件写全（如 `for fast != nil && fast.Next != nil`），访问前确保非 nil。③**头结点边界处理遗漏**——头结点可能被删/被改却没特殊处理，或返回了错误的头。避免：涉及头结点增删改时用**哑结点 dummy** 统一逻辑，最后 `return dummy.Next`。④**指针连接/断开的顺序错误**——多个指针调整顺序不对，导致成环或断链。避免：操作前**画图**，标清每个指针当前指向和目标指向，按正确顺序逐步修改。⑤**意外造成环或没断开旧指针**——如反转后忘了把原头的 Next 置 nil（递归反转里要 `head.Next = nil`），导致成环或尾部错误。避免：反转/重排后检查尾节点 Next 是否正确置空。⑥**有环链表遍历死循环**——对可能有环的链表直接遍历到 nil 会无限循环。避免：先判环或限制步数。总的避免原则：**先画图理清指针、改指针前先暂存后继、用 dummy 处理头结点、循环条件判空要全、操作后检查首尾指针**。链表题考的就是指针操作的严谨和细心，画图 + 小心处理边界是关键。

</details>
