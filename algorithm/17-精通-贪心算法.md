# 精通贪心算法

> 贪心算法每一步都选"当前看起来最好的"，期望最终得到全局最优。它简单高效，但**不是所有问题都能贪心**——关键是判断"局部最优能否导致全局最优"。本篇讲清贪心的适用条件、与 DP 的区别，以及如何验证贪心的正确性。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、贪心是什么

**贪心算法（Greedy）**：在每一步都做出**当前看起来最优的选择**（局部最优），不回头、不考虑全局，期望这一连串局部最优能累积成全局最优。

```go
// 分发饼干：贪心——尽量用小饼干满足胃口小的孩子
func findContentChildren(g, s []int) int {
    sort.Ints(g) // 孩子胃口排序
    sort.Ints(s) // 饼干尺寸排序
    child := 0
    for i := 0; i < len(s) && child < len(g); i++ {
        if s[i] >= g[child] { // 当前饼干能满足当前孩子
            child++ // 满足一个
        }
    }
    return child
}
```

贪心的特点：**简单、高效**（通常 O(n) 或 O(n log n)，常需先排序），无需像 DP 那样保存所有子问题状态。但**适用范围窄**——必须满足贪心选择性质。

---

## 二、贪心的前提

贪心能用，要满足两个条件：

1. **贪心选择性质**：**局部最优选择能导致全局最优**——每一步的最优选择不依赖后续，且不会让后面变差。这是贪心与 DP 的本质区别（DP 要考虑所有选择，贪心只选一个且不反悔）。
2. **最优子结构**：大问题的最优解包含子问题的最优解（这点和 DP 一样）。

**难点在第 1 条**——很多问题局部最优 ≠ 全局最优（贪心失效，见第六节）。所以用贪心前要**确认/证明贪心选择性质成立**，否则会得到错误答案。

---

## 三、贪心 vs DP

| 维度 | 贪心 | 动态规划 |
|---|---|---|
| 选择 | 每步只选**一个**局部最优，不反悔 | 考虑**所有**可能选择，记录所有子问题 |
| 是否回头 | 不回头 | 通过状态保留所有可能 |
| 正确性 | 需满足贪心选择性质（不总成立） | 总能得最优（只要状态/转移对） |
| 复杂度 | 通常更低（O(n)/O(n log n)） | 较高（O(n²) 等） |
| 难点 | 证明贪心正确 | 设计状态和转移 |

关系：**贪心是 DP 的特例**——当每步的最优选择唯一确定、不需要回溯比较所有子问题时，DP 退化为贪心。**能贪心就贪心（更快），不确定能否贪心就用 DP（保险）**。例如零钱兑换：特定币值（如 1/5/10）能贪心，任意币值必须 DP（见第六节）。

---

## 四、如何证明贪心正确

面试若用贪心，最好能**论证它为什么对**（或至少举例验证），常用两种方法：

- **交换论证（Exchange Argument）**：假设有一个最优解和贪心解不同，证明可以把最优解里的某步换成贪心的选择而不变差（甚至更好），从而说明贪心解也是最优的。
- **反证法 / 数学归纳**：假设贪心不是最优，推出矛盾。

实战中，面试**不一定要严格证明，但要能说出"为什么这样贪是对的"的直觉**，或**举几个例子验证**（包括边界）。如果想不出反例且直觉成立，可以先用贪心；担心错就改 DP。**贪心最大的风险是"看起来对其实不对"**，所以要警惕。

## 五、经典题

```go
// 跳跃游戏：能否到达最后一个下标（贪心维护能到达的最远位置）
func canJump(nums []int) bool {
    maxReach := 0
    for i := 0; i < len(nums); i++ {
        if i > maxReach { // 当前位置都到不了
            return false
        }
        if i+nums[i] > maxReach {
            maxReach = i + nums[i] // 更新最远可达
        }
    }
    return true
}

// 无重叠区间：移除最少区间使剩余不重叠（贪心：按结束时间排序，优先保留早结束的）
func eraseOverlapIntervals(intervals [][]int) int {
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1] // 按结束时间排序
    })
    count, end := 0, intervals[0][1]
    for i := 1; i < len(intervals); i++ {
        if intervals[i][0] >= end { // 不重叠，保留
            end = intervals[i][1]
        } else {
            count++ // 重叠，移除当前（贪心：移除结束晚的）
        }
    }
    return count
}
```

经典贪心题及贪心点：
- **跳跃游戏**：维护"最远可达位置"。
- **区间调度/无重叠区间**：**按结束时间排序**，优先选/保留早结束的（给后面留最多空间）。
- **分发饼干**：小饼干给胃口小的。
- **加油站**：总油量够则一定有解，找起点。
- **合并区间**：按起点排序（[02](./02-精通-数组与字符串技巧.md)）。

很多贪心题的关键是**排序**（按结束时间、起点、大小等），排序后贪心选择。

## 六、贪心失效的例子

**贪心不总对**——经典反例是**零钱兑换**（用最少硬币凑出金额）：

- 币值 [1, 5, 10, 25]，凑 30：贪心（每次拿最大）→ 25+5 = 2 枚，正确。
- 但币值 [1, 3, 4]，凑 6：贪心 → 4+1+1 = 3 枚；**最优是 3+3 = 2 枚**。**贪心错了！**

因为"每次拿最大"这个局部最优，在某些币值组合下不是全局最优。所以**任意币值的零钱兑换必须用 DP**（[15](./15-精通-动态规划基础.md)），只有特定币值（如标准货币）才能贪心。

这说明：**用贪心前一定要验证它对不对**，不能想当然。想不出反例 + 能论证 → 贪心；有反例 → 老实用 DP。

## 七、识别与套路

**何时考虑贪心**：
- 求**最优值**（最大/最小/最多/最少），且**每步有明显的"最优选择"**。
- **排序后能顺序决策**（区间、调度、分配类）。
- 局部最优**直觉上**能导致全局最优（需验证）。

**贪心套路**：
1. 想一个贪心策略（每步选什么）。
2. **举例验证**（尤其找反例）。
3. 想不出反例 + 能论证 → 用贪心；否则 → 改 DP。
4. 常需先**排序**（按某关键字），再线性扫描贪心选择。

**和 DP 的取舍**：不确定能否贪心时，DP 更保险（一定对）；确认能贪心则贪心更快更简洁。

---

## 陷阱清单

- **想当然用贪心不验证**：局部最优 ≠ 全局最优（如任意币值零钱兑换）。用前必须验证/举反例。
- **该用 DP 却用贪心**：贪心选择性质不成立时贪心给错误答案，老实用 DP。
- **排序关键字选错**：区间调度按"结束时间"排（不是开始时间），排错则贪心错。
- **贪心 + 没排序**：很多贪心需先排序才能顺序决策，漏了排序逻辑错。
- **只测了几个用例就以为对**：贪心的反例可能很隐蔽，要尽量找边界反例。
- **混淆贪心和 DP 的适用**：能贪心更快，但不确定时 DP 保险——别为了快用错。
- **加油站等问题贪心边界**：起点、环形、总量判断的边界要想清。

## 2026 现状

- **贪心是高频但有迷惑性的题型**：很多题"看起来能贪心"，面试官爱考你能不能识别贪心是否成立、能不能举反例。
- **贪心常与排序、区间结合**：区间调度、会议室、任务分配是经典贪心 + 排序题。
- **贪心 vs DP 的判断是考点**：能说清"为什么这题能/不能贪心"、给出反例或论证，体现算法素养。
- **工程中的贪心**：调度（最短作业优先）、缓存淘汰、资源分配、Huffman 编码（贪心建树）等。
- **配合刷题**：LeetCode 贪心标签（跳跃游戏、区间调度、分发饼干、加油站、买卖股票）必刷，注意对比哪些能贪心、哪些要 DP（见 [16](./16-精通-经典DP专题.md)、[20](./20-精通-高频题型与刷题路线.md)）。

## 练习题

1. 贪心算法的基本思想是什么？使用贪心需要满足哪两个条件？

<details><summary>参考答案</summary>

**基本思想**：贪心算法在求解问题时，把问题分成一系列步骤，在**每一步都做出在当前看来最好（最优）的选择**（即局部最优选择），并且**做了选择就不再反悔、不回头**，期望通过每一步的局部最优累积，最终得到全局最优解。它不像动态规划那样保存和比较所有子问题的解，而是每步只"贪心地"选一个当下最优的，因此通常简单、高效（常配合排序，复杂度 O(n) 或 O(n log n)）。**使用贪心需要满足的两个条件**：①**贪心选择性质（Greedy Choice Property）**——**通过一系列局部最优的选择能够得到全局最优解**，即每一步所做的当前最优选择不依赖于未来的选择、也不会导致后续无法得到最优（局部最优可以"安全地"成为全局最优的一部分）。这是贪心区别于动态规划的本质：贪心做完选择就确定下来、不再考虑其他可能，而 DP 要考虑所有选择。这个性质**不是所有问题都具备**，是能否用贪心的关键、也是难点。②**最优子结构**——一个问题的最优解包含其子问题的最优解（这点和 DP 相同），即在做出贪心选择后，剩下的子问题的最优解与已做选择组合起来构成原问题的最优解。**关键**在于第一条：必须确认/证明"局部最优能导致全局最优"贪心才正确，否则贪心会给出错误答案（如任意币值的零钱兑换，局部拿最大币不一定是全局最少硬币数）。所以用贪心前一定要验证贪心选择性质成立（通过证明或举反例排除），不能想当然。

</details>

2. 贪心算法和动态规划有什么区别和联系？如何选择用哪个？

<details><summary>参考答案</summary>

**区别**：①**选择方式**——贪心在每一步只做**一个**当前看起来最优的选择，且做了不反悔、不回头；动态规划则**考虑所有可能的选择**，通过记录所有子问题的解（状态）来保留各种可能性，再从中选出最优。②**是否回溯/全局视角**——贪心是"目光短浅"的、只看当前局部最优、不保留其他选项；DP 是"全局"的、保留所有子状态，能从整体上保证最优。③**正确性**——DP 只要状态定义和转移正确就**一定能得到最优解**；贪心只有在满足"贪心选择性质"时才正确，**不是所有问题都能贪心**（局部最优可能不等于全局最优）。④**效率**——贪心通常更快、更省空间（常 O(n) 或 O(n log n)，不需要存所有状态）；DP 通常复杂度更高（如 O(n²)、O(n×m)）、需要额外空间存 dp 表。⑤**难点不同**——贪心的难点是**证明贪心策略正确（贪心选择性质）**；DP 的难点是**设计状态和转移方程**。**联系**：贪心可以看作动态规划的一种**特例**——当问题满足贪心选择性质（每一步的最优选择是唯一确定的、不需要回过头比较所有子问题的解）时，DP 中"考虑所有选择取最优"就退化成了"直接选那个确定的局部最优"，于是 DP 简化为贪心。两者都要求最优子结构。**如何选择**：①如果能确定/证明问题满足贪心选择性质（局部最优必然导致全局最优），**优先用贪心**——它更快更简洁；②如果不确定能否贪心、或已找到贪心的反例（局部最优≠全局最优），就**用动态规划**——它更保险、一定能得到最优解。实践策略：先想贪心策略并**举例验证（尤其找反例）**，想不出反例且能论证则用贪心；一旦发现反例或没把握，就退回到 DP。典型对比：零钱兑换在标准币值下可贪心、在任意币值下必须用 DP；区间调度类问题通常可贪心（按结束时间排序）。记住"能贪心则贪心（快），没把握用 DP（稳）"。

</details>

3. 如何验证一个贪心策略是否正确？

<details><summary>参考答案</summary>

验证贪心策略正确性有"严格证明"和"实践验证"两个层面。**严格证明方法**：①**交换论证（Exchange Argument）**——这是证明贪心最常用的方法。思路是：假设存在一个最优解 OPT，它与贪心解 GREEDY 在某一步的选择不同；然后证明，可以把 OPT 中那个与贪心不同的选择**替换成贪心的选择，而不会使解变差**（结果至少一样好，甚至更好且仍然合法）。通过一步步把 OPT 向 GREEDY"靠拢"而不损失最优性，最终说明贪心解也是最优解。例如区间调度问题，可论证"选结束时间最早的区间"总不劣于其他选择（它给后面留下最多空间）。②**反证法 / 数学归纳法**——假设贪心解不是最优，推导出矛盾；或用归纳法证明"每一步贪心选择后都能保持可以扩展为最优解"。**实践验证方法**（面试中更常用、更快）：①**举例 + 找反例**——用多个例子（特别是**边界和极端情况**）测试贪心策略，努力构造一个让"局部最优 ≠ 全局最优"的反例。如果能找到反例，说明贪心**不成立**，必须换 DP（如零钱兑换币值 [1,3,4] 凑 6，贪心 4+1+1=3 枚 ≠ 最优 3+3=2 枚，这个反例就否定了贪心）。②如果**想了很久都构造不出反例、且贪心策略在直觉上能说通**（能讲清"为什么这样贪是安全的"），则较有信心用贪心。**面试中的实用建议**：不一定要写出严格的数学证明，但**至少要能说出贪心策略为什么对的直觉理由**（如"按结束时间排序优先选早结束的，能给后续留最多空间"），并**用几个例子（含边界）验证一遍**。最稳妥的态度是：贪心策略想出来后先尝试找反例——找到反例就用 DP，找不到且能论证就用贪心。**贪心最大的陷阱就是"看起来对其实不对"**，所以验证（尤其找反例）这一步绝不能省。

</details>

4. 区间调度问题（如无重叠区间、会议室）为什么按"结束时间"排序贪心？

<details><summary>参考答案</summary>

以"选择最多个互不重叠的区间"（活动选择问题）为例：贪心策略是**按区间的结束时间从早到晚排序，然后依次选择那些与已选区间不冲突（开始时间 ≥ 上一个已选区间的结束时间）的区间**。**为什么按结束时间排序、优先选结束早的**：核心直觉是——**在能选的区间中，选择结束时间最早的那个，会给后面剩下的时间留出最大的空间，从而有机会容纳更多的区间**。结束得越早，后面可用的时间段就越长，越可能再塞进更多不重叠的区间；反之如果贪心地选了一个结束很晚的区间（即使它开始得早），它会占用很长的时间、挤掉后面本可以安排的多个区间。所以"结束最早"是局部最优选择，能导向"选出最多区间"的全局最优。**用交换论证可以证明它正确**：假设某个最优解的第一个区间不是结束最早的那个，那么把它替换成结束最早的区间，由于结束更早、不会与最优解中后续选的区间冲突（后续区间的开始时间本来就 ≥ 原第一个区间的结束时间 ≥ 结束最早区间的结束时间），替换后仍是合法解且区间数不减少——可一直这样替换，说明存在一个"总是先选结束最早区间"的最优解，即贪心解最优。**对比"按开始时间排序"为什么不对**：如果按开始时间排序贪心选，可能先选了一个开始很早但持续很久（结束很晚）的区间，它会与很多后面的区间重叠、导致只能选很少——局部（开始早）最优不等于全局最优。所以是按**结束时间**而非开始时间。相关变体：无重叠区间（移除最少区间使其不重叠）= 总数 − 最多不重叠区间数，同样按结束时间贪心；会议室 II（最少需要几个会议室）则用按开始时间排序 + 最小堆维护结束时间（见堆 13）。一句话：区间调度类问题，**按结束时间排序、优先保留/选择结束早的**，是给后续留最大空间的贪心，能证明最优。

</details>

5. 举一个贪心算法失效的例子，说明为什么这种情况下必须用动态规划。

<details><summary>参考答案</summary>

经典的贪心失效例子是**零钱兑换问题**（给定不同面额的硬币，求凑出目标金额所需的**最少**硬币数）。**贪心策略**（每次都贪心地选当前能用的最大面额硬币）在某些币值组合下会失效。**反例**：硬币面额为 [1, 3, 4]，要凑出金额 6。①**贪心解**：每次拿不超过剩余金额的最大硬币——先拿 4（剩 2），再拿 1（剩 1），再拿 1（剩 0），共用了 **3 枚**硬币（4+1+1）。②**最优解**：实际上用两枚 3（3+3=6）就能凑出，只需 **2 枚**硬币。贪心给出的 3 枚不是最优，**贪心失败了**。**为什么失效**：贪心"每次拿最大面额"这个局部最优选择，在面额 [1,3,4] 下不满足贪心选择性质——选了最大的 4 之后，剩下的 2 只能用两个 1 来凑，反而比"放弃 4、改用两个 3"更差。也就是说，**当前看起来最优的选择（拿 4）会导致全局不是最优**，局部最优 ≠ 全局最优。只有在某些"良好"的币值体系下（如标准货币 1、5、10、25，满足特定性质）贪心才恰好正确；对**任意**币值组合，贪心都可能出错。**为什么必须用动态规划**：因为要保证得到最少硬币数这个最优解，就必须**考虑所有可能的凑法、而不是只贪心地走一条路**。DP 的做法：定义 dp[amount] = 凑出金额 amount 所需的最少硬币数，转移方程 `dp[amount] = min(dp[amount - coin] + 1)`（遍历每一种硬币面额 coin，尝试用它作为最后一枚，取所有方案的最小值），base case dp[0]=0。这样 DP 会穷尽所有硬币组合的可能、保留每个子金额的最优解，最终保证 dp[目标] 是真正的最少硬币数（如上例 dp[6] 会正确算出 2）。这个例子说明：**当贪心选择性质不成立（局部最优不一定全局最优）时，贪心会给出错误答案，必须用动态规划"考虑所有选择、记录所有子问题最优解"来保证正确性**。这也是为什么用贪心前一定要验证（举反例）——零钱兑换正是一道"看起来能贪心、实则需要 DP"的经典陷阱题。

</details>

6. 看到一道求最优解的题，你如何判断该尝试贪心还是直接上 DP？

<details><summary>参考答案</summary>

判断思路（一个实用的决策流程）：①**先看问题类型和规模**——如果是求最优值（最大/最小/最多/最少）、且每一步似乎有一个"明显当下最优"的选择，可以**先考虑贪心**（贪心更简单高效）；如果问题明显涉及"每步多种选择、且选择之间相互影响、有重叠子问题"，则倾向 DP。②**尝试构造贪心策略并找反例**——这是最关键的一步。想一个贪心规则（每步选什么，常配合排序），然后**用例子尤其是边界/极端情况去验证它，努力寻找反例**（构造一个"局部最优导致全局非最优"的输入）。如果**很快找到反例** → 贪心不成立，**直接用 DP**；如果**怎么都构造不出反例、且能讲清贪心为什么安全（直觉/简单论证成立）** → 较有信心**用贪心**。③**从暴力递归判断重叠子问题**——如果写出暴力递归后发现有大量**重叠子问题**（同一子问题被反复计算），这通常是 DP 的强信号（加记忆化即 DP，见 15）；而贪心问题往往不需要回头比较子问题、一遍扫描就能决策。④**看是否需要"考虑所有选择"**——如果直觉上"只走一条贪心路径就够了、不需要回头权衡其他选择"，倾向贪心；如果"必须比较多种选择组合才能确定最优"（一步的最优依赖后续、或当前最优会影响后面使其变差），就该 DP。⑤**不确定时，DP 更保险**——DP 只要状态和转移正确就一定能得到最优解，是"稳"的选择；贪心快但有"看似对实则错"的风险。所以**没有十足把握能贪心时，优先用 DP 保证正确**，等确认贪心成立（找不到反例 + 能论证）再用贪心优化。实战经验法则：①经典区间调度/分配类（按某关键字排序后顺序决策）多为贪心；②"凑成某值的最少/方案数""最长××子序列""带约束的最优路径"等多为 DP；③拿不准就先 DP 求对，再思考能否贪心简化。一句话：**先试贪心 + 找反例，找到反例或没把握就上 DP（DP 一定对，贪心更快但要验证）**。

</details>
