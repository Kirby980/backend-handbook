# 精通栈与队列

> 栈（LIFO）和队列（FIFO）是最基础的线性结构，但**单调栈**和**单调队列**这两个进阶技巧能优雅解决"下一个更大元素""滑动窗口最大值"等难题，是面试高频亮点。本篇讲清基础用法和这两个利器。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、栈与队列基础

- **栈（Stack）**：后进先出（LIFO），只在一端（栈顶）增删。
- **队列（Queue）**：先进先出（FIFO），一端进（队尾）一端出（队头）。
- **双端队列（Deque）**：两端都能进出，是单调队列的基础。

Go 中用 slice 模拟（没有内置 stack/queue）：

```go
// 栈：用 slice
stack := []int{}
stack = append(stack, x)            // push
top := stack[len(stack)-1]          // peek
stack = stack[:len(stack)-1]        // pop

// 队列：用 slice（出队挪头，或用双指针/list）
queue := []int{}
queue = append(queue, x)            // enqueue
front := queue[0]                   // peek
queue = queue[1:]                   // dequeue（注意频繁这样会有底层数组不回收问题，大量数据用 container/list 或环形缓冲）
```

## 二、栈的应用

栈天然适合"**最近匹配 / 后进先出**"的场景：

```go
// 有效括号：栈匹配
func isValid(s string) bool {
    pairs := map[byte]byte{')': '(', ']': '[', '}': '{'}
    stack := []byte{}
    for i := 0; i < len(s); i++ {
        c := s[i]
        if c == '(' || c == '[' || c == '{' {
            stack = append(stack, c) // 左括号入栈
        } else {
            if len(stack) == 0 || stack[len(stack)-1] != pairs[c] {
                return false // 右括号不匹配栈顶
            }
            stack = stack[:len(stack)-1] // 匹配，出栈
        }
    }
    return len(stack) == 0 // 栈空才全匹配
}
```

栈的经典应用：**括号匹配、表达式求值（中缀转后缀/逆波兰）、函数调用栈、递归转迭代、撤销操作、浏览器前进后退**。核心是"最近的先处理"。

## 三、单调栈

**单调栈（Monotonic Stack）**：栈内元素保持单调（递增或递减），用于求"**下一个更大/更小元素**"这类问题，O(n)。

```go
// 下一个更大元素：返回每个元素右边第一个比它大的，没有则 -1
func nextGreaterElements(nums []int) []int {
    n := len(nums)
    res := make([]int, n)
    for i := range res {
        res[i] = -1
    }
    stack := []int{} // 存下标，栈内对应的值单调递减
    for i := 0; i < n; i++ {
        // 当前元素比栈顶大 → 栈顶找到了它的"下一个更大元素"
        for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
            top := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            res[top] = nums[i]
        }
        stack = append(stack, i) // 当前下标入栈
    }
    return res
}
```

原理：栈里维护"还没找到下一个更大元素"的下标（值单调递减）；遇到更大的就把栈里所有比它小的弹出并记录答案。**每个元素入栈出栈各一次，O(n)**（摊还）。

应用：下一个更大/更小元素、**柱状图中最大的矩形**、接雨水、每日温度。看到"找左/右第一个比它大/小的"就想单调栈。

---

## 四、队列与双端队列

队列用于"**按顺序处理 / 层级遍历**"：
- **BFS**（广度优先，[14 图论](./14-精通-图论.md)、[12 二叉树层序](./12-精通-二叉树.md)）的核心结构。
- **双端队列（Deque）**：两端可进出，是单调队列、滑动窗口的基础。

Go 没有内置 deque，可用 slice 模拟两端操作，或 `container/list`（双向链表）。

---

## 五、单调队列

**单调队列（Monotonic Queue）**：双端队列里维护单调性，用于求"**滑动窗口最大值/最小值**"，把每次取窗口最值从 O(k) 降到 **O(1)**（整体 O(n)）。

```go
// 滑动窗口最大值：单调递减队列（存下标）
func maxSlidingWindow(nums []int, k int) []int {
    var res []int
    deque := []int{} // 存下标，对应值单调递减，队头是窗口最大值
    for i := 0; i < len(nums); i++ {
        // 1. 队尾：弹出比当前小的（它们不可能再成为最大值）
        for len(deque) > 0 && nums[deque[len(deque)-1]] < nums[i] {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i) // 当前下标入队尾
        // 2. 队头：弹出滑出窗口的下标
        if deque[0] <= i-k {
            deque = deque[1:]
        }
        // 3. 窗口形成后，队头即最大值
        if i >= k-1 {
            res = append(res, nums[deque[0]])
        }
    }
    return res
}
```

原理：队列保持**单调递减**，队头永远是当前窗口最大值。新元素入队时，把队尾所有比它小的弹掉（它们被新元素"挡住"，不可能再是最大）；同时把滑出窗口的队头移除。**每个元素入队出队各一次，O(n)**。

这是滑动窗口（[05](./05-精通-滑动窗口.md)）求窗口最值的最优解——配合滑窗使用。

## 六、栈实现队列 / 队列实现栈

经典设计题，考察对两种结构的理解：

```go
// 用两个栈实现队列：in 栈进、out 栈出
type MyQueue struct {
    in, out []int
}
func (q *MyQueue) Push(x int) {
    q.in = append(q.in, x) // 入队压 in 栈
}
func (q *MyQueue) Pop() int {
    q.peekTransfer()
    x := q.out[len(q.out)-1]
    q.out = q.out[:len(q.out)-1]
    return x
}
func (q *MyQueue) peekTransfer() {
    if len(q.out) == 0 { // out 空了，把 in 全倒进 out（顺序反转两次=原序）
        for len(q.in) > 0 {
            q.out = append(q.out, q.in[len(q.in)-1])
            q.in = q.in[:len(q.in)-1]
        }
    }
}
```

原理：栈是 LIFO，倒一次反转顺序，倒两次（in→out）变回 FIFO。均摊 O(1)（每个元素最多被搬一次）。反过来"两个队列实现栈"也是经典题。

## 七、识别与套路

- **括号/匹配/最近处理/嵌套** → 栈。
- **找下一个/上一个更大/更小元素**、柱状图矩形、接雨水 → **单调栈**。
- **层级遍历 / BFS** → 队列。
- **滑动窗口最值** → **单调队列**。
- **表达式求值、逆波兰** → 栈。

单调栈/单调队列的共同思想：**及时丢弃"不可能成为答案"的元素**（被更大/更小的挡住的），保持单调性，使每个元素只进出一次，O(n)。

---

## 陷阱清单

- **Go 用 slice 做队列频繁 `queue[1:]`**：底层数组不释放、内存泄漏风险；大数据用 container/list 或双指针 + 复用。
- **单调栈/队列存值还是存下标**：通常**存下标**（能算距离、判断窗口范围），别只存值。
- **单调性方向搞反**：求下一个更大用单调递减栈，求窗口最大值用单调递减队列——想清"弹出谁"。
- **空栈/空队列访问**：peek/pop 前判空，否则越界 panic。
- **括号匹配忘了最后判栈空**：遍历完栈非空说明有未匹配的左括号。
- **滑动窗口最值用暴力 O(nk)**：用单调队列降到 O(n)。
- **栈实现队列没均摊理解**：以为每次 pop 都 O(n)，其实每个元素只搬一次、均摊 O(1)。

## 练习题

1. 栈和队列分别是什么特性？各适合解决什么问题？

<details><summary>参考答案</summary>

**栈（Stack）** 是**后进先出（LIFO，Last In First Out）**的线性结构：只能在一端（栈顶）进行插入（push）和删除（pop），最后进入的元素最先被取出。**队列（Queue）** 是**先进先出（FIFO，First In First Out）**的线性结构：一端（队尾）入队、另一端（队头）出队，最先进入的元素最先被取出。**栈适合的问题**：凡是涉及"**最近/最后处理的优先**""嵌套匹配""逆序"的场景——如括号匹配（最近的左括号先匹配）、表达式求值与逆波兰（中缀转后缀）、函数调用栈、递归转迭代（用栈模拟递归）、DFS 深度优先搜索、撤销/重做操作、浏览器前进后退历史等。核心是"最后进来的最先出去"。**队列适合的问题**：凡是涉及"**按到达/产生顺序依次处理**""逐层扩展"的场景——如 BFS 广度优先搜索（按层访问，是队列最经典的应用，见图论/二叉树层序遍历）、任务/请求的顺序处理、生产者-消费者缓冲、消息队列等。核心是"先来先服务"。此外它们各有进阶变体：**单调栈**（栈内保持单调，解决"下一个更大/更小元素"）和**单调队列**（双端队列保持单调，解决"滑动窗口最值"），以及双端队列（Deque，两端可进出）。选择口诀：需要"后进先出/最近匹配/嵌套/回溯"用栈；需要"先进先出/按序处理/层级遍历/BFS"用队列。

</details>

2. 单调栈解决什么类型的问题？以"下一个更大元素"为例说明原理和复杂度。

<details><summary>参考答案</summary>

**单调栈**（栈内元素保持单调递增或递减）专门高效解决"**为每个元素找它左边或右边第一个比它大（或比它小）的元素**"这类问题，典型题有：下一个更大元素、每日温度（下一个更暖的天）、柱状图中最大的矩形、接雨水、股票跨度等。看到"找左/右第一个更大/更小"就应想到单调栈。**以"下一个更大元素"为例**（为每个元素找右边第一个比它大的）：从左到右遍历，维护一个**栈内对应元素值单调递减的栈**，栈里存的是"**还没有找到下一个更大元素的元素的下标**"。遍历到当前元素 nums[i] 时：只要栈非空且**当前元素大于栈顶下标对应的值**，就说明 nums[i] 正是栈顶那个元素苦苦等待的"下一个更大元素"——于是把栈顶弹出、记录它的答案为 nums[i]；重复这个弹出过程，直到栈顶元素 ≥ 当前元素（或栈空）；然后把当前下标 i 压入栈。遍历结束时，栈里剩下的元素都没有更大的元素（答案为 -1）。**原理**：栈中维护的是一批"递减的、尚未找到更大值的候选"；一旦来了个更大的元素，就能一次性把栈里所有比它小的元素的答案都确定下来。**复杂度 O(n)**：虽然有内层 while 弹栈循环，但**每个元素最多入栈一次、出栈一次**，所有弹栈操作的总次数不超过 n（摊还分析），所以整体是线性 O(n)，远优于暴力对每个元素向后扫描的 O(n²)。空间 O(n)（栈）。注意单调栈通常**存下标**而非值（便于计算距离、定位元素），单调方向（递增还是递减）取决于求更大还是更小。

</details>

3. 单调队列如何在 O(n) 内求"滑动窗口最大值"？为什么比暴力快？

<details><summary>参考答案</summary>

**暴力解**是对每个窗口位置都遍历窗口内 k 个元素求最大值，共 n 个窗口、每个 O(k)，总 O(nk)。**单调队列**能做到 O(n)。做法：维护一个**双端队列（deque），队列里存元素下标、且这些下标对应的值保持单调递减**（队头是当前窗口的最大值的下标）。遍历数组，对每个 nums[i]：①**维护单调性（队尾操作）**——把队尾所有"对应值小于 nums[i]"的下标弹出，因为它们在 nums[i] 进入窗口后永远不可能再成为窗口最大值了（被更大且更靠右的 nums[i] "挡住"了，nums[i] 会比它们活得更久还更大），然后把 i 加入队尾；②**维护窗口范围（队头操作）**——如果队头下标已经滑出了当前窗口（队头下标 ≤ i-k），就把它从队头移除；③**取最大值**——当窗口形成后（i ≥ k-1），队头下标对应的值就是当前窗口的最大值，记录它。**为什么是 O(n)**：虽然有队尾弹出的内层循环，但**每个元素的下标最多入队一次、出队一次**（要么从队尾被更大的元素挤掉、要么从队头因滑出窗口被移除），所有入队出队操作总次数不超过 2n，所以整体是 O(n)（摊还分析）。**为什么比暴力快**：暴力每次都重新扫描整个窗口找最大值、做了大量重复比较；单调队列通过"及时丢弃那些不可能再成为最大值的元素"，让队头始终维护着当前窗口的最大值，取最大值是 O(1)、维护是均摊 O(1)，避免了重复扫描。核心思想和单调栈一样：**及时淘汰不可能成为答案的元素，保持单调性，使每个元素只进出一次**。它是滑动窗口求最值问题的最优解（配合 05 滑动窗口使用）。

</details>

4. 如何用两个栈实现一个队列？它的复杂度如何？

<details><summary>参考答案</summary>

用两个栈 in（输入栈）和 out（输出栈）来模拟队列的 FIFO 行为。**入队（push）**：直接把元素压入 **in 栈**（O(1)）。**出队（pop）/ 取队头（peek）**：先检查 out 栈是否为空——如果 **out 栈为空，就把 in 栈里的所有元素依次弹出并压入 out 栈**（即把 in 栈整个"倒"进 out 栈），然后从 out 栈顶弹出/读取元素；如果 out 栈非空，直接从 out 栈顶弹出/读取。**原理**：栈是 LIFO，一个元素经过"压入 in → 从 in 弹出 → 压入 out → 从 out 弹出"，相当于被反转了两次，顺序就变回了原始的进入顺序，从而实现 FIFO。比如依次入队 1、2、3 都进 in 栈（栈内自底向上是 1,2,3），第一次出队时把 in 倒进 out（out 自底向上变成 3,2,1），从 out 顶弹出的是 1，正是最先入队的——符合队列先进先出。关键点：**只有当 out 栈空时才从 in 栈搬运**（不能每次都搬，否则顺序乱），这保证了已经在 out 里的元素顺序正确、且后续入队的新元素不会插队。**复杂度**：入队 O(1)。出队**均摊 O(1)**——虽然某一次出队遇到 out 空时要把 in 的元素全部搬过去（那一次是 O(n)），但**每个元素一生中只会被搬运一次**（从 in 到 out），之后就一直在 out 里直到被弹出，所以把搬运成本均摊到每个元素上是 O(1)。这是均摊分析的典型例子（类似动态数组扩容），不能因为单次最坏 O(n) 就认为整体低效。反过来"用两个队列实现栈"也是经典题，但通常某个操作是 O(n)。

</details>

5. 单调栈和单调队列存元素的下标还是值？为什么？

<details><summary>参考答案</summary>

通常都**存下标（index）**，而不是直接存值。原因：①**能定位元素、计算距离/范围**——很多问题需要的不只是"更大的值是多少"，还需要知道"它在什么位置""相隔多远""是否在某个窗口范围内"。例如"每日温度"要求的是"还要等几天才有更暖的一天"，需要用下标相减算出天数；柱状图最大矩形要用下标算宽度；滑动窗口最大值要用下标判断队头是否已滑出窗口（队头下标 ≤ i-k 就移除）。如果只存值，就无法做这些位置相关的计算。②**通过下标随时能取到值**——存了下标 i，需要值时用 nums[i] 即可，所以存下标不损失任何信息，反而信息更全（既有位置又能取值）；而只存值则丢失了位置信息。③**处理重复值**——存下标能区分值相同但位置不同的元素，避免歧义。具体到两者：**单调栈**存下标，便于在弹出时为"被弹出的那个下标"记录答案、并计算它与当前元素的距离（如每日温度的天数差、矩形的宽度）；**单调队列**存下标，便于判断队头元素是否还在当前滑动窗口内（用下标和窗口边界 i-k 比较），从而及时把滑出窗口的队头移除。所以惯例是：单调栈/单调队列里**存下标**，需要比较或取值时通过 nums[下标] 获取值。这是这类题的一个重要实现细节，初学者容易只存值而无法处理"距离/窗口范围"这类要求。

</details>

6. 在 Go 中用 slice 实现队列，频繁执行 `queue = queue[1:]` 出队有什么隐患？

<details><summary>参考答案</summary>

隐患主要是**内存不会被释放、可能导致内存泄漏和浪费**。在 Go 中，`queue = queue[1:]` 这种"切掉头部"的出队操作并**不会真正释放或移动底层数组的内存**——它只是让 slice 的起始指针后移一位、长度减一，但**底层数组依然完整存在**，被切掉的前面那些元素所占的内存仍然被这个底层数组持有、无法被 GC 回收（因为 slice 还引用着同一个底层数组，只是"看不到"前面部分了）。如果一个队列不断地入队（append，底层数组向后增长甚至扩容）和出队（queue[1:]，起始指针不断后移），底层数组会**越来越长、前面已出队的空间却一直不回收**，造成内存持续增长、浪费——尤其在长时间运行、吞吐量大的场景下，相当于内存泄漏。此外如果被切掉的元素是指针或包含指针的对象，这些对象也因为底层数组还引用着而无法被回收。**解决办法**：①**用 `container/list`（双向链表）**实现队列，出队真正删除节点、释放内存；②**用双指针 + 定期重置**：维护 head 指针标记队头位置（出队只移动 head 不切 slice），当 head 过大时把剩余有效元素拷贝到新 slice（或移到数组前部）并重置，平摊回收空间；③**用环形缓冲区（ring buffer）**：固定大小数组循环复用，head/tail 指针绕回，不产生持续增长；④如果数据量小、队列生命周期短，`queue[1:]` 也可接受（影响不大）。面试中提到"Go 没有内置队列、用 slice 模拟要注意出队的内存问题、大数据量用 list 或环形缓冲"能体现对底层的理解。补充：`queue[1:]` 出队是 O(1)（只移指针），但若改用 `append(queue[:0], queue[1:]...)` 或拷贝来真正前移元素则是 O(n)，所以要在"内存"和"时间"间权衡，环形缓冲是兼顾两者的方案。

</details>
