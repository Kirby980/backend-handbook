# 精通数组与字符串技巧

> 数组和字符串是算法面试最基础也最高频的数据结构。前缀和、差分、原地操作、区间合并这些技巧出现在大量题目里。本篇打好数组/字符串的基本功，后面的双指针（[04](./04-精通-双指针.md)）、滑动窗口（[05](./05-精通-滑动窗口.md)）都建立在此之上。
>
> **📅 基准：2026 年 6 月。** 代码用 Go。

---

## 一、数组的特点

数组（Go 里常用 slice）是**连续内存**存储的同类型元素集合：

- **随机访问 O(1)**：按下标直接定位（`arr[i]` = 首地址 + i×元素大小）。
- **中间插入/删除 O(n)**：要搬移后续元素。
- Go 的 slice 是动态数组（底层数组 + len + cap），append 均摊 O(1)（见 [01 均摊](./01-精通-复杂度分析与算法面试方法论.md)）。

数组题的核心优势是**下标即位置**，很多技巧（前缀和、计数数组、原地标记）都利用这一点。

---

## 二、前缀和

**前缀和（Prefix Sum）**：预处理出 `prefix[i] = nums[0] + ... + nums[i-1]`，则**任意区间和 [l, r] = prefix[r+1] - prefix[l]**，O(1) 查询。

```go
// 预处理 O(n)，之后每次区间和查询 O(1)
func buildPrefix(nums []int) []int {
    prefix := make([]int, len(nums)+1) // prefix[0]=0
    for i, x := range nums {
        prefix[i+1] = prefix[i] + x
    }
    return prefix
}
// 区间 [l, r] 的和（闭区间）
func rangeSum(prefix []int, l, r int) int {
    return prefix[r+1] - prefix[l]
}
```

适用：**多次查询区间和**（一次预处理，多次 O(1) 查询，把每次 O(n) 降到 O(1)）。这是"空间换时间 + 预处理"的典型（见 [01](./01-精通-复杂度分析与算法面试方法论.md)）。扩展到**二维前缀和**（矩阵区域和）、**前缀异或**、配合哈希表解"和为 k 的子数组"。

## 三、差分数组

**差分（Difference Array）** 是前缀和的逆操作，用于**频繁对区间整体加减**：

- `diff[i] = nums[i] - nums[i-1]`。
- 对区间 [l, r] 整体加 val，只需 `diff[l] += val; diff[r+1] -= val`（O(1)）。
- 最后对 diff 求前缀和，还原出修改后的数组。

```go
// 多次区间更新 O(1)/次，最后 O(n) 还原
func rangeUpdate(n int, ops [][3]int) []int { // ops: [l, r, val]
    diff := make([]int, n+1)
    for _, op := range ops {
        l, r, val := op[0], op[1], op[2]
        diff[l] += val
        diff[r+1] -= val
    }
    res := make([]int, n)
    cur := 0
    for i := 0; i < n; i++ {
        cur += diff[i]
        res[i] = cur
    }
    return res
}
```

适用：**大量区间更新、最后查询**（如航班预订、区间加法）。把每次 O(n) 的区间更新降到 O(1)。

## 四、原地操作

**原地（in-place）** = O(1) 额外空间，直接在原数组上改。常配合双指针（见 [04](./04-精通-双指针.md)）：

```go
// 原地反转数组：对撞双指针，O(1) 空间
func reverse(nums []int) {
    l, r := 0, len(nums)-1
    for l < r {
        nums[l], nums[r] = nums[r], nums[l]
        l++
        r--
    }
}

// 原地移除元素（移除所有等于 val 的）：快慢指针
func removeElement(nums []int, val int) int {
    slow := 0
    for fast := 0; fast < len(nums); fast++ {
        if nums[fast] != val {
            nums[slow] = nums[fast] // 保留的往前放
            slow++
        }
    }
    return slow // 新长度
}
```

面试常要求 O(1) 空间，原地 + 双指针是标准手段。

## 五、字符串基础

Go 的字符串是**不可变的字节序列**（UTF-8 编码）：

- `string` 不可变，要修改先转 `[]byte`（ASCII/字节）或 `[]rune`（Unicode 字符）。
- **`[]byte` vs `[]rune`**：英文/ASCII 用 `[]byte`（按字节）；含中文等多字节字符要用 `[]rune`（按字符），否则按字节遍历会拆坏字符。
- 拼接用 `strings.Builder`（避免反复创建字符串，类似 Java StringBuilder）。

```go
// 反转字符串（含 Unicode 安全）
func reverseString(s string) string {
    r := []rune(s)          // 转 rune 切片，按字符处理
    for l, rr := 0, len(r)-1; l < rr; l, rr = l+1, rr-1 {
        r[l], r[rr] = r[rr], r[l]
    }
    return string(r)
}
```

字符串题本质多是数组（字符数组）题，双指针、滑窗、哈希计数都适用。

## 六、区间问题

区间题（合并区间、插入区间、区间重叠）的通用套路：**先按起点排序，再线性扫描合并**。

```go
import "sort"

// 合并重叠区间
func merge(intervals [][]int) [][]int {
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0] // 按起点排序
    })
    res := [][]int{intervals[0]}
    for _, cur := range intervals[1:] {
        last := res[len(res)-1]
        if cur[0] <= last[1] { // 重叠：当前起点 <= 上一个终点
            if cur[1] > last[1] {
                last[1] = cur[1] // 合并，扩展终点
            }
        } else {
            res = append(res, cur) // 不重叠，新增
        }
    }
    return res
}
```

**两个区间 [a1,b1] 和 [a2,b2] 重叠的判断：`a1 <= b2 && a2 <= b1`**。区间题排序后扫描是通用模板，复杂度 O(n log n)（排序主导）。

## 七、常见技巧

- **计数/标记数组**：用数组下标当 key 计数（值域小的整数），O(1) 查询，比哈希表更快（如统计字符频次用 `[26]int`）。
- **原地哈希**：把数组本身当哈希表用（值和下标映射，如"找缺失的第一个正数"把 nums[i] 放到下标 nums[i]-1）。
- **模拟**：按题意一步步模拟（如螺旋矩阵、Z 字变换），注意边界和方向控制。
- **双指针/滑窗**：见 [04](./04-精通-双指针.md)、[05](./05-精通-滑动窗口.md)。

## 陷阱清单

- **前缀和数组下标错位**：`prefix` 长度应为 n+1、prefix[0]=0，区间 [l,r] 和 = prefix[r+1]-prefix[l]，下标容易差一。
- **差分忘了 diff[r+1] -= val**：区间更新要在 r+1 处减回去，且 diff 长度要 n+1 防越界。
- **字符串按字节遍历中文**：含多字节字符时用 `[]rune`，按 `[]byte` 会拆坏字符。
- **区间重叠判断写错**：注意是 `a1<=b2 && a2<=b1`，边界相等算不算重叠看题意。
- **原地操作改坏数据**：原地移动时注意 slow/fast 指针逻辑，别覆盖还没处理的数据。
- **Go slice 共享底层数组**：切片是引用，子切片改动会影响原数组，必要时 copy。
- **字符串频繁 + 拼接**：用 strings.Builder，别在循环里 +（见 [Go 字符串](../golang/G02-精通-Go-数据类型-Rune-与字符串内幕.md)）。

## 练习题

1. 前缀和解决什么问题？为什么 prefix 数组长度通常设为 n+1？

<details><summary>参考答案</summary>

前缀和解决的核心问题是**多次查询区间和**：在不修改数组的前提下，需要反复求"区间 [l, r] 内元素之和"。如果每次都现场累加，单次是 O(n)、q 次查询就是 O(nq)；用前缀和预处理后，每次区间和查询降到 O(1)。做法：预处理 `prefix[i]` 表示原数组前 i 个元素之和，则区间 [l, r]（闭区间）的和 = prefix[r+1] - prefix[l]——一次 O(n) 预处理，之后每次查询 O(1)，是"预处理 + 空间换时间"的典型。**prefix 长度设为 n+1（而非 n）的原因**：多设一个 prefix[0]=0 作为"空前缀"的哨兵，使得 prefix[i] 统一表示"前 i 个元素的和"，这样区间和公式 `prefix[r+1] - prefix[l]` 对所有区间（包括从下标 0 开始的区间，l=0 时减去 prefix[0]=0）都成立、无需特殊处理 l=0 的边界。如果只用长度 n、让 prefix[i] 表示包含 nums[i] 的前缀和，那么求 [0, r] 时就要单独判断、容易出错。多一个 0 哨兵让公式统一、避免差一错误。注意下标对应关系：prefix[i+1] = prefix[i] + nums[i]。这是前缀和最常见的实现细节，也是易错点。

</details>

2. 差分数组适合什么场景？它和前缀和是什么关系？

<details><summary>参考答案</summary>

差分数组适合**频繁对区间进行整体加减、最后统一查询结果**的场景（如多次给区间 [l,r] 内所有元素加上某个值，最后看每个位置的最终值）。如果直接对每次区间更新都遍历修改，单次是 O(区间长度)、最坏 O(n)，m 次更新就是 O(nm)；用差分数组，每次区间更新只需 O(1)，最后一次 O(n) 还原，总复杂度 O(n+m)。做法：差分数组 diff 满足 `diff[i] = nums[i] - nums[i-1]`；要给区间 [l, r] 整体加 val，只需令 `diff[l] += val` 和 `diff[r+1] -= val`（O(1) 完成一次区间更新）；所有更新做完后，对 diff 求前缀和就还原出修改后的数组（diff 的前缀和 = 原数组）。**它和前缀和的关系是互逆操作**：前缀和是"由原数组求累加和"，差分是"由原数组求相邻差"；对差分数组求前缀和能还原原数组，对前缀和数组求差分也能还原。直观理解：差分把"区间修改"转化为"两个端点的单点修改"（在 l 处加、在 r+1 处减），延迟到最后用前缀和一次性累积生效；而前缀和把"区间查询"转化为"两个端点前缀的相减"。一个优化区间更新、一个优化区间查询，互为逆运算。

</details>

3. 在 Go 中处理含中文的字符串，为什么不能直接按 byte 遍历？应该怎么做？

<details><summary>参考答案</summary>

因为 Go 的字符串底层是 **UTF-8 编码的字节序列**，而 UTF-8 是变长编码：ASCII 字符（英文、数字）占 1 个字节，但中文等字符通常占 **3 个字节**（其他 Unicode 字符可能 2 或 4 字节）。如果直接按 byte 遍历（`for i := 0; i < len(s); i++ { s[i] }` 或 `[]byte(s)`），你遍历的是一个个字节而非一个个"字符"——一个中文字会被拆成 3 个独立的字节，按字节处理（如反转、按位置取字符、计数）就会破坏字符的完整性，得到乱码或错误结果。正确做法是把字符串转成 **`[]rune`**（`r := []rune(s)`）：rune 是 Go 中表示一个 Unicode 码点（字符）的类型（int32），`[]rune` 会把字符串按完整字符切分，每个元素是一个完整字符，这样按字符遍历、反转、索引、计数才正确。例如反转含中文的字符串要先转 []rune 再反转。或者用 `for i, r := range s` 直接 range 字符串——Go 的 range 字符串会自动按 rune（字符）迭代、r 是当前字符、i 是其起始字节索引。总结：纯 ASCII 场景可以用 []byte（更省内存）；只要可能含多字节字符（中文等），就用 []rune 或 range 来按字符处理，避免按字节拆坏字符。

</details>

4. 如何判断两个区间 [a1, b1] 和 [a2, b2] 是否重叠？合并区间的通用套路是什么？

<details><summary>参考答案</summary>

**判断两个区间是否重叠**：两个闭区间 [a1, b1] 和 [a2, b2] 重叠的充要条件是 `a1 <= b2 && a2 <= b1`（即"一个区间的起点不超过另一个区间的终点，且反之亦然"）。反过来，不重叠的条件是 `b1 < a2 || b2 < a1`（一个完全在另一个左边或右边）。是否把"端点相等"（如 b1 == a2）算作重叠，要看题目对开闭区间的定义，需要时向面试官澄清。**合并区间的通用套路**：①**先按区间起点升序排序**（O(n log n)，这是关键的预处理——排序后重叠的区间一定相邻，只需线性扫描一次）；②初始化结果列表，放入第一个区间；③**线性遍历**剩余区间，对每个当前区间 cur 与结果列表中最后一个区间 last 比较：如果 `cur[0] <= last[1]`（当前起点 ≤ 上一个终点，说明重叠或相邻），就合并——把 last 的终点更新为 `max(last[1], cur[1])`；否则不重叠，把 cur 作为新区间加入结果列表。整体复杂度由排序主导，是 O(n log n)，扫描是 O(n)。这个"排序 + 一次线性扫描合并"是区间类题目（合并区间、插入区间、区间覆盖、会议室等）的通用模板，核心思想是用排序把无序的重叠关系变成有序相邻、从而能一次扫描处理。

</details>

5. 什么是"用数组当哈希表/计数数组"？相比真正的哈希表有什么优势和限制？

<details><summary>参考答案</summary>

"用数组当哈希表/计数数组"是指：当 key 是**范围有限的非负整数**（或能映射成这样的整数，如小写字母 'a'-'z' 映射成 0-25）时，直接用一个数组、以 key 作为下标来存储计数或标记，而不用真正的哈希表（map）。例如统计一个字符串里各字母出现次数，用 `cnt := [26]int{}`，对字符 c 执行 `cnt[c-'a']++`；判断某数是否出现过用布尔数组 `seen[x] = true`。**优势**：①**更快**——数组按下标访问是 O(1) 且常数极小（直接内存寻址），没有哈希计算、哈希冲突、装箱等开销，比 map 快很多；②**省空间且无哈希开销**——值域小时一个紧凑数组就够；③代码简单、无需处理哈希表的扩容等。**限制**：①**只适用于 key 是范围已知且不大的非负整数**（或可映射成这样）——如果 key 是任意整数、字符串、浮点数、或值域非常大/稀疏（如 key 可能是 10⁹），用数组就会浪费巨量内存甚至无法分配，这时必须用哈希表；②需要预先知道值域大小来开数组；③负数/超界的 key 需要额外偏移映射。所以经验是：**值域小的整数/字符计数，优先用计数数组（更快）；key 是大范围整数、字符串或其他类型，用哈希表（map）**。这也是为什么字符统计常用 [26]int 或 [128]int（ASCII）而非 map[rune]int——前者更高效。

</details>

6. 题目要求"原地（O(1) 额外空间）移除数组中所有等于 val 的元素"，如何用双指针实现？

<details><summary>参考答案</summary>

用**快慢双指针**原地实现，O(n) 时间、O(1) 额外空间。思路：用一个慢指针 slow 指向"下一个要保留的元素应该放的位置"，用一个快指针 fast 遍历整个数组。遍历过程中，对每个 nums[fast]：如果它**不等于 val**（即需要保留），就把它复制到 nums[slow] 位置，然后 slow++（slow 向前移动一格，表示又保留了一个）；如果它等于 val（需要移除），就跳过、只移动 fast、不动 slow。这样遍历结束后，nums 的前 slow 个元素就是所有"不等于 val"的元素（按原相对顺序保留），slow 就是移除后的新长度。代码核心：`slow := 0; for fast := 0; fast < len(nums); fast++ { if nums[fast] != val { nums[slow] = nums[fast]; slow++ } }; return slow`。它的精髓是：慢指针维护"已处理好的、要保留的部分"的边界，快指针负责探索；只把要保留的元素往前"压实"，要删除的元素自然被后面保留的元素覆盖掉，全程不开新数组（原地），所以是 O(1) 额外空间。这种"快慢指针原地压实"是一类原地删除/去重题（移除元素、删除有序数组重复项、移动零等）的通用模板。

</details>
