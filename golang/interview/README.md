## 🧭 怎么用

### 场景 A：自检（30 分钟摸底）

打开任意一篇，从头扫题目（不看答案），心里默答。

- 80% 能讲清楚 → 该主题没问题
- 50%-80% → 重点看那些"心虚"的题
- < 50% → 配合 [G 系列章节](../INDEX.md)系统补

### 场景 B：突击（一周面试准备）

按主题逐个过，每天 1-2 个主题，**口述**答案给自己听。

推荐顺序：
```
基础 → 并发 → 内存与 GC → 接口与泛型 → 性能与工程化 → 生态与生产
```

### 场景 C：深挖（找薄弱面）

每题都有"常见追问"小节——能秒答正题但卡在追问的，就是面试官真正想考的点。

### 场景 D：面试官视角

每题的"陷阱/容易答错"小节，是面试官筛人的最佳手段。

## 📐 题目格式（示例）

```markdown
### Q ⭐⭐⭐⭐ 简述 GMP 调度模型

**答**：

GMP 是 Go 调度器的三层模型：

- **G** (Goroutine)：用户态轻量协程，初始栈 2KB，可动态伸缩
- **M** (Machine)：内核线程的抽象，真正执行 G 的载体
- **P** (Processor)：逻辑处理器，G 与 M 之间的调度上下文，数量 = GOMAXPROCS

核心机制：本地队列 + 全局队列、Work Stealing、异步抢占（Go 1.14+）、syscall 解绑。

📎 **深入阅读**: [G11-精通-Goroutines-与-GMP-调度](../G11-精通-Goroutines-与-GMP-调度.md)

**常见追问**：
- Q: P 数量默认为什么 = CPU 核数？
- Q: 一个 G 阻塞会发生什么（按 syscall/channel/网络 IO 分类回答）？
- Q: Go 1.25 容器感知 GOMAXPROCS 解决了什么问题？

**陷阱**：把 GOMAXPROCS 设成核数 × 2 通常无用——P 不是抢占资源，并行度被 CPU 物理核心数限制。
```

## ⚠️ 使用提醒

- **不要背答案**：背的痕迹一开口就被识别。理解原理后用自己的话讲。
- **代码先于话术**：能写 Mutex / channel / context 就业基本面没问题。
- **追问能扛住才算过关**：一个题答出 80%，三个追问扛住 60%，比五个题各答 50% 强。
- **承认不会**：不知道就说"这块我没深入研究过"，编出来的答案有 10 倍概率被穿帮。
