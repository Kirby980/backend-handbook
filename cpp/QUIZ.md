## C01 编译模型与构建

1.（单选）下面报错最可能发生在哪个阶段？`int main(){ foo(); }`，其中 `foo` 只有声明没有定义。
   A. 预处理　B. 编译　C. 链接　D. 运行
2.（判断）`inline` 的主要作用是让编译器把函数内联展开。
3.（简答）为什么模板函数的定义通常要放在头文件里？
4.（简答）`static int x;` 放在头文件被两个 `.cpp` 包含，会发生 ODR 冲突吗？为什么？
5.（简答）`extern "C"` 解决什么问题？

### 参考答案

1. **C（链接）**。`main` 编译时只需 `foo` 的声明即可通过；链接时找不到定义 → `undefined reference to 'foo()'`。
2. **假**。`inline` 在现代 C++ 的核心语义是"允许跨 TU 多重定义（ODR 豁免）"，使函数/变量能放头文件；是否真的内联展开由编译器自行决定。
3. 模板按需实例化——编译器在**使用模板的那个 TU** 看到具体类型才生成代码。定义放在别的 `.cpp` 里，使用方的 TU 看不到定义，无法实例化 → 链接错误。
4. **不冲突**。`static` 给变量内部链接，每个 TU 各有一份独立的 `x`，互不可见。但每 TU 一份副本通常不是想要的，共享全局应用 `inline` 变量或 `extern` + 单一定义。
5. 解决 **C/C++ 混编的符号名不匹配**。C++ 对函数做 name mangling，C 不做；`extern "C"` 让 C++ 按 C 方式生成符号名，使二者能互相调用。

## C02 类型系统与 auto

1.（简答）`int i=0; auto a=i; auto& b=i; decltype(i) c=i;`（设 `i` 为 `const int`）各推出什么类型？
2.（简答）`int* const p` 和 `const int* p` 区别？
3.（找 bug）`for (auto name : names)`（`names` 是 `vector<string>`）只读遍历有什么性能问题？
4.（单选）多态向下转型且需要运行期安全检查应该用哪种 cast？
   A. static_cast　B. dynamic_cast　C. reinterpret_cast　D. const_cast
5.（简答）`constexpr` 和 `const` 的区别？

### 参考答案

1. 设 `i` 为 `const int`：`a` 是 `int`（auto 丢引用和顶层 const）；`b` 是 `const int&`（auto& 保留）；`c` 是 `const int`（decltype 精确保留）。
2. `int* const p` 是 **const 指针**——指向不可变，但能改 `*p`；`const int* p` 是**指向 const 的指针**——能改 p 的指向，但不能通过 p 改值。
3. `auto name` 每次迭代**拷贝一个 string**（堆分配 + 复制字符）。只读遍历应用 `const auto& name`，零拷贝。
4. **B（dynamic_cast）**。用 RTTI 在运行期检查，失败时指针返回 nullptr、引用抛 `bad_cast`；要求类型多态。
5. `const` 是"运行期只读"（值可运行期算出）；`constexpr` 是"编译期可求值"（更强，可作数组大小/模板参数）。所有 `constexpr` 隐含 const，反之不然。

## C03 值类别与移动语义

1.（简答）判断左值还是右值：`x`、`42`、`x+1`、`std::move(x)`、`std::string{}`。
2.（简答）`std::move` 到底做了什么？为什么对 const 对象无效？
3.（简答）为什么移动构造要标 `noexcept`？
4.（找 bug）`class S { int* p; public: S(S&& o):p(o.p){} ~S(){delete p;} };`
5.（单选）下面哪个返回写法更好？
   A. `std::string f(){ std::string s="x"; return std::move(s); }`
   B. `std::string f(){ std::string s="x"; return s; }`

### 参考答案

1. `x` 左值；`42` 右值（prvalue）；`x+1` 右值（prvalue）；`std::move(x)` 右值（xvalue）；`std::string{}` 右值（prvalue 临时对象）。
2. `std::move(x)` 只是 `static_cast<T&&>(x)`，把 x 标记为右值使重载决议选中移动函数，本身不移动数据。对 const 对象：移动需修改/置空源，const 不可改，匹配不上 `T&&`，退化到拷贝构造 `const T&`。
3. 标准容器（如 vector 扩容）需要强异常保证时，只有移动构造 `noexcept` 才用移动，否则退回拷贝。不标 noexcept → 移动优化失效。
4. 移动构造**没把源 `o.p` 置空**，`o` 与 `*this` 析构时对同一指针双重 `delete` → **双重释放**。修正：`p(o.p){ o.p=nullptr; }`。
5. **B 更好**。`return s` 触发 NRVO（零拷贝零移动）；`return std::move(s)` 返回右值引用表达式，**禁用 NRVO**，最多得到移动。

## C04 完美转发与引用折叠

1.（单选）函数模板参数 `template<class T> void f(T&& x)` 中的 `T&&` 是什么？
   A. 右值引用　B. 转发引用（万能引用）　C. 左值引用　D. 常量引用
2.（简答）写出四条引用折叠规则（`T& &`、`T& &&`、`T&& &`、`T&& &&` 各折成什么）。
3.（简答）`std::forward<T>` 与 `std::move` 的本质区别是什么？
4.（找 bug）转发模板里写 `g(x);`（x 为转发引用参数）有什么问题？
5.（判断）`void f(int&& x)` 的参数 `x` 是右值引用，所以在函数体内 `x` 也是右值。

### 参考答案

1. **B（转发引用）**。仅当 `T` 是函数模板的待推导参数且形如 `T&&` 时成立；传左值推 `T=U&`，传右值推 `T=U`。
2. `T& &`→`T&`；`T& &&`→`T&`；`T&& &`→`T&`；`T&& &&`→`T&&`。口诀：**有一个左值引用就折成左值引用，全是右值引用才是右值引用**。
3. `std::move` 无条件转成右值；`std::forward<T>` **有条件**——根据模板推导出的 `T` 保持原值类别（传左值就转左值、传右值就转右值），用于完美转发。
4. `x` 是具名变量，本身是**左值**，直接 `g(x)` 丢失原始值类别（右值实参也按左值转发）。应写 `g(std::forward<T>(x))`。
5. **假**。具名的右值引用变量本身是**左值**（有名字）；要再次以右值传递需 `std::move(x)`。

## C05 RAII 与智能指针

1.（简答）什么是 RAII？它如何保证异常安全下的资源释放？
2.（单选）哪种智能指针用于打破 `shared_ptr` 循环引用？
   A. unique_ptr　B. shared_ptr　C. weak_ptr　D. auto_ptr
3.（简答）`shared_ptr` 的控制块包含哪些信息？为什么 `make_shared` 比 `shared_ptr<T>(new T)` 更优？
4.（找 bug）`shared_ptr<int> p(raw); shared_ptr<int> q(raw);`（raw 为裸指针）有何隐患？
5.（简答）什么是"零法则"？

### 参考答案

1. RAII = 资源获取即初始化：把资源生命周期绑定到对象生命周期，构造时获取、析构时释放。栈对象析构在作用域退出/栈展开时自动发生，因此即使抛异常也能释放资源。
2. **C（weak_ptr）**。它不增加引用计数，观察但不拥有对象，用 `lock()` 临时提升为 shared_ptr。
3. 控制块含强引用计数、弱引用计数（及删除器/分配器）。`make_shared` **一次分配**同时容纳控制块与对象（更少分配、更好缓存局部性，且异常安全）；`shared_ptr(new T)` 需两次分配。
4. 两个独立的 shared_ptr 各建一个控制块管理同一裸指针 → 引用计数互不知情 → **双重释放**。同一对象只能从一个 shared_ptr 派生（用拷贝共享）。
5. 零法则：尽量不手写任何特殊成员函数，用 RAII 类型（vector/string/unique_ptr 等）管理资源，让编译器自动生成正确的拷贝/移动/析构。

## C06 拷贝控制与五法则

1.（简答）列出五个特殊成员函数（五法则）。
2.（判断）只要声明了析构函数，编译器仍会自动生成移动构造。
3.（简答）`=default` 和 `=delete` 各有什么用途？
4.（找 bug）一个管理 `new[]` 资源的类只写了析构和拷贝构造，没写拷贝赋值，会有什么问题？
5.（简答）"三法则""五法则""零法则"分别指什么？

### 参考答案

1. 析构函数、拷贝构造、拷贝赋值、移动构造、移动赋值。
2. **假**。一旦用户声明了析构（或任一拷贝操作），编译器**不再自动生成移动**操作，对象会退回到拷贝语义。
3. `=default` 显式要求编译器生成默认实现（保留 trivial 性质、表明意图）；`=delete` 禁用某函数（如禁止拷贝），调用即编译错误。
4. 默认生成的拷贝赋值做**浅拷贝**，赋值后两对象指向同一块内存 → 双重释放 + 内存泄漏（旧内存未释放）。需自定义拷贝赋值（或遵循五法则/零法则）。
5. 三法则（C++98）：写了析构/拷贝构造/拷贝赋值之一就应写齐三个；五法则（C++11）：加上移动构造与移动赋值；零法则：一个都不写，靠 RAII 成员。

## C07 类与对象布局

1.（单选）影响类对象大小的对齐填充（padding）主要由什么决定？
   A. 成员声明顺序与最大对齐要求　B. 成员个数　C. 是否有构造函数　D. 命名空间
2.（简答）什么是 EBO（空基类优化）？它解决什么问题？
3.（简答）`sizeof(空类)` 是多少？为什么不是 0？
4.（找 bug）`struct S { char c; double d; char c2; };` 在 64 位平台 sizeof 偏大，如何优化？
5.（简答）trivial 类型、标准布局（standard-layout）、POD 三者关系？

### 参考答案

1. **A**。每个成员按其对齐要求放置，编译器插入填充字节；整体大小是最大成员对齐的整数倍。重排成员顺序可减少填充。
2. EBO：当基类为空（无非静态成员）时，允许其在派生类中**不占空间**（地址可与派生类首成员重合）。用于让无状态的策略/分配器零开销，如 `std::tuple`、容器对分配器的存储。
3. **1 字节**。C++ 要求不同对象有不同地址，空类也需占至少 1 字节以保证数组中各元素地址唯一。
4. 重排成员把同对齐的放一起：`struct S { double d; char c; char c2; };`，把两个 char 紧邻可减少 padding（典型从 24 降到 16 字节）。
5. trivial：构造/拷贝/析构均平凡（可 memcpy 复制、无自定义逻辑）；标准布局：成员布局与 C 兼容、可 `reinterpret_cast`；POD = trivial **且** 标准布局（C++20 已弃用 POD 概念，改用前两个细分）。

## C08 虚函数与多态

1.（简答）vtable 和 vptr 分别是什么？虚调用如何分派？
2.（判断）只要基类有虚函数，sizeof 一定增加一个指针大小（首个虚函数时）。
3.（找 bug）`Base* p = new Derived; delete p;`，Base 析构非 virtual，后果是什么？
4.（简答）`override` 和 `final` 关键字各有什么作用？
5.（单选）下面哪种情况虚函数调用会退化为静态绑定？
   A. 通过基类指针调用　B. 在构造/析构函数中调用虚函数　C. 通过引用调用　D. 多态对象数组

### 参考答案

1. vtable 是每个多态类一份的函数指针表（存各虚函数实际地址）；vptr 是每个对象内的隐藏指针，指向其类的 vtable。虚调用通过 vptr 找到 vtable，再按固定槽位取函数地址间接调用（运行期分派）。
2. **真**。引入首个虚函数时对象多出一个 vptr（通常 8 字节），后续虚函数复用同一 vptr。
3. **未定义行为**：只调用 `~Base`，`Derived` 的析构不被调用 → 派生类资源泄漏。基类析构应声明为 `virtual`。
4. `override` 显式表明覆盖基类虚函数，签名不匹配时编译报错（防笔误）；`final` 禁止该虚函数被进一步覆盖，或禁止类被继承。
5. **B**。构造/析构期间对象的动态类型为当前正在构造/析构的类，虚调用按当前类静态绑定，不会调到派生类版本。

## C09 继承与 CRTP

1.（简答）public / protected / private 继承在语义上分别表示什么？
2.（简答）什么是菱形继承问题？虚继承如何解决？
3.（简答）CRTP 是什么？它如何实现"静态多态"？
4.（单选）相比虚函数，CRTP 静态多态的主要优势是什么？
   A. 支持运行期类型替换　B. 无 vtable/虚调用开销、可内联　C. 减少编译时间　D. 自动生成析构
5.（找 bug）虚继承下，虚基类子对象由谁负责初始化？写错会怎样？

### 参考答案

1. public 继承表示 "is-a"（里氏替换）；protected 继承表示"按受保护方式实现继承"（派生的派生仍可见）；private 继承表示 "implemented-in-terms-of"（仅复用实现，对外不是 is-a）。
2. 多重继承中两条路径继承同一基类，导致基类子对象出现两份、数据冗余且访问二义。虚继承让该基类在最派生对象中**只存一份共享子对象**。
3. CRTP：`class D : public Base<D>`，基类以派生类为模板参数，可在基类中 `static_cast<D*>(this)` 调用派生实现。编译期确定调用目标即静态多态。
4. **B**。无虚表/虚指针、调用可内联，零运行期开销；代价是失去运行期动态替换能力。
5. 虚基类由**最派生类（most-derived）**直接初始化，中间基类对虚基类的初始化被忽略。若最派生类未显式初始化虚基类，会调用其默认构造；无默认构造则编译错误。

## C10 运算符重载与三路比较

1.（简答）`<=>`（三路比较运算符）返回什么类型？编译器据此能自动生成哪些运算符？
2.（判断）声明 `auto operator<=>(const T&) const = default;` 后无需再写 `==`，所有比较都可用。
3.（简答）`explicit` 用在构造函数和转换运算符上各防止什么？
4.（单选）哪些运算符**不能**被重载？
   A. `+` `-`　B. `[]` `()`　C. `::` `.` `.*` `?:`　D. `<=>` `==`
5.（简答）成员函数形式与非成员（友元）形式重载运算符，如何选择？

### 参考答案

1. 返回比较类别类型：`std::strong_ordering` / `std::weak_ordering` / `std::partial_ordering`。默认 `<=>` 可让编译器派生出 `<`、`>`、`<=`、`>=`（C++20 重写规则）。
2. **半对**。`= default` 的 `<=>` 会同时隐式生成 `==`（C++20 规则：默认 `<=>` 推出默认 `==`）。但若**自定义**了 `<=>`，则需单独提供 `==`（自定义 `<=>` 不自动给 `==`）。
3. 构造函数 `explicit` 禁止隐式转换/拷贝初始化（防意外单参隐式构造）；转换运算符 `explicit` 禁止隐式类型转换（仅允许显式 cast、或语境转换如 if 中的 bool）。
4. **C**。`::`、`.`、`.*`、`?:`（及 `sizeof`、`typeid`）不可重载。
5. 需要左操作数支持隐式转换、或保持对称（如 `1 + obj`）时用非成员/友元；需要访问私有且左操作数必为本类型（如 `=`、`[]`、`()`、`->`）时用成员。

## C11 模板基础

1.（简答）函数模板和类模板的实例化时机有何不同（按需实例化）？
2.（简答）全特化与偏特化的区别？函数模板支持偏特化吗？
3.（单选）什么是两阶段名称查找（two-phase lookup）？
   A. 模板定义期 + 实例化期分别查找名称　B. 编译 + 链接　C. 声明 + 定义　D. 预处理 + 编译
4.（找 bug）类模板成员函数定义在 `.cpp` 中，另一个 TU 使用时报链接错误，为什么？
5.（简答）什么是 CTAD（类模板实参推导）？举一例。

### 参考答案

1. 函数/类模板都按需实例化；类模板的成员函数**只有被实际调用时**才实例化（未用的成员可以含对该类型非法的操作而不报错）。
2. 全特化为某具体类型提供完整专门实现；偏特化为一类参数（如所有指针 `T*`）提供实现。**函数模板不支持偏特化**，只能全特化或用重载替代。
3. **A**。模板定义期查找不依赖模板参数的名称；实例化期再查找依赖名称（含 ADL）。这要求对依赖名用 `typename`/`template` 消歧。
4. 模板成员需在使用处看到定义才能实例化；放 `.cpp` 后其他 TU 看不到定义 → 未实例化 → 链接缺符号。模板定义应放头文件（或显式实例化）。
5. CTAD：从构造实参推导类模板参数，免写尖括号。例：`std::vector v{1,2,3};` 推出 `vector<int>`；`std::pair p{1, "a"};`。

## C12 可变参数模板

1.（简答）什么是参数包（parameter pack）？`sizeof...(args)` 做什么？
2.（简答）写出折叠表达式的四种形式（一元左/右、二元左/右）。
3.（单选）`(... + args)` 是哪种折叠？
   A. 一元右折叠　B. 一元左折叠　C. 二元左折叠　D. 二元右折叠
4.（找 bug）递归展开可变参数时忘记写递归终止重载（基例），会怎样？
5.（简答）如何用折叠表达式实现"对每个参数调用 `f`"？

### 参考答案

1. 参数包代表零个或多个模板/函数参数；`sizeof...(args)` 在编译期返回包中元素个数。
2. 一元右：`(args op ...)`；一元左：`(... op args)`；二元右：`(args op ... op init)`；二元左：`(init op ... op args)`。
3. **B（一元左折叠）**：`(... + args)` 展开为 `((a1 + a2) + a3) ...`，从左结合。
4. 递归到空包时找不到匹配的非模板/零参重载 → **编译错误**（无终止）。需提供基例（如零参重载或 `if constexpr (sizeof...(rest)>0)` 守卫）。
5. `(f(args), ...);`（用逗号运算符的一元右折叠，对每个参数依次调用 `f`）。

## C13 模板元编程与 SFINAE

1.（简答）SFINAE 是什么？它发生在重载决议的哪个阶段？
2.（简答）`std::enable_if` 的原理是什么？
3.（单选）`if constexpr` 相比 SFINAE 的主要优势是？
   A. 运行期更快　B. 编译期按条件丢弃分支、代码更直观　C. 减少二进制大小　D. 支持虚函数
4.（简答）`type_traits` 中 `std::is_same_v`、`std::remove_reference_t` 各做什么？
5.（找 bug）`template<class T> typename T::type f(T);` 传入 `int` 会硬错误还是 SFINAE？

### 参考答案

1. SFINAE = 替换失败不是错误。模板实参替换到**函数签名**时若产生无效类型/表达式，仅把该候选移出重载集，而非报编译错误。发生在重载决议的模板实参推导/替换阶段。
2. `enable_if<cond, T>` 仅当 `cond` 为真时才有成员 `type`；用作返回类型或模板参数时，条件为假则替换失败（SFINAE）移除该重载。
3. **B**。`if constexpr` 在编译期求条件、丢弃未选分支（被丢弃分支不实例化），写法接近普通 if，远比 SFINAE 直观。
4. `is_same_v<A,B>` 判断两类型是否完全相同（编译期 bool）；`remove_reference_t<T>` 去掉引用得到底层类型（`int&`→`int`）。
5. 若 `T::type` 出现在**签名**（这里返回类型）中，传 `int` 时 `int::type` 替换失败 → **SFINAE**（候选被移除）；若错误发生在函数体内部则是硬错误。

## C14 Concepts

1.（简答）concept 是什么？相比 SFINAE/enable_if 有何优势？

## C15 模板进阶

1.（简答）依赖名（dependent name）为什么有时要加 `typename` 或 `template` 前缀？
2.（简答）什么是 ADL（实参依赖查找）？举一个它生效的例子。
3.（单选）策略模式（policy-based design）在 C++ 里通常借助什么实现？
   A. 虚函数　B. 模板参数注入策略类　C. 宏　D. 函数指针数组
4.（找 bug）`template<class T> void f(){ T::template inner<int> x; }` 漏写 `template` 关键字会怎样？
5.（简答）变量模板（variable template）是什么？举一例。

### 参考答案

1. 在模板里，依赖于模板参数的名称编译器默认按非类型处理。当它实为类型时要加 `typename`（如 `typename T::value_type`）；当它实为成员模板时要加 `template`（如 `obj.template get<0>()`）以消除 `<` 的歧义。

4. `inner<int>` 中 `<` 会被解析为小于号而非模板实参列表 → 编译错误。需写 `T::template inner<int>`。
5. 变量模板是参数化的变量定义。例：`template<class T> constexpr T pi = T(3.1415926535);`，用 `pi<float>` / `pi<double>` 取不同精度值。

## C16 STL 容器内部

1.（简答）`vector` 扩容时容量如何增长？为什么用倍增策略？
2.（简答）`std::map` 与 `std::unordered_map` 的底层结构与复杂度差异？
3.（找 bug）遍历 `vector` 时 `v.push_back(...)` 触发扩容，之前保存的迭代器/引用还有效吗？
4.（单选）下面哪个操作**不会**使 `unordered_map` 的元素引用失效？
   A. rehash（超过负载因子）　B. insert 导致 rehash　C. 单纯 erase 其他元素　D. clear
5.（简答）`reserve` 与 `resize` 区别？

### 参考答案

1. 通常按因子（libstdc++ 为 2 倍、MSVC 约 1.5 倍）几何增长，使 n 次 push_back 的**摊还复杂度为 O(1)**；线性增长会退化为 O(n²) 总拷贝。
2. `map` 是红黑树，键有序，查找/插入 O(log n)，迭代有序；`unordered_map` 是哈希表（桶 + 链/开放寻址），平均 O(1)、最坏 O(n)，无序。

4. **C**。`unordered_map` 的 erase 只使被删元素的迭代器失效，其余元素引用/指针仍有效（rehash 才使所有迭代器失效，但引用/指针在 rehash 后仍指向有效元素——标准保证元素引用不因 rehash 失效，仅迭代器失效）。
5. `reserve(n)` 只预留容量（不改变 size、不构造元素）；`resize(n)` 改变 size（增多时构造新元素、减少时析构）。

## C17 迭代器与范围

1.（简答）列出 C++ 迭代器的五（六）个类别，并说明能力递进。
2.（简答）C++20 引入的 sentinel（哨兵）解决了什么问题？
3.（单选）`std::list` 的迭代器属于哪一类？
   A. 随机访问　B. 双向　C. 前向　D. 输入
4.（找 bug）`auto it = v.begin(); v.erase(it); ++it;` 有什么问题？
5.（简答）为什么 `std::sort` 不能直接作用于 `std::list`？

### 参考答案

1. 输入（只读单遍）→ 输出（只写单遍）→ 前向（多遍读写）→ 双向（可 `--`）→ 随机访问（`+n`、`[]`、O(1) 跳转）；C++20 增 contiguous（元素连续，可取裸指针）。能力逐级增强。

## C23 原子与内存模型

1.（简答）`std::atomic` 的 `is_lock_free()` 表示什么？

3.（单选）默认（不指定 memory_order）的原子操作使用哪种内存序？
   A. relaxed　B. acquire　C. release　D. seq_cst
4.（简答）什么是 happens-before 关系？它为什么重要？
5.（找 bug）用 `relaxed` 序实现"标志位 + 数据"的发布-订阅，读者可能读到旧数据吗？

### 参考答案

1. `co_await`（挂起等待 awaitable）、`co_yield`（产出一个值并挂起，常用于生成器）、`co_return`（结束协程并返回）。
2. `promise_type` 定义协程的行为：初始/最终挂起点、如何处理返回值（`return_value`/`yield_value`）、异常处理、获取返回对象等，是协程框架的定制点。
3. **B（协程）**。含任一协程关键字即为协程，编译器生成协程帧与状态机。
4. **不安全**。协程帧独立于调用栈，但被引用的局部变量随调用方栈帧销毁 → 悬垂引用。应按值传入或保证生命周期。
5. 定义返回类型（含 `promise_type` 的 `yield_value`），在协程体内用 `co_yield` 逐个产出；其迭代器每次 `++` 恢复协程到下一个 `co_yield`，实现按需惰性产生（C++23 已有 `std::generator`）。

## C26 异常与错误处理

1.（简答）什么是栈展开（stack unwinding）？它如何配合 RAII？
2.（简答）三种异常安全保证（基本/强/不抛）分别是什么？
3.（单选）析构函数默认是 noexcept；若析构抛出异常且正在栈展开会怎样？
   A. 被忽略　B. 调用 std::terminate　C. 重新抛出　D. 转为返回码
4.（简答）`std::expected<T,E>`（C++23）相比异常有何优势场景？
5.（找 bug）`catch (std::exception e)` 捕获有什么问题？

### 参考答案

1. 抛异常后，从抛出点到匹配 catch 之间，已构造的自动对象按逆序析构（释放资源）——这正是 RAII 保证异常下资源不泄漏的机制。
2. 基本保证：不泄漏、对象保持有效状态（但状态可能改变）；强保证：操作要么完全成功要么回滚到原状态（事务性）；不抛保证：noexcept，绝不抛出。
3. **B**。栈展开中再抛异常 → `std::terminate`。析构不应抛异常（默认 noexcept）。
4. 用于"可预期的失败"且希望显式处理、避免异常开销/控制流隐藏的场景；返回值即结果或错误，调用方必须显式检查，无栈展开成本。
5. 按值捕获导致**对象切片**（派生异常被切成基类，丢失多态信息）并多一次拷贝。应 `catch (const std::exception& e)` 按 const 引用捕获。

## C27 constexpr 编译期编程

1.（简答）`constexpr`、`consteval`、`constinit` 三者区别？
2.（简答）`if constexpr` 与普通 `if` 的本质差异？
3.（单选）C++20 起，下面哪项在 constexpr 上下文中**被允许**？
   A. 动态分配（new/delete，需编译期释放）　B. reinterpret_cast　C. 未定义行为　D. 调用纯虚函数
4.（找 bug）`constexpr int f(int n){ return rand()%n; }` 为何不能用于编译期？
5.（简答）为什么 C++20 之后能在编译期使用 `std::vector`/`std::string`？

### 参考答案

1. `constexpr`：可在编译期求值（也可运行期）；`consteval`：**立即函数**，必须编译期求值（否则报错）；`constinit`：保证静态/线程存储期变量在编译期完成初始化（防静态初始化顺序问题），但变量本身可变。
2. `if constexpr` 在编译期判断条件并**丢弃未选分支**（被丢弃分支不实例化，可含对当前类型非法的代码）；普通 `if` 两分支都要通过编译、运行期选择。
3. **A**。C++20 允许编译期 `new/delete`（须在同一常量求值内释放，不能"泄漏"到运行期）。其余在 constexpr 中均非法。
4. `rand()` 不是 constexpr（有运行期副作用、依赖运行期状态），调用它使函数无法在编译期求值，只能退化为运行期调用。
5. C++20 起允许 constexpr 内的瞬态动态分配，且 `vector`/`string` 的成员被标 constexpr，故可在编译期分配/释放其内部缓冲，实现编译期容器运算。

## C28 Modules

1.（简答）模块（modules）相比头文件解决了哪些问题？
2.（简答）`export module M;`、`import M;`、`export` 声明各做什么？
3.（单选）模块相比 `#include` 在编译速度上的主要收益来自？
   A. 更少代码　B. 接口预编译、避免重复解析头文件　C. 自动并行　D. 去掉链接
4.（判断）模块内未 `export` 的实体，对导入方不可见。
5.（简答）什么是模块分区（module partition）？

### 参考答案

1. 避免头文件的重复解析、宏污染、包含顺序依赖与 ODR 风险；提供真正的封装边界与更快的编译。
2. `export module M;` 声明模块 M 的接口单元；`import M;` 导入模块 M 的导出实体；`export` 标记某声明对导入方可见（未标记则为模块内部）。
3. **B**。模块接口编译为二进制模块接口（BMI）一次，导入时直接复用，避免每个 TU 重复预处理/解析同一头文件。
4. **真**。未 `export` 的实体属于模块内部实现，导入方看不到（强封装）。
5. 模块分区把一个模块拆成多个文件单元（接口分区 `M:part` / 实现分区），便于组织大型模块，对外仍作为单一模块 M 呈现。

## C29 字符串与 format

1.（简答）`std::string_view` 是什么？使用时最大的陷阱是什么？
2.（简答）`std::format`（C++20）相比 `printf` 和 iostream 的优势？
3.（单选）C++23 新增、可直接输出且支持格式化的函数是？
   A. std::puts　B. std::print / std::println　C. std::cout　D. std::write
4.（找 bug）函数返回 `std::string_view` 指向其内部局部 `std::string`，有什么问题？
5.（简答）如何让自定义类型支持 `std::format`？

### 参考答案

1. string_view 是对字符序列的**非拥有只读视图**（指针 + 长度），零拷贝传参。陷阱：不持有数据，若底层字符串销毁则成悬垂视图；且不保证以 `\0` 结尾。
2. 类型安全（编译期检查格式串）、可扩展（自定义 formatter）、性能好、语法统一（`{}` 占位、支持位置/对齐/精度），优于 printf 的不安全与 iostream 的冗长。
3. **B**。`std::print`/`std::println`（`<print>`）直接格式化输出到流，效率与可读性兼优。
4. 返回后局部 string 析构，string_view 成**悬垂视图**，调用方读取是未定义行为。应返回 `std::string` 或保证底层存活。
5. 特化 `std::formatter<MyType>`，实现 `parse` 与 `format` 成员，即可在 `std::format("{}", obj)` 中使用。

## C30 内存管理进阶

1.（简答）`placement new` 是什么？为什么常与显式析构配合？
2.（简答）`std::pmr`（多态分配器）解决了什么问题？
3.（单选）内存池（memory pool）相比频繁 `new/delete` 的主要收益是？
   A. 自动垃圾回收　B. 减少分配开销与碎片、提升局部性　C. 线程安全　D. 编译期分配
4.（找 bug）`operator new` 自定义后忘记配套 `operator delete`，会有什么风险？
5.（简答）`alignas` 和 `std::aligned_storage`（或 `alignof`）用于什么场景？

### 参考答案

1. placement new 在**已分配的内存**上构造对象（不分配内存）。因其只构造不分配，需手动调用析构函数 `p->~T()` 销毁对象，再自行释放/复用内存。
2. 让容器在**运行期**选择分配策略（如单调缓冲、池）而不改变容器类型——分配器通过虚接口注入，避免分配器作为模板参数造成类型膨胀。
3. **B**。预分配大块按需切分，减少系统调用与碎片，提升缓存局部性；适合大量同尺寸短生命周期对象。
4. 分配与释放不匹配（如大小/对齐处理不一致）易导致内存错误；且类的 `new[]`/`delete[]`、带对齐版本需成对提供，否则行为未定义或泄漏。
5. 控制对齐：`alignas(N)` 指定变量/类型对齐到 N（如 SIMD、缓存行对齐避免伪共享）；`alignof` 查询对齐要求。aligned_storage（C++23 弃用，改用对齐的字节数组/union）用于手动管理对齐的原始存储。

## C31 性能优化

1.（简答）什么是 RVO/NRVO？C++17 的"保证拷贝消除"指什么？
2.（简答）"缓存友好"的数据布局为什么重要？SoA 与 AoS 区别？
3.（单选）下面哪个是未定义行为（UB），可能被编译器据此激进优化？
   A. 有符号整数溢出　B. 无符号整数回绕　C. 取数组首地址　D. 调用虚函数
4.（找 bug）`return std::move(local);`（local 为局部变量）为何可能反而更慢？
5.（简答）性能优化为什么要"先测量再优化"？常用工具有哪些？

### 参考答案

1. RVO：返回临时对象时直接在调用方位置构造，省去拷贝/移动；NRVO 是对具名局部返回值的同类优化。C++17 对 prvalue 返回**强制**省略拷贝（保证拷贝消除），无需可访问的拷贝/移动构造。
2. CPU 按缓存行加载，连续访问命中率高、预取有效，能大幅提速。AoS（结构体数组）适合整体访问对象；SoA（数组的结构体）让同字段连续，利于只访问部分字段的批处理与向量化。
3. **A**。有符号整数溢出是 UB，编译器可假设不发生并据此优化；无符号是良定义的回绕。
4. 对具名局部变量返回，`std::move` **禁用 NRVO**，把"完全省略"降级为一次移动，反而更慢。直接 `return local;`。
5. 避免凭直觉优化错地方（瓶颈常不在预想处）、防止过早优化损害可读性。工具：`perf`、`valgrind --tool=callgrind`、火焰图、godbolt 看汇编、各类 profiler。

## C32 C++23/26 新特性与现状

1.（简答）列举三个 C++23 的重要新特性。
2.（简答）"deducing this"（显式对象形参）解决了什么问题？
3.（单选）下面哪些属于 **C++26**（进展中）方向？
   A. Concepts / Ranges　B. 反射 / 契约 / std::execution / 模式匹配　C. 移动语义 / lambda　D. 智能指针
4.（简答）`std::expected`、`std::print`、`std::mdspan` 各属于哪方面改进？
5.（判断）C++23 已把 `<print>` 与 `std::expected` 纳入标准库。

### 参考答案

1. `std::expected<T,E>`、`std::print`/`std::println`、deducing this、`std::mdspan`、`flat_map`/`flat_set`、ranges 增强（如 `views::zip`、`to`）等任三。
2. 显式对象形参（`auto&& self`）允许成员函数按值类别/常量性统一推导 `this`，免去为 `&`/`&&`/`const` 写多份重载（消除四重重复），也便于递归 lambda。
3. **B**。反射、契约（contracts）、`std::execution`（发送者/接收者异步模型）、模式匹配是 C++26 主要方向。
4. `std::expected` 改进错误处理（值或错误）；`std::print` 改进格式化输出；`std::mdspan` 提供多维数组非拥有视图（科学计算/性能）。
5. **真**。两者均为 C++23 标准库正式特性。
