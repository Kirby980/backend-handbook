# 系统设计深度课程 · 总目录

> 面向后端工程师面试与生产的系统设计专题，共 **15 篇**深度长文。
> 每篇约 10000-15000 字，含**需求澄清 → 容量估算 → 高层架构 → 数据模型 → 扩展演进 → 权衡取舍 → 陷阱清单 → 练习题**。
>
> **📅 内容基准：2026 年 6 月**——QPS/延迟数字按当代硬件校准（NVMe / 100GbE / Redis 8）、案例参考主流大厂公开架构、组件选型对齐 PostgreSQL 18 / Redis 8·Valkey / Kafka 4 (KRaft) / Elasticsearch 8.x / RocketMQ 5。
>
> 本专题**不重复讲组件内部原理**（索引、MVCC、复制协议在 `../backend/`、`../mysql/`、`../postgresql/` 等专题里讲透了），而是讲**「在一道设计题里如何选型、如何组合、如何表达权衡」**——这是面试系统设计环节真正考的东西。

## 🗺️ 按模块组织

### 🟢 模块一：方法论与估算（S01-S02）

> 系统设计面试栽跟头，90% 不是不会组件，而是**没框架、不估算、不表达权衡**。先把套路和数字背熟。

- **S01 方法论**：RESHADED 框架（需求 → 估算 → API → 数据模型 → 高层设计 → 扩展 → 权衡）、如何澄清功能/非功能需求、如何画图、如何说"取舍"而不是"标准答案"、面试 45 分钟节奏分配
- **S02 容量估算**：QPS / 存储 / 带宽 / 连接数估算套路、必背 Latency Numbers（2026 校准版）、Little 定律、读写比、热点与长尾、2 的幂与单位换算速查

### 🔵 模块二：可扩展性构件（S03-S05）

> 几乎每道设计题都在这三层上做文章。这里讲**设计决策**（何时引入、怎么选），内部原理链接到对应专题。

- **S03 接入层**：DNS / Anycast、L4 vs L7 负载均衡、API 网关职责、无状态化与会话外置、CDN 与边缘、同城双活 / 异地多活入口；何时该加哪一层
- **S04 数据层**：读写分离与读副本、分库分表的**分片键选择**与扩容（resharding）、冷热分离、一致性级别如何选（强/读己之写/最终）→ 链接 [B11 分片](../backend/B11-精通分片与分区.md) / [B12 复制 CAP](../backend/B12-精通数据库复制与-CAP.md)
- **S05 缓存与异步**：多级缓存（本地 + Redis）、缓存一致性（旁路 / 双删 / 订阅 binlog）、消息削峰填谷、最终一致与对账、消费幂等 → 链接 [B15 缓存](../backend/B15-精通缓存策略.md) / [B17 消息队列](../backend/B17-精通消息队列.md)

### 🟡 模块三：经典设计案例（S06-S15）

> 面试官真正会让你"设计一个 X"的高频题，按出现频率与难度梯度排列。每篇都走完整 RESHADED 流程，可直接当答题模板。

- **S06 短链 TinyURL**：发号策略（自增/号段/雪花/哈希取余冲突）、62 进制编码、301 vs 302 的统计/缓存取舍、缓存与布隆过滤器防刷、点击量异步统计
- **S07 秒杀 / 抢购**：防超卖（DB 乐观锁 / Redis 原子扣减 / Lua）、限流与削峰、预扣库存与异步下单、热点 key 隔离、库存最终一致与回补 ⭐ 高频中的高频
- **S08 Feed 流 / 朋友圈**：读扩散（拉）vs 写扩散（推）vs 推拉结合、大 V 粉丝风暴、时间线存储、Feed 排序与去重、冷启动
- **S09 IM 即时通讯**：长连接接入层（WebSocket）、在线状态、消息**可靠投递 + 去重 + 有序**、单聊/群聊扩散、已读回执、离线消息与推送
- **S10 排行榜与计数**：Redis ZSet 实时榜、海量计数（点赞/播放）的写聚合、近实时榜单分桶、防刷与去重、持久化与重建
- **S11 网盘 / 对象存储**：元数据与块分离、分块上传 + 秒传（内容哈希去重）、断点续传、分享链接与权限、配额与回收站
- **S12 搜索与自动补全**：倒排索引与 ES 落地、相关性排序（BM25 + 业务加权）、自动补全（Trie / FST / ES completion suggester）、拼写纠错 → 链接 [elasticsearch/](../elasticsearch/INDEX.md)
- **S13 附近的人 / LBS**：GeoHash 与 Google S2、矩形/圆形范围查询、Redis GEO、热点城市分片、移动中的位置更新
- **S14 延迟队列 / 定时任务**：时间轮、Redis ZSet 延迟队列、RocketMQ/Kafka 延迟方案、海量定时器、调度去重与不丢不重、分布式调度（XXL-JOB 思路）
- **S15 支付 / 订单交易**：订单状态机、**幂等**（防重复下单/支付/回调）、对账与差错处理、最终一致（本地消息表 / TCC）、超时关单与库存回滚 ⭐ 与 OfferPilot 自身订单/支付链路直接相关

## 🆕 2026 估算基准速查

| 项 | 2026 参考值 |
|---|---|
| 单机内存随机读 | ~100 ns |
| Redis GET（同机房网络往返） | ~0.2-0.5 ms |
| NVMe SSD 随机读 | ~20-100 μs（比 2010 年代 SATA SSD 快一个量级） |
| 同城机房 RTT | ~0.5-2 ms |
| 跨城 RTT（京沪） | ~30 ms |
| 单 Redis 实例 QPS | ~10 万级（pipeline 更高） |
| 单 MySQL 主库写 | ~数千-1 万 TPS（视行宽与索引） |
| 单 Kafka broker 吞吐 | ~数十万 msg/s |
| 万兆网卡 | ~1.25 GB/s；25/100GbE 已普及 |

> 详见 [S02 容量估算](./S02-精通-容量估算与必背数字.md)。面试说数字要给区间 + 说假设，别背死值。

## ✅ 完读检查清单

读完整个系列后，应该能：

- [ ] 接到"设计一个 X"，先用 5 分钟澄清功能/非功能需求，而不是直接画框
- [ ] 估算出系统的 QPS、存储增量/年、带宽，并说清假设
- [ ] 判断一道题是读密集还是写密集，并据此选扩展策略
- [ ] 给出分片键并解释热点与扩容代价
- [ ] 说清强一致 / 读己之写 / 最终一致在这道题里选哪个、为什么
- [ ] 独立设计短链、秒杀、Feed、IM 四道高频题并讲出权衡
- [ ] 在设计里正确放置缓存层并避免雪崩/穿透/击穿
- [ ] 用状态机 + 幂等 + 对账设计一个不丢钱的支付/订单系统
- [ ] 面对追问能给出"方案 A vs 方案 B"的取舍表，而不是唯一答案
