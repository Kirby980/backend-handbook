## 引言：暴力匹配在什么输入上会退化

在主串 `S` 里找模式串 `T` 第一次出现的位置，最直白的写法是双重循环：

```go
func bruteForce(s, t string) int {
    n, m := len(s), len(t)
    for i := 0; i+m <= n; i++ {
        j := 0
        for j < m && s[i+j] == t[j] {
            j++
        }
        if j == m {
            return i
        }
    }
    return -1
}
```

对随机文本它跑得飞快——因为通常第一个字符就不匹配，内层循环立刻退出，实测接近 O(n)。但换成这组输入：

```
S = "aaaaaaaaaaaaaaaaaaaaab"    (n 个 a 后跟一个 b)
T = "aaaaab"                     (m-1 个 a 后跟一个 b)
```

每次外层循环都要比到最后一个字符才发现失配，内层跑满 m 次，总共 **O(n × m)**。n = 10⁶、m = 10³ 时是 10⁹ 次比较——几秒钟。

真正致命的是**这种退化在真实数据里并不罕见**：DNA 序列（只有 ACGT 四个字符）、二进制协议帧、日志里的重复分隔符，都会让暴力匹配掉进最坏情况。

KMP 把它降到 **O(n + m)**，靠的是一个观察：

> 暴力匹配失配后，主串指针 `i` 回退到 `i+1` 重新开始——**但前面已经匹配上的那部分字符，我们是知道内容的**。这些信息足以推断出「模式串该往右滑多远」，主串指针**完全不需要回退**。

这个「已匹配部分」的自我重复结构，就是 next 数组要刻画的东西。本章会把 next 数组从定义、手算、代码实现到 nextval 优化完整推一遍——它是 408 数据结构里**唯一需要背算法细节**的知识点，也是最容易在手算题上丢分的地方。

## 第一章 串的定义与存储

### 1.1 基本概念

**串（string）**是由零个或多个字符组成的**有限序列**：`S = 'a₁a₂...aₙ'`。

| 术语 | 定义 | 注意 |
|---|---|---|
| **串长** | 字符个数 n | n = 0 时称**空串**（记作 `''` 或 Ø） |
| **空格串** | 由一个或多个空格组成的串 | **空格串 ≠ 空串**，`' '` 长度为 1 |
| **子串** | 串中任意个**连续**字符组成的子序列 | 必须连续！`"ace"` 不是 `"abcde"` 的子串 |
| **主串** | 包含子串的串 | |
| **位置** | 字符在串中的序号，**从 1 开始** | 408 约定，与 Go 下标从 0 差 1 |
| **串相等** | 长度相等**且**对应字符都相等 | |

**三个高频判断题**：

1. 空串是任意串的子串 —— **对**
2. 空格串是空串 —— **错**（长度不同）
3. 一个串的子串个数（含空串）= `n(n+1)/2 + 1` —— **对**（长度 k 的子串有 n−k+1 个，累加得 n(n+1)/2，再加空串）

### 1.2 串的存储结构

| 结构 | 定义 | 特点 |
|---|---|---|
| **定长顺序存储** | `[MaxLen]byte` + 长度 | 超长会截断（**串的「截断」现象**） |
| **堆分配存储** | 动态数组，按需分配 | 最常用 |
| **块链存储** | 链表，每结点存多个字符 | 存储密度可调，但操作复杂 |

**块链存储的取舍**：每个结点存 1 个字符时存储密度极低（1 字节数据 + 8 字节指针 = 11%），存 4 个字符时密度升到 33%，但**串的插入删除要处理跨结点边界**，代码复杂度陡增。实际很少使用。

> **Go 的 `string` 是不可变的定长顺序存储**：底层是 `struct { data *byte; len int }`，指向一块只读内存。所以：
>
> - `s[i]` 返回的是 **byte（字节）不是字符**——对中文会得到 UTF-8 的单个字节
> - `len(s)` 是**字节数不是字符数**——`len("中文")` 是 6
> - 拼接 `s1 + s2` 会**分配新内存并拷贝**，循环里拼接要用 `strings.Builder`
>
> 本章算法都按 ASCII 处理（408 也如此），涉及中文时应先 `[]rune(s)` 转换。详见 [golang/G02 Rune 与字符串内幕](../../golang/G02-精通-Go-数据类型-Rune-与字符串内幕.md)。

### 1.3 串的基本操作

```
StrAssign(&T, chars)      赋值
StrCopy(&T, S)            复制
StrEmpty(S)               判空
StrCompare(S, T)          比较：S<T 返回负，S=T 返回 0，S>T 返回正
StrLength(S)              求长
SubString(&Sub, S, pos, len)   求子串
Concat(&T, S1, S2)        连接
Index(S, T)               ★ 定位：求 T 在 S 中首次出现的位置 —— 本章主角
ClearString(&S)           清空
DestroyString(&S)         销毁
```

**`Index` 就是模式匹配**，也是本章唯一真正重要的操作。

## 第二章 暴力匹配（BF 算法）

### 2.1 算法与复杂度

```go
// 返回 t 在 s 中首次出现的下标（0-based），不存在返回 -1
func bruteForce(s, t string) int {
    n, m := len(s), len(t)
    if m == 0 {
        return 0
    }
    i, j := 0, 0
    for i < n && j < m {
        if s[i] == t[j] {
            i++ // 匹配则同步后移
            j++
        } else {
            i = i - j + 1 // ★ 主串指针【回退】到本轮起点的下一个
            j = 0         // 模式串指针归零
        }
    }
    if j == m {
        return i - m // 匹配成功，返回起始位置
    }
    return -1
}
```

**`i = i - j + 1` 这一行是全部低效的根源**：`i - j` 是本轮匹配的起点，回退后从起点的下一个字符重新开始。

```
S = a a a a a b
T = a a b
                     i,j 移动轨迹
轮 1: i=0..2, 比 3 次 → 失配，i 回退到 1
      a a a a a b
      a a b            ↑ 第 3 位失配
轮 2: i=1..3, 比 3 次 → 失配，i 回退到 2
      a a a a a b
        a a b
轮 3: ... 每轮都比满 m 次
```

| 情况 | 复杂度 |
|---|---|
| 最好 | O(n + m)（每轮第一个字符就失配） |
| **最坏** | **O(n × m)** |
| 平均（随机文本） | 接近 O(n + m) |

### 2.2 关键浪费在哪

看轮 1 失配的瞬间：

```
S = a a a a a b
    a a b
        ↑ j=2 失配，但 j=0,1 已确认 S[0]='a', S[1]='a'
```

暴力做法回退到 `i=1` 重新比较 `S[1]` 和 `T[0]`。但我们**已经知道** `S[1] = 'a' = T[0]`——这次比较是白做的。

**KMP 的核心洞察**：失配时，已匹配的那段 `S[i-j..i-1]` 与 `T[0..j-1]` 完全相同。要找下一个可能的匹配起点，只需在 **T 自己内部**找：`T[0..j-1]` 的哪个**前缀**同时也是它的**后缀**？找到最长的那个，模式串就能直接滑到那里，主串指针 `i` **一次都不用回退**。

## 第三章 next 数组

### 3.1 前缀、后缀与部分匹配值

对串 `T[0..j-1]`：

- **前缀**：以第一个字符开头的**真**子串（不含自身）
- **后缀**：以最后一个字符结尾的**真**子串（不含自身）
- **部分匹配值 PM**：最长的「既是前缀又是后缀」的子串长度

以 `T = "ababa"` 为例，逐位算：

| j（前 j 个字符） | 子串 | 所有前缀 | 所有后缀 | 最长公共 | **PM** |
|---|---|---|---|---|---|
| 1 | `a` | — | — | — | 0 |
| 2 | `ab` | `a` | `b` | 无 | 0 |
| 3 | `aba` | `a`, `ab` | `ba`, `a` | `a` | **1** |
| 4 | `abab` | `a`,`ab`,`aba` | `bab`,`ab`,`b` | `ab` | **2** |
| 5 | `ababa` | `a`,`ab`,`aba`,`abab` | `baba`,`aba`,`ba`,`a` | `aba` | **3** |

**PM 数组 = [0, 0, 1, 2, 3]**

### 3.2 从 PM 到 next（408 的 1-based 定义）

408 教材的 next 数组定义（**下标从 1 开始**）：

```
         ┌  0                                        j = 1
next[j] =┤
         └  max{ k | 1 < k < j 且 T[1..k-1] = T[j-k+1..j-1] }   其他
            若不存在这样的 k，则 next[j] = 1
```

这个定义很拗口，但有个**极简的记法**：

> **408 的 next[j] = PM[j−1] + 1**，且 `next[1] = 0`。

用 `T = "ababa"` 验证：

| j | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| T[j] | a | b | a | b | a |
| PM | 0 | 0 | 1 | 2 | 3 |
| **next（408）** | **0** | **1** | **1** | **2** | **3** |

**next[j] 的含义**：当 `T[j]` 与主串失配时，**下一趟用 `T[next[j]]` 与主串当前字符继续比较**——即模式串右滑，让第 `next[j]` 个字符对齐当前失配位。

### 3.3 手算 next 的三步法（408 考场用）

**这是本章最重要的一节**，选择题和大题都直接考手算。

以 `T = "abaabc"` 为例：

**第一步：算 PM（每位的最长公共前后缀长度）**

| j | 前 j 个字符 | 最长公共前后缀 | PM |
|---|---|---|---|
| 1 | `a` | — | 0 |
| 2 | `ab` | 无 | 0 |
| 3 | `aba` | `a` | 1 |
| 4 | `abaa` | `a` | 1 |
| 5 | `abaab` | `ab` | 2 |
| 6 | `abaabc` | 无（c 结尾，前缀都以 a 开头） | 0 |

**第二步：整体右移一位，首位补 −1，其余照抄**

```
PM      :  0  0  1  1  2  0
右移一位:  -  0  0  1  1  2       （最后一位 PM[6]=0 被挤掉，不用）
```

**第三步：全部 +1**

```
next    :  0  1  1  2  2  3
j       :  1  2  3  4  5  6
T[j]    :  a  b  a  a  b  c
```

> **为什么要右移**：`next[j]` 关心的是「`T[j]` 失配时怎么办」，而失配意味着 `T[1..j-1]` 已经匹配成功——所以要用的是**前 j−1 个字符**的 PM 值，即 `PM[j-1]`。
>
> **为什么要 +1**：408 的 next 是**位序**（从 1 开始），PM 是**长度**。长度为 k 的公共前缀，其下一个待比较字符正是第 k+1 位。

**验算技巧**：`next[1]` 恒为 0，`next[2]` 恒为 1（因为 `T[1..1]` 无真前缀）。这两位算出别的值一定错了。

### 3.4 next 数组怎么用

```
S:  a b a a b a b a a b c
T:  a b a a b c
              ↑ j=6 失配（T[6]='c' ≠ S[6]='b'）

next[6] = 3  →  下一趟从 T[3] 开始比，主串 i 不动

S:  a b a a b a b a a b c
T:        a b a a b c
              ↑ 从这里继续比
```

**模式串右滑了 `j − next[j] = 6 − 3 = 3` 位**，而主串指针 `i` **完全没退**。

### 3.5 求 next 的代码（自举过程）

408 的 1-based 版本（`T` 下标从 1 用起，`T[0]` 闲置）：

```go
// 408 风格：1-based，t[0] 不用
func getNext408(t []byte) []int {
    m := len(t) - 1 // 实际串长
    next := make([]int, m+1)
    next[1] = 0
    i, j := 1, 0
    for i < m {
        if j == 0 || t[i] == t[j] {
            i++
            j++
            next[i] = j // ★ 匹配成功，next 值就是当前匹配长度 + 1
        } else {
            j = next[j] // ★ 失配，j 回退 —— 【用 next 求 next】
        }
    }
    return next
}
```

**`j = next[j]` 是整个算法的灵魂**：求 next 的过程本身就是「模式串和自己做 KMP 匹配」。已经求出的 next 值，被用来加速后续 next 值的计算——这就是**自举**。

**力扣/工程常用的 0-based 版本**（更简洁，但与 408 的值差 1）：

```go
// 0-based：next[j] = t[0..j] 的最长公共真前后缀【长度】
// 这个版本在力扣题解里通常叫 lps（longest proper prefix which is also suffix）
func buildNext(t string) []int {
    m := len(t)
    next := make([]int, m)
    j := 0 // 当前最长公共前后缀长度
    for i := 1; i < m; i++ {
        for j > 0 && t[i] != t[j] {
            j = next[j-1] // 回退到次长的公共前后缀
        }
        if t[i] == t[j] {
            j++
        }
        next[i] = j
    }
    return next
}
```

**两个版本的对照**（`T = "abaabc"`）：

| j / i | 1/0 | 2/1 | 3/2 | 4/3 | 5/4 | 6/5 |
|---|---|---|---|---|---|---|
| 字符 | a | b | a | a | b | c |
| **408 next（1-based，位序）** | 0 | 1 | 1 | 2 | 2 | 3 |
| **0-based next（长度）** | 0 | 0 | 1 | 1 | 2 | 0 |

**两者不是简单差 1**！0-based 版是 `T[0..i]` 的 PM 值，408 版是 `PM[j-1] + 1`。混用是本章最高频的错误来源：

> **考试用 1-based（位序），刷题用 0-based（长度）。写之前先确认自己在哪个体系里。**

### 3.6 KMP 主过程

```go
// 408 风格，返回位序（1-based），失败返回 0
func kmp408(s, t []byte, next []int) int {
    n, m := len(s)-1, len(t)-1
    i, j := 1, 1
    for i <= n && j <= m {
        if j == 0 || s[i] == t[j] {
            i++ // ★ i 只增不减，永不回退
            j++
        } else {
            j = next[j] // 只回退模式串指针
        }
    }
    if j > m {
        return i - m
    }
    return 0
}
```

```go
// 0-based 版本（力扣用这个）
func strStr(haystack, needle string) int {
    if len(needle) == 0 {
        return 0
    }
    next := buildNext(needle)
    j := 0
    for i := 0; i < len(haystack); i++ {
        for j > 0 && haystack[i] != needle[j] {
            j = next[j-1]
        }
        if haystack[i] == needle[j] {
            j++
        }
        if j == len(needle) {
            return i - len(needle) + 1
        }
    }
    return -1
}
```

### 3.7 复杂度证明

**时间 O(n + m)**，用摊还论证（呼应 [DS01 §5.2](./DS01-精通-绪论与复杂度分析.md)）：

- **主串指针 i 单调递增**，最多走 n 步 → O(n)
- **模式串指针 j**：每次匹配成功 `j++`（最多 n 次），每次失配 `j = next[j]` 使 j **严格减小**。j 的总增加量 ≤ n，而 j ≥ 0，所以**总减少量也 ≤ n** → 失配回退总次数 ≤ n
- 求 next 数组同理：O(m)

**总计 O(n + m)**。

**为什么内层 `for` 不会让复杂度变成 O(n×m)**：这正是「数嵌套层数会得出错误答案」的经典案例——必须用总量分析。`j` 就像一个只能慢慢涨、可以猛跌的计数器，跌的总量不会超过涨的总量。

**空间 O(m)**：只需存 next 数组。

## 第四章 nextval 优化

### 4.1 next 数组的一个浪费

看 `T = "aaaab"`，next 数组是：

| j | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| T[j] | a | a | a | a | b |
| next | 0 | 1 | 2 | 3 | 4 |

假设在 `j = 4` 处失配（`S[i] ≠ 'a'`）：

```
next[4] = 3  →  下一趟比 T[3]，但 T[3] 也是 'a'  →  必然再次失配
next[3] = 2  →  比 T[2]，还是 'a'                →  又失配
next[2] = 1  →  比 T[1]，仍是 'a'                →  再失配
next[1] = 0  →  终于换主串字符
```

**连续 4 次无意义的比较**：既然 `T[4] == T[3]`，而 `T[4]` 已经和 `S[i]` 失配了，那 `T[3]` 和 `S[i]` 必然也失配——这次比较可以**直接跳过**。

### 4.2 nextval 的定义与计算

```
              ┌  nextval[next[j]]     若 T[j] == T[next[j]]
nextval[j] =  ┤
              └  next[j]              若 T[j] ≠ T[next[j]]
```

**一句话**：如果回退后要比的字符和当前字符相同，就**继续往前跳**，直接用那个位置的 nextval。

**手算 nextval 的方法**（在 next 基础上从左往右逐位判断）：

以 `T = "aaaab"` 为例：

| j | T[j] | next[j] | T[next[j]] | 相同？ | nextval[j] |
|---|---|---|---|---|---|
| 1 | a | 0 | — | — | **0**（首位恒等于 next[1]） |
| 2 | a | 1 | T[1]=a | **是** | `nextval[1]` = **0** |
| 3 | a | 2 | T[2]=a | **是** | `nextval[2]` = **0** |
| 4 | a | 3 | T[3]=a | **是** | `nextval[3]` = **0** |
| 5 | b | 4 | T[4]=a | 否 | `next[5]` = **4** |

**nextval = [0, 0, 0, 0, 4]**

现在 `j=4` 失配时直接跳到 `nextval[4] = 0`，一步到位，省掉三次无用比较。

**再看一例** `T = "abaabc"`：

| j | T[j] | next[j] | T[next[j]] | 相同？ | nextval[j] |
|---|---|---|---|---|---|
| 1 | a | 0 | — | — | **0** |
| 2 | b | 1 | T[1]=a | 否 | **1** |
| 3 | a | 1 | T[1]=a | **是** | `nextval[1]` = **0** |
| 4 | a | 2 | T[2]=b | 否 | **2** |
| 5 | b | 2 | T[2]=b | **是** | `nextval[2]` = **1** |
| 6 | c | 3 | T[3]=a | 否 | **3** |

**nextval = [0, 1, 0, 2, 1, 3]**

**注意 j=5**：`T[5]='b'` 与 `T[next[5]]=T[2]='b'` 相同，所以取 `nextval[2] = 1`（**不是 `next[2]`，而是已算好的 `nextval[2]`**）。这是手算最易错的一处——**必须用已求出的 nextval 值，而不是 next 值**。

### 4.3 代码实现

```go
func getNextval408(t []byte) []int {
    m := len(t) - 1
    nextval := make([]int, m+1)
    nextval[1] = 0
    i, j := 1, 0
    for i < m {
        if j == 0 || t[i] == t[j] {
            i++
            j++
            if t[i] != t[j] { // ★ 与 next 的唯一差别就在这个 if-else
                nextval[i] = j
            } else {
                nextval[i] = nextval[j]
            }
        } else {
            j = nextval[j]
        }
    }
    return nextval
}
```

**与 `getNext408` 相比只多了一个 if-else**——但省掉的比较次数在最坏情况下相当可观。

### 4.4 next vs nextval

| | next | nextval |
|---|---|---|
| 定义 | 最长公共前后缀（+1） | next 的「压缩」版，跳过必然失配的位置 |
| 最坏比较次数 | O(n + m) | O(n + m)，**常数更小** |
| 渐进复杂度 | 相同 | **相同** |
| 408 考法 | 手算 next | **手算 nextval（更常考）** |

**重要澄清**：nextval **不改变渐进复杂度**，两者都是 O(n+m)。它只是减少常数。408 考的是「你是否理解 next 的语义」，所以 nextval 反而是更受青睐的考点。

## 第五章 408 高频考点与陷阱清单

### 5.1 考点分布

第 4 章在 408 里通常是 **1-2 道选择题（2-4 分）**，**几乎必考手算 next / nextval**。极少出算法大题（因为 KMP 代码太固定，区分度低）。

**唯一需要背的**：next 数组的手算方法。其他都可以现场推。

### 5.2 六大陷阱

**陷阱 1：混用 1-based 和 0-based 的 next**

这是本章第一大坑。

| | 408（1-based） | 力扣（0-based） |
|---|---|---|
| next[j] 的含义 | 失配时下一个要比的**位序** | `T[0..j]` 的最长公共前后缀**长度** |
| `T = "abaabc"` | `0 1 1 2 2 3` | `0 0 1 1 2 0` |
| 首位 | `next[1] = 0` | `next[0] = 0` |

**考试写 1-based，刷题写 0-based。开始算之前先明确自己在哪个体系。**

**陷阱 2：手算时忘了「右移一位」**

PM 数组 ≠ next 数组。必须**右移一位再 +1**。直接把 PM+1 当 next 是最常见的错误。

**陷阱 3：算 nextval 时用了 next 而不是 nextval**

```
nextval[j] = nextval[next[j]]    ✓ 正确 —— 用【已算好的 nextval】
nextval[j] = next[next[j]]       ✗ 错误
```

因为要「连续往前跳」，必须递归地用 nextval。

**陷阱 4：以为 nextval 改变了时间复杂度**

**没有**。next 和 nextval 都是 O(n+m)，nextval 只减小常数。

**陷阱 5：以为 KMP 的主串指针会回退**

**不会**。`i` 单调递增是 KMP 的核心特征，也是它能做**流式匹配**（数据边到边匹配，无需缓存）的原因。这个性质在网络协议解析、日志实时匹配里很有用。

**陷阱 6：空格串与空串**

`''` 是空串（长度 0），`' '` 是空格串（长度 1）。判断题常考。

### 5.3 手算流程速查卡

```
求 next（408, 1-based）：
  ① 逐位算 PM = 最长公共真前后缀【长度】
  ② 整体右移一位（首位空出）
  ③ 首位填 0，其余 +1
  ④ 验算：next[1] = 0，next[2] = 1

求 nextval（在 next 基础上，从左往右）：
  nextval[1] = next[1] = 0
  对 j = 2..m：
     若 T[j] == T[next[j]]  →  nextval[j] = nextval[next[j]]   ← 用 nextval！
     否则                    →  nextval[j] = next[j]
```

**459 重复的子字符串**——next 数组最漂亮的应用：

```go
func repeatedSubstringPattern(s string) bool {
    n := len(s)
    next := buildNext(s) // 0-based，next[n-1] = 最长公共前后缀长度
    l := next[n-1]
    // ★ 若 l > 0 且 n 能被 (n - l) 整除，则 s 由长度 (n-l) 的子串重复而成
    return l > 0 && n%(n-l) == 0
}
```

**为什么成立**：设最长公共前后缀长度为 `l`，则**周期 = n − l**。

```
s = "abcabcabc"   n = 9
    ├─ 前缀 "abcabc" (l=6)
       后缀 "abcabc" (l=6)
    周期 = 9 − 6 = 3，且 9 % 3 == 0  →  由 "abc" 重复 3 次组成 ✓

s = "aba"         n = 3, l = 1
    周期 = 3 − 1 = 2，但 3 % 2 ≠ 0   →  不是重复子串 ✓
```

**「n − next[n−1] 就是最小周期」是 next 数组的隐藏性质**，值得单独记住——它把一个字符串周期问题变成了 O(n) 的一行判断。

**214 最短回文串的构造技巧**：

```go
func shortestPalindrome(s string) string {
    if len(s) == 0 {
        return s
    }
    rev := reverse(s)
    // ★ 中间的 '#' 必须有：防止 next 值跨过中点，超过 len(s)
    combined := s + "#" + rev
    next := buildNext(combined)
    l := next[len(combined)-1] // s 的最长【回文前缀】长度
    return rev[:len(s)-l] + s
}
```

**`#` 的作用**：若不加分隔符，`s = "aaaa"` 时 next 值会算出 7（跨过中点），得到错误答案。分隔符保证公共前后缀不会同时横跨两个部分。这是所有「拼接求 next」类题目的通用技巧。

验证：`S[7..12] = "aabaac"` = T ✓

**8. 证明**

设 `l = next[n]`（最长公共真前后缀长度），`p = n − l`，已知 `n % p == 0`。

**由 next 的定义**：`S[1..l] = S[n−l+1..n]`，即**前 l 个字符与后 l 个字符相同**。

对任意 `1 ≤ i ≤ l`，有 `S[i] = S[i + p]`（因为 `S[i]` 是前缀的第 i 个，`S[i+p] = S[i + n − l]` 是后缀的第 i 个）。

这说明 **S 具有周期 p**：任意相距 p 的两个字符相同。

```
S:  s₁ s₂ ... s_p | s_{p+1} ... s_{2p} | ... | s_{n-p+1} ... s_n
    └── 一个周期 ──┘
    对任意 i ≤ n−p：S[i] = S[i+p]
```

又因为 `n % p == 0`，设 `n = k·p`（k ≥ 2，因为 `l > 0` 保证 `p < n`）。

由周期性递推：`S[i] = S[i+p] = S[i+2p] = ... `，所以整个串就是 `S[1..p]` 重复 k 次。

**∴ S 由长度为 `p = n − l` 的子串重复 `k = n/p` 次构成。∎**

**反过来的必要性**（即「若 S 由某子串重复构成，则必有 `n % (n − l) == 0`」）也成立，因此力扣 459 的判定是**充要**的。

> **`n − next[n]` 是 S 的最小周期**——这个结论是 next 数组最有价值的副产品，能 O(n) 解决一批周期相关的题。

| 要点 | 一句话 |

| 空串 vs 空格串 | `''` 长度 0，`' '` 长度 1，判断题常考 |

| KMP 核心 | 已匹配部分的自我重复结构 → **主串指针永不回退** |
| next[j] 语义 | 失配时下一个要比的位序 = `PM[j−1] + 1`（408, 1-based） |
| 手算三步 | 算 PM → 右移一位 → 全部 +1；验算 `next[1]=0, next[2]=1` |
| 求 next 的自举 | `j = next[j]` —— 用已求的 next 加速求后续 next |
| nextval | `T[j] == T[next[j]]` 时取 `nextval[next[j]]`（**用 nextval 不是 next**） |
| 复杂度 | next 和 nextval **都是 O(n+m)**，nextval 只减常数 |
| 1-based vs 0-based | 408 用位序（`0 1 1 2 2 3`），力扣用长度（`0 0 1 1 2 0`），**别混** |
| 最小周期 | `n − next[n]`，若整除 n 则串由该子串重复构成（力扣 459/1392） |
| 流式匹配 | `i` 单调不减 → KMP 可用于边到边匹配的数据流 |
