```mermaid
    B --> C["形象比喻:<br>一根装满水的管子<br>横截面=带宽 长度=传播时延"]
    C --> D["工程后果:<br>长肥管道 LFN<br>发送窗口必须 ≥ 时延带宽积<br>否则带宽跑不满"]
```

**最重要的辨析**：

| | 发送时延 | 传播时延 |
|---|---|---|
| 公式 | `数据长度 / 发送速率` | `信道长度 / 电磁波传播速度` |
| 与**带宽** | **成反比**（带宽越大越小） | **无关** ⭐ |
| 与**数据长度** | 成正比 | **无关** ⭐ |
| 发生位置 | 发送方网卡 | 链路上 |

> **"升级到千兆宽带后 ping 值没变"**，原因就是 ping 值主要由传播时延与排队时延决定，而带宽只影响发送时延。

## 📶 信道极限：奈奎斯特与香农（CN02）

```mermaid
flowchart TD
    Q{"信道有噪声吗"}
    Q -->|"理想无噪声"| N["奈奎斯特定理<br>C = 2W × log₂V<br>W=带宽Hz V=码元种类数<br>限制来自码间串扰"]
    Q -->|"有噪声"| S["香农定理<br>C = W × log₂(1 + S/N)<br>S/N 为功率比 非 dB<br>限制来自热噪声"]

    N --> R["两个都能算时<br>取较小者 ⭐"]
    S --> R

    style R fill:#ffcdd2
```

**三个必踩陷阱**：

1. **信噪比单位换算**：题目常给 dB，`S/N(dB) = 10·log₁₀(S/N)` → `30 dB` 对应功率比 **1000**，不是 30。
2. **比特率 vs 波特率**：`比特率(bps) = 波特率(Baud) × log₂V`。**只有二进制（V=2）时两者数值才相等**。
3. **香农定理与码元种类无关**——提高 V 能突破奈氏极限，但**永远突破不了香农极限**。

## 🪟 三种可靠传输协议（CN02）

```mermaid
graph LR
    SW["停止-等待<br>W_T=1 W_R=1<br>利用率 U = T_D/(T_D+RTT+T_A)"] --> GBN["后退 N 帧 GBN<br>W_T ≤ 2ⁿ-1  W_R=1<br>累计确认 · 出错回退重传全部"]
    GBN --> SR["选择重传 SR<br>W_T + W_R ≤ 2ⁿ<br>通常 W_T = W_R = 2^(n-1)<br>只重传出错帧 · 需接收缓存"]

    style SW fill:#bbdefb
    style GBN fill:#fff9c4
    style SR fill:#c8e6c9
```

| | 停止-等待 | GBN | SR |
|---|---|---|---|
| 发送窗口 | 1 | `≤ 2ⁿ - 1` | `≤ 2^(n-1)` |
| 接收窗口 | 1 | **1** | `= 发送窗口` |
| 确认方式 | 逐个 | **累计确认** | 逐个 / 累计 |
| 出错重传 | 重传该帧 | **重传出错帧及其后全部** | **只重传出错帧** |
| 缓存需求 | 最小 | 小 | **大** |

**速记**：**接收窗口为 1 → 必须按序接收 → 是 GBN**；序号位数 `n` 决定序号空间 `2ⁿ`，窗口约束是每年选择题的常客。

## 🚦 CSMA/CD 与最小帧长（CN03 必考）

```mermaid
flowchart TD
    S["准备发送"] --> L{"监听信道空闲?"}
    L -->|"忙"| S
    L -->|"空闲"| T["边发送边监听"]
    T --> D{"检测到冲突?"}
    D -->|"否 · 发完"| OK["发送成功"]
    D -->|"是"| J["立即停止 + 发送 32/48 位干扰信号"]
    J --> B["二进制指数退避<br>k = min(重传次数, 10)<br>从 {0,1,...,2^k-1} 取 r<br>等待 r × 2τ"]
    B --> C{"重传 ≥ 16 次?"}
    C -->|"是"| F["丢弃 · 报告上层"]
    C -->|"否"| L

    style J fill:#ffcdd2
    style B fill:#fff9c4
```

**最小帧长的由来**（每年必考的推导）：

```
要能检测到冲突，帧还没发完时冲突信号就得回来
→ 发送时延 ≥ 2τ（争用期 / 冲突窗口）
→ 最小帧长 = 2τ × 数据率
```

- 10 Mbps 以太网：`2τ = 51.2 μs` → `51.2μs × 10Mbps = 512 bit = **64 字节**`
- **不足 64 字节要填充**；**收到的小于 64 字节的帧一律视为无效帧丢弃**
- 数据率提高 10 倍而帧长不变时，**网段最大长度要缩短 10 倍**（这是千兆以太网引入"载波延伸"的原因）

## 🔢 子网划分与最长前缀匹配（CN04 必考）

```mermaid
flowchart TD
    IP["32 位 IPv4 地址"] --> A["分类编址<br>A: 0xxx  1-126  /8<br>B: 10xx  128-191 /16<br>C: 110x  192-223 /24"]
    IP --> B2["子网划分<br>从主机号借 n 位做子网号<br>子网数 2ⁿ · 主机数 2^m - 2"]
    IP --> C2["CIDR 无类别<br>a.b.c.d/前缀长度<br>可任意长度前缀 · 支持聚合"]

    C2 --> M["最长前缀匹配 ⭐<br>多条路由都匹配时<br>选前缀最长的那条<br>= 最具体的路由"]

    style B2 fill:#fff9c4
    style M fill:#ffcdd2
```

**三个必记的"减 2"与"不减 2"**：

- 一个子网的**可用主机数 = 2^主机位数 − 2**（减掉全 0 的网络地址与全 1 的广播地址）
- **子网数不减 2**（现代 CIDR 允许全 0 和全 1 子网；老教材可能要求减 2，**看题目说明**）
- **点对点链路用 /31 或 /30**：/30 只有 2 个可用地址，正好一端一个

**解题四步**：① 由前缀长度写出子网掩码 → ② `IP AND 掩码` = 网络地址 → ③ 主机位全置 1 = 广播地址 → ④ 中间即可用范围。

## ✂️ IP 分片（CN04）

```mermaid
flowchart LR
    O["原数据报<br>总长度 L<br>首部 20B"] --> S{"L > MTU?"}
    S -->|"否"| N["不分片"]
    S -->|"是"| F["分片<br>每片数据 ≤ MTU-20<br>且必须是 8 的倍数"]
    F --> R["片偏移 = 前面各片数据字节数 / 8<br>MF=1 表示后面还有片<br>最后一片 MF=0<br>标识字段相同"]

    style F fill:#ffcdd2
    style R fill:#fff9c4
```

**三条铁律**：① **片偏移以 8 字节为单位**；② **除最后一片外，每片的数据部分必须是 8 的倍数**；③ **每一片都要带 20 字节 IP 首部**，所以分片会放大总流量。
**DF = 1 时不允许分片**——超过 MTU 只能丢弃并回 ICMP 差错报文，这正是 **PMTU 发现**的工作方式。

## 🤝 TCP 三次握手与四次挥手（CN05 必考）

```mermaid
sequenceDiagram
    participant C as 客户端
    participant S as 服务器
    Note over C,S: 三次握手（建立连接）
    C->>S: ① SYN=1, seq=x　【SYN_SENT】
    S->>C: ② SYN=1, ACK=1, seq=y, ack=x+1　【SYN_RCVD】
    C->>S: ③ ACK=1, seq=x+1, ack=y+1　【ESTABLISHED】
    Note over C,S: 数据传输
    Note over C,S: 四次挥手（释放连接）
    C->>S: ④ FIN=1, seq=u　【FIN_WAIT_1】
    S->>C: ⑤ ACK=1, ack=u+1　【CLOSE_WAIT / 半关闭】
    Note over S: 服务器把剩余数据发完
    S->>C: ⑥ FIN=1, ACK=1, seq=w, ack=u+1　【LAST_ACK】
    C->>S: ⑦ ACK=1, ack=w+1　【TIME_WAIT → 等 2MSL → CLOSED】
```

| 问题 | 答案 |
|---|---|
| 为什么握手不是**两次** | 防止**已失效的连接请求**突然到达服务器，导致服务器白白建立连接并等待，浪费资源 |
| 为什么挥手要**四次** | TCP 是**全双工**的，一方 FIN 只表示"我没数据发了"，另一方**可能还有数据要发**，所以 ACK 与 FIN 不能合并 |
| TIME_WAIT 为什么等 **2MSL** | ① 保证**最后一个 ACK 能到达**（丢了对方会重发 FIN，自己还能补发 ACK）；② 让本连接的**所有报文在网络中消散**，不干扰下一个同四元组的连接 |
| 第三次握手能否携带数据 | **可以**（前两次不行——尚未确认对方存在，携带数据会成为攻击面） |

**排障对照**：`CLOSE_WAIT` 大量堆积 = **应用层收到 FIN 后没调用 close()**（代码 bug）；`TIME_WAIT` 大量堆积 = 本机是**主动关闭方**（如短连接压测的客户端、每请求新建连接的反向代理）。

## 📈 TCP 拥塞控制（CN05 必考）

```mermaid
flowchart TD
    Start["cwnd = 1 MSS"] --> SS["慢开始<br>每收到一个 ACK cwnd += 1<br>即每 RTT cwnd 翻倍 指数增长"]
    SS --> T{"cwnd ≥ ssthresh?"}
    T -->|"是"| CA["拥塞避免<br>每 RTT cwnd += 1<br>线性增长 加法增大"]
    T -->|"否"| SS

    CA --> E{"检测到拥塞"}
    E -->|"超时 RTO<br>网络严重拥塞"| TO["ssthresh = cwnd / 2<br>cwnd = 1<br>重新慢开始 ⚠️"]
    E -->|"3 个重复 ACK<br>只是个别丢包"| FR["快重传 + 快恢复<br>ssthresh = cwnd / 2<br>cwnd = ssthresh<br>直接进入拥塞避免"]

    TO --> SS
    FR --> CA

    style TO fill:#ffcdd2
    style FR fill:#c8e6c9
```

**两种拥塞信号的处理差异是最高频考点**：

| 触发 | ssthresh | cwnd | 后续阶段 |
|---|---|---|---|
| **超时** | `cwnd / 2` | **1** | 慢开始 |
| **三个重复 ACK** | `cwnd / 2` | `ssthresh`（即 `cwnd/2`） | **直接拥塞避免** |

**流量控制 vs 拥塞控制**：

| | 流量控制 | 拥塞控制 |
|---|---|---|
| 解决什么 | **接收方**处理不过来 | **网络**承载不了 |
| 作用范围 | 点对点（**两端之间**） | **全局**（所有主机、路由器） |
| 依据的窗口 | 接收窗口 **rwnd**（对方在 TCP 首部里告诉你） | 拥塞窗口 **cwnd**（发送方自己算） |

**实际发送窗口 = min(rwnd, cwnd)** —— 这个公式必背。

```mermaid
    L->>T: 查询 www.example.com
    T-->>L: 去问 example.com 的权限服务器
    L->>A: 查询 www.example.com
    A-->>L: IP = 93.184.x.x
    L-->>H: IP = 93.184.x.x（并缓存）
```

| | 递归查询 | 迭代查询 |
|---|---|---|
| 谁替谁跑腿 | **被问的服务器负责查到底** | 被问的服务器**只回复"下一步问谁"** |
| 典型用在 | **主机 → 本地域名服务器** | **本地域名服务器 → 根/顶级/权限** |
| 负担 | 落在被查询的服务器 | 落在**本地域名服务器** |

**陷阱**：本地域名服务器→根服务器**也可以**用递归（协议允许），但根服务器出于负载考虑**一律只做迭代**，408 按"本地之后全是迭代"作答。命令行验证：`dig +trace www.example.com` 打印的就是完整的迭代过程。

## 🌍 HTTP 连接管理与 RTT 计算（CN06）

```mermaid
graph TD
    A["非持久连接 HTTP/1.0<br>每个对象一条 TCP 连接<br>每对象 2 RTT"] --> B["持久连接 HTTP/1.1<br>一条连接传多个对象<br>建连 1 RTT + 每对象 1 RTT"]
    B --> C["流水线 pipelining<br>不等响应就连发请求<br>建连 1 RTT + 全部对象共 1 RTT<br>❌ 队头阻塞"]
    C --> D["HTTP/2 多路复用<br>二进制分帧 · 一条 TCP 上多流<br>解决 HTTP 层队头阻塞<br>❌ TCP 层仍有"]
    D --> E["HTTP/3 QUIC<br>基于 UDP · 流独立<br>彻底解决队头阻塞<br>0-RTT 重连"]

    style C fill:#fff9c4
    style E fill:#c8e6c9
```

**RTT 计算模板**（请求 1 个 HTML + `n` 个内嵌对象，忽略传输时延）：

| 方式 | 总 RTT |
|---|---|
| 非持久、非并行 | `2 × (n + 1)` |
| 非持久、并行 `m` 条 | `2 + 2 × ⌈n / m⌉` |
| 持久、非流水线 | `2 + n` |
| **持久 + 流水线** | **`2 + 1 = 3`** |

> "2" = 建立 TCP 连接的 1 个 RTT + 请求 HTML 的 1 个 RTT。**若题目还要求 DNS 解析，再加 1 个 RTT**。
