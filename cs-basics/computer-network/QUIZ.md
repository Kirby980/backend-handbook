## CN01 网络体系结构与性能指标

1.（计算）一条链路带宽 **1 Gbps**，长度 **2000 km**，信号传播速度 `2 × 10⁸ m/s`。发送一个 **1000 字节**的分组，求：① 发送时延；② 传播时延；③ 时延带宽积（bit 与 MB 各是多少）。
2.（简答）发送时延与传播时延的区别是什么？为什么"把家里宽带从 100M 升到 1000M 后，ping 游戏服务器的延迟几乎没变"？
3.（简答）实体、协议、服务、服务访问点（SAP）四个概念分别指什么？「协议是水平的、服务是垂直的」怎么理解？
4.（计算）用停止-等待协议在 **1 Mbps** 链路上传送 **1000 bit** 的数据帧，单向传播时延 **20 ms**，确认帧长度与处理时间忽略不计。① 求信道利用率；② 若改用连续 ARQ，要让利用率达到 **80%**，发送窗口至少要多大？
5.（单选）下列关于各层设备与 PDU 的说法，**错误**的是：
   A. 集线器工作在物理层，不能隔离冲突域
   B. 交换机工作在数据链路层，处理的 PDU 是帧
   C. 路由器工作在网络层，能隔离广播域
   D. 传输层的 PDU 叫做**分组**

### 参考答案

1. ① **发送时延** = `数据长度 / 带宽` = `1000 × 8 bit / 10⁹ bps` = `8 × 10⁻⁶ s` = **8 μs**
   ② **传播时延** = `距离 / 传播速度` = `2 × 10⁶ m / (2 × 10⁸ m/s)` = `0.01 s` = **10 ms**
   ③ **时延带宽积** = `带宽 × 单向传播时延` = `10⁹ × 0.01` = `10⁷ bit` = **10 Mbit = 1.25 MB**

   **解读**：传播时延是发送时延的 **1250 倍**——数据"推上链路"只要 8 μs，但"跑到对面"要 10 ms。时延带宽积说明这条链路上可以**同时容纳 10⁷ 个比特在飞行**，因此发送窗口若小于 1.25 MB，链路带宽就永远跑不满（这就是**长肥管道 LFN** 问题，也是 TCP 需要窗口扩大选项的原因）。
   **单位陷阱**：`1 Gbps = 10⁹ bps`（网络领域用十进制），而 `1 MB = 2²⁰ B`（存储领域用二进制）。408 计算带宽时**一律按十进制**。

2. | | 发送时延 | 传播时延 |
   |---|---|---|
   | 定义 | 把整个数据**推上链路**所需时间 | 信号在**介质中传播**所需时间 |
   | 公式 | `数据长度 / 发送速率` | `信道长度 / 传播速度` |
   | 与带宽 | **成反比** | **完全无关** ⭐ |
   | 与数据长度 | 成正比 | **完全无关** ⭐ |
   | 发生位置 | 发送方网卡 | 链路上 |

   **ping 值不变的原因**：ping 测的是 RTT，其构成是 `2 × (发送时延 + 传播时延 + 处理时延 + 排队时延)`。ICMP 报文只有几十字节，即便在 100 Mbps 下发送时延也不到 10 μs；而传播时延（几十毫秒，由**物理距离和光速**决定）+ 排队时延才是主导项。**带宽升级只压缩了那微不足道的几微秒**。
   **一句话**：**带宽决定"一次能搬多少"，不决定"跑一趟要多久"**。想降延迟只能缩短物理距离（CDN、边缘节点）或减少排队（QoS）。

3. | 概念 | 含义 |
   |---|---|
   | **实体（entity）** | 任何**能发送或接收信息的硬件或软件进程**。第 n 层的实体叫"第 n 层实体"，不同机器上的同层实体称为**对等实体**。 |
   | **协议（protocol）** | **对等实体之间**通信必须遵守的规则集合，包含**语法**（数据格式）、**语义**（该做什么动作）、**同步/时序**（先后顺序）三要素。 |
   | **服务（service）** | 下层向**紧邻的上层**提供的功能。上层**只能看到服务，看不到下层协议**（协议对上层透明）。 |
   | **服务访问点 SAP** | 相邻两层实体交换信息的**逻辑接口**。例：传输层的 SAP 是**端口号**，网络层的 SAP 是 **IP 地址**，链路层的 SAP 是 **MAC 帧的类型字段**。 |

   **"协议水平、服务垂直"**：协议是**两台机器的同一层之间**横向约定的（A 的 TCP ↔ B 的 TCP），而服务是**同一台机器的下层向上层**纵向提供的（IP 层 → TCP 层）。
   **两个必考陷阱**：① **只有能被上层"看得见"的功能才叫服务**——协议内部为实现该功能而做的一切（重传、校验）对上层不可见；② **要实现本层协议，还需要使用下层提供的服务**。

4. ① 停止-等待协议中，发一帧要等确认才能发下一帧。
   - 数据帧发送时延 `T_D = 1000 bit / 10⁶ bps = 1 ms`
   - `RTT = 2 × 20 ms = 40 ms`
   - **信道利用率** `U = T_D / (T_D + RTT + T_A)`，`T_A ≈ 0` → `U = 1 / (1 + 40) = 1/41 ≈ **2.44%**`

   ② 连续 ARQ 中一个"周期"内可连发 `W` 帧：`U = W × T_D / (T_D + RTT)`

   ```
   0.8 ≤ W × 1 / 41  →  W ≥ 32.8  →  W = 33 帧
   ```

   **至少 33 帧**。

   **解读**：这道题的本质与第 1 题一样——**长传播时延链路上，窗口必须开大才能填满管道**。停等协议在 RTT 远大于发送时延时利用率惨不忍睹，这正是 GBN / SR / TCP 滑动窗口存在的理由。
   **陷阱**：若题目**不忽略确认帧**，分母要加上 `T_A`（确认帧的发送时延）；若给出**处理时延**也要计入。默认忽略时务必在答卷上写明。

5. **D**。传输层的 PDU 是 **报文段（segment，TCP）/ 用户数据报（datagram，UDP）**；**"分组（packet）"是网络层的 PDU**。

   | 层 | PDU | 设备 |
   |---|---|---|
   | 应用层 | 报文（message） | — |
   | 传输层 | **报文段 / 用户数据报** | — |
   | 网络层 | **分组 / IP 数据报** | 路由器 |
   | 数据链路层 | **帧（frame）** | 交换机 / 网桥 |
   | 物理层 | **比特（bit）** | 集线器 / 中继器 |

   A、B、C 均正确：集线器是物理层设备、所有端口在**同一个冲突域**；交换机按 MAC 地址转发**帧**；路由器隔离广播域（**广播不跨路由器**）。

## CN02 物理层与数据链路层

1.（计算）某信道带宽 **3 kHz**，信噪比为 **30 dB**，若采用 **16 种码元**进行传输。求该信道的极限数据率，并说明该用哪个定理的结果。
2.（计算）待发送数据 `M = 101110`，生成多项式 `G(x) = x⁴ + x + 1`。求 **CRC 冗余码**与实际发送的**帧**，并验证接收方无差错。
3.（计算）要传输 **8 位**信息，采用海明码纠正**一位错**，至少需要多少个校验位？校验位应放在哪些位置？
4.（简答）若帧序号用 **3 bit** 表示，GBN 与 SR 的发送窗口最大分别是多少？GBN 的发送窗口取 8 会出什么问题？
5.（简答）停止-等待、GBN、SR 三种协议在**发送窗口 / 接收窗口 / 确认方式 / 重传范围 / 缓存需求**上分别如何？

### 参考答案

1. **香农定理**（有噪声信道）：先把 dB 换算成功率比

   ```
   30 dB = 10 · log₁₀(S/N)  →  S/N = 10³ = 1000
   C = W · log₂(1 + S/N) = 3000 × log₂(1001) ≈ 3000 × 9.97 ≈ 29 900 bps ≈ 29.9 kbps
   ```

   **奈奎斯特定理**（码元种类给定）：

   ```
   C = 2W · log₂V = 2 × 3000 × log₂16 = 6000 × 4 = 24 000 bps = 24 kbps
   ```

   **两者取较小值 → 极限数据率 = 24 kbps**（受限于码元种类数，而非噪声）。

   **三个必踩陷阱**：
   - **dB 必须换算**：`30 dB` 是 **1000** 倍功率比，不是 30。换算式 `S/N = 10^(dB/10)`。
   - **奈氏定理里 W 要乘 2，香农定理里不乘**。
   - **两个都能算时取小者**；只给带宽和信噪比（不给码元数）就只能用香农，只说"理想无噪声"就只能用奈氏。
   - 引申：提高 `V`（用更高阶的 QAM）能突破奈氏极限，**但永远突破不了香农极限**——这是信息论的硬上界。

2. `G(x) = x⁴ + x + 1` → 二进制 **10011**，最高次 `r = 4` → 数据后补 **4 个 0**。

   被除数 `M·2⁴ = 1011100000`，做**模 2 除法**（逐位异或，不进位不借位）。用"余数寄存器"逐步推演：

   | 步骤 | 当前 5 位 | 最高位 | 操作 | 剩余 4 位 |
   |---|---|---|---|---|
   | 取前 5 位 | `10111` | 1 | ⊕ `10011` = `00100` | `0100` |
   | 拼入第 6 位 `0` | `01000` | 0 | 不异或 | `1000` |
   | 拼入第 7 位 `0` | `10000` | 1 | ⊕ `10011` = `00011` | `0011` |
   | 拼入第 8 位 `0` | `00110` | 0 | 不异或 | `0110` |
   | 拼入第 9 位 `0` | `01100` | 0 | 不异或 | `1100` |
   | 拼入第 10 位 `0` | `11000` | 1 | ⊕ `10011` = `01011` | **`1011`** ← 余数 |

   **CRC 冗余码（FCS）= 1011**，**发送的帧 = 101110 1011 = `1011101011`**（10 位）。

   **接收方验证**：用同一个 `10011` 去除 `1011101011`——

   `10111 ⊕ 10011 = 00100` → 拉位得 `01000` → `10001 ⊕ 10011 = 00010` → `00100` → `01001` → `10011 ⊕ 10011 = 00000`

   **余数为 0 → 传输无差错**。

   **陷阱**：
   - 模 2 运算**只做异或，不进位不借位**，手算时千万别代入十进制思维。
   - **补 0 的个数 = 生成多项式的最高次数 r**，不是位数（`10011` 是 5 位但 `r = 4`）。
   - CRC **只能检错不能纠错**；检出错误后链路层的动作是**直接丢弃该帧**。

3. 海明码校验位数 `k` 需满足：

   ```
   2^k ≥ n + k + 1     （n = 信息位数 = 8）
   ```

   - `k = 3`：`2³ = 8 < 8 + 3 + 1 = 12` ❌
   - `k = 4`：`2⁴ = 16 ≥ 8 + 4 + 1 = 13` ✅

   **至少需要 4 个校验位**，码字总长 12 位。

   **校验位放在 2 的幂次位置**：第 **1、2、4、8** 位（`P₁ P₂ P₄ P₈`），其余位置 3、5、6、7、9、10、11、12 放信息位。

   分组规则：`P₁` 校验所有**位号二进制第 0 位为 1** 的位（1,3,5,7,9,11）；`P₂` 校验第 1 位为 1 的（2,3,6,7,10,11）；`P₄` 校验第 2 位为 1 的（4,5,6,7,12）；`P₈` 校验第 3 位为 1 的（8~12）。

   **纠错原理**：接收方对四组分别做校验，把结果按 `S₈S₄S₂S₁` 拼成一个二进制数——**这个数的值就是出错位的位号**（全 0 表示无错）。例如结果是 `0101` = 5，则第 5 位出错，取反即可纠正。
   **必记的三个数字**：**检错 `d` 位需码距 `d+1`；纠错 `d` 位需码距 `2d+1`；纠 1 位同时检 2 位需码距 4**。海明码码距为 3，故能纠 1 位错。

4. 序号 3 bit → 序号空间 `2³ = 8`（0~7）。

   | 协议 | 窗口约束 | 本题最大发送窗口 |
   |---|---|---|
   | 停止-等待 | `W_T = W_R = 1` | 1 |
   | **GBN** | `1 ≤ W_T ≤ 2ⁿ − 1`，`W_R = 1` | **7** |
   | **SR** | `W_T + W_R ≤ 2ⁿ`，通常 `W_T = W_R` | **4**（`2^(n-1)`） |

   **GBN 取 8 的问题**：假设发送方发出 0~7 共 8 帧，接收方全部正确收到并逐一确认，但**所有确认帧都在途中丢失**。此时——
   - 接收方期待下一帧序号为 **0**（序号回绕）；
   - 发送方超时后**重传旧的 0~7**；
   - 接收方收到重传的 **0 号帧，无法分辨这是"新的一轮 0"还是"上一轮的重传"** → **把重复帧当作新数据接收**，数据错乱。

   把窗口限制为 `2ⁿ − 1 = 7` 后，接收方期待的序号与发送方可能重传的序号**不会完全重叠**，歧义消失。
   **SR 的约束更严**（`W_T + W_R ≤ 2ⁿ`）：因为 SR 的接收窗口 > 1，会缓存乱序帧，两个窗口的序号范围都不能重叠。**这三个窗口公式是选择题送分点，必须背死。**

5. | 维度 | 停止-等待 | GBN（后退 N 帧） | SR（选择重传） |
   |---|---|---|---|
   | **发送窗口** | 1 | `≤ 2ⁿ − 1` | `≤ 2^(n-1)` |
   | **接收窗口** | 1 | **1**（必须按序接收） | `= 发送窗口`（可乱序缓存） |
   | **确认方式** | 逐帧确认 | **累计确认**（ACK n 表示 n 及之前全收到） | 逐帧确认 / 也可累计 |
   | **重传范围** | 该帧 | **出错帧及其之后的全部帧** | **仅出错帧** |
   | **缓存需求** | 最小 | 发送方要缓存窗口内的帧 | **收发双方都要缓存**，最大 |
   | **信道利用率** | 最低 `T_D/(T_D+RTT)` | 高 | **最高** |
   | **复杂度** | 最简单 | 中等 | **最复杂**（需排序、逐帧计时器） |

   **速记三条**：
   - **接收窗口 = 1 → 必须按序 → 是停等或 GBN**
   - **"后退 N"这个名字就是重传范围**：出错帧之后的全都白发了，**误码率高时 GBN 性能急剧下降**
   - **SR 每一帧都要一个独立的计时器**，这是它工程上最贵的地方；TCP 实际用的是**混合方案**（累计确认 + SACK 选择确认），兼取两者之长

## CN03 局域网与介质访问控制

1.（计算）100 Mbps 以太网，最小帧长 **64 字节**，信号传播速度 `2 × 10⁸ m/s`。求理论上的**最大网段长度**。为什么实际标准（100BASE-TX）规定的双绞线长度只有 100 m？
2.（计算）10 Mbps 以太网中，某站已经历 **3 次冲突**。求第 4 次重传前的退避时间取值范围（争用期 `2τ = 51.2 μs`）。若冲突次数达到多少次会放弃发送？
3.（简答）CSMA/CD 与 CSMA/CA 有哪些区别？无线局域网为什么**不能**采用冲突检测？
4.（计算）某网络中，5 台主机接入一台**集线器**，该集线器与另外两台主机一起接入一台 **8 口交换机**，交换机再接入**路由器**的一个接口。求整个网络的**冲突域**与**广播域**各有几个。
5.（计算）CDMA 系统中，站 A 的码片序列为 `(-1, -1, -1, +1, +1, -1, +1, +1)`。某时刻接收站测得叠加信号为 `S = (-1, +1, -3, +1, -1, -3, +1, +1)`。判断站 A 发送了什么。

### 参考答案

1. 最小帧长的物理意义是：**帧还没发完，冲突信号就必须能传回来**，即

   ```
   最小帧的发送时延 ≥ 争用期 2τ
   ```

   - 最小帧发送时延 = `64 × 8 bit / 10⁸ bps` = `512 / 10⁸` = `5.12 μs`
   - 故 `2τ = 5.12 μs` → **单程传播时延 τ = 2.56 μs**
   - **最大网段长度** = `τ × 传播速度` = `2.56 × 10⁻⁶ × 2 × 10⁸` = **512 m**

   **为什么实际只有 100 m**：512 m 是**只考虑光速传播**的理论上界，真实网络还要扣除：
   - **中继器 / 集线器的转发延迟**（每级几百纳秒，标准允许最多 4 级中继）
   - **网卡收发电路的处理延迟**
   - **信号衰减与串扰**——双绞线超过 100 m 后信噪比不足，这往往才是决定性因素
   - **安全余量**——标准必须在最坏情况下仍能保证冲突检测有效

   **规律**：`最小帧长 = 2τ × 数据率`。数据率提高 10 倍而最小帧长不变 → **网段长度缩短 10 倍**。所以千兆以太网要么把最小帧长扩到 512 字节（**载波延伸**），要么干脆放弃 CSMA/CD 改用**全双工交换**（这正是现代以太网的做法——**交换式全双工以太网根本不需要 CSMA/CD**）。

2. **二进制指数退避算法**：第 `i` 次冲突后，取 `k = min(i, 10)`，从集合 `{0, 1, 2, ..., 2^k − 1}` 中**随机**取一个整数 `r`，退避时间 = `r × 2τ`。

   本题 `i = 3` → `k = min(3, 10) = 3` → `r ∈ {0, 1, 2, ..., 7}`（8 个可能值）

   **退避时间 = r × 51.2 μs，取值范围为 `0 ~ 7 × 51.2 = 358.4 μs`**，共 8 种等概率取值。

   **放弃条件**：重传达到 **16 次**仍未成功，则丢弃该帧并向高层报告错误。

   **三个必记数字**：
   - `k = min(重传次数, **10**)` —— 退避区间最大到 `2¹⁰ = 1024`，之后不再翻倍
   - 重传上限 **16 次**
   - 10 Mbps 以太网的争用期 `2τ = **51.2 μs** = 512 比特时间`

   **陷阱**：退避的时间单位是**争用期 2τ**，不是 τ；且 `r` 是从 `0` 开始取的（**可能不等待直接重发**）。

3. | 维度 | CSMA/CD | CSMA/CA |
   |---|---|---|
   | 用于 | **有线**以太网（IEEE 802.3） | **无线**局域网（IEEE 802.11） |
   | 核心思想 | **冲突检测**——边发边听，冲突了就停 | **冲突避免**——发之前尽量错开，降低冲突概率 |
   | 传输中监听 | **是**（边发送边检测） | **否**（发出去就发完） |
   | 确认机制 | **无 ACK**（靠上层） | **必须有 ACK**，收不到就重传 |
   | 关键手段 | 二进制指数退避 | **帧间间隔 IFS + 随机退避 + RTS/CTS 可选** |

   **无线不能做冲突检测的三个原因**：
   1. **收发功率差距悬殊**：无线网卡发射的信号强度比接收到的远端信号强上百万倍（约 60~100 dB），**自己的发射会完全淹没对方的信号**，物理上根本"听不见"冲突。做全双工收发隔离的硬件成本极高。
   2. **隐蔽站问题**：A 与 C 都能与中间的 B 通信，但 A、C **互相听不到**。A 监听信道"空闲"就发，实际在 B 处与 C 的信号相撞——**发送方检测不到接收方处的冲突**。这是 CSMA/CD 的前提（"发送方能感知冲突"）在无线下彻底失效。
   3. 反过来还有**暴露站问题**：B 在发给 A，C 听到信道忙就不发，其实 C 发给 D 并不会干扰 —— 白白浪费了机会。

   **解法**：CSMA/CA 用 **RTS/CTS 握手**预约信道（解决隐蔽站）+ **ACK 确认**（无法检测冲突，只能靠"没收到 ACK"来推断失败）+ **退避计时器在信道忙时冻结**。

4. **冲突域**：由**集线器**连接的所有设备处于**同一个**冲突域；**交换机的每个端口是一个独立的冲突域**。
   - 集线器 + 其下 5 台主机 → **1 个**冲突域（通过交换机的 1 个端口接入）
   - 交换机另外接的 2 台主机 → **2 个**冲突域
   - 交换机与路由器之间的链路 → **1 个**冲突域

   **冲突域 = 1 + 2 + 1 = 4 个**

   **广播域**：交换机**不隔离**广播域（未划 VLAN 时），路由器**隔离**广播域。集线器、5 台主机、2 台主机、交换机全部处于同一个广播域。

   **广播域 = 1 个**（路由器的另一侧属于其他广播域，本题未给出）

   | 设备 | 隔离冲突域 | 隔离广播域 |
   |---|---|---|
   | 集线器 / 中继器（物理层） | ❌ | ❌ |
   | **交换机 / 网桥**（链路层） | ✅ **每端口一个** | ❌（划 VLAN 后 ✅） |
   | **路由器**（网络层） | ✅ | ✅ **每接口一个** |

   **数数口诀**：从交换机端口出发数冲突域；从路由器接口出发数广播域；**集线器整个算一个冲突域**。

5. CDMA 的解码规则：把叠加信号 `S` 与目标站的码片序列 `A` 做**规格化内积**（内积除以码片长度 `m`）：

   ```
   S · A / m = +1  →  该站发送了比特 1
   S · A / m = -1  →  该站发送了比特 0
   S · A / m =  0  →  该站没有发送
   ```

   计算内积（`m = 8`）：

   ```
   S =  (-1, +1, -3, +1, -1, -3, +1, +1)
   A =  (-1, -1, -1, +1, +1, -1, +1, +1)
   逐项相乘: (+1) + (-1) + (+3) + (+1) + (-1) + (+3) + (+1) + (+1) = 8
   规格化内积 = 8 / 8 = +1
   ```

   **站 A 发送了比特 `1`**。

   **原理**：各站的码片序列**两两正交**（规格化内积为 0），所以在做内积时，**其他站的贡献全部抵消为 0**，只剩下目标站自己的分量。这正是"多个站可以同时同频发送而互不干扰"的数学基础。
   **陷阱**：
   - 码片序列在计算时用 **`+1 / -1`** 表示，而书写时常用 `0/1`（`0` 对应 `-1`）——**别混用**。
   - 发送比特 `0` 时，站发出的是码片序列的**反码**（各项取负），所以内积得 `-1`。
   - **规格化**这一步别漏（要除以码片长度 `m`），否则得不到 `±1`。

## CN04 网络层

1.（计算）某主机 IP 为 `172.16.45.100`，子网掩码 `255.255.240.0`。求：① 前缀长度；② 网络地址；③ 广播地址；④ 该子网的可用主机数与可用地址范围。
2.（计算）某路由器的转发表如下，收到目的地址为 `192.168.5.130` 的分组，应从哪个接口转发？

   | 目的网络 | 下一跳接口 |
   |---|---|
   | `192.168.0.0/16` | S0 |
   | `192.168.4.0/22` | S1 |
   | `192.168.5.128/25` | S2 |
   | `0.0.0.0/0`（默认路由） | S3 |

3.（计算）一个总长度为 **3800 字节**的 IP 数据报（其中首部 20 字节），要通过 **MTU = 1420 字节**的链路。写出各分片的**总长度、数据长度、片偏移与 MF 标志**。
4.（简答）主机 A（`192.168.1.10/24`）要给主机 B（`10.0.0.5/24`）发数据，中间经过一台路由器。A 发出的以太网帧中，**目的 MAC 地址**是谁的？ARP 在这个过程中解析的是什么？
5.（计算）路由器 R 的 RIP 路由表如下。现从相邻路由器 **C** 收到一个 RIP 报文，内容为 `N1: 4, N2: 5, N3: 1, N4: 4`。写出 R 更新后的路由表。

   | 目的网络 | 距离 | 下一跳 |
   |---|---|---|
   | N1 | 7 | A |
   | N2 | 2 | C |
   | N3 | 8 | F |
   | N4 | 4 | E |

### 参考答案

1. 掩码 `255.255.240.0` → 二进制 `11111111.11111111.11110000.00000000` → **前缀长度 /20**。

   ② **网络地址** = `IP AND 掩码`。只需算第 3 字节：`45 = 0010 1101`，`240 = 1111 0000`，按位与 → `0010 0000 = 32`。
   → **网络地址 = `172.16.32.0/20`**

   ③ **广播地址** = 主机位全置 1。主机位有 `32 − 20 = 12` 位（第 3 字节的低 4 位 + 整个第 4 字节）：
   第 3 字节 `0010 0000` → `0010 1111 = 47`，第 4 字节 → `255`
   → **广播地址 = `172.16.47.255`**

   ④ **可用主机数** = `2¹² − 2 = 4096 − 2 = **4094**`
   **可用地址范围** = `172.16.32.1 ~ 172.16.47.254`

   **解题四步固定套路**：① 掩码转前缀 → ② `AND` 得网络地址 → ③ 主机位全 1 得广播地址 → ④ 中间去掉首尾即可用范围。
   **陷阱**：`−2` 是减掉**网络地址（主机位全 0）**和**广播地址（主机位全 1）**。但**子网数不减 2**（CIDR 下全 0、全 1 子网可用），且 `/31` 点对点链路是特例（RFC 3021，2 个地址都可用）。

2. **最长前缀匹配**：把目的地址与每条路由逐一比对，选**匹配成功且前缀最长**的那条。

   `192.168.5.130` 的第 3、4 字节：`5 = 0000 0101`，`130 = 1000 0010`

   | 路由 | 是否匹配 | 判断过程 |
   |---|---|---|
   | `192.168.0.0/16` | ✅ | 前 16 位 `192.168` 相同 |
   | `192.168.4.0/22` | ✅ | /22 只看第 3 字节高 6 位：`5 = 000001|01` → 高 6 位 `000001` = `4` ✅ |
   | **`192.168.5.128/25`** | ✅ | 第 3 字节全同（5），第 4 字节高 1 位：`130 = 1|0000010` → 高位 1，`128 = 1|0000000` ✅ |
   | `0.0.0.0/0` | ✅ | 默认路由永远匹配 |

   四条全部匹配，取**前缀最长的 /25** → **从接口 S2 转发**。

   **要点**：
   - **默认路由 `0.0.0.0/0` 前缀长度为 0，永远是最后的兜底选项**。
   - 最长前缀匹配的本质是"**最具体的路由优先**"——这是 CIDR 取消分类编址后能保证转发唯一性的关键机制。
   - 工程实现用 **Trie 树 / TCAM** 加速，否则线性扫描几十万条 BGP 路由撑不住。

3. IP 首部 20 字节 → **数据部分 = 3800 − 20 = 3780 字节**。
   MTU = 1420 → 每片**数据部分**最多 `1420 − 20 = 1400` 字节，且**必须是 8 的倍数**：`1400 / 8 = 175` ✅ 正好符合，无需再向下取整。

   `3780 = 1400 + 1400 + 980`

   | 分片 | 数据长度 | **总长度** | **片偏移** | **MF** | 标识 |
   |---|---|---|---|---|---|
   | 第 1 片 | 1400 | `1400 + 20 = **1420**` | **0** | **1** | 与原报文相同 |
   | 第 2 片 | 1400 | **1420** | `1400 / 8 = **175**` | **1** | 相同 |
   | 第 3 片 | 980 | `980 + 20 = **1000**` | `2800 / 8 = **350**` | **0** | 相同 |

   **三条铁律**：
   - **片偏移以 8 字节为单位**，值 = **前面所有片的数据字节数之和 ÷ 8**（不含首部！）
   - **除最后一片外，每片的数据长度必须是 8 的倍数**（因为片偏移字段的粒度是 8 字节）
   - **每片都要带完整的 20 字节首部**，且**标识字段相同**（接收方靠它把碎片拼回去）；MF（More Fragment）除最后一片为 0 外都是 1

   **陷阱**：计算时**先减首部再分片**，别拿 3800 直接除；总长度字段**含首部**，而片偏移**只算数据**——这两个"含不含首部"的差异是最常见的失分点。

4. **目的 MAC 地址是路由器接口（网关）的 MAC 地址**，不是主机 B 的。

   完整过程：
   1. A 用自己的**子网掩码**判断：`10.0.0.5` 与 `192.168.1.10` **不在同一网段** → 必须交给**默认网关**转发。
   2. A 检查 ARP 缓存中有没有网关 `192.168.1.1` 的 MAC。没有则**广播 ARP 请求**："谁是 192.168.1.1？请告诉 192.168.1.10"。
   3. 路由器应答自己的 MAC。A 封装以太网帧：**源 MAC = A，目的 MAC = 路由器接口**；而 **IP 首部里的源 IP = A，目的 IP = B（始终不变）**。
   4. 路由器收到后**剥掉链路层首部**，查路由表，从另一个接口**重新封装一个新帧**：源 MAC = 路由器出接口，目的 MAC = B（或下一跳路由器）的 MAC——**这里再做一次 ARP**。

   **核心结论（每年必考）**：
   > **IP 地址（源/目的）在整个传输过程中保持不变（NAT 除外）；MAC 地址每经过一个路由器就变一次。**

   ARP 解析的**永远是"下一跳"的 MAC**——同网段时是目标主机本身，跨网段时是网关。
   **陷阱**：ARP **只能在同一个局域网（广播域）内工作**——ARP 请求是广播帧，**路由器不转发广播**。所以 A 永远不可能直接 ARP 到 B 的 MAC。

5. **RIP 距离向量更新的三步法则**（收到相邻路由器 X 的报文后）：
   1. 把报文中每一项的**距离加 1**，下一跳全部改为 **X**；
   2. 对每一项：
      - 若**原表中没有**该目的网络 → **直接添加**；
      - 若**原表中该项的下一跳就是 X** → **无条件用新值替换**（对方说什么就是什么，因为路径必经它）；
      - 若**下一跳不是 X** → **只有新距离更小时才更新**，否则保持不变。

   收到的报文加 1 并改下一跳后：`N1: 5(C), N2: 6(C), N3: 2(C), N4: 5(C)`

   | 目的 | 原表 | 新值 | 判断 | **更新后** |
   |---|---|---|---|---|
   | N1 | 7, A | 5, C | 下一跳不是 C，但 **5 < 7** → 更新 | **N1, 5, C** |
   | N2 | 2, C | 6, C | **下一跳就是 C** → 无条件替换（哪怕变差） | **N2, 6, C** |
   | N3 | 8, F | 2, C | 下一跳不是 C，**2 < 8** → 更新 | **N3, 2, C** |
   | N4 | 4, E | 5, C | 下一跳不是 C，**5 > 4** → 不变 | **N4, 4, E** |

   **最终路由表**：

   | 目的网络 | 距离 | 下一跳 |
   |---|---|---|
   | N1 | **5** | **C** |
   | N2 | **6** | C |
   | N3 | **2** | **C** |
   | N4 | 4 | E |

   **最大陷阱**：**N2 那一行**——新距离 6 比原来的 2 **更差**，但因为下一跳本来就是 C，说明这条路径的实际情况变糟了（C 那边链路出问题），**必须无条件接受**。很多人在这里错答"距离变大不更新"。
   **配套记忆**：RIP 用**跳数**作度量，**16 表示不可达**（最大有效 15 跳），每 **30 秒**广播一次，**180 秒**未收到则判定邻居失效。它的致命缺点是**"坏消息传得慢"（计数到无穷）**，缓解手段有**水平分割、毒性逆转、触发更新**。

## CN05 传输层

1.（简答）TCP 建立连接为什么是**三次**握手而不是两次？释放连接为什么要**四次**挥手？TIME_WAIT 状态为什么要等 **2MSL**？
2.（计算）TCP 的 MSS = 1 KB，慢开始门限 `ssthresh` 初值为 **8**，初始 `cwnd = 1`。第 1~4 个 RTT 正常传输，在**第 8 个 RTT 结束时发生超时**，第 9~12 个 RTT 恢复正常。写出第 1~12 个 RTT 开始时的 `cwnd` 值。
3.（计算）主机 A 向 B 发送数据，`seq = 501`，携带 **200 字节**数据。① B 的确认号应为多少？② 若 A 接着发送 `seq = 701` 携带 300 字节，B 的确认号？③ 若第二个报文丢失，A 又发来 `seq = 1001` 的报文，B 应回复什么确认号？
4.（简答）UDP 的**伪首部**是什么？为什么说它"参与校验但不发送"？UDP 校验和与 TCP 校验和有什么区别？
5.（简答）流量控制与拥塞控制有什么区别？什么是**零窗口死锁**，TCP 怎么解决？

### 参考答案

1. **为什么握手是三次**（不能是两次）：

   核心是要**双方都确认"对方的发送能力和自己的接收能力都正常"**。两次握手时，**服务器无法确认客户端是否收到了自己的确认**。

   经典反例：客户端发出的**第一个 SYN 在网络中滞留**（拥塞导致延迟），客户端超时后重发并完成了一次正常连接、传完数据也关闭了。此时那个**滞留的旧 SYN 才姗姗来迟**到达服务器——
   - **两次握手**下：服务器认为这是新连接请求，回复确认后**直接进入连接已建立状态**，分配缓冲区并傻等数据。客户端根本不理它 → **服务器资源被白白占用**。
   - **三次握手**下：服务器发出 SYN+ACK 后处于 `SYN_RCVD`，等不到客户端的第三次确认 → **超时后释放资源**，问题自动消解。

   **为什么挥手是四次**：TCP 是**全双工**的，两个方向的数据流要**分别关闭**。收到 FIN 只说明"对方没有数据要发了"，但**自己可能还有数据没发完**——所以先单独回一个 ACK（进入**半关闭 CLOSE_WAIT**），把剩余数据发完后再发自己的 FIN。**ACK 与 FIN 不能合并，故比握手多一次**。（握手时服务器的 SYN 与 ACK 可以合并，因为此时没有数据要传。）

   **TIME_WAIT 等 2MSL 的两个理由**（MSL = 最长报文段寿命，通常取 2 分钟）：
   1. **保证最后一个 ACK 能到达对方**。若这个 ACK 丢失，对方会在超时后**重传 FIN**；本方还处在 TIME_WAIT 就能**重新发一次 ACK** 并重新计时。若立刻 CLOSED，对方将收不到确认而无法正常关闭。
   2. **让本连接产生的所有报文段在网络中消失**。防止"旧连接的迟到报文"被下一个**使用相同四元组**的新连接错误接收。

   **工程对照**：`ss -tan | grep TIME-WAIT` 数量大 = 本机是主动关闭方（短连接客户端）；`CLOSE_WAIT` 堆积 = **应用代码收到 FIN 后忘了调 `close()`**，这是最常见的连接泄漏 bug。

2. 规则回顾：
   - **慢开始**：`cwnd < ssthresh` 时，每个 RTT `cwnd` **翻倍**
   - **拥塞避免**：`cwnd ≥ ssthresh` 时，每个 RTT `cwnd` **加 1**
   - **超时**：`ssthresh = cwnd / 2`，`cwnd = 1`，**重新慢开始**

   | RTT 序号 | cwnd（KB） | 所处阶段 |
   |---|---|---|
   | 1 | **1** | 慢开始 |
   | 2 | **2** | 慢开始 |
   | 3 | **4** | 慢开始 |
   | 4 | **8** | 达到 ssthresh = 8，**转入拥塞避免** |
   | 5 | **9** | 拥塞避免（+1） |
   | 6 | **10** | 拥塞避免 |
   | 7 | **11** | 拥塞避免 |
   | 8 | **12** | 拥塞避免 → **本轮结束时超时** |
   | 9 | **1** | `ssthresh = 12/2 = 6`，`cwnd = 1`，重新慢开始 |
   | 10 | **2** | 慢开始 |
   | 11 | **4** | 慢开始 |
   | 12 | **6** | 达到新 ssthresh = 6，**转入拥塞避免** |

   **最容易错的两处**：
   - 第 4 个 RTT 时 `cwnd = 8` **正好等于** ssthresh，此时**转入拥塞避免**（`≥` 就转，不是 `>`）。
   - 超时后 `ssthresh` 取的是**超时那一刻的 cwnd 的一半**（12/2 = 6），不是初始值的一半。
   - **对比记忆**：若是**收到 3 个重复 ACK**（而非超时），则执行**快重传 + 快恢复**：`ssthresh = cwnd/2 = 6`，`cwnd = ssthresh = 6`（**不降到 1**），**直接进入拥塞避免**。这两条路径的差异是本章最高频考点。

3. TCP 的确认号含义：**期望收到的下一个字节的序号**，且是**累计确认**。

   ① 收到 `seq = 501`、200 字节 → 覆盖字节 `501 ~ 700` → **确认号 = 701**
   ② 收到 `seq = 701`、300 字节 → 覆盖 `701 ~ 1000` → **确认号 = 1001**
   ③ 第二个报文丢失，B 只收到 `501~700` 和 `1001~...`。由于**中间有空洞**，B **仍然只能确认 701**——即**重复发送 `ack = 701`**。

   这正是**快速重传**的触发机制：A 连续收到 **3 个重复的 `ack = 701`** 后，不等超时计时器到期就**立即重传 701 开始的那个报文段**。

   **三个必记要点**：
   - **确认号 = 已正确按序收到的最后一个字节的序号 + 1**
   - **TCP 是面向字节流的**，序号编的是**字节**不是报文段
   - **SYN 和 FIN 各消耗一个序号**（虽然不携带数据）——所以握手时 `ack = x + 1`

   **陷阱**：TCP 的确认是**累计确认**，收到失序报文时**不能**确认后面的部分（除非用 **SACK 选项**告知对方"我已经收到 1001~1300 了"，但**基本确认号仍是 701**）。408 默认不考虑 SACK。

4. **伪首部**是一个 **12 字节**的临时数据块，只在**计算校验和时临时拼接在 UDP 数据报前面**，包含：

   | 字段 | 长度 |
   |---|---|
   | 源 IP 地址 | 4 B |
   | 目的 IP 地址 | 4 B |
   | 全 0 填充 | 1 B |
   | 协议号（UDP = 17，TCP = 6） | 1 B |
   | UDP 长度 | 2 B |

   **"参与校验但不发送"的含义**：计算校验和时把它拼上去一起算，**算完就丢弃**，实际发送到链路上的报文中**没有这 12 字节**。接收方收到后，**自己从 IP 首部里取出源/目的 IP 重新构造伪首部**再校验。

   **作用**：把**网络层的信息（IP 地址、协议号）纳入传输层的校验范围**，从而能检测出「**IP 数据报被误投递到了错误的主机**」或「**协议字段被篡改**」这类跨层错误——单靠传输层自己的首部是查不出来的。
   **注意**：伪首部的存在**违反了严格的分层原则**（传输层"偷看"了网络层的信息），这是 TCP/IP 为了实用性做的妥协，408 会考这个说法。

   | | UDP 校验和 | TCP 校验和 |
   |---|---|---|
   | 是否必需 | **可选**（IPv4 下可置全 0 表示不校验；**IPv6 下强制**） | **强制** |
   | 校验范围 | 伪首部 + UDP 首部 + 数据 | 伪首部 + TCP 首部 + 数据 |
   | 出错处理 | **直接丢弃，不通知发送方** | 丢弃并**不确认**，触发发送方超时重传 |
   | 算法 | 二进制反码求和 | 相同 |

5. | 维度 | 流量控制 | 拥塞控制 |
   |---|---|---|
   | 解决什么 | **接收方**缓冲区处理不过来 | **整个网络**（路由器、链路）负载过重 |
   | 作用范围 | **点对点**（发送方 ↔ 接收方两端） | **全局**（涉及所有主机、路由器与链路） |
   | 控制窗口 | **接收窗口 rwnd**——由**接收方**在 TCP 首部的"窗口"字段告知 | **拥塞窗口 cwnd**——由**发送方**根据网络状况自行计算 |
   | 触发信号 | 对方通告的窗口变小 | **超时** 或 **三个重复 ACK** |
   | 类比 | 你说话太快，听的人跟不上 | 高峰期整条高速堵车 |

   **发送窗口 = min(rwnd, cwnd)** —— 两个限制取严者，必背。

   **零窗口死锁**：接收方缓冲区满时通告 `rwnd = 0`，发送方停止发送；后来接收方腾出空间，发送一个**窗口更新报文**告知 `rwnd > 0`——**但这个报文丢失了**。于是：
   - 发送方以为窗口仍是 0，**一直不发数据**；
   - 接收方以为已经通知过了，**等着收数据**；
   - 而**窗口更新报文不携带数据、不会被重传**（TCP 只重传携带数据的报文段） → **双方永久互等，死锁**。

   **解决方案：持续计时器（persistence timer）**。发送方收到零窗口通告后**立即启动持续计时器**；计时器超时就发送一个**零窗口探测报文（仅 1 字节数据）**，强迫接收方回复一个包含当前窗口值的确认。若仍是 0，则重置计时器继续等（间隔按指数退避增长）。这样即使更新报文丢失，也能靠周期性探测恢复。
   **陷阱**：探测报文**必须携带 1 字节数据**——因为纯 ACK 不会得到对方的确认，也就问不出窗口值。

## CN06 应用层

1.（简答）递归查询与迭代查询有什么区别？描述一次完整的 DNS 解析（本地缓存全部未命中）经过了哪些服务器。
2.（简答）FTP 为什么要建立**两个**连接？主动模式（PORT）与被动模式（PASV）有什么区别，为什么客户端在防火墙/NAT 之后必须用被动模式？
3.（计算）某网页包含 1 个 HTML 文件和 **5 个**小图片对象，客户端与服务器的 RTT 为 `T`，忽略传输时延与处理时延。分别计算以下四种方式所需的总时间：① 非持久连接、串行；② 非持久连接、**5 条并行**；③ 持久连接、非流水线；④ 持久连接 + 流水线。
4.（简答）HTTP 状态码分为哪五类？**301 与 302**、**Cookie 与 Session** 分别有什么区别？
5.（简答）电子邮件系统中 SMTP、POP3、IMAP 各负责哪一段？为什么说 **SMTP 是"推"而 POP3 是"拉"**？

### 参考答案

1. | | 递归查询 | 迭代查询 |
   |---|---|---|
   | 谁负责查到底 | **被询问的服务器代为查完**，直接返回最终结果 | 被询问的服务器**只回复"下一步该问谁"** |
   | 询问者的工作 | 问一次就等结果 | **反复询问多个服务器** |
   | 负担落在 | 被询问的服务器 | **询问者（通常是本地域名服务器）** |
   | 典型用于 | **主机 → 本地域名服务器** | **本地域名服务器 → 根 / 顶级域 / 权限域名服务器** |

   **完整解析流程**（查询 `www.example.com`，全部未命中缓存）：

   1. 主机查询**本地域名服务器**（递归）——"我要 `www.example.com` 的 IP，你给我查好"
   2. 本地域名服务器问**根域名服务器**（迭代）→ 根回复："我不知道，去问 **`.com` 顶级域名服务器**，地址是 …"
   3. 本地域名服务器问 **`.com` 顶级域名服务器**（迭代）→ 回复："去问 **`example.com` 的权限域名服务器**"
   4. 本地域名服务器问**权限域名服务器**（迭代）→ 回复："IP 是 `93.184.x.x`"
   5. 本地域名服务器把结果返回主机，**并缓存该记录**（按 TTL 过期）

   共 **4 次查询、4 次应答**（主机 1 次 + 本地服务器 3 次）。

   **两个陷阱**：
   - **根域名服务器不直接给最终 IP**，只给顶级域服务器的地址。全球 13 组根服务器（逻辑上 13 个，物理上靠任播部署了上千台）。
   - 协议上本地服务器**也可以**对根服务器发起递归查询，但根服务器出于负载考虑**一律只做迭代应答**。408 按"主机→本地是递归，其余全是迭代"作答。
   - 验证：`dig +trace www.example.com` 打印的正是这个迭代过程；`dig www.example.com` 则是向本地服务器发一次递归查询。

2. **两个连接的分工**：

   | 连接 | 端口 | 用途 | 生命周期 |
   |---|---|---|---|
   | **控制连接** | **21** | 传输**命令与响应**（登录、切目录、发起传输） | **整个会话期间一直保持** |
   | **数据连接** | **20**（主动模式） | 传输**文件内容与目录列表** | **每传一个文件建立一次，传完就关** |

   **设计理由**：① 命令通道始终畅通，**传输过程中可以随时发送 ABOR 中止命令**；② 控制信息与数据分离，协议解析简单；③ 数据连接不必解析命令，可以纯字节流传输。这是 **FTP 有状态**（记住当前目录、传输模式）而 HTTP 无状态的根本区别。

   | | 主动模式（PORT） | 被动模式（PASV） |
   |---|---|---|
   | 谁发起数据连接 | **服务器 → 客户端** | **客户端 → 服务器** |
   | 流程 | 客户端用 `PORT` 命令告知自己监听的 IP+端口，服务器**从 20 端口主动连过去** | 客户端发 `PASV`，服务器回复一个**临时端口**，客户端**主动连过去** |
   | 服务器端口 | **固定 20** | 随机高位端口 |

   **客户端在 NAT/防火墙后必须用被动模式**，因为：
   - 主动模式要求**服务器主动连接客户端**。但 NAT 后的客户端只有**私有 IP**，`PORT` 命令里告知的是私有地址，服务器根本路由不到；
   - 即便 IP 可达，**防火墙默认拒绝所有入站连接**——服务器发起的这个连接会被直接拦掉；
   - 被动模式下**两条连接都由客户端主动发起（出站）**，NAT 会自动建立映射、防火墙也放行出站连接，畅通无阻。

   **代价**：被动模式把负担转给服务器——服务器要开放**一大段高位端口**供数据连接使用，这是防火墙配置 FTP 时最麻烦的地方（也是 FTP 逐渐被 HTTP/SFTP 取代的原因之一）。

3. 记号：建立一条 TCP 连接需 **1 个 RTT**（三次握手的前两次），请求并收到一个对象需 **1 个 RTT**。

   | 方式 | 计算 | 总时间 |
   |---|---|---|
   | ① 非持久、串行 | 每个对象都要"建连 1 + 请求 1" = 2 RTT，共 6 个对象 | `2T × 6 = **12T**` |
   | ② 非持久、5 条并行 | HTML：2T；5 张图**并行**只需 2T | `2T + 2T = **4T**` |
   | ③ 持久、非流水线 | 建连 1T + 请求 HTML 1T + 5 张图**逐个**各 1T | `T + T + 5T = **7T**` |
   | ④ 持久 + 流水线 | 建连 1T + 请求 HTML 1T + 5 张图**一次性全发出**共 1T | `T + T + T = **3T**` |

   **解题模板**（请求 1 个 HTML + `n` 个内嵌对象）：

   ```
   非持久串行     : 2 × (n + 1)
   非持久 m 条并行 : 2 + 2 × ⌈n / m⌉
   持久非流水线    : 2 + n
   持久 + 流水线   : 2 + 1 = 3
   ```

   **三个陷阱**：
   - "2" 里包含 **建连 1 RTT + 请求响应 1 RTT**，别只算一个。
   - 若题目**还要求 DNS 解析**，总时间再 **+1 个 RTT**（或题目给出的 DNS 查询时间）。
   - 若题目**不忽略传输时延**，每个对象还要加上 `对象大小 / 带宽`。
   - **必须先拿到 HTML 才知道有哪些图片**，所以 HTML 的那 1 个 RTT 无论如何都无法与图片并行。

4. **五类状态码**：

   | 类别 | 含义 | 常见 |
   |---|---|---|
   | **1xx** | 信息性——请求已收到，继续处理 | `100 Continue`、`101 Switching Protocols`（WebSocket 升级） |
   | **2xx** | **成功** | `200 OK`、`204 No Content`、`206 Partial Content`（断点续传） |
   | **3xx** | **重定向** | `301`、`302`、`304 Not Modified`（**缓存命中**） |
   | **4xx** | **客户端错误** | `400 Bad Request`、`401 Unauthorized`、`403 Forbidden`、`404 Not Found` |
   | **5xx** | **服务器错误** | `500 Internal Server Error`、`502 Bad Gateway`、`503 Service Unavailable` |

   **301 vs 302**：

   | | 301 Moved Permanently | 302 Found（临时重定向） |
   |---|---|---|
   | 语义 | 资源**永久**搬走了 | **临时**去别处，原地址以后还有效 |
   | 浏览器行为 | **缓存该重定向**，下次直接请求新地址 | **不缓存**，每次仍先请求原地址 |
   | 搜索引擎 | **转移权重**到新 URL | 保留原 URL 的权重 |
   | 典型用途 | 域名更换、`http → https` | 登录跳转、A/B 测试、临时维护页 |

   **Cookie vs Session**：

   | | Cookie | Session |
   |---|---|---|
   | 存放位置 | **客户端**（浏览器） | **服务器端**（内存 / Redis / 数据库） |
   | 安全性 | 低（用户可查看修改，需签名/加密） | **高**（客户端只持有一个不透明的 ID） |
   | 容量 | 小（单个约 4 KB） | 不受限 |
   | 关系 | — | **Session ID 通常就是靠 Cookie 传递的**（`Set-Cookie: JSESSIONID=...`） |

   **本质**：**HTTP 本身是无状态的**——服务器不记得你上一次请求过什么。Cookie/Session 是在**无状态协议之上补出来的状态机制**：Cookie 把状态存在客户端随请求带回，Session 把状态存在服务端而只让客户端带一个凭证。

5. | 协议 | 负责哪一段 | 方向 | 端口 |
   |---|---|---|---|
   | **SMTP** | 发送方用户代理 → **发送方邮件服务器** → **接收方邮件服务器** | **推（push）** | 25（提交用 587） |
   | **POP3** | 接收方邮件服务器 → 接收方用户代理 | **拉（pull）** | 110 |
   | **IMAP** | 同上，但保持服务器端状态同步 | **拉（pull）** | 143 |

   完整链路：`发件人用户代理 --SMTP--> 发件方邮件服务器 --SMTP--> 收件方邮件服务器 --POP3/IMAP--> 收件人用户代理`

   **"推"与"拉"的根本原因**：**接收方的用户代理（个人电脑、手机）不是一台 24 小时在线的服务器**——它没有固定 IP、随时可能关机。所以邮件只能先"推"到**始终在线的接收方邮件服务器**上暂存，等用户上线后**主动"拉"取**。
   若强行让 SMTP 直接推到用户代理，用户关机时邮件就投递失败了——这就是**为什么收信不能用 SMTP**（408 高频简答）。

   **POP3 vs IMAP**：

   | | POP3 | IMAP |
   |---|---|---|
   | 邮件存在哪 | **下载到本地后默认从服务器删除** | **始终保存在服务器**，本地只是缓存 |
   | 多设备同步 | ❌ 一台设备收了，另一台就看不到 | ✅ **已读/已删/文件夹状态全部同步** |
   | 部分下载 | ❌ 必须整封下载 | ✅ **可只下载首部**，按需取正文与附件 |
   | 服务器负担 | 小 | **大**（要长期存储并维护状态） |
   | 离线可用 | 好 | 需连接（有离线模式但更复杂） |

   **MIME 的作用**：SMTP 原本**只能传 7 位 ASCII 文本**。MIME（多用途互联网邮件扩展）**不改变 SMTP 本身**，而是定义了首部字段（`Content-Type`、`Content-Transfer-Encoding`）与编码方式（**Base64**、Quoted-Printable），把二进制数据（图片、附件、中文）**编码成 ASCII 再传，接收方解码还原**。这是"在不改协议的前提下扩展能力"的经典设计。

**最易错的七个点**（历年失分统计口径）：

1. **信噪比 dB 未换算** —— `30 dB` 是 1000 倍，不是 30
2. **片偏移单位** —— 以 **8 字节**为单位，且只算数据不含首部
3. **RIP 更新时"下一跳相同则无条件替换"** —— 距离变大也要更新
4. **超时 vs 三个重复 ACK 的处理差异** —— 前者 `cwnd = 1`，后者 `cwnd = ssthresh`
5. **跨网段通信的目的 MAC** —— 是**网关**的 MAC，不是目标主机的
6. **忘了"取小者"** —— 奈奎斯特与香农都能算时，极限速率取两者中的较小值
7. **HTTP RTT 计算漏掉建连的那 1 个 RTT** —— "每对象 2 RTT"里的第一个是握手
