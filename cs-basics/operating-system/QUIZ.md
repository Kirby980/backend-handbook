## OS01 操作系统概述与运行环境

1.（单选）下列指令中，**只能**在内核态执行的是：
   A. 算术加法指令　B. 关中断指令　C. 读通用寄存器指令　D. 条件转移指令
2.（简答）中断与异常的区别是什么？异常（内中断）分为哪三类，各自处理完后 PC 指向哪里？
3.（判断）系统调用是用户程序主动执行陷入指令（trap）引发的，属于内中断中的"陷阱"，因此**不能**由用户程序用一条普通跳转指令替代。
4.（简答）说明操作系统四大特征中「并发」与「并行」的区别，以及「虚拟」的四种典型技术。
5.（简答）大内核与微内核在结构、性能、可靠性上各有什么取舍？为什么微内核性能通常更差？
6.（简答）① 描述从加电到第一个用户进程启动的完整引导流程；② 引导程序为什么要分成"ROM 里的一小段"和"磁盘上的一大段"？③ 第一类 VMM 与第二类 VMM 有哪些区别？容器算哪一类？

### 参考答案

1. **B**。特权指令的判别标准是：**执行它会影响其他进程或整个系统的运行**。关中断、开中断、置时钟、I/O 指令、修改 PSW、加载页表基址寄存器、切换到用户态（注意：**从内核态转用户态**是特权指令，反向不是指令而是中断）都属特权指令。A、C、D 是普通运算与控制流，用户态可执行。

2. | 维度 | 内中断（异常 / 例外） | 外中断（狭义中断） |
   |---|---|---|
   | 来源 | **CPU 内部**，与当前指令相关 | **CPU 外部**，与当前指令无关 |
   | 例子 | 缺页、除零、非法指令、系统调用 | 时钟中断、I/O 完成、键盘输入 |
   | 检测时机 | 指令执行**过程中** | 一条指令**执行结束后** |

   异常三类：
   - **故障（Fault）**：可恢复，如缺页、除零。处理完**返回引发故障的那条指令重新执行**。
   - **陷阱（Trap）**：有意为之，如系统调用、断点。处理完**返回下一条指令**。
   - **终止（Abort）**：不可恢复的硬件错误，如控制器出错。**不返回**，直接终止进程。

   **陷阱**：408 最爱考「缺页中断处理完返回哪条指令」——**同一条**，因为要重新访问那个刚调入内存的页面。

3. **对**。用户程序不能直接跳转到内核代码，理由有二：① **权限**——内核代码页在页表里被标记为特权级，用户态访问会触发保护故障；② **入口可控**——陷入指令（x86 的 `int 0x80` / `syscall`，MIPS 的 `syscall`）会把 CPU 切到内核态**并强制跳转到中断向量表指定的统一入口**，内核由此检查系统调用号与参数合法性。如果允许任意跳转，用户就能跳到内核任意一条指令中间，绕过全部检查。
   补充：**陷入指令本身是用户态可执行的非特权指令**——这是 408 高频陷阱，它是"申请进内核"的唯一合法途径，如果它本身是特权指令，用户态永远进不去。

4. **并发 vs 并行**：并发是**宏观同时、微观交替**（单核也能并发）；并行是**同一时刻真的一起执行**（必须多核 / 多处理机）。四大特征中**并发与共享是最基本的两个特征，互为存在前提**。

   **虚拟的四种技术**：

   | 技术 | 把什么虚拟成什么 | 依据 |
   |---|---|---|
   | 时分复用 | 一个 CPU → 多个"逻辑 CPU" | 进程分时轮转 |
   | 空分复用 | 一片物理内存 → 多个独立地址空间 | 分页 / 分段 |
   | 虚拟存储器 | 小内存 → 大逻辑地址空间 | 局部性原理 |
   | 虚拟设备（SPOOLing） | 一台独占打印机 → 多台"逻辑打印机" | 输入输出井 |

   **陷阱**：如果失去并发，虚拟就没有意义（只有一个进程时不需要虚拟出多份资源）。

5. | 维度 | 大内核（宏内核） | 微内核 |
   |---|---|---|
   | 结构 | 进程管理、内存、文件、设备驱动**全在内核态** | 内核只留**进程通信、基本调度、低级内存管理、中断处理**，其余移到用户态服务进程 |
   | 性能 | **高**——模块间是函数调用 | **低**——模块间要走消息传递 |
   | 可靠性 | 一个驱动崩溃可拖垮整个系统 | 服务进程崩溃可单独重启，故障隔离好 |
   | 可扩展性 | 改内核要重编译 | 加服务即可 |
   | 代表 | Linux、UNIX、Windows NT（混合） | Mach、QNX、L4、seL4 |

   **性能差的根因**：一次原本的内核函数调用，在微内核下变成「用户态服务 A → 陷入内核 → 消息传递 → 切到用户态服务 B → 再切回来」，**至少两次用户/内核态切换 + 两次进程上下文切换**。切换要保存/恢复寄存器组、刷新 TLB、污染 Cache，开销远大于一次函数调用。
   工程现实：Linux 是宏内核但用**可加载内核模块（LKM）**获得了部分可扩展性；Linux 5.x 后 [用户态驱动框架](../../linux/INDEX.md)（如 DPDK、SPDK、FUSE）又把一部分微内核思想拿了回来。

6. **① 完整引导流程**：

   ```
   ① 加电/复位 → CPU 的 PC 被硬件置为固定地址，指向主板 ROM
   ② 执行 ROM 中的 BIOS/UEFI：POST 自检 + 初始化硬件 + 按启动顺序枚举设备
   ③ 读磁盘【0 号扇区】= MBR（512 字节，含主引导记录 + 分区表）
   ④ MBR 中的程序扫描分区表，找到【活动分区】
   ⑤ 读活动分区的第一个扇区（引导扇区 / 引导块），得到完整引导程序（GRUB 等）
   ⑥ 完整引导程序把【OS 内核】读入内存并跳转
   ⑦ 内核初始化：建页表、初始化中断向量表与设备驱动
   ⑧ 创建第一个用户进程 init / systemd，切换到用户态
   ```

   **② 为什么分两段**：ROM **只读且难更新**（要刷固件），而引导逻辑会随操作系统变化。把"不变的部分"（读磁盘 0 号块并跳过去）固化进 ROM，把"会变的部分"（识别文件系统、找内核、传参数）放在**磁盘的引导块**上——这样**换 OS、升级内核、装双系统都不必动主板固件**。此外 512 字节的扇区也根本装不下完整的引导程序。

   **③ 两类 VMM 对比**：

   | 维度 | **第一类（裸金属）** | **第二类（宿主型）** |
   |---|---|---|
   | 运行位置 | **直接在硬件上**，本身就是一个 OS | 宿主 OS 上的**一个进程** |
   | 对硬件控制 | 直接控制 | 必须**经宿主 OS** |
   | 资源分配 | VMM 直接分配 | 宿主 OS 先分给 VMM，VMM 再二次分配 |
   | 运行模式 | 内核态 | 主体在用户态 |
   | 性能 / 虚拟机数量 | **高 / 多** | 低 / 少 |
   | 代表 | **VMware ESXi、Xen、Hyper-V** | **VMware Workstation、VirtualBox** |

   **容器哪一类都不是**。容器**没有 VMM，也没有 Guest OS 内核**——它共享宿主机内核，靠 `namespace`（隔离视图）+ `cgroup`（限制资源）实现隔离，属于**操作系统级虚拟化**。所以它启动快（毫秒级）、开销小，但**隔离强度弱于虚拟机**（内核漏洞可横向逃逸）。这正是 AWS 发明 Firecracker **microVM** 的动机：用虚拟机的隔离性换取接近容器的启动速度。
   **陷阱**：KVM 是边界情况（Linux 内核模块，加载后把内核变成 VMM），**408 若考按第一类处理**。

## OS02 进程与线程

1.（单选）在进程五状态模型中，下列状态转换**不可能**发生的是：
   A. 运行 → 就绪　B. 就绪 → 运行　C. **就绪 → 阻塞**　D. 阻塞 → 就绪
2.（简答）PCB 里存了哪几类信息？为什么进程切换的开销明显大于同进程内的线程切换？
3.（简答）用户级线程与内核级线程有什么区别？「一个线程阻塞导致整个进程被阻塞」发生在哪种模型下，为什么？
4.（简答）IPC 的三种方式各是什么？管道通信有哪些必须记住的约束？
5.（计算）在单 CPU 系统中有 n 个进程，处于运行态、就绪态、阻塞态的进程数各自最多和最少是多少？再看下面这段 C 代码，一共创建了多少个**子**进程？

```c
for (int i = 0; i < 3; i++)
    fork();
```

### 参考答案

1. **C**。五状态模型中不可能的转换有两条：
   - **就绪 → 阻塞**：阻塞是进程主动请求资源/等待事件的结果，而就绪态进程根本没在 CPU 上跑，无法执行"请求"这个动作。
   - **阻塞 → 运行**：等待的事件完成后只能先回到就绪队列，**必须再被调度程序选中**才能上 CPU。

   合法的四条：运行→就绪（时间片到 / 被抢占）、就绪→运行（被调度）、运行→阻塞（**主动**，如请求 I/O）、阻塞→就绪（**被动**，事件完成）。
   **速记**：阻塞是主动进的、被动出的；就绪与阻塞之间**不能直接互转**。

2. PCB 四类内容：
   - **进程描述信息**：PID、UID、父进程指针
   - **进程控制与管理信息**：进程状态、优先级、程序计数器、代码入口
   - **资源分配清单**：**页表 / 段表基址**、打开文件表、已分配的 I/O 设备
   - **处理机相关信息**：通用寄存器组、PSW 的现场保存区

   **切换开销差异**：线程切换只换**寄存器组 + 栈指针 + 程序计数器**；进程切换在此之上还要**切换地址空间**——加载新的页表基址寄存器（CR3），这会导致：
   - **TLB 全部失效**（除非有 ASID/PCID 支持），后续访存要重走多级页表
   - **Cache 大量失效**，工作集要重新预热

   所以 408 标准答案是：「**进程切换涉及进程运行环境（地址空间）的切换，线程切换不涉及**」。这也是 Linux 用 `clone()` 时共享 `mm_struct` 的线程更轻的根因。

3. | 维度 | 用户级线程（ULT） | 内核级线程（KLT） |
   |---|---|---|
   | 由谁管理 | **用户态线程库**，内核不感知 | **内核**，有对应的内核数据结构 |
   | 切换开销 | 小，不需陷入内核 | 大，要陷入内核 |
   | 能否并行 | **不能**（内核只看到一个进程 → 只分一个核） | 能，多个线程可分到多个核 |
   | 一个线程阻塞 | **整个进程阻塞** | 只阻塞该线程 |
   | 调度单位 | 进程 | 线程 |

   「一个阻塞全阻塞」发生在**多对一模型（纯用户级线程）**：内核根本不知道进程内部有多个线程，某线程执行阻塞式系统调用时，**内核把整个进程置为阻塞态**，其余用户级线程虽然就绪也拿不到 CPU。
   工程对照：Go 的 goroutine 是**多对多模型**（M:N），runtime 在 goroutine 因系统调用阻塞时会把 M（内核线程）与 P 解绑并新建/复用另一个 M，从而避免整个进程被拖住——这正是 408 里"多对多模型综合了两者优点"的真实工程实例，详见 [golang/](../../golang/INDEX.md) GMP 调度。

4. | 方式 | 机制 | 同步要求 |
   |---|---|---|
   | **共享存储** | 双方在各自地址空间映射同一块物理内存 | 由**用户自己**用 PV 保证互斥（内核只负责分配） |
   | **消息传递** | 以"格式化消息"为单位，走 `send`/`receive` 原语。直接通信（指名进程）/ 间接通信（经信箱） | 内核负责传递与同步 |
   | **管道** | 内核中的一个**固定大小的循环缓冲区**（本质是特殊文件） | 内核提供互斥与同步 |

   管道的五条必背约束：
   - **半双工**：同一时刻只能单向传输，要双向得开两个管道
   - 大小固定（Linux 默认 64KB），**写满则写进程阻塞、读空则读进程阻塞**
   - 数据是**字节流**，且**读走即消失**——同一份数据不能被读两次
   - 有**多个读进程时数据会被抢**，无法确定谁读到（所以通常一读一写）
   - 无名管道只能用于**父子等有亲缘关系**的进程；命名管道（FIFO）无此限制

5. **状态数量**：

   | 状态 | 最多 | 最少 |
   |---|---|---|
   | 运行态 | **1**（单 CPU） | 0（所有进程都阻塞时） |
   | 就绪态 | **n-1**（一个在跑，其余全就绪） | 0 |
   | 阻塞态 | **n**（全部在等 I/O，此时无运行进程） | 0 |

   **fork 题**：每轮循环中**所有已存在的进程**都会各执行一次 `fork()`，进程总数翻倍。3 轮后共 `2³ = 8` 个进程，其中 1 个是原始父进程 → **子进程 7 个**。
   通式：`for (i = 0; i < n; i++) fork();` 创建 `2ⁿ - 1` 个子进程。
   **陷阱**：若写成 `fork(); fork(); fork();` 结果完全一样；但若是 `if (fork() == 0) fork();` 之类带分支的，必须画进程树逐层数。Go 没有 `fork`（runtime 多线程后 fork 语义不安全），只能用 `os/exec` 起新进程，考场按 C 答。

## OS03 CPU 调度

1.（计算）四个进程如下，用 **FCFS** 与 **非抢占式 SJF** 分别计算平均周转时间与平均带权周转时间：

   | 进程 | 到达时间 | 服务时间 |
   |---|---|---|
   | A | 0 | 7 |
   | B | 2 | 4 |
   | C | 4 | 1 |
   | D | 5 | 4 |

2.（简答）周转时间、带权周转时间、等待时间、响应时间的定义分别是什么？为什么带权周转时间恒 ≥ 1？
3.（简答）SJF 为什么会导致饥饿？HRRN 用什么办法解决，响应比公式是什么？
4.（简答）时间片大小对 RR 算法有什么影响？时间片过大和过小分别退化成什么？
5.（简答）多级反馈队列的三条核心规则是什么？它同时兼顾了哪几类进程的需求？

### 参考答案

1. **FCFS**（按到达顺序 A→B→C→D）：

   | 进程 | 到达 | 服务 | 开始 | 完成 | 周转 | 带权周转 |
   |---|---|---|---|---|---|---|
   | A | 0 | 7 | 0 | 7 | 7 | 7/7 = 1 |
   | B | 2 | 4 | 7 | 11 | 9 | 9/4 = 2.25 |
   | C | 4 | 1 | 11 | 12 | 8 | 8/1 = **8** |
   | D | 5 | 4 | 12 | 16 | 11 | 11/4 = 2.75 |

   平均周转 = `(7+9+8+11)/4 = 35/4 = **8.75**`；平均带权周转 = `(1+2.25+8+2.75)/4 = 14/4 = **3.5**`。

   **非抢占 SJF**：0 时刻只有 A 到达 → 先跑 A（0–7）。7 时刻 B、C、D 都已就绪，服务时间 4、1、4 → 选 C（7–8）→ B 与 D 同为 4，先到的 B（8–12）→ D（12–16）。

   | 进程 | 到达 | 服务 | 开始 | 完成 | 周转 | 带权周转 |
   |---|---|---|---|---|---|---|
   | A | 0 | 7 | 0 | 7 | 7 | 1 |
   | C | 4 | 1 | 7 | 8 | 4 | 4 |
   | B | 2 | 4 | 8 | 12 | 10 | 2.5 |
   | D | 5 | 4 | 12 | 16 | 11 | 2.75 |

   平均周转 = `(7+10+4+11)/4 = 32/4 = **8**`；平均带权周转 = `(1+2.5+4+2.75)/4 = 10.25/4 = **2.5625**`。

   **结论**：SJF 的平均周转时间更短——在**所有进程同时到达**的前提下 SJF 是最优的；本题非同时到达，所以 SJF **不保证**最优（真正最优要用抢占式 SRTN）。408 常考这个措辞：「SJF 平均等待时间最短」这句话**必须加上"同时到达"的限定**。

2. | 指标 | 定义 |
   |---|---|
   | **周转时间** | 完成时间 − 到达时间 |
   | **带权周转时间** | 周转时间 ÷ 实际服务时间 |
   | **等待时间** | 周转时间 − 服务时间（进程在**就绪队列**等待的总时长） |
   | **响应时间** | 从提出请求到**首次**被响应（首次上 CPU）所用时间 |

   带权周转 ≥ 1 是因为**周转时间 = 服务时间 + 等待时间 ≥ 服务时间**，等待时间不可能为负。带权周转越接近 1，说明该进程等待占比越小、体验越好；短进程一旦等久了，带权周转会非常难看（本题 FCFS 下 C 的 8 就是典型），这正是带权周转比裸周转更能反映**短作业受不受委屈**的原因。

3. SJF 每次都选**当前就绪队列中服务时间最短**的进程。如果短进程持续到达，长进程就永远排不到队头 → **饥饿（starvation）**，极端情况长进程"饿死"。

   HRRN（最高响应比优先）在每次调度时计算：

   ```
   响应比 R = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 要求服务时间
   ```

   - 服务时间相同时，**等待越久 R 越大** → 兼顾了 FCFS 的公平
   - 等待时间相同时，**服务时间越短 R 越大** → 保留了 SJF 对短作业的偏好
   - 长作业等得越久 R 单调增长，**终会超过新来的短作业** → **不会饥饿**

   **陷阱**：HRRN 是**非抢占**的，只在进程主动放弃 CPU 时才重新计算响应比；且计算发生在**调度时刻**，不是每一时刻都算。

4. RR 的时间片 `q`：

   | q 的取值 | 后果 |
   |---|---|
   | **过大**（大于所有进程的运行时间） | 每个进程一个时间片就跑完 → **退化为 FCFS**，响应时间变长 |
   | **过小** | 进程切换过于频繁，**切换开销占比过高**，CPU 有效利用率骤降（极端情况系统忙于切换而不做事，即"颠簸") |

   经验准则：**时间片应使 80% 左右的进程能在一个时间片内完成一次 CPU 突发**，且切换开销控制在时间片的 1% 以内（典型值 10–100 ms）。
   **陷阱**：RR 是**唯一严格按时间片抢占**的算法，且它**只考虑公平不考虑作业长短**，因此**对短作业不友好**（短作业也要排队轮转），平均周转时间通常不如 SJF。

5. 多级反馈队列（MFQ）三条规则：
   1. 设置**多个就绪队列**，第 1 级优先级最高、**时间片最小**，级别越低优先级越低、时间片**成倍增长**。
   2. 新进程进**第 1 级队尾**。若在本级时间片内没跑完，**降入下一级队尾**；已在最低级则在该级内轮转（RR）。
   3. 仅当第 1 ~ i-1 级**全空**时才调度第 i 级；进程运行期间若有更高级队列**来了新进程**，立即被抢占并放回**原级队尾**。

   同时满足四类需求：

   | 需求 | 靠什么满足 |
   |---|---|
   | 短作业快速完成 | 短作业在高优先级的小时间片里就跑完了，近似 SJF |
   | I/O 密集型进程响应快 | 它们频繁主动放弃 CPU，**始终留在高优先级队列** |
   | CPU 密集型不被饿死 | 降级后仍能在低级队列轮转到（可再加"定期提升"防饥饿） |
   | 无需预知运行时间 | 靠**观察实际行为**动态调整，这是它相对 SJF 最大的工程优势 |

   **工程对照**：Linux O(1) 调度器就是 MFQ 的实现；CFS/EEVDF 改用红黑树 + 虚拟运行时间，思路不同但目标一致，见 [linux/](../../linux/INDEX.md)。

## OS04 同步与互斥

1.（简答）临界区问题的四个原则是什么？「双标志先检查法」违反了哪一条？「双标志后检查法」和「Peterson 算法」各违反哪条？
2.（设计）用信号量写出**单生产者-单消费者**问题的完整解法，并解释为什么互斥信号量的 `P` 必须放在同步信号量的 `P` **之后**。
3.（设计）写出**读者-写者问题（读优先）**的信号量解法，并说明写进程为什么可能饥饿、怎么改成写优先。
4.（简答）哲学家进餐问题的死锁是怎么产生的？给出三种不同的解决思路。
5.（简答）管程与信号量的关系是什么？条件变量的 `wait`/`signal` 与信号量的 `P`/`V` 有什么本质区别？

### 参考答案

1. 四原则：**空闲让进、忙则等待、有限等待、让权等待**。

   | 方案 | 违反的原则 | 原因 |
   |---|---|---|
   | 单标志法 | **空闲让进** | 必须两个进程交替进入，一个不想进时另一个也进不去 |
   | 双标志**先检查** | **忙则等待** | 检查与置位之间可能被切换，两个进程都通过检查 → 同时进临界区 |
   | 双标志**后检查** | **空闲让进 + 有限等待** | 先都置位再检查 → 都以为对方要进 → **谁也进不去（活锁）** |
   | Peterson | **让权等待** | 逻辑正确（前三条都满足），但落选者在 `while` 里**忙等**空转，不释放 CPU |
   | 中断屏蔽 | 只适用单处理机 | 关中断期间该 CPU 不切换，但**多核下其他核照跑** |
   | TSL / Swap | **让权等待** | 硬件保证了原子性，但仍是忙等自旋 |

   **速记**：软件方案没有一个能同时满足四条；**只有信号量机制四条全满足**（用阻塞队列实现了让权等待）。

2. ```go
   // 三个信号量：
   //   empty = n  空闲缓冲区数量（同步）
   //   full  = 0  产品数量（同步）
   //   mutex = 1  缓冲区互斥访问（互斥）

   // 生产者
   for {
       生产一个产品
       P(empty)     // ① 先申请空位
       P(mutex)     // ② 再申请互斥
       放入缓冲区
       V(mutex)
       V(full)
   }

   // 消费者
   for {
       P(full)      // ① 先申请产品
       P(mutex)     // ② 再申请互斥
       从缓冲区取出
       V(mutex)
       V(empty)
       消费产品
   }
   ```

   **为什么 `P(mutex)` 必须在后**：假设生产者写成 `P(mutex); P(empty);`，当缓冲区已满时——
   - 生产者拿到了 `mutex`，然后卡在 `P(empty)` 上阻塞；
   - 消费者想取产品，执行 `P(full)` 通过，却卡在 `P(mutex)` 上（锁被生产者攥着）；
   - 生产者等消费者腾空位，消费者等生产者放锁 → **循环等待，死锁**。

   **通用规则**：**同步信号量的 P 在前，互斥信号量的 P 在后；V 操作顺序无所谓**（V 不会阻塞，不可能造成死锁）。这是 408 PV 大题的第一得分点。
   Go 对照：`chan` 天然把 empty/full/mutex 三者合一——`ch := make(chan T, n)` 的发送/接收就是上面这段的封装，所以 Go 写生产者消费者不会踩这个坑。

3. ```go
   // count  = 0  当前读者数量
   // mutex  = 1  保护 count
   // rw     = 1  保证读写互斥、写写互斥

   // 写者
   P(rw)
   写文件
   V(rw)

   // 读者
   P(mutex)
   if count == 0 { P(rw) }   // 第一个读者负责"上锁"
   count++
   V(mutex)
   读文件
   P(mutex)
   count--
   if count == 0 { V(rw) }   // 最后一个读者负责"开锁"
   V(mutex)
   ```

   **写者饥饿的原因**：只要读者源源不断地来，`count` 永不归零 → `rw` 永不释放 → 写者一直阻塞在 `P(rw)`。这个版本叫**读优先**。

   **改成写优先（读写公平）**：增设一个信号量 `w = 1`，读者与写者进入前都先 `P(w)`：

   ```go
   // 写者：P(w); P(rw); 写; V(rw); V(w)
   // 读者：P(w); P(mutex); if count==0 {P(rw)}; count++; V(mutex); V(w); 读; ...
   ```

   写者一旦执行 `P(w)` 成功，后续到达的读者都会堵在 `P(w)` 上，**已在读的读者读完后写者即可进入** → 写者最多等一批读者，不会饿死。
   **陷阱**：读者代码里 `V(w)` 的位置要在**读文件之前**——否则读者之间又变成互斥的了，失去并发读的意义。

4. **死锁产生**：五位哲学家同时拿起**左边**的筷子，此时每人各持一根、都在等右边那根 → 四个必要条件全部满足（互斥、占有并等待、不可剥夺、循环等待）。

   三种解法：

   | 思路 | 做法 | 破坏的条件 |
   |---|---|---|
   | **限制人数** | 最多允许 4 位哲学家同时**尝试**取筷子（设信号量 `count = 4`） | 循环等待（5 根筷子分给 4 人，必有一人能拿到两根） |
   | **奇偶分组** | 奇数号先拿左、偶数号先拿右 | 循环等待（打破了同向环） |
   | **原子取双** | 用互斥信号量把「拿左 + 拿右」包成一个不可分割的操作，两根都可用才拿 | 占有并等待 |

   ```go
   // 解法三（原子取双）
   P(mutex)
   P(chopstick[i])            // 左
   P(chopstick[(i+1) % 5])    // 右
   V(mutex)
   进餐
   V(chopstick[i]); V(chopstick[(i+1) % 5])
   ```

   **陷阱**：`V` 操作**不能**放在 `mutex` 保护区内——那会让整个进餐过程串行化，五个人排队吃饭，失去并发。

5. **管程 = 一组共享数据 + 一组操作这些数据的过程 + 初始化代码**，它把同步逻辑从"散落在各进程里的 PV 调用"收拢到一个语言级模块中。

   | 维度 | 信号量 | 管程 |
   |---|---|---|
   | 互斥由谁保证 | **程序员**手工配对 P/V，写错就死锁 | **编译器 / 运行时自动**保证同一时刻只有一个进程在管程内 |
   | 同步机制 | 信号量本身 | **条件变量** + `wait`/`signal` |
   | 出错风险 | 高（P/V 顺序、漏写 V） | 低 |
   | 层次 | 低级同步原语 | **高级**（语言级）同步机制 |

   `wait`/`signal` 与 `P`/`V` 的三点本质区别：

   1. **条件变量没有值**，只有一个等待队列；信号量有整数值，记录可用资源数。
   2. `wait(c)` **一定**阻塞当前进程并释放管程；`P(s)` 只在 `s ≤ 0` 时才阻塞。
   3. `signal(c)` 在**没有进程等待时什么也不做（信号丢失）**；`V(s)` **一定**把 `s` 加 1，这个"1"会被后来的 `P` 取走（信号被记住）。

   **工程对照**：Go 的 `sync.Cond` 就是条件变量，其 `Wait()` 必须放在 `for` 循环里重新检查条件——正因为 `Signal()` 可能丢失、也可能有虚假唤醒。Java 的 `synchronized` + `wait/notify` 是管程的直接实现（Hoare 管程的 Mesa 变体）。

## OS05 死锁

1.（计算）系统有 5 个进程 P0–P4、3 类资源 A(10) B(5) C(7)，某时刻状态如下（Available = (3, 3, 2)）：

   | 进程 | Allocation (A,B,C) | Max (A,B,C) |
   |---|---|---|
   | P0 | 0, 1, 0 | 7, 5, 3 |
   | P1 | 2, 0, 0 | 3, 2, 2 |
   | P2 | 3, 0, 2 | 9, 0, 2 |
   | P3 | 2, 1, 1 | 2, 2, 2 |
   | P4 | 0, 0, 2 | 4, 3, 3 |

   ① 求 Need 矩阵，判断当前状态是否安全并给出安全序列；② 若 P1 请求 `(1, 0, 2)`，能否分配？

2.（简答）死锁的四个必要条件是什么？破坏每一条各要付出什么代价？
3.（计算）系统中有 n 个进程，每个进程最多需要 m 个同类资源。若系统的该类资源总数为 `R`，则**保证不会死锁**的最小 `R` 是多少？举例：3 个进程各最多需要 4 个，至少要几个资源？
4.（简答）死锁、饥饿、死循环三者有什么区别？
5.（简答）资源分配图化简法怎么判断死锁？死锁定理是什么？

### 参考答案

1. **① Need = Max − Allocation**：

   | 进程 | Allocation | Max | **Need** |
   |---|---|---|---|
   | P0 | 0,1,0 | 7,5,3 | **7,4,3** |
   | P1 | 2,0,0 | 3,2,2 | **1,2,2** |
   | P2 | 3,0,2 | 9,0,2 | **6,0,0** |
   | P3 | 2,1,1 | 2,2,2 | **0,1,1** |
   | P4 | 0,0,2 | 4,3,3 | **4,3,1** |

   安全性检查（Work 初值 = Available = (3,3,2)）：

   | 步骤 | Work | 可满足的进程 | 回收其 Allocation 后 Work |
   |---|---|---|---|
   | 1 | 3,3,2 | **P1**（Need 1,2,2 ≤ Work） | 3+2, 3+0, 2+0 = **5,3,2** |
   | 2 | 5,3,2 | **P3**（0,1,1 ≤） | **7,4,3** |
   | 3 | 7,4,3 | **P4**（4,3,1 ≤） | **7,4,5** |
   | 4 | 7,4,5 | **P0**（7,4,3 ≤） | **7,5,5** |
   | 5 | 7,5,5 | **P2**（6,0,0 ≤） | **10,5,7** = 系统总量 ✅ |

   所有进程都能加入序列 → **当前状态安全**，安全序列 **P1 → P3 → P4 → P0 → P2**（不唯一，如 P1→P3→P0→P2→P4 也可）。

   **② P1 请求 (1,0,2)**，三步检查：
   - `Request(1,0,2) ≤ Need(1,2,2)` ✅（没超过声明的最大需求）
   - `Request(1,0,2) ≤ Available(3,3,2)` ✅（资源够）
   - **试探性分配**：Available → (2,3,0)，P1 的 Allocation → (3,0,2)，Need → (0,2,0)

   再做安全性检查：Work=(2,3,0) → P1（Need 0,2,0 ≤）✅ → Work=(5,3,2) → P3 ✅ → (7,4,3) → P4 ✅ → (7,4,5) → P0 ✅ → (7,5,5) → P2 ✅。
   存在安全序列 **P1→P3→P4→P0→P2** → **可以分配**，正式提交这次分配。

   **陷阱**：银行家算法的三步检查**顺序不能乱**，且第三步必须是**试探性**的——若试探后不安全，要**恢复原状**并让进程等待。另外「不安全状态 ≠ 死锁」，只是**可能**演变成死锁。

2. | 必要条件 | 含义 | 破坏方式与代价 |
   |---|---|---|
   | **互斥** | 资源同一时间只能被一个进程使用 | 用 SPOOLing 把独占设备改造成共享设备。**代价**：大多数资源（打印机、临界区）**本质上就是互斥的**，无法破坏 |
   | **不可剥夺** | 已分配的资源不能被强行抢走 | 申请新资源失败时**主动释放已有资源**，或由高优先级进程抢占。**代价**：实现复杂，前期工作作废，**反复申请释放可能导致饥饿** |
   | **请求并保持** | 已持有资源的同时申请新资源 | **静态分配**：运行前一次性申请全部资源。**代价**：**资源利用率极低**（用一次的资源全程占着），且可能饥饿（大需求进程凑不齐） |
   | **循环等待** | 存在进程-资源的循环等待链 | **顺序资源分配法**：给资源编号，进程只能按**序号递增**申请。**代价**：编号一旦定死难以增删设备，用户编程必须遵守顺序，**可能造成资源浪费**（先用高号资源的进程要提前占低号） |

   **陷阱**：四个条件是死锁的**必要**条件（都满足才可能死锁），不是充分条件；**只有在资源分配图中每类资源只有一个实例时，环路才是死锁的充要条件**。

3. **最坏情况分析**：让每个进程都"差一个"——每个进程各拿到 `m-1` 个资源，此时无人能推进，需要总量 `n(m-1)`。若系统再多出 **1** 个资源，就一定能让某个进程凑满 `m` 个、跑完并释放全部资源，进而带动其余进程。

   ```
   R ≥ n(m - 1) + 1
   ```

   例：`n = 3, m = 4` → `R ≥ 3 × 3 + 1 = **10**`。
   **变式（同样高频）**：已知资源总数 `R`、每进程最多需 `m`，求**最多能有几个进程不死锁** → `n ≤ (R - 1)/(m - 1)` 向下取整。
   **陷阱**：题目问的是「**保证**不死锁」（最坏情况）还是「**可能**不死锁」（最好情况）——后者只需 `R ≥ m`（一个一个串行跑）。看清措辞。

4. | | 死锁 | 饥饿 | 死循环 |
   |---|---|---|---|
   | 本质 | 多个进程**互相等待对方持有的资源** | 某进程长期得不到资源，但系统整体在推进 | 代码逻辑错误，一直执行同一段指令 |
   | 涉及进程数 | **至少 2 个** | **可以只有 1 个** | 1 个 |
   | 进程状态 | **阻塞态**（不占 CPU） | 阻塞或就绪 | **运行态**（占着 CPU 空转） |
   | 归属 | 操作系统资源管理问题 | 操作系统调度策略问题 | **程序员的 bug**，OS 无责 |
   | 例子 | 哲学家同时拿左筷子 | SJF 中的长作业、写者-读者中的写者 | `while(1);` |

   **速记**：死锁的进程**都在睡觉**，死循环的进程**在拼命干活但没意义**；死锁是**系统的错**，死循环是**程序员的错**。

5. **化简步骤**：
   1. 在资源分配图中找一个**既不阻塞又非孤立**的进程结点（它申请的资源都还有富余，能继续运行）。
   2. 消去该结点的**全部**请求边与分配边，使之成为**孤立结点**（相当于让它跑完并释放资源）。
   3. 释放的资源可能让其他进程从阻塞变为可满足，回到步骤 1 重复。

   **死锁定理**：**当且仅当资源分配图不可完全简化（化简后仍有非孤立结点）时，系统处于死锁状态**；能完全简化则无死锁。

   两个易错点：
   - **化简顺序不影响最终结论**——不管先消哪个可满足的进程，最后是否能完全简化是确定的。
   - **有环 ≠ 死锁**。只有**每类资源仅一个实例**时，"有环"才等价于死锁；多实例情况下有环也可能被化简掉（另一个实例被别的进程释放了）。

4.（计算）页面大小 1KB，某进程页表为 `0→2号帧, 1→5号帧, 2→8号帧`。求逻辑地址 `2500` 对应的物理地址。若访问逻辑地址 `4000` 会发生什么？
5.（简答）分页与分段有哪五点区别？段页式的一次访存要访问几次内存，怎么优化？
6.（计算+简答）① 某程序的调用结构为：主程序 A(8KB) 调用 B(8KB) 与 C(10KB)；B 调用 D(12KB) 与 E(4KB)；C 调用 F(6KB)。采用覆盖技术后至少需要多少内存？② 交换技术把进程换到外存的哪个区域，该区域为什么用连续分配？③ 交换时 PCB 要不要一起换出？

### 参考答案

1. - **内部碎片**：分配给进程的空间中**进程用不完**的那部分（在分区**内部**浪费）。
   - **外部碎片**：内存中**存在但太小以致无法利用**的空闲区（在分区**之间**浪费）。

   | 分配方式 | 碎片类型 | 原因 |
   |---|---|---|
   | 固定分区 | **内部** | 分区大小固定，进程装不满 |
   | 动态分区 | **外部** | 按需切割，反复分配释放后留下大量小空隙 |
   | **分页** | **内部** | 最后一页通常装不满（平均浪费半页） |
   | **分段** | **外部** | 段长可变，本质上就是动态分区 |
   | 段页式 | **内部** | 段内再分页，只有每段的最后一页有浪费 |

   **速记**：**固定大小 → 内部碎片；可变大小 → 外部碎片**。分页是固定大小的框，所以是内部；分段按逻辑划分长度不一，所以是外部。
   外部碎片可用**紧凑（拼接）技术**解决，但要求**动态重定位**（有重定位寄存器），且移动内存开销很大。

2. **首次适应（First Fit，从低地址开始找第一个够用的）**：

   | 请求 | 分到哪块 | 分配后 |
   |---|---|---|
   | 12KB | 20KB（起址 100） | 剩 8KB（起址 112） |
   | 10KB | 10KB（起址 300） | 剩 0，该块被完全用掉 |
   | 9KB | 15KB（起址 500） | 剩 6KB（起址 509） |

   剩余空闲：`[8KB, 112] [6KB, 509] [9KB, 700]`

   **最佳适应（Best Fit，找能容纳的最小块）**：

   | 请求 | 候选块 | 选中 | 分配后 |
   |---|---|---|---|
   | 12KB | 20KB / 15KB | **15KB**（最小的够用块） | 剩 3KB（起址 512） |
   | 10KB | 20KB / 10KB | **10KB** | 剩 0 |
   | 9KB | 20KB / 9KB | **9KB** | 剩 0 |

   剩余空闲：`[20KB, 100] [3KB, 512]`

   **对比结论**：
   - 首次适应实现最简单、**综合表现最好**（408 与实测都是这个结论），低地址区被反复切割是它的缺点。
   - 最佳适应**每次留下最小的余块** → 制造大量无法利用的**小碎片**，看似"最佳"其实碎片最严重。
   - 最坏适应总切最大块 → **大块很快被耗尽**，大进程无处安身。
   - 邻近适应（首次适应的变体，从上次结束位置继续找）→ 让高地址的大块也被切碎，**通常还不如首次适应**。

3. ① 页面 4KB = 2¹² → **页内偏移 12 位**；32 − 12 = **页号 20 位**。
   ② 页表项数 = 2²⁰ = 1 048 576 个，每项 4B → **4MB**。（**这就是引入多级页表的直接动机**：每个进程都要 4MB 页表且必须连续存放，几十个进程就撑不住了。）
   ③ 4KB ÷ 4B = **1024 = 2¹⁰ 个**。
   ④ 20 位页号按"一个页面正好装 1024 项"拆成两半：

   ```
   ┌──────────┬──────────┬──────────────┐
   │ 一级页号  │ 二级页号  │  页内偏移     │
   │  10 位   │  10 位   │    12 位      │
   └──────────┴──────────┴──────────────┘
   ```

   **拆分口诀**：**从后往前拆**——先定页内偏移（由页面大小决定），再让每一级页表**恰好占一个页面**（由「一页能装多少项」决定），剩下的位给最高级。
   代价：两级页表要**三次访存**（查一级页表 → 查二级页表 → 访问数据），靠 **TLB** 把常见情况压回一次。

4. 页面 1KB = 1024B。
   - 页号 = `2500 / 1024 = 2`，页内偏移 = `2500 % 1024 = 2500 - 2048 = 452`
   - 查页表：2 号页 → **8 号物理帧**
   - 物理地址 = `8 × 1024 + 452 = 8192 + 452 = **8644**`

   访问逻辑地址 `4000`：页号 = `4000 / 1024 = 3`，而页表长度只有 3（页号 0~2）→ **页号 ≥ 页表长度，越界** → 硬件产生**地址越界中断（越界故障）**，操作系统终止该进程。

   **陷阱**：地址变换的第一步永远是**用页表长度寄存器检查页号是否越界**，然后才是查页表。408 大题若漏掉越界检查会扣分。另外要区分「**越界中断**」（页号超出页表长度，进程有错）和「**缺页中断**」（页号合法但页不在内存，正常现象）。

5. | 维度 | 分页 | 分段 |
   |---|---|---|
   | **划分依据** | 由**硬件/系统**按固定大小机械划分 | 由**用户/编译器**按**逻辑功能**划分（代码段、数据段、栈段） |
   | **对用户是否可见** | **透明**，用户看到的是一维地址空间 | **可见**，用户地址是二维的（段号 + 段内偏移） |
   | **长度** | 固定（页面大小由系统定） | **可变**（由逻辑模块大小决定） |
   | **碎片** | 内部碎片 | 外部碎片 |
   | **共享与保护** | 不便（一个页面里可能混着代码与数据） | **方便**（整段共享，权限按段设置） |

   **段页式的访存次数**：① 查**段表**得页表基址 → ② 查**页表**得帧号 → ③ 访问**数据** = **3 次访存**。
   优化手段：**快表 TLB**。TLB 命中时（段号+页号 → 帧号一步到位）只需 **1 次**访存。命中率通常 > 95%，所以有效访问时间接近一次访存。
   **陷阱**：题目问"访存几次"时要看清是否**有快表、快表是否命中**，以及页表本身是否在内存（请求分页下还可能缺页）。

6. **① 覆盖技术的最小内存**：

   | 区域 | 内容 | 大小 |
   |---|---|---|
   | **固定区** | 主程序 A（全程需要） | **8 KB** |
   | **覆盖区 1** | B 与 C（同层兄弟，不同时调用） | `max(8, 10) = **10 KB**` |
   | **覆盖区 2** | D、E、F（分属不同分支，不同时使用） | `max(12, 4, 6) = **12 KB**` |

   **总计 = 8 + 10 + 12 = 30 KB**（不用覆盖需要 `8+8+10+12+4+6 = 48 KB`）。
   **解题三步**：找出全程需要的部分作固定区 → **按调用树的层次分组** → 每层取**最大值**后全部相加。

   **② 换到「对换区」，用连续分配的原因**：磁盘分成**文件区**与**对换区**，两者的**管理目标不同**——

   | | 文件区 | **对换区** |
   |---|---|---|
   | 目标 | **提高空间利用率** | **提高换入换出速度** |
   | 分配方式 | 离散分配（链接 / 索引） | **连续分配** |

   换入换出直接发生在进程等待期间，**直接影响响应时间**，所以对换区不惜浪费空间也要用连续分配——**一次寻道就能读完整个进程映像**。而文件长期驻留，碎片浪费不可接受，故用离散分配。

   **③ PCB 不能换出，必须常驻内存**。因为操作系统要**随时通过 PCB 知道这个进程的状态、以及它被换到了外存的什么位置**；连 PCB 都换走，OS 就"忘记"了这个进程的存在。
   **陷阱**：选择题里的「交换时把进程的**全部内容**换出到外存」是错的。
   顺带记住三者的演化：**覆盖**（手动、按段、进程内、不透明、已淘汰）→ **交换**（自动、按进程、进程间、透明）→ **虚拟内存**（自动、按页、两者兼顾）——粒度越来越细，自动化程度越来越高。

## OS07 虚拟内存

1.（计算）页面访问串 `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`，物理块数为 3（初始全空）。分别求 **OPT、FIFO、LRU** 的缺页次数（含最初的调入）。
2.（简答）什么是 Belady 异常？举一个具体的访问串说明。为什么 LRU 和 OPT 不会出现 Belady 异常？
3.（简答）CLOCK 算法怎么工作？改进型 CLOCK 用哪两个位、最多扫描几轮？
4.（简答）缺页中断属于哪一类中断？处理流程是什么？处理完后返回哪条指令？
5.（简答）什么是抖动（颠簸）？成因是什么？工作集模型怎么解决它？

### 参考答案

1. **OPT（最佳置换，替换将来最久不用的）= 9 次缺页**

   前 3 次（7、0、1）填满物理块；后续关键替换：`2` 替 7、`3` 替 1、`4` 替 0、`0` 替 4、`1` 替 3、`7` 替 2 —— 共 `3 + 6 = **9** 次`。

   **FIFO（先进先出）= 15 次缺页**

   | 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 | 1 | 2 | 0 | 1 | 7 | 0 | 1 |
   |---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
   | 缺页 | ✗ | ✗ | ✗ | ✗ | | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | | | ✗ | ✗ | | | ✗ | ✗ | ✗ |

   合计 **15 次**。

   **LRU（最近最久未使用）= 12 次缺页**

   | 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 | 1 | 2 | 0 | 1 | 7 | 0 | 1 |
   |---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
   | 缺页 | ✗ | ✗ | ✗ | ✗ | | ✗ | | ✗ | ✗ | ✗ | ✗ | | | ✗ | | ✗ | | ✗ | | |

   合计 **12 次**。

   **结论**：`OPT(9) < LRU(12) < FIFO(15)`。OPT 是理论下界（需要预知未来，**不可实现**，只用作评价其他算法的标尺）；LRU 是对 OPT 的"用过去预测未来"式逼近，**性能最接近 OPT 但实现开销大**（要维护访问时间戳或栈）。
   **答题技巧**：画表格逐列填，每列写出三个块的内容 + 是否缺页，**千万别心算**。

2. **Belady 异常**：**增加物理块数反而导致缺页次数上升**的反常现象。

   经典访问串 `1 2 3 4 1 2 5 1 2 3 4 5`：
   - **3 个物理块 + FIFO → 9 次缺页**
   - **4 个物理块 + FIFO → 10 次缺页** ← 块数变多反而更差

   **根因**：FIFO 的置换依据（进入时间）与页面的**未来使用可能性完全无关**，物理块变多会改变淘汰顺序，可能恰好把马上要用的页淘汰掉。

   **LRU / OPT 不会有 Belady 异常**，因为它们属于**栈式算法（stack algorithm）**：满足**包含性质**——`n` 个物理块时驻留的页面集合，**必定是 `n+1` 个物理块时驻留集合的子集**。既然大集合包含小集合，大集合能命中的一定不少于小集合，缺页次数不可能上升。
   **速记**：**只有 FIFO 有 Belady 异常**（CLOCK 作为 FIFO 的改良版，理论上也可能出现）。

3. **CLOCK（最近未用 NRU / 二次机会）**：
   - 每个页面配一个**访问位** `A`。页面被访问时硬件置 `A = 1`。
   - 所有页面组成**循环队列**，指针从当前位置向前扫描：
     - 遇到 `A = 0` → **选它淘汰**，指针停在下一个位置
     - 遇到 `A = 1` → **置为 0，给一次"缓刑"**，继续往前扫
   - 最多扫描 **2 轮**必定找到（第一轮全清零，第二轮必遇 0）。

   **改进型 CLOCK** 增加**修改位** `M`，用 `(A, M)` 二元组分四类，扫描顺序：

   | 轮次 | 找什么 | 含义 | 是否修改访问位 |
   |---|---|---|---|
   | 第 1 轮 | `(0, 0)` | 最近没用过、也没改过 —— **最理想** | 否 |
   | 第 2 轮 | `(0, 1)` | 最近没用过但改过 —— 淘汰要**写回磁盘** | **扫过的置 A=0** |
   | 第 3 轮 | `(0, 0)` | 第 2 轮清零后重找 | 否 |
   | 第 4 轮 | `(0, 1)` | 仍找不到就退而求其次 | — |

   **最多扫描 4 轮**。核心思想是**优先淘汰不需要写回磁盘的页面**，因为一次磁盘写的代价远大于多扫一圈内存。
   **工程对照**：Linux 的页面回收（PFRA）用的就是 CLOCK 的变体（活跃/非活跃双 LRU 链表），Redis 的 `maxmemory-policy allkeys-lru` 也是近似 LRU 而非精确 LRU——**精确 LRU 太贵，工程上一律用近似算法**，这与 408 的结论一致。

4. 缺页中断属于**内中断（异常）中的「故障 Fault」**——它在**指令执行过程中**由 MMU 检测到（页表项有效位为 0）而产生，且**可以恢复**。

   完整处理流程：
   1. MMU 发现页表项的**存在位/有效位 = 0** → 产生缺页中断，CPU 转入内核态
   2. 操作系统的**缺页中断处理程序**接管，保存现场
   3. 检查**是否有空闲物理块**：
      - 有 → 直接分配
      - 无 → 用**页面置换算法**选一个页淘汰；若该页**修改位 = 1**，先**写回外存**（脏页回写），再腾出块
   4. 从**外存（对换区 / 文件区）读入所需页面**——这是一次**磁盘 I/O，进程被阻塞**
   5. I/O 完成后修改页表项（填帧号、置存在位 = 1、置访问位），若有快表则**更新 TLB**
   6. 恢复现场，进程回到就绪队列

   **返回哪条指令**：**引发缺页的那一条指令，重新执行**。这是「故障」类异常的定义特征——因为该指令根本没执行成功（操作数还没取到），必须重来。
   **对比记忆**：陷阱（系统调用）返回**下一条**，故障（缺页、除零）返回**当前这条**，终止**不返回**。

5. **抖动（Thrashing / 颠簸）**：进程**大部分时间都在换页而不是执行指令**——刚换出的页面马上又要用、马上又换入，CPU 利用率急剧下降。

   **成因**：
   - 直接原因：**分配给进程的物理块数 < 进程当前活跃使用的页面数**，导致每次访问几乎都缺页。
   - 系统级放大：多道程序度过高 → 每个进程分到的块更少 → 缺页更多 → CPU 因等 I/O 而空闲 → **调度程序误以为"CPU 不忙，再多调入几个进程"** → 恶性循环。这是 408 最爱考的**正反馈崩溃链条**。

   **工作集模型**：
   - 定义：**工作集 W(t, Δ)** = 在时刻 `t` 之前的 `Δ` 个时间单位（**窗口尺寸**）内，进程实际访问过的页面集合。
   - 依据：**局部性原理**——工作集近似等于进程"当前真正需要"的页面。
   - 做法：操作系统**监测每个进程的工作集大小，为其分配不少于工作集大小的物理块**；当所有进程的工作集之和超过物理内存总量时，**挂起（换出）一部分进程**，降低多道程序度。

   **陷阱**：窗口尺寸 `Δ` 太小 → 工作集偏小 → 仍会抖动；`Δ` 太大 → 包含已过时的页面 → 浪费内存。工作集**通常取"页面数"而不是"具体哪些页"**用于分配决策。
   相关手段还有**缺页率（PFF）控制**：缺页率过高就多给块、过低就回收块，比工作集更易实现。

## OS08 文件管理

1.（计算）UNIX 混合索引：盘块大小 **1KB**，每个盘块地址占 **4B**，inode 中有 **10 个直接地址**、**1 个一级间址**、**1 个二级间址**、**1 个三级间址**。求：① 一个间址块能存多少个地址；② 可表示的最大文件长度；③ 访问文件第 `100KB` 处的数据需要几次磁盘读（不含数据块本身）？
2.（简答）连续分配、链接分配（隐式 / 显式 FAT）、索引分配三种物理分配方式各有什么优缺点？哪些支持高效随机访问？
3.（简答）硬链接与软链接在 inode 层面有什么区别？删除源文件后两者分别会怎样？
4.（计算）用位示图管理空闲盘块，字长 32 位，字号与位号均从 0 开始，盘块号也从 0 开始。① 盘块号 100 对应哪个字的哪一位？② 字号 5、位号 7 对应哪个盘块？
5.（简答）目录结构从单级演进到无环图各解决了什么问题？为什么现代文件系统要把 FCB 拆成「目录项（文件名 + inode 号）」与「inode（其余属性）」两部分？
6.（简答）① 画出一个分区在磁盘上的典型布局，说明超级块存了什么；② 创建文件与删除文件各做了哪些事？③ VFS 是什么、解决什么问题、它的四大对象分别代表什么？

### 参考答案

1. ① 一个盘块 1KB = 1024B，每个地址 4B → **1024 / 4 = 256 个地址**。

   ② 最大文件长度：

   | 部分 | 可寻址盘块数 | 容量 |
   |---|---|---|
   | 10 个直接地址 | 10 | 10 KB |
   | 一级间址 | 256 | 256 KB |
   | 二级间址 | 256² = 65 536 | **64 MB** |
   | 三级间址 | 256³ = 16 777 216 | **16 GB** |

   **总计 ≈ 16 GB + 64 MB + 256 KB + 10 KB ≈ 16.06 GB**（严格值 `16 843 018 KB`）。

   ③ 第 100KB 处 → 逻辑块号 `100 / 1 = 100`（第 100 块，从 0 计则是第 100 号块）。
   - 直接地址覆盖块号 **0 ~ 9**
   - 一级间址覆盖块号 **10 ~ 265**（10 + 256 − 1）
   - 100 落在一级间址范围内 → 需要**先读一级间址块（1 次）**，从中取出块地址，再读数据块。

   **不含数据块本身则为 1 次**；若 inode 也不在内存还要 +1。
   **陷阱**：这类题必须**先算出各级覆盖的块号区间**再判断落点，且要看清题目问的是"几次磁盘访问"（含数据块）还是"几次间址块读取"（不含）。另外注意单位：**块号从 0 还是 1 开始**、盘块大小是 1KB 还是 4KB，一个都不能错。

2. | 方式 | 优点 | 缺点 | 随机访问 |
   |---|---|---|---|
   | **连续分配** | 顺序读写**最快**（磁头移动最少）；支持随机访问，寻址公式 `物理块号 = 起始块号 + 逻辑块号` | 产生**外部碎片**；**文件难以动态增长**（后面被占了就得整体搬迁）；必须预知文件大小 | ✅ **最好** |
   | **隐式链接** | 无外部碎片；文件可任意增长 | **只能顺序访问**——找第 i 块必须从头读 i 次；每块要拿出几字节存指针；**任何一个指针损坏则后续全丢** | ❌ |
   | **显式链接（FAT）** | 把所有指针集中到**内存中的 FAT 表**，查链不用访问磁盘 → **支持随机访问**；无外部碎片 | **FAT 表要常驻内存**，占空间且随磁盘增大而膨胀（这是 FAT32 单文件 4GB 上限之外的另一硬伤） | ✅ |
   | **索引分配** | 支持**随机访问**；文件可动态增长；无外部碎片 | 每个文件要额外一个**索引块**（小文件浪费明显）；大文件需要**链接 / 多级 / 混合索引**扩展 | ✅ |

   **速记**：**隐式链接是唯一不支持随机访问的**——这是必考点。UNIX 选混合索引，是因为它对小文件（直接地址即可，零额外开销）和大文件（三级间址支持到 TB 级）都友好。

3. | 维度 | 硬链接（Hard Link） | 软链接 / 符号链接（Symbolic Link） |
   |---|---|---|
   | 本质 | **多个目录项指向同一个 inode** | **一个独立的文件**，其内容是**目标文件的路径字符串** |
   | inode | **共用同一个 inode**，inode 中的**链接计数 +1** | **有自己的 inode**（类型标记为 symlink） |
   | 跨文件系统 | ❌ 不行（inode 号只在本文件系统内唯一） | ✅ 可以 |
   | 能否指向目录 | ❌ 一般禁止（会造成目录环，破坏无环图） | ✅ 可以 |
   | 访问开销 | 与原文件完全相同 | 多一次**路径解析** |

   **删除源文件后**：
   - **硬链接**：只是把 inode 的**链接计数减 1**，计数 > 0 时文件数据**依然存在**，通过硬链接照常访问。**只有计数归 0 且无进程打开时才真正回收盘块**。
   - **软链接**：源文件删了，链接文件还在，但指向的路径已失效 → 变成**悬空链接（dangling link）**，访问时报"文件不存在"。

   **陷阱**：`rm` 删除的从来不是"文件"，而是**目录项 + inode 链接计数减一**——这解释了为什么删除大文件很快（不清数据块内容），也解释了为什么「删了文件但磁盘空间没释放」（还有进程持有打开的文件描述符，计数未归零）。

4. 位示图中，**盘块号 `b`、字号 `i`、位号 `j`** 的换算（字长 `L = 32`，三者均从 0 开始）：

   ```
   b = i × L + j
   i = b / L   （整除）
   j = b % L
   ```

   ① `b = 100` → `i = 100 / 32 = 3`，`j = 100 % 32 = 4` → **字号 3、位号 4**。
   ② `i = 5, j = 7` → `b = 5 × 32 + 7 = **167**`。

   **陷阱（几乎必踩）**：题目若说**字号和位号从 1 开始**，公式要改成 `b = (i - 1) × L + (j - 1)`；若**盘块号也从 1 开始**则再 `+1` → `b = (i-1)×L + j`。**做题第一步永远是圈出"从 0 还是从 1 开始"**。
   分配流程：顺序扫描位示图找为 0 的位 → 换算成盘块号 → **置该位为 1**；回收则是**反向换算后置 0**。位示图的优点是**便于连续分配**（找连续的 0 位串很方便）。

5. **目录结构演进**：

   | 结构 | 解决的问题 | 遗留问题 |
   |---|---|---|
   | 单级目录 | 实现了"按名存取" | **不允许重名**；多用户下检索慢 |
   | 两级目录（主目录 + 用户目录） | **不同用户可以重名**；提高了检索效率 | 同一用户内不能重名；**无法对文件分类** |
   | 树形目录 | 支持任意层次分类、绝对/相对路径、当前目录 | **不便于文件共享**（一个文件只能挂在一个位置） |
   | **无环图目录** | 用**链接**让多个目录指向同一文件，实现**共享**；用**共享计数器**决定何时真正删除 | 必须保证**无环**（否则引用计数永远不为 0，形成垃圾），删除逻辑变复杂 |

   **FCB 拆分成目录项 + inode 的理由**：
   - 目录检索时，**只需要"文件名 → 找到对应记录"这一个信息**，其余属性（权限、时间戳、盘块地址表）在检索过程中根本用不上。
   - 拆分后目录项极小（Linux 中约 8~16B：文件名 + inode 号），**一个盘块能装下的目录项数量提升数十倍** → 读取一个目录只需极少次磁盘 I/O → **检索速度大幅提升**。
   - 附带好处：inode 独立后，**多个目录项可以指向同一个 inode**，这正是**硬链接的实现基础**。

   工程细节见 [linux/](../../linux/INDEX.md) 的 VFS 与 ext4 章节。

6. **① 分区的外存布局**：

   ```
   ┌──────┬───────────────────────────────────────────────────────────┐
   │ MBR  │  分区 1  │  分区 2  │ ...                                  │
   └──────┴───────────────────────────────────────────────────────────┘
     ↑ 整盘唯一，0 号扇区，含分区表（不属于任何分区）

   每个分区内部：
   ┌────────┬────────┬──────────────────┬──────────┬──────────────────┐
   │ 引导块 │ 超级块 │ inode位图+块位图 │ inode 区 │    数据块区      │
   └────────┴────────┴──────────────────┴──────────┴──────────────────┘
   ```

   **超级块**存的是**整个文件系统的元数据**：块大小、块总数、空闲块数、inode 总数、空闲 inode 数、位图位置、文件系统类型与状态。它在**挂载时第一个被读入内存**，损坏则整个文件系统不可用，所以现代文件系统都保存**多个备份**。
   两个必记结论：**inode 数量在格式化时就固定了**（用尽则空间够也建不了文件，`df -i` 可查）；**目录本身也是文件**，其内容（目录项数组）就存在数据块区里。

   **② 创建与删除文件**：

   | 操作 | 步骤 |
   |---|---|
   | **创建** | ① 在 inode 位图找空闲 inode、数据块位图找空闲块 → ② 填写 inode（属性、权限、大小 0）→ ③ **在父目录的数据块中加一条目录项**（文件名 + inode 号）→ ④ 更新超级块的空闲计数 |
   | **删除** | ① 在父目录中**删除该目录项** → ② inode 的**链接计数减 1** → ③ 计数为 0 **且无进程打开**时，回收数据块与 inode（位图置 0）→ ④ 更新超级块 |

   **陷阱**：删除**不清除数据块内容**，只抹目录项和位图。这解释了三件事——删大文件为什么快、误删为什么可能恢复、以及"删了文件但 `df` 空间没释放"（还有进程持有 fd，链接计数未归零，`lsof | grep deleted` 可查）。

   **③ VFS（虚拟文件系统）**：位于用户程序与各具体文件系统之间的**抽象层**。

   - **解决的问题**：一台机器上同时有 ext4、NTFS、FAT32、NFS、procfs，实现天差地别。VFS 向上提供**统一的系统调用接口**（`open/read/write/close`），向下要求每个具体文件系统实现**一组规定的函数指针**——本质上是**用 C 实现的接口与多态**。
   - **四大对象**：

   | 对象 | 代表什么 | 磁盘上对应 |
   |---|---|---|
   | **超级块** | 一个**已挂载的文件系统** | 磁盘超级块 |
   | **inode** | 一个**文件本身**（元数据） | 磁盘 inode |
   | **dentry（目录项）** | 一个**名字 → inode 的映射** | 目录文件里的一条记录 |
   | **file** | **一次"打开"**（含读写指针） | 无，**纯内存对象** |

   三者关系正好串起前面的知识：多个 **dentry** 指向同一个 **inode** 就是**硬链接**；多个 **file** 对象指向同一个 inode 就是**同一文件被多进程打开**（各有读写指针）。
   **"一切皆文件"正是靠 VFS 实现的**——`/proc`、`/sys`、`/dev/null`、socket、管道都实现了 VFS 接口，于是都能用 `read()` 读。
   **陷阱**：**VFS 不是一种具体文件系统**，它自己不管理任何磁盘空间。

## OS09 磁盘与 I/O 管理

1.（计算）磁头当前位于 **100** 号磁道，请求队列为 `55, 58, 39, 18, 90, 160, 150, 38, 184`。分别用 **FCFS、SSTF、SCAN（先向磁道号增大方向）、C-SCAN** 计算磁头移动总道数与平均寻道长度。
2.（简答）磁盘地址由柱面号、盘面号、扇区号三部分组成，为什么**柱面号必须放在最前面**？
3.（计算）某系统从磁盘读入一块数据到缓冲区耗时 `T`，从缓冲区送到用户区耗时 `M`，CPU 处理一块耗时 `C`。求**单缓冲**与**双缓冲**下处理 `n` 块数据各需多少时间。
4.（简答）I/O 控制的四种方式分别是什么？各自的数据传送单位与 CPU 干预频率如何？
5.（简答）SPOOLing 系统由哪几部分组成？它怎么把独占设备改造成共享设备？
6.（简答）① SSD 的读、写、擦除各以什么为单位？为什么它不能像磁盘那样原地更新数据？② 什么是写放大，它从哪来？③ 为什么磁盘调度算法在 SSD 上失去了意义？

### 参考答案

1. **FCFS（先来先服务）**：`100→55→58→39→18→90→160→150→38→184`

   移动量：`45 + 3 + 19 + 21 + 72 + 70 + 10 + 112 + 146 = **498**`，平均 `498 / 9 ≈ **55.3**` 道。

   **SSTF（最短寻道时间优先）**：`100→90→58→55→39→38→18→150→160→184`

   移动量：`10 + 32 + 3 + 16 + 1 + 20 + 132 + 10 + 24 = **248**`，平均 `248 / 9 ≈ **27.6**` 道。

   **SCAN（电梯算法，先向磁道号增大方向，到最远请求后折返）**：`100→150→160→184→90→58→55→39→38→18`

   移动量：`50 + 10 + 24 + 94 + 32 + 3 + 16 + 1 + 20 = **250**`，平均 `250 / 9 ≈ **27.8**` 道。

   **C-SCAN（循环扫描，只在一个方向服务，到头后直接返回起点）**：`100→150→160→184→18→38→39→55→58→90`

   移动量：`84 + (184 - 18) + (90 - 18) = 84 + 166 + 72 = **322**`，平均 `322 / 9 ≈ **35.8**` 道。

   **必须注意的陷阱**：
   - **SCAN 严格定义是"走到磁盘最边缘才折返"**。若题目给出磁道范围（如 0~199），严格 SCAN = `(199-100) + (199-18) = 99 + 181 = **280**`。上面算的 250 其实是 **LOOK**（走到最远的**请求**就折返）。**题目不明说时按"到最远请求折返"算并写明假设**，这是每年都有人失分的地方。
   - **C-SCAN 的返回过程**（184 → 18）通常**要计入**移动距离；若按严格 C-SCAN 到端点，则是 `(199-100) + 199 + 90 = 388`。同样需写明假设。
   - **方向未说明时默认向磁道号增大方向**，但最好在答卷上写一句"假设初始向外移动"。

   **算法特性对比**：

   | 算法 | 优点 | 缺点 |
   |---|---|---|
   | FCFS | 绝对公平，实现简单 | 性能最差，磁头大幅来回跑 |
   | SSTF | 性能好 | **可能饥饿**（远处请求一直被插队） |
   | SCAN | 性能好且**不会饥饿** | 对**刚被磁头经过的位置**不公平（要等一个来回） |
   | C-SCAN | **各磁道等待时间更均匀** | 返程要空跑，总移动距离通常更大 |

2. 磁盘的物理结构决定了三段的顺序必须是 **柱面号 → 盘面号 → 扇区号**，理由是：

   - **寻道（移动磁臂换柱面）是三段延迟中最慢的**（毫秒级），而换盘面只需**电子切换磁头**（微秒级）、换扇区靠盘片旋转。
   - 把柱面号放在最前，意味着**地址连续的数据块会先填满同一柱面上的所有盘面和扇区，再移到下一柱面**。这样读一大段连续数据时，**只需一次寻道就能读完整个柱面（所有盘面）**，寻道次数降到最低。
   - 若把盘面号放最前，连续的块会分布在同一盘面的不同柱面上 → **每读一块就要寻道一次**，性能断崖式下降。

   相关优化（同属减少延迟的手段）：
   - **交替编号**：同一磁道上的扇区不按 0,1,2… 物理相邻编号，而是隔开排列，让 CPU 处理完一个扇区后，下一个逻辑扇区**恰好转到磁头下**，避免等一整圈。
   - **错位命名**：相邻盘面的起始扇区**错开一个角度**，让换磁头（换盘面）的电子延迟期间盘片转过的角度被抵消。

   **公式**：`平均存取时间 = 平均寻道时间 + 平均旋转延迟 + 传输时间`，其中**平均旋转延迟 = 转一圈时间 / 2**。

3. **单缓冲**：缓冲区只有一个，**必须等缓冲区腾空后才能再冲入下一块**，所以「磁盘读入 T」与「送到用户区 M」不能重叠。

   一块的处理周期 = `max(C, T) + M`，n 块总时间 ≈ **`n × (max(C, T) + M)`**

   推导：设 `T > C`。第一块 T 秒充满缓冲区 → M 秒送到用户区（此时缓冲区空了，下一块可以开始冲入）→ CPU 花 C 秒处理用户区数据，**与下一块的 T 并行**。故每块周期是 `max(C, T) + M`。

   **双缓冲**：两个缓冲区交替使用，**冲入下一块与"传送+处理"上一块可以完全并行**。

   一块的处理周期 = `max(T, C + M)`，n 块总时间 ≈ **`n × max(T, C + M)`**

   - 若 `T > C + M`（磁盘慢，常见）→ 总时间 ≈ `n × T`，**磁盘成为唯一瓶颈，缓冲效果最佳**
   - 若 `T < C + M`（CPU 慢）→ 总时间 ≈ `n × (C + M)`

   **陷阱**：教材对双缓冲的公式有两种口径（有的写 `max(C+M, T)`，有的在特定假设下写 `max(C, T)`），**答题时务必写出推导过程**而不是直接套公式。缓冲区的四点作用要背：**① 缓和 CPU 与 I/O 设备速度不匹配；② 减少 I/O 中断频率；③ 解决数据粒度不匹配；④ 提高 CPU 与设备的并行性**。

4. | 方式 | 数据传送单位 | CPU 干预频率 | 数据流向 | 特点 |
   |---|---|---|---|---|
   | **程序直接控制（轮询）** | **字（字节）** | **极高**——全程忙等查询状态位 | 设备 → **CPU 寄存器** → 内存 | 实现最简单，**CPU 利用率最低** |
   | **中断驱动** | **字（字节）** | 高——每传一个字中断一次 | 设备 → **CPU 寄存器** → 内存 | CPU 等待期间可执行其他进程；**中断处理开销随数据量线性增长** |
   | **DMA** | **块** | 低——仅在**传送开始和结束**时 | 设备 → **内存**（不经 CPU） | 需 DMA 控制器（含 DR、MAR、DC、CR 四类寄存器）；**每传一个字要挪用一个存储周期** |
   | **通道控制** | **一组块** | **最低**——一组数据传送完才中断一次 | 设备 → 内存 | 通道是**弱化的专用 CPU**，能执行**通道程序**，可管理多台设备 |

   **演进主线**：**CPU 干预越来越少、每次传送的数据量越来越大、并行度越来越高**。四种方式的关系是逐级"把搬运工作从 CPU 卸载出去"。
   **陷阱**：中断驱动方式下，数据**仍然要经过 CPU 寄存器中转**——这是它与 DMA 的关键区别（DMA 是设备与内存**直连**）。另外 DMA 的"周期挪用"挪的是**存储周期**不是指令周期，CPU 只是访存时被让路，并不中断执行。

5. **SPOOLing（Simultaneous Peripheral Operation On-Line，假脱机技术）三大组成**：

   | 组成 | 位置 | 作用 |
   |---|---|---|
   | **输入井 / 输出井** | **磁盘**上开辟的存储区 | 模拟脱机输入/输出时的磁带，暂存数据 |
   | **输入缓冲区 / 输出缓冲区** | **内存**中 | 缓和 CPU 与磁盘之间的速度矛盾 |
   | **输入进程 / 输出进程** | 软件 | 模拟脱机时的外围控制机，负责在设备与井之间搬运数据 |

   另需一张**请求打印队列表**（记录每个用户的打印请求与数据在输出井中的位置）。

   **共享改造原理**（以打印机为例）：
   1. 用户进程请求打印时，系统**并不真的把打印机分配给它**，而是做两件事：
      - 在**输出井**中为它申请一块空闲区，把要打印的数据写进去；
      - 在**请求打印队列表**中挂一个表项。
   2. 这两步做完，**用户进程立即"认为自己打印完了"**，可以继续执行——它感受到的是一台**随时可用的"虚拟打印机"**。
   3. 输出进程在后台**按队列顺序**，把输出井中的数据一份份真正送到物理打印机。

   **本质**：把「多个进程争抢一台慢速独占设备」转化为「多个进程并发写各自的磁盘区域 + 一个后台进程串行使用设备」。
   - 它实现了操作系统四大特征中的**「虚拟」**——一台物理打印机虚拟成多台逻辑打印机。
   - **陷阱**：SPOOLing 用**磁盘（共享设备）模拟独占设备**，因此它是**以空间换独占性**；且它并**没有提高打印机本身的速度**，只是让用户进程不必等待。

6. **① 三个操作的粒度不同**：

   | 操作 | 单位 | 耗时量级 |
   |---|---|---|
   | **读** | **页**（4~16 KB） | ~几十 μs |
   | **写（编程）** | **页** | ~几百 μs |
   | **擦除** | **块**（含 128~256 页） | **~几 ms**，最慢 |

   **不能原地更新的原因**：闪存的编程操作**只能把位从 1 变成 0**（往浮栅注入电子）；**要把 0 变回 1 必须施加高电压，而这个电压的作用范围是整个块**。所以"改一个字节"在硬件层面等于"擦掉整个块（可能几 MB）再重写"——代价无法接受。
   **对策**：SSD 主控里的 **FTL（闪存转换层）**做**异地更新**——把新数据写到一个空白页，更新 `逻辑页号 → 物理页号` 的映射，把旧页标记为**无效**。这与虚拟内存的页表是同一个思想：**加一层间接映射，把物理上做不到的事变成逻辑上做到了**。

   **② 写放大（Write Amplification）**：

   ```
   WAF = 实际写入闪存的数据量 / 主机请求写入的数据量
   ```

   来源是**垃圾回收**：无效页越积越多但不能单独复用（擦除只能整块进行），GC 必须**先把块内仍有效的页搬到别处**，再整块擦除。**这些搬运本身就是额外写入**。
   顺序写、大块写时 WAF 接近 1；**小块随机写**时一个块里的有效页极其零散，WAF 可达 5~10 —— 这就是 **SSD 随机写明显慢于随机读、且更伤寿命**的根本原因，也是 **WAL / LSM-Tree / Kafka 日志这些 append-only 设计在 SSD 时代依然正确**的理由（只是原因从"避免寻道"变成了"降低写放大"）。
   **TRIM 命令**用于缓解：文件系统删除文件后主动告知 SSD"这些 LBA 我不要了"，GC 就不必再搬运这些其实是垃圾的"有效页"。

   **③ 磁盘调度失效的原因**：磁盘调度（SCAN / C-SCAN 等）的**全部价值建立在"寻道很贵"这一前提上**——它做的唯一事情就是重排请求顺序、减少磁头移动。而 SSD **没有任何机械部件，任意页的读取代价完全相同**，重排请求带来的收益已经小于调度算法自身消耗的 CPU 开销。
   **工程佐证**：Linux 对 NVMe SSD **默认使用 `none`（不调度）**，块层也从单队列换成了 `blk-mq` **多队列**（每 CPU 核一个队列）以榨干 SSD 的并行能力；主机接口协议也从 AHCI（1 队列 × 32 深度）换成了 NVMe（最多 64K 队列 × 64K 深度）。
   **这是"技术演进让经典算法退场"的典型案例**——但仍要理解它，因为机械硬盘在冷存储、备份、大容量场景中还在大量使用。
   **补充必记点**：**磨损均衡**（让各块擦写次数尽量均匀，分动态与静态两种）解决的是"热点块先坏导致整盘报废"；**预留空间 OP**（出厂保留 7%~28% 容量不对主机可见）供 GC 与磨损均衡周转，**OP 越大写放大越低、寿命越长**。

**最易错的九个点**（历年失分统计口径）：

1. **PV 操作中互斥信号量与同步信号量的 P 顺序** —— 写反直接死锁，大题零分
2. **缺页中断返回哪条指令** —— 答成"下一条"（那是陷阱类）
3. **SCAN 与 LOOK 混淆** —— 没写明"是否走到磁盘边缘"的假设
4. **位示图字号位号的起始基准** —— 从 0 还是从 1，公式差一位
5. **Belady 异常只有 FIFO 有** —— 误答 LRU 也有
6. **银行家算法的三步检查顺序** —— 漏掉"Request ≤ Need"这一步，或忘了试探失败要回滚
7. **交换时 PCB 也换出** —— 错，**PCB 必须常驻内存**
8. **第二类 VMM 性能更好 / 容器是轻量级虚拟机** —— 都错，两个新考点的典型误答
9. **SSD 的擦除单位** —— 答成"页"，正确是**块**（读写才是页）
