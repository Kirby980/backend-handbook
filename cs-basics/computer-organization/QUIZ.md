## CO01 计算机系统概述与性能指标

1.（计算）某 CPU 主频 1.2 GHz。程序 A 共 5×10⁸ 条指令，其中算术指令占 40%（CPI=2）、访存指令占 40%（CPI=4）、分支指令占 20%（CPI=3）。求：平均 CPI、程序执行时间、MIPS 值。
2.（计算）某程序 60% 的执行时间可以并行化。用 4 核处理器能获得多大加速比？核数增加到无穷多呢？
3.（单选）以下关于冯·诺依曼结构的说法，**错误**的是：
   A. 指令和数据以同等地位存放在存储器中，按地址访问
   B. 指令和数据都用二进制表示
   C. 指令由操作码和地址码组成
   D. 存储器按内容访问，CPU 根据数据内容找到存放位置
4.（简答）为什么「主频 4.0 GHz 的 CPU 一定比 3.0 GHz 的快」是错的？完整的性能公式是什么？
5.（判断）指令周期一定大于机器周期，机器周期一定大于时钟周期。

### 参考答案

1. **平均 CPI** `= 0.4×2 + 0.4×4 + 0.2×3 = 0.8 + 1.6 + 0.6 = **3.0**`
   **执行时间** `= 指令数 × CPI × 时钟周期 = 5×10⁸ × 3.0 / (1.2×10⁹) = 1.5×10⁹ / 1.2×10⁹ = **1.25 s**`
   **MIPS** `= 指令数 / (执行时间 × 10⁶) = 5×10⁸ / (1.25 × 10⁶) = **400 MIPS**`
   （校验：`MIPS = 主频(MHz) / CPI = 1200 / 3 = 400` ✅ 两种算法必须一致。）

2. Amdahl 定律 `S = 1 / ((1-p) + p/k)`，其中 `p=0.6`：
   - 4 核：`S = 1 / (0.4 + 0.6/4) = 1 / (0.4 + 0.15) = 1/0.55 ≈ **1.82**`
   - 无穷核：`S = 1 / 0.4 = **2.5**`（上限）

   **结论**：加速比的天花板由**不可并行的部分**决定，堆核数收益递减。这也是"优化要优化热点"的理论依据。

3. **D**。按内容访问的是**相联存储器**（如 TLB、全相联 Cache），冯·诺依曼机的主存是**按地址访问**。A、B、C 都是冯·诺依曼结构的正确描述。

4. 因为主频只是性能公式里的一项：
   **`程序执行时间 = 指令条数 × CPI × 时钟周期 = 指令条数 × CPI / 主频`**
   主频高但 CPI 也高（如流水线设计差、Cache 命中率低），或指令集效率低导致完成同样工作需要更多指令，总时间反而更长。
   典型反例：早期 Pentium 4 靠超长流水线冲高主频（3.8 GHz），实际性能不敌主频更低的 Pentium M / Core 架构。**衡量性能只能用"执行相同任务的时间"**，即 CPU 执行时间或 SPEC 之类的基准。

5. **错**。前半句对（一个指令周期由若干机器周期组成），后半句在**单周期机器周期**的情形下不成立——机器周期可以**等于**一个时钟周期。准确表述是：**指令周期 ≥ 机器周期 ≥ 时钟周期**，且时钟周期是最小时间单位，不可再分。

## CO02 数据的表示与 IEEE 754

1.（计算）把十进制 `-0.4375` 编码成 IEEE 754 单精度浮点数，写出二进制与十六进制结果。
2.（简答）8 位补码能表示 `-128`，但 8 位原码不能。为什么？补码的表示范围为什么"多一个负数"？
3.（计算）8 位补码运算 `(+72) + (+82)`，写出二进制过程，判断是否溢出，并说明 OF 与 CF 各是多少。
4.（简答）从位级角度解释为什么 `0.1 + 0.2 != 0.3`。金额计算应该怎么处理？
5.（计算）在 32 位小端机器上，如下 Go 结构体占多少字节？说明填充位置。

```go
type S struct {
    a byte    // 1 字节
    b int32   // 4 字节
    c byte     // 1 字节
    d int64   // 8 字节
}
```

### 参考答案

1. `0.4375 = 0.0111₂`（`0.25 + 0.125 + 0.0625`）。规格化：`0.0111 = 1.11 × 2⁻²`。
   - 符号位 `S = 1`（负数）
   - 阶码 `E = -2 + 127 = 125 = 0111 1101`
   - 尾数 `M = 1100 0000 0000 0000 0000 000`（隐含的 1 不存）

   **二进制：`1 01111101 11000000000000000000000`**
   四位一组：`1011 1110 1110 0000 0000 0000 0000 0000` → **十六进制 `0xBEE00000`**

2. 原码用「符号位 + 绝对值」，8 位能表示的绝对值最大是 `127`（`0111 1111`），`1000 0000` 被解释成 `-0`，与 `0000 0000` 的 `+0` 重复。所以原码范围是 `-127 ~ +127`，**有两个零、共 255 个有效值**。
   补码消除了 `-0`：`1000 0000` 不再是 `-0`，而被定义为 `-128`（因为 `[-128]补 = 1000 0000`，符合 `-2⁷`）。**零唯一 → 省出一个编码 → 范围变成 `-128 ~ +127`，恰好 256 个值全部用上**。
   代价：`-128` 取相反数会溢出（`-(-128) = 128` 表示不了），这是 C/Go 里 `abs(INT_MIN)` 的经典 UB / 陷阱。

3. `[+72]补 = 0100 1000`，`[+82]补 = 0101 0010`

   ```
     0100 1000   (72)
   + 0101 0010   (82)
   -------------
     1001 1010   → 作为补码解释是 -102
   ```

   - **OF = 1**（溢出）。判据一：最高位进位 `C_out = 0`，次高位进位 `C_in = 1`，`OF = 0 ⊕ 1 = 1`。判据二：**正 + 正 = 负**，必溢出。判据三（双符号位法）：`00 1001000 + 00 1010010 = 01 0011010`，双符号位 `01` 不同 → 正溢出。
   - **CF = 0**。无符号解释下 `72 + 82 = 154 ≤ 255`，没有进位。

   **本题精髓**：同一次加法，有符号溢出（OF=1）但无符号不溢出（CF=0）。**OF 和 CF 是两套独立的判断，取哪个取决于你把数据当成什么解释**——硬件两个都算，由指令（`JO` 还是 `JC`）决定用哪个。

4. `0.1` 和 `0.2` 都是**二进制无限循环小数**：`0.1₁₀ = 0.0001100110011…₂`。IEEE 754 双精度只有 52 位尾数，必须截断舍入，所以存进去的已经不是精确的 0.1、0.2，而是最接近它们的双精度数。两个近似值相加，结果（`0.30000000000000004`）与"最接近 0.3 的双精度数"不是同一个位模式，故 `!=`。
   **金额处理**：① 用**整数存最小单位**（分 / 厘），运算全程整数；② 用**定点/十进制类型**（Go 的 `shopspring/decimal`、Java `BigDecimal`、PostgreSQL `numeric`）；③ 绝不用 `float` 存钱，也不要用 `==` 比较浮点，改用 `math.Abs(a-b) < eps`。

5. **24 字节**。按对齐规则（每个字段的偏移必须是其自身大小的整数倍，结构体总大小是最大字段对齐值的整数倍）：

   | 字段 | 偏移 | 大小 | 说明 |
   |---|---|---|---|
   | `a` | 0 | 1 | |
   | *填充* | 1-3 | 3 | 让 `b` 对齐到 4 的倍数 |
   | `b` | 4 | 4 | |
   | `c` | 8 | 1 | |
   | *填充* | 9-15 | 7 | 让 `d` 对齐到 8 的倍数 |
   | `d` | 16 | 8 | |
   | 合计 | | **24** | 已是 8 的倍数，无需尾部填充 |

   **优化**：把字段按大小**从大到小**重排（`d, b, a, c`）→ `8 + 4 + 1 + 1 = 14`，补到 8 的倍数 = **16 字节**，省 33%。详见 [golang/G05](../../golang/G05-精通-Go-Struct-内存布局与嵌入.md)。

## CO03 运算方法与运算器

1.（计算）8 位机器上执行 `0x80 + 0x80`，写出结果与 `CF / ZF / SF / OF` 四个标志位的值。
2.（简答）串行进位加法器的延迟瓶颈是什么？先行进位（超前进位）加法器怎么解决？代价是什么？
3.（简答）浮点数加减法的四个步骤是什么？对阶时为什么必须是「小阶向大阶看齐」而不能反过来？
4.（计算）用**不恢复余数法（加减交替法）**计算 `11 ÷ 3`（4 位无符号），写出每步的余数与商。
5.（简答）原码一位乘与补码布斯（Booth）乘法的核心差异是什么？Booth 算法为什么能直接处理负数？

### 参考答案

1. `0x80 = 1000 0000`：

   ```
     1000 0000
   + 1000 0000
   -------------
   1 0000 0000  → 截断到 8 位，结果 0x00
   ```

   - **CF = 1**：最高位有进位（无符号 `128 + 128 = 256 > 255` 溢出）
   - **ZF = 1**：结果为 0
   - **SF = 0**：结果最高位为 0
   - **OF = 1**：最高位进位 1、次高位进位 0，`1 ⊕ 0 = 1`；有符号解释是 `-128 + (-128) = -256`，超出 `[-128,127]` 范围

   四个标志位同时有效，是本章最典型的综合考点。

2. **瓶颈**：串行（行波）进位中，第 i 位的进位 `C_i` 必须等 `C_{i-1}` 算完才能产生，n 位加法器的延迟是 **O(n)**——64 位加法要等 64 级门延迟串起来。
   **先行进位**：把递推式 `C_i = G_i + P_i·C_{i-1}`（`G_i = A_i·B_i` 进位生成、`P_i = A_i ⊕ B_i` 进位传递）**完全展开**，使每一位的进位只依赖最初的 `C₀` 和各位的 G/P，所有进位**并行**产生，延迟降到 **O(1)**（实际是常数级门延迟）。
   **代价**：展开后表达式的项数随位数**指数增长**，电路面积和扇入急剧上升。所以实际做法是**分组先行进位**（如 4 位一组组内并行、组间再并行），在延迟 O(log n) 与面积之间折中。

3. 四步：**① 对阶 → ② 尾数求和/差 → ③ 规格化 → ④ 舍入**（有的教材把"判溢出"单列为第五步）。
   对阶必须**小阶向大阶看齐**（小阶的尾数右移，每右移一位阶码加 1，直到两阶相等）。
   **原因**：右移丢掉的是尾数**最低位**（精度损失小，且可通过保护位/舍入位补偿）；若反过来让大阶向小阶看齐，尾数就要**左移**，会把**最高有效位移出去**——那是数量级的丢失，属于致命错误。
   **一句话**：宁可损失精度，不可损失量级。

4. `被除数 X = 1011（11）`，`除数 Y = 0011（3）`，`[-Y]补 = 1101`。加减交替法：余数为正则**下商 1、下一步减**；余数为负则**下商 0、下一步加**。

   | 步骤 | 操作 | 余数（4 位 + 符号） | 上商 |
   |---|---|---|---|
   | 初始 | R = 0，取被除数最高位 | R = 0001 | — |
   | 1 | R - Y = 1 - 3 = -2 | 负 | **0** |
   | 2 | R 左移补下一位，R = -2×2+0 = -4；R + Y = -4+3 = -1 | 负 | **0** |
   | 3 | R 左移，R = -1×2+1 = -1；R + Y = -1+3 = 2 | 正 | **1** |
   | 4 | R 左移，R = 2×2+1 = 5；R - Y = 5-3 = 2 | 正 | **1** |

   **商 = 0011 = 3，余数 = 2** ✅（`11 = 3×3 + 2`）
   **与恢复余数法的差异**：恢复余数法在余数为负时要先「加回除数」再左移（多一次加法）；加减交替法用"下一步做加法"直接抵消，**省掉恢复步骤，硬件更快**。

5. **原码一位乘**：符号位单独处理（异或），数值位用绝对值相乘，最后拼上符号。逻辑简单但**符号要单独走一条路**，且不能直接用补码加法器。
   **Booth 算法**：直接对**补码**操作，通过检查相邻两位 `y_i y_{i+1}`（末位后补一个 0）决定这一步做什么：

   | `y_i y_{i+1}` | 操作 |
   |---|---|
   | `00` / `11` | 只右移（跳过连续相同位） |
   | `01` | 加 `[X]补` 后右移 |
   | `10` | 减 `[X]补`（即加 `[-X]补`）后右移 |

   **能处理负数的原因**：Booth 的数学基础是把乘数改写成 `Σ(y_{i+1} - y_i)·2^i` 的形式，这个恒等式对**补码的符号位也成立**（补码最高位的权值是 `-2^(n-1)`，正好被差分式自然吸收）。因此符号位不需要特殊处理，正负数走同一套流程。
   **附带好处**：连续的 1 或 0 会被跳过，乘数中连续位越多，加减次数越少。

## CO04 存储系统

1.（简答）存取时间（Ta）与存取周期（Tm）有什么区别？为什么 DRAM 的存取周期明显大于存取时间？
2.（计算）某 DRAM 芯片存储阵列为 128×128，读写周期 0.5 μs，刷新周期 2 ms。分别计算**集中刷新**的死区时间与死时间率，以及**分散刷新**下系统存取周期变成多少。
3.（计算）用 `1K×4 位` 的 RAM 芯片构成 `4K×8 位` 的存储器，需要多少片？地址线共几根？其中片内地址线与片选地址线各几根？
4.（简答）SRAM 与 DRAM 的五点主要区别是什么？为什么 Cache 用 SRAM、主存用 DRAM？
5.（计算）四体低位交叉存储器，存储周期 T = 200 ns，总线传输周期 r = 50 ns。连续读取 4 个字需要多长时间？与单体顺序存储相比快多少？该配置是否"恰好"满足流水要求？
6.（计算）① 要传输 **32 位**信息并能纠正一位错，海明码至少需要多少校验位？校验位放在哪些位置？② 为什么 ECC 内存条是 72 位而普通内存是 64 位？③ 奇偶校验为什么不能纠错，且只能检出奇数位错？
7.（计算+简答）某服务器有 **6 块 4 TB 磁盘**。分别用 RAID 0、RAID 1、RAID 5、RAID 6、RAID 10 组建阵列，求各自的**可用容量**与**最多能坏几块盘**。数据库场景为什么通常选 RAID 10 而不是更省盘的 RAID 5？

### 参考答案

1. **存取时间 Ta**：从发出读写命令到数据稳定输出所需时间。
   **存取周期 Tm**：连续两次独立访问之间的**最小间隔**，`Tm = Ta + 恢复时间`。
   DRAM 用**电容存储电荷**，读操作是**破坏性**的（读完电荷被放掉），必须在读后**重写（预充电）**恢复原值，这段恢复时间被计入存取周期，所以 `Tm >> Ta`。SRAM 用触发器，读不破坏，恢复时间很短，`Tm ≈ Ta`。

2. **集中刷新**：在刷新周期末尾集中刷新全部 128 行，每行一个读写周期：
   - 死区时间 `= 128 × 0.5 μs = **64 μs**`
   - 死时间率 `= 64 μs / 2000 μs = **3.2%**`
   - 特点：刷新期间**完全不能访问**（"死区"），但其余时间存取速度不受影响。

   **分散刷新**：每个读写周期后紧跟一次刷新：
   - 系统存取周期 `= 0.5 + 0.5 = **1 μs**`（整整慢一倍）
   - 特点：**无死区**，但访存速度永久减半，且刷新过于频繁（远超必要）。

   **异步刷新**（实际采用）：把 2 ms 均分给 128 行，`2ms / 128 ≈ 15.6 μs` 刷一行，既无长死区、又不浪费——这是三种方案里唯一的工程解。

3. **芯片数**：`(4K × 8) / (1K × 4) = (4096×8) / (1024×4) = 32768/4096 = **8 片**`
   组织方式：**先位扩展**（2 片并联凑够 8 位）**再字扩展**（4 组串联凑够 4K）→ `2 × 4 = 8 片` ✅
   **地址线**：总容量 4K = 2¹² → **12 根**
   - **片内地址线**：单片 1K = 2¹⁰ → **10 根**（A0–A9，接到每片）
   - **片选地址线**：`12 - 10 = **2 根**`（A10–A11，经 2-4 译码器产生 4 个片选信号，每个信号同时选中一组的 2 片）

   **数据线**：8 根（每组内 2 片各提供 4 位，拼成 8 位）。

4. | 维度 | SRAM | DRAM |
   |---|---|---|
   | 存储原理 | 双稳态触发器（6 管） | 电容 + 1 管 |
   | 是否需刷新 | ❌ 不需要 | ✅ 必须周期刷新 |
   | 读出是否破坏 | 非破坏性 | **破坏性**，需重写 |
   | 速度 | 快（ns 级） | 慢（几十 ns） |
   | 集成度 / 成本 | 低 / 贵 | **高 / 便宜** |
   | 功耗 | 静态功耗高 | 相对低 |

   Cache 要求**极致速度**且容量小（几十 KB ~ 几十 MB），SRAM 的快正好匹配、贵也承受得起；主存要求**大容量、低单价**（几十 GB），只有 DRAM 的高集成度能做到。这是典型的**速度 vs 容量 vs 成本**三角权衡。

5. **低位交叉**：地址按低位轮流分配到 4 个体，可流水式重叠访问。
   连续读 m=4 个字：`T总 = T + (m-1)×r = 200 + 3×50 = **350 ns**`
   单体顺序：`4 × 200 = **800 ns**`
   **加速比 ≈ 800/350 ≈ 2.29 倍**
   **是否恰好满足**：流水不断流的条件是 `T ≤ m × r`，即 `200 ≤ 4 × 50 = 200` ✅ **恰好满足，一个不多一个不少**。
   若把体数降到 3（`3×50 = 150 < 200`），第一个体还没恢复完就轮到它了，流水会**断流**，必须插入等待。这就是"体数至少要 `m ≥ T/r`"的由来。

6. **① 校验位个数**：需满足 `2^k ≥ n + k + 1`，`n = 32`：
   - `k = 5`：`2⁵ = 32 < 32 + 5 + 1 = 38` ❌
   - `k = 6`：`2⁶ = 64 ≥ 32 + 6 + 1 = 39` ✅

   **至少 6 位校验位**，码字总长 38 位。**校验位放在 2 的幂次位置**：第 **1、2、4、8、16、32** 位。

   **为什么必须放 2 的幂次位**：这些位号的二进制表示中**只有一个 1**，保证每个校验位只属于自己负责的那一组，各组相互独立——这样接收方把各组校验结果按 `S₃₂S₁₆S₈S₄S₂S₁` 拼起来，**得到的数值就直接是出错位的位号**，取反即完成纠错。

   **② ECC 内存 72 位的来历**：64 位数据要纠 1 位错，代入公式 `2^k ≥ 64 + k + 1` 得 `k = 7`（`2⁷=128 ≥ 72`）。再加 **1 位用于检出双位错（DED）**，共 **8 位冗余** → `64 + 8 = **72 位**`。所以 ECC 内存条上会多出一颗颗粒，实现的是 **SEC-DED（纠一位、检两位，码距 4）**。

   **③ 奇偶校验的局限**：它只有 **1 位冗余**，**码距为 2**。
   - **不能纠错**：由 `纠 t 位需码距 ≥ 2t+1` 得纠 1 位至少需码距 3。码距 2 只够满足 `检 1 位需码距 ≥ 2`——**能发现出错，但无法定位是哪一位**。
   - **只能检奇数位错**：校验的是"1 的个数的奇偶性"。**偶数位同时翻转时，1 的个数的奇偶性不变**，校验位看起来完全正常，错误被漏过。

7. **各级别的容量与容错**（6 块 × 4 TB = 24 TB 原始容量）：

   | 级别 | 可用容量公式 | **可用容量** | **最多坏几块** |
   |---|---|---|---|
   | **RAID 0** | `n` | **24 TB** | **0 块**（坏任意一块全丢） |
   | **RAID 1** | `n/2` | **12 TB** | 每个镜像组各 1 块（共 3 组 → 最多 3 块，但**必须不同组**） |
   | **RAID 5** | `n − 1` | **20 TB** | **1 块** |
   | **RAID 6** | `n − 2` | **16 TB** | **2 块** |
   | **RAID 10** | `n/2` | **12 TB** | 每个镜像组各 1 块（**同组两块全坏则失败**） |

   **数据库选 RAID 10 的两个原因**：

   1. **写惩罚**。RAID 5 修改一个数据块要做 **2 次读 + 2 次写**（读旧数据、读旧校验、写新数据、写新校验），**随机写性能明显劣于 RAID 10**（后者只需写两份数据，无校验计算）。数据库正是典型的**小块随机写**负载。
   2. **重建风险**。单盘容量进入 TB 级后，RAID 5 重建要跑十几个小时，且重建的高负载本身最容易诱发第二块盘故障——**而 RAID 5 此时已无冗余**。RAID 10 重建只需从镜像盘做一次顺序拷贝，快且不影响其他组。

   **必记的两个陷阱**：① **RAID 0 没有任何冗余**，`n` 块盘的故障概率是单盘的 `n` 倍，**可靠性反而低于单盘**；② **RAID 5 最少 3 块盘、只能坏 1 块**，能坏 2 块的是 RAID 6（最少 4 块）。
   **RAID 5 的恢复原理**是异或的自反性：`P = D1 ⊕ D2 ⊕ D3` → `D2 = P ⊕ D1 ⊕ D3`。
   **最后一句**：**RAID 防的是硬件故障，不能替代备份**——误删、勒索软件、文件系统损坏都会被忠实地同步到所有盘上。

## CO05 Cache 与虚拟存储器

1.（计算）某机按字节编址，主存容量 256 MB，Cache 数据区容量 64 KB，块大小 64 B，采用**4 路组相联**映射。求主存地址如何划分（标记位 / 组号 / 块内地址各几位）。
2.（计算）L1 命中时间 1 个周期、缺失率 10%；L2 命中时间 10 个周期、缺失率 2%；主存访问 200 个周期。求平均访问时间 AMAT。
3.（简答）写直达与写回各自的优缺点？写不命中时的两种策略如何与它们搭配？
4.（简答）下面两段 Go 代码功能相同，为什么第一段快得多？

```go
// A：行优先
for i := 0; i < N; i++ { for j := 0; j < N; j++ { sum += a[i][j] } }
// B：列优先
for j := 0; j < N; j++ { for i := 0; i < N; i++ { sum += a[i][j] } }
```

5.（简答）在同时有 TLB、页表、Cache 的系统中，「TLB 命中」「页表命中（页在内存）」「Cache 命中」三者的组合共 8 种，哪些是**不可能**出现的？为什么？

### 参考答案

1. - 主存地址位数 `= log₂(256 MB) = log₂(2²⁸) = **28 位**`
   - **块内地址** `= log₂(64 B) = **6 位**`
   - Cache 总行数 `= 64 KB / 64 B = 1024 行`；4 路组相联 → 组数 `= 1024 / 4 = 256 组`
   - **组号** `= log₂256 = **8 位**`
   - **标记位** `= 28 - 6 - 8 = **14 位**`

   **地址格式：`| 标记 14 位 | 组号 8 位 | 块内地址 6 位 |`**
   （检查：`14+8+6 = 28` ✅。这类题的唯一诀窍是**从右往左算**：先块内、再组号、剩下全是标记。）

2. `AMAT = L1命中时间 + L1缺失率 × (L2命中时间 + L2缺失率 × 主存时间)`
   `= 1 + 0.1 × (10 + 0.02 × 200)`
   `= 1 + 0.1 × (10 + 4)`
   `= 1 + 1.4 = **2.4 个周期**`
   **注意**：L2 的缺失率这里是**局部缺失率**（在访问到 L2 的请求中缺失的比例）。若题目给的是**全局缺失率**（相对全部访存），公式要改成 `AMAT = 1 + 0.1×10 + 全局缺失率×200`，读题必须分清。

3. | | 写直达 Write Through | 写回 Write Back |
   |---|---|---|
   | 做法 | 同时写 Cache 和主存 | 只写 Cache，置**脏位**；替换时才写回 |
   | 优点 | 主存始终是最新，**一致性简单**（多核 / DMA 友好） | **写流量小**，速度快 |
   | 缺点 | 写流量大，速度受主存限制（常配**写缓冲**缓解） | 需脏位；主存可能过期，一致性协议复杂 |

   **搭配**：
   - **写回 + 写分配**：写不命中时先把块调入 Cache 再写。理由是写回本就假设"写会重复发生"，调进来后续的写都能命中。
   - **写直达 + 非写分配**：写不命中时直接写主存，不调块。理由是反正每次写都要穿透到主存，调块进 Cache 没有收益。

4. 二维数组在内存中按**行优先**连续存放。A 的访问顺序与内存布局一致：读 `a[i][0]` 时把整个 cache line（如 64 B = 8 个 int64）一次性载入，接下来 7 次访问全部**命中**，空间局部性被充分利用。
   B 每次跨一整行（步长 `N × 元素大小`），若 `N` 较大则每次访问都落在不同的 cache line 上，**每次都缺失**，还可能引发 TLB 缺失和 Cache 抖动。
   **量级**：N 较大时 B 比 A 慢 **5–10 倍**是常见结果，且差距随 N 增大而扩大。这是 CO05 最有工程价值的一条——**遍历顺序要跟着内存布局走**。

5. **不可能的组合有 2 种**：
   - **TLB 命中 + 页表未命中（缺页）**：TLB 是页表的缓存，TLB 里有该项就说明页**一定在内存中**且页表项有效，不可能同时缺页。
   - **页表未命中（缺页）+ Cache 命中**：页都不在主存里，其内容自然不可能已经在 Cache 中（Cache 缓存的是主存内容）。

   剩下 6 种都可能，例如：
   - TLB 命中 + Cache 命中（最快路径）
   - TLB 命中 + Cache 缺失（要访主存）
   - TLB 缺失 + 页表命中 + Cache 命中（TLB 没缓存到，但数据在 Cache 里）
   - TLB 缺失 + 页表命中 + Cache 缺失
   - TLB 缺失 + 缺页 + Cache 缺失（最慢路径，要调页）

   **另一个必然关系**：TLB 缺失时，**页表一定要查**（可能命中也可能缺页），这是它与前两条的区别。

## CO06 指令系统

3.（填空）写出下列寻址方式的有效地址 EA 计算式：立即、直接、间接、寄存器、寄存器间接、相对、基址、变址。
4.（简答）基址寻址与变址寻址的形式几乎一样（`EA = 寄存器 + A`），它们的本质区别是什么？
5.（简答）RISC 相比 CISC 有哪些设计特点？为什么 RISC 更适合流水线？现代 x86 CPU 是 CISC 还是 RISC？
6.（读代码）下面是 gcc 编译出的 x86-64 汇编（AT&T 语法）。① 它对应的 C 代码在做什么？② 若 `%edi` 传入的是 5，返回值是多少？

```gas
f:
    movl    $0, %eax
    movl    $1, %edx
    testl   %edi, %edi
    jle     .L2
.L3:
    addl    %edx, %eax
    addl    $1, %edx
    cmpl    %edi, %edx
    jle     .L3
.L2:
    ret
```

7.（简答）① `call` 与 `ret` 指令各自完成了哪些操作？返回地址保存在哪里？② x86-64 中前 6 个整型参数分别通过哪些寄存器传递，返回值放在哪？③ 画出一次函数调用后的栈帧结构，并说明"调用者保存"与"被调用者保存"寄存器的区别。

### 参考答案

1. 二地址指令格式：`| OP 4 位 | A1 6 位 | A2 6 位 |`，操作码 4 位最多 16 种编码。
   - 已用 12 条 → 剩 `16 - 12 = 4` 个编码可用于扩展
   - **一地址指令**：格式 `| OP 10 位 | A 6 位 |`，操作码从 4 位扩展到 `4+6 = 10` 位。每个空出的 4 位前缀可派生 `2⁶ = 64` 条 → 最多 `4 × 64 = **256 条**`
   - **零地址指令**：若一地址指令用满 256 条，就没有编码留给零地址了。所以要留：设一地址实际用 `x` 条，则零地址最多 `(256 - x) × 2⁶` 条。若一地址用 255 条，零地址最多 `1 × 64 = 64` 条。

   **答题要点**：扩展操作码的核心是**短码不能是长码的前缀**（类似哈夫曼编码的前缀性质），题目若不给具体分配，就用"每空出一个 n 位编码，就能扩展出 2^(地址码位数) 个下一级编码"这个递推关系答。

2. **`2008H`**。
   `EA = (PC) + A`。关键在于**取指结束后 PC 已经自动指向下一条指令**：指令占 2 字节，取完 `2000H` 处的指令后 `PC = 2000H + 2 = 2002H`。
   故 `EA = 2002H + 06H = **2008H**`。
   **最高频陷阱**：直接用 `2000H + 06H = 2006H` 是错的。凡是相对寻址题，**先问自己"PC 现在指哪"**。

3. | 寻址方式 | 有效地址 EA | 访存次数（取操作数） |
   |---|---|---|
   | 立即寻址 | 无 EA，操作数 = A（在指令中） | **0 次** |
   | 直接寻址 | `EA = A` | 1 次 |
   | 间接寻址 | `EA = (A)` | **2 次及以上**（多级间址更多） |
   | 寄存器寻址 | 无 EA，操作数在 `R_i` | **0 次** |
   | 寄存器间接 | `EA = (R_i)` | 1 次 |
   | 相对寻址 | `EA = (PC) + A`（A 为补码偏移） | 1 次 |
   | 基址寻址 | `EA = (BR) + A` | 1 次 |
   | 变址寻址 | `EA = (IX) + A` | 1 次 |

   （堆栈寻址 `EA = (SP)` 隐含；隐含寻址操作数在 ACC，不访存。）

4. | | 基址寻址 | 变址寻址 |
   |---|---|---|
   | 谁改寄存器 | **操作系统 / 装入程序**，用户不可变 | **用户程序**，循环中不断修改 |
   | 变的是哪部分 | 基址寄存器内容变，形式地址 A 固定 | 变址寄存器内容变，形式地址 A 固定（A 是**数组首址**） |
   | 主要用途 | **程序重定位**（多道程序装入不同内存位置） | **数组 / 字符串的顺序访问、循环处理** |
   | A 的含义 | 相对于基址的**偏移量** | 数组**首地址** |

   **一句话**：基址是"程序搬到哪儿了"（系统视角），变址是"我遍历到第几个了"（用户视角）。两者可组合成 `EA = (BR) + (IX) + A`。

5. RISC 的设计特点：① **指令数量少、长度固定、格式规整**；② **只有 load/store 访存**，其余指令只在寄存器间运算；③ 寻址方式少（通常 3–5 种）；④ **通用寄存器多**；⑤ 以**硬布线控制器**为主（不用微程序）；⑥ 优化编译器承担更多工作。
   **适合流水线的原因**：指令**等长**使取指阶段周期固定；格式**规整**使译码简单且可并行；**只有 load/store 访存**使 MEM 段的行为可预测；**单周期执行**使各段耗时均衡——流水线最怕的就是"某条指令特别长把整条线卡住"，RISC 从指令集层面消除了这个问题。
   **现代 x86**：对外**保持 CISC 指令集**（为了二进制兼容），内部**把 CISC 指令译码成类 RISC 的微操作（μops）**再送入乱序流水线执行。所以答案是「**外 CISC 内 RISC**」——两条路线在实现层已经融合，ARM64 则是彻底的 RISC 路线。

6. **① 它在做什么**：这是一个**循环**（有向后跳转的 `jle .L3` 构成回边），计算 **1 + 2 + … + n 的累加和**。

   逐行还原：

   | 汇编 | 含义 |
   |---|---|
   | `movl $0, %eax` | `sum = 0`（`%eax` 是返回值寄存器） |
   | `movl $1, %edx` | `i = 1` |
   | `testl %edi, %edi` | 测试参数 `n`（`%edi` = 第 1 个参数）是否 ≤ 0 |
   | `jle .L2` | **n ≤ 0 直接跳到结尾**（循环一次都不执行） |
   | `.L3: addl %edx, %eax` | `sum += i` |
   | `addl $1, %edx` | `i++` |
   | `cmpl %edi, %edx` | 计算 `i - n`（**AT&T 顺序相反**！） |
   | `jle .L3` | `i <= n` 则**跳回循环体** |

   对应的 C 代码：

   ```c
   int f(int n) {
       int sum = 0;
       for (int i = 1; i <= n; i++)
           sum += i;
       return sum;
   }
   ```

   **② `n = 5` 时返回 `1+2+3+4+5 = 15`。**

   **三个必抓的识别特征**：
   - **有向后跳转（跳到前面的标号）→ 是循环**；只有向前跳转 → 是分支。
   - **`cmpl %edi, %edx` 在 AT&T 里算的是 `%edx - %edi`**，即 `i - n`。看成 `n - i` 整题就反了。
   - 开头的 `testl` + `jle` 是编译器把 `for` 转成 **do-while 形式**时加的**前置判断**——保证 `n ≤ 0` 时循环体一次都不执行。这样每轮只需一次跳转，比朴素 while 少一次。

7. **① `call` 与 `ret`**：

   | 指令 | 等价操作 |
   |---|---|
   | **`call 目标`** | ① **`push %rip`**——把**下一条指令的地址**压入栈<br/>② `jmp 目标` |
   | **`ret`** | **`pop %rip`**——从**栈顶**弹出返回地址送入 PC |

   **返回地址保存在【栈】里**，由 `call` 指令**自动完成**，不需要程序员写。
   由此可推出两个结论：**函数调用必然访存**（哪怕参数全在寄存器中）；**递归深度受栈空间限制**，过深就是栈溢出。

   **② 参数与返回值**：

   ```
   第 1~6 个整型参数：%rdi → %rsi → %rdx → %rcx → %r8 → %r9
   第 7 个及以后    ：【压栈】传递
   返回值           ：【%rax】
   ```

   （这是 x86-64 的 System V ABI；**32 位 x86 才是全部参数压栈**，看清题目问的位数。）

   **③ 栈帧结构**（x86-64 栈**向低地址增长**）：

   ```
   高地址  ┌────────────────────────┐
           │  调用者的栈帧            │
           ├────────────────────────┤
           │  第 7 个及以后的参数      │
           ├────────────────────────┤
           │  【返回地址】            │ ← call 自动压入
           ├────────────────────────┤
           │  保存的旧 %rbp          │ ← %rbp 指向这里（帧底，固定）
           ├────────────────────────┤
           │  被调用者保存的寄存器     │
           ├────────────────────────┤
           │  局部变量（-8(%rbp) …）  │
           ├────────────────────────┤
           │  为下一层准备的参数       │ ← %rsp 指向这里（栈顶，浮动）
   低地址  └────────────────────────┘
   ```

   固定套路：**序言** `push %rbp; mov %rsp,%rbp; sub $N,%rsp`；**尾声** `leave; ret`（`leave` = `mov %rbp,%rsp; pop %rbp`）。

   **两类寄存器保存责任**：

   | 类别 | 寄存器 | 规则 |
   |---|---|---|
   | **调用者保存** | `%rax` `%rcx` `%rdx` `%rsi` `%rdi` `%r8`–`%r11` | 被调用者**可随意修改**；调用方若 `call` 之后还要用，**必须自己先保存** |
   | **被调用者保存** | `%rbx` `%rbp` `%r12`–`%r15` | 被调用者**要用就得先存、返回前恢复**，让调用方察觉不到 |

   **为什么分两类**：全用调用者保存则每次 `call` 前都要存一大堆（哪怕对方没用）；全用被调用者保存则相反。分开后**编译器可按实际使用情况只保存必要的部分**——纯粹的性能权衡。
   **延伸**：局部数组也在栈帧里且**紧邻返回地址**，写越界就能覆盖返回地址——这正是**缓冲区溢出攻击**的原理，现代防御手段是栈保护（canary）、不可执行栈（NX）与地址随机化（ASLR）。

## CO07 中央处理器

1.（计算）某 5 段流水线，各段耗时均为 1 个时钟周期 Δt，连续执行 100 条指令（无冒险）。求流水线执行时间、吞吐率、加速比与效率。
2.（简答）数据冒险有哪三种？哪一种在顺序流水线中最常见？转发（forwarding）能解决所有数据冒险吗？
3.（简答）硬布线控制器与微程序控制器在速度、灵活性、实现方式上有何差异？各适用于什么场景？
4.（计算）某微程序控制器的控制存储器容量为 `512 × 48 位`。微指令中下地址字段至少需要多少位？若采用水平型微指令、共有 30 个微命令，操作控制字段用**直接控制（不译码）**方式至少需要多少位？
5.（简答）单周期 CPU、多周期 CPU、流水线 CPU 三者在 CPI 与时钟周期上各是什么特点？

### 参考答案

1. - **执行时间** `T = (k + n - 1) × Δt = (5 + 100 - 1) × Δt = **104Δt**`
   - **吞吐率** `TP = n / T = 100 / 104Δt ≈ **0.96/Δt**`（理想最大吞吐率是 `1/Δt`）
   - **加速比** `S = T不流水 / T流水 = (100 × 5 × Δt) / 104Δt = 500/104 ≈ **4.81**`
   - **效率** `E = S / k = 4.81 / 5 ≈ **96.2%**`（也可用面积法：`E = (n×k×Δt)/(k×T) = 500/(5×104) = 0.962`）

   **规律**：`n >> k` 时加速比趋近 k、效率趋近 1。填充和排空的开销 `(k-1)Δt` 是固定的，指令越多越摊薄。

2. 三种：
   - **RAW（写后读，真相关）**：后指令要读前指令还没写回的结果。**顺序流水线中只有这一种真实发生**。
   - **WAR（读后写，反相关）**：只在**乱序执行**中出现（后指令抢先写了前指令还没读的寄存器）。
   - **WAW（写后写，输出相关）**：同样只在乱序 / 多周期不等长执行中出现。

   **转发不能解决所有 RAW**：`load-use 冒险` 是例外——`lw R1, 0(R2)` 后紧跟 `add R3, R1, R4`，`R1` 的值要到 **MEM 段结束**才拿到，而 `add` 在 **EX 段**就要用它，时间上根本来不及。必须**停顿 1 个周期**（插入气泡）再转发，或由编译器**调度一条无关指令**填进去。

3. | 维度 | 硬布线控制器 | 微程序控制器 |
   |---|---|---|
   | 实现方式 | **组合逻辑电路**（与或门阵列） | **控制存储器**中存微程序，逐条取微指令 |
   | 速度 | **快**（一级门延迟） | 慢（每个微操作要访问控存一次） |
   | 灵活性 | **差**，改指令要重新设计电路 | **好**，改微程序即可增删指令 |
   | 规整性 | 差，电路杂乱难维护 | 好，结构规整易设计 |
   | 适用 | **RISC**、追求极致速度 | **CISC**、指令复杂且多变 |

   **趋势**：现代高性能 CPU 主要用硬布线（快），仅对少数极复杂指令保留微码（如 x86 的字符串指令、`CPUID`）——同时也留下了"微码更新"这个修复硬件漏洞的后门（Spectre / Meltdown 缓解就走这条路）。

4. - **下地址字段**：控存有 512 个单元 → 微地址需 `log₂512 = **9 位**`。
   - **操作控制字段（直接控制方式）**：直接控制即**每个微命令占一个二进制位**（1 表示发出该微命令），30 个微命令 → 至少 **30 位**。

   （校验：`30 + 9 = 39 ≤ 48`，剩下 9 位可用于判别测试字段等，合理 ✅）
   **对比**：若改用**字段直接编码**，把互斥的微命令分组编码，位数可大幅压缩（如分 3 组，每组 10 个互斥命令 → `4+4+4 = 12 位`），代价是多一级译码延迟。这就是**水平型（长、快、并行度高）vs 垂直型（短、慢、类似机器指令）**的取舍。

5. | | 单周期 CPU | 多周期 CPU | 流水线 CPU |
   |---|---|---|---|
   | CPI | **恒为 1** | **> 1**（各指令周期数不同） | **理想接近 1**（实际因冒险略大于 1） |
   | 时钟周期 | **最长**（要迁就最慢的指令，如 `lw`） | 较短（等于最长的**单个阶段**） | 较短（等于最长的**流水段**） |
   | 部件利用率 | 低（每周期只用到一部分） | 较高（可复用同一部件） | **最高**（各段同时工作） |
   | 性能 | 最差 | 中等 | **最好** |

   **常见陷阱**：单周期 CPU 的 CPI = 1 看起来最优，但它的时钟周期被最慢指令拖到极长，**总性能反而最差**——再次印证 `执行时间 = 指令数 × CPI × 时钟周期`，三项要一起看。

## CO08 总线与输入输出系统

1.（计算）某同步总线的时钟频率为 100 MHz，总线宽度 32 位，每传送一次数据需要 2 个时钟周期。求该总线的带宽（MB/s）。若改为每个时钟周期传一次呢？
2.（简答）总线仲裁的三种集中式方式（链式查询、计数器定时查询、独立请求）在**控制线数量、速度、优先级灵活性**上如何对比？
3.（简答）异步定时的三种互锁方式是什么？异步相比同步的优势与代价各是什么？
4.（计算）某磁盘转速 7200 rpm，平均寻道时间 8 ms，数据传输率 40 MB/s。读取一个 4 KB 的扇区，平均总时间约为多少？
5.（简答）DMA 与中断在数据通路、传送单位、响应时机、CPU 介入程度、优先级五个维度上有什么区别？DMA 的三种传送方式各是什么？

### 参考答案

1. 每次传送 `32 位 = 4 字节`，每 2 个时钟周期传一次：
   `带宽 = 4 B × (100 MHz / 2) = 4 × 50×10⁶ = 200×10⁶ B/s = **200 MB/s**`
   每个时钟周期传一次：`4 B × 100×10⁶ = **400 MB/s**`
   **通用公式**：`带宽 = 总线宽度(字节) × 总线频率 / 每次传送所需周期数`。若题目给的是"总线周期"而非频率，注意 `频率 = 1/总线周期`。

2. | 方式 | 控制线数（n 个设备） | 速度 | 优先级灵活性 | 可靠性 |
   |---|---|---|---|---|
   | **链式查询** | **最少**（约 3 根，BS/BR/BG） | 慢（信号逐级串行传递） | **最差**（离控制器越近优先级越高，固定） | 差（任一设备故障则后面全瘫） |
   | **计数器定时查询** | 中等（约 `log₂n + 2`） | 中 | **好**（改计数初值即可调整优先级） | 较好 |
   | **独立请求** | **最多**（`2n + 1`） | **最快**（并行判优，一次到位） | **最好**（可任意编程） | 好 |

   **记忆线索**：**线越多 → 越快 → 越灵活 → 越贵**，三者是一条单调的权衡链。

3. 三种互锁（以输入为例，`请求 Request` 与 `回答 Acknowledge` 两条握手线）：
   - **不互锁**：主设备发请求后经一段时间自动撤销，从设备回答后也自动撤销，**双方不等对方**。最快，但可靠性最低。
   - **半互锁**：主设备**必须等到**从设备的回答信号才撤销请求；从设备的回答则自动撤销。**单向等待**。
   - **全互锁**：主设备等回答才撤请求，从设备也要等**请求撤销**后才撤回答。**双向等待**，最可靠也最慢。

   **异步 vs 同步**：
   - 优势：不需要统一时钟，**能连接速度差异极大的设备**（快设备不必迁就慢设备的固定节拍），扩展性好。
   - 代价：需要**握手信号线和握手过程**，控制复杂、单次传输开销大、总体速度通常低于同步方式。
   - 折中方案是**半同步**（有时钟但允许插入等待周期 `WAIT`），也是实际总线的主流做法。

4. - **平均寻道时间** = 8 ms（题目给定）
   - **平均旋转延迟** = 转半圈的时间。`7200 rpm = 7200/60 = 120 转/秒`，一转 `1/120 s ≈ 8.33 ms`，**半转 ≈ 4.17 ms**
   - **传输时间** = `4 KB / 40 MB/s = 4096 / (40×10⁶) s ≈ 0.1 ms`

   **平均总时间 ≈ 8 + 4.17 + 0.1 ≈ 12.3 ms**
   **要点**：① 旋转延迟取**半圈**（平均值），不是整圈；② 机械盘的时间几乎全被**寻道 + 旋转**吃掉（`12.17 / 12.3 ≈ 99%`），传输时间可忽略——这正是"随机 IOPS 只有百量级"和"顺序读远快于随机读"的根本原因，也是 SSD 能快几个数量级的原因（无机械部件，寻道和旋转延迟为 0）。

5. | 维度 | 中断方式 | DMA 方式 |
   |---|---|---|
   | 数据通路 | 设备 → **CPU 寄存器** → 主存 | 设备 ↔ 主存**直连**，不经 CPU |
   | 传送单位 | 字 / 字节 | **数据块** |
   | 响应时机 | 一条**指令执行结束**后 | 一个**机器周期（存取周期）结束**后 |
   | CPU 介入 | 每传一个字都要执行中断服务程序 | 只在**传送前的初始化**和**传送后的中断**时介入 |
   | 优先级 | 低 | **高于中断**（DMA 请求更紧急，缓冲区会溢出） |
   | 实现 | 软件（中断服务程序）为主 | **硬件（DMA 控制器）**为主 |

   **DMA 三种传送方式**：
   - **停止 CPU 访存**：DMA 期间 CPU 完全让出总线。传输效率最高，但 CPU 长时间空闲，浪费大。
   - **周期挪用（周期窃取）**：DMA 只在需要时"偷"一个存取周期。若与 CPU 冲突，**DMA 优先**。**最常用**的折中方案。
   - **DMA 与 CPU 交替访存**：把一个存取周期分成两半，前半给 CPU、后半给 DMA，**不需要总线申请与释放**，效率高但硬件复杂。

**最易错的六个点**：
1. **相对寻址忘了 PC 已自增** —— 直接用指令地址加偏移
2. **OF 与 CF 混用** —— 有符号看 OF、无符号看 CF，两者独立
3. **Cache 地址划分算反方向** —— 必须从右（块内地址）往左算
4. **旋转延迟取整圈** —— 平均值是半圈
5. **按字编址 vs 按字节编址** —— 地址位数差 `log₂(字长/8)` 位
6. **MIPS 与执行时间的关系** —— MIPS 高不代表快，跨指令集比较 MIPS 无意义
