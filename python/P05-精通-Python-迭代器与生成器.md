# 精通 Python 迭代器与生成器

> 迭代器和生成器是 Python 处理数据流的核心,也是惰性求值、省内存的关键。面试常问:"iterable 和 iterator 区别?""yield 干了什么?""生成器为什么省内存?"本篇讲透迭代协议与生成器,串起 [P02 容器](./P02-精通-Python-内置容器底层.md)、[P07 推导式](./P07-精通-Python-推导式与函数式.md)、[P22 协程](./P22-精通-Python-asyncio与协程.md)。
>
> **📅 基准:2026 年 6 月,Python 3.13 / 3.14。**

---

## 一、可迭代对象 vs 迭代器

两个易混概念:

- **可迭代对象(iterable)**:实现了 `__iter__()`、能返回一个迭代器的对象。list/dict/set/str/文件都是 iterable。
- **迭代器(iterator)**:实现了 `__next__()`(返回下一个值,耗尽时抛 `StopIteration`)和 `__iter__()`(返回自身)的对象。

```python
nums = [1, 2, 3]          # 可迭代对象
it = iter(nums)           # 调 __iter__ 拿到迭代器
print(next(it))           # 1  调 __next__
print(next(it))           # 2
# ... 耗尽后 next(it) 抛 StopIteration
```

关键区别:**iterable 可以反复 `iter()` 出新迭代器;iterator 是"一次性"的**——耗尽就不能再用,且 `iter(iterator)` 返回它自己。

## 二、for 循环的本质

`for x in obj` 是语法糖,底层做的是:

```python
it = iter(obj)            # 1. 取迭代器
while True:
    try:
        x = next(it)      # 2. 反复取下一个
    except StopIteration: # 3. 抛 StopIteration 就结束
        break
    ...                   # 循环体
```

所以**任何实现了迭代协议的对象都能用 `for`**——这是鸭子类型(见 [P13](./P13-精通-Python-鸭子类型与协议.md))的体现。自定义类实现 `__iter__`(通常返回一个生成器)即可被 `for` 遍历。

## 三、生成器函数:yield

函数体里出现 `yield`,它就变成**生成器函数**——调用它不执行函数体,而是返回一个**生成器对象(迭代器)**。每次 `next()` 执行到下一个 `yield` 暂停、产出值并**保存全部局部状态**;再次 `next()` 从暂停处继续。

```python
def countdown(n):
    print("start")
    while n > 0:
        yield n           # 暂停、产出 n、保存状态
        n -= 1

g = countdown(3)          # 不打印 start!只创建生成器
print(next(g))            # 打印 start,返回 3
print(next(g))            # 返回 2(从上次暂停处继续)
for x in g: print(x)      # 1(接着之前的状态)
```

生成器是**惰性**的:值用一个算一个,不一次性生成全部。这让它能:
- **省内存**:处理大文件/大数据流时不把全部装进内存。
- **表示无限序列**:`def naturals(): n=0; while True: yield n; n+=1`。

---

## 四、生成器表达式

把列表推导的 `[]` 换成 `()` 就是**生成器表达式**——惰性版推导,不立即构建列表:

```python
# 列表推导:立即生成完整 list,占 N 份内存
total = sum([x*x for x in range(10**7)])
# 生成器表达式:惰性逐个产出,几乎不占额外内存 ✅
total = sum(x*x for x in range(10**7))
```

当结果**只需遍历一次**(传给 `sum`/`any`/`max`/`join` 等)时,优先用生成器表达式而非列表推导,省内存(见 [P07](./P07-精通-Python-推导式与函数式.md))。需要多次遍历、随机索引时才用 list。

## 五、生成器进阶:yield from 与管道

- **`yield from iterable`**:把另一个可迭代/生成器的值逐个产出,简化嵌套委托:
  ```python
  def chain(*iterables):
      for it in iterables:
          yield from it          # 等价于 for x in it: yield x
  ```
- **生成器管道**:生成器可串成惰性流水线,每个阶段只在被拉取时处理一个元素(类比 Unix 管道):
  ```python
  lines = (line.strip() for line in open("big.log"))
  errors = (l for l in lines if "ERROR" in l)
  first10 = itertools.islice(errors, 10)   # 全程惰性,只读到够 10 条
  ```
- **`send()` 与协程历史**:生成器的 `send(value)` 能往暂停的 `yield` 处"喂值",是早期协程的基础;现代异步已用 `async/await`(见 [P22](./P22-精通-Python-asyncio与协程.md)),但底层仍是这套暂停/恢复机制。

## 六、itertools:迭代器工具箱

标准库 `itertools` 提供高效的惰性迭代器组合:

```python
import itertools as it
it.count(10, 2)              # 无限:10,12,14,...
it.cycle("AB")               # 无限循环:A,B,A,B,...
it.islice(it.count(), 5)     # 切片惰性迭代器:0,1,2,3,4
it.chain([1,2], [3,4])       # 串联:1,2,3,4
it.groupby(data, key)        # 分组(需先排序)
it.product/permutations/combinations(...)  # 笛卡尔积/排列/组合
a, b = it.tee(iterable, 2)   # 复制一个迭代器为两个
```

这些都返回惰性迭代器,组合起来处理大数据流时几乎零额外内存。

## 陷阱清单

- **迭代器是一次性的**:耗尽后再遍历得到空;生成器同理不能重复迭代。需要多次遍历就转 list 或重新创建。
- **`tee` / 多次遍历生成器**:对生成器用 `list()` 后再多次用,或 `itertools.tee`(但 tee 会缓存,内存未必省)。
- **迭代中修改底层容器**:`RuntimeError`(dict/set)或行为异常(list)。
- **生成器表达式当 list 用**:`gen[0]` 不支持下标;需要索引就用列表推导。
- **`StopIteration` 在生成器内泄漏**:在生成器里 `raise StopIteration` 会被转成 `RuntimeError`(PEP 479);要结束就 `return`。
- **把惰性误当立即**:生成器表达式不传给消费者就不执行;副作用别藏在生成器里。
- **重复遍历大生成器导致重新计算**:第一次遍历已耗尽,第二次为空——容易"数据莫名为空"。

---

## 2026 现状

- **生成器/惰性迭代是处理大数据、流式日志、分页拉取的标准手段**,配合 `itertools` 写出零拷贝的处理管道。
- **异步生成器(`async def` + `yield`)与 `async for`**(见 [P23](./P23-精通-Python-异步实战与陷阱.md))把惰性流扩展到异步 IO(如分页异步拉取)。
- **`yield from` / 协程基础**是理解 asyncio 底层(协程的暂停恢复)的钥匙(见 [P22](./P22-精通-Python-asyncio与协程.md))。
- 与 Go 对照:Go 1.23 的 `range over func`(iter.Seq)迭代器和 Python 生成器异曲同工,都是"惰性产出 + 调用方拉取"。

## 练习题

1. 可迭代对象(iterable)和迭代器(iterator)有什么区别?

<details><summary>参考答案</summary>

**可迭代对象(iterable)**是实现了 `__iter__()` 方法、能够返回一个迭代器的对象——它表示"可以被遍历",但本身不维护遍历位置。list、tuple、dict、set、str、文件对象等都是可迭代对象。**迭代器(iterator)**是实现了 `__next__()` 方法(每次调用返回下一个元素,没有元素时抛 `StopIteration`)、并且也实现了 `__iter__()`(返回自身)的对象——它**维护着遍历的当前位置/状态**,知道"下一个该给谁"。关系:对可迭代对象调用 `iter(obj)`(触发 `__iter__`)会得到一个迭代器;对迭代器调用 `next(it)`(触发 `__next__`)逐个取值。关键区别:①**可迭代对象可以被反复遍历**——每次 `iter()` 都返回一个全新的、从头开始的迭代器(如一个 list 可以 for 循环很多次);②**迭代器是一次性的、有状态的**——它记录消费进度,耗尽(抛过 StopIteration)后就空了,不能复用,且对迭代器再调用 `iter()` 返回的是它**自己**(不会重置)。所以"list 是 iterable 但不是 iterator","`iter(list)` 得到的才是 iterator"。这个区分解释了一个常见 bug:把生成器(迭代器)遍历一次后再遍历会得到空。需要多次遍历就保留可迭代对象(或转成 list),而不是保留迭代器。

</details>

2. `for` 循环底层是怎么工作的?

<details><summary>参考答案</summary>

`for x in obj:` 是语法糖,底层步骤是:①先对 `obj` 调用 `iter(obj)`(即触发它的 `__iter__()` 方法)获得一个**迭代器**;②进入循环,反复调用 `next(迭代器)`(触发 `__next__()`)取出下一个元素赋给 `x`,执行一次循环体;③当迭代器耗尽、`__next__()` 抛出 **`StopIteration`** 异常时,`for` 捕获这个异常并**正常结束循环**(不会把异常往外抛)。用伪代码表示就是:`it = iter(obj); while True: try: x = next(it) except StopIteration: break; <循环体>`。这个机制的意义在于:**任何实现了迭代协议(`__iter__` 返回迭代器、迭代器有 `__next__`)的对象都能直接用于 `for` 循环**,这正是鸭子类型的体现——`for` 不关心对象具体是什么类型,只要它"可迭代"即可。因此我们可以给自定义类实现 `__iter__`(通常返回一个生成器或一个配套的迭代器对象),它就能像内置容器一样被 `for` 遍历、被 `list()`/`sum()`/解包等消费。同理 `in`、推导式、`*` 解包、`zip`/`map` 等也都基于这套协议。理解这点也解释了为什么 `for` 能优雅处理生成器、文件逐行读取、无限序列(配合 break)等。

</details>

3. `yield` 是什么?生成器为什么能"省内存"?

<details><summary>参考答案</summary>

当一个函数体内出现 `yield` 关键字,这个函数就变成**生成器函数**:调用它时**不会执行函数体**,而是立即返回一个**生成器对象**(它是一个迭代器)。只有当对这个生成器调用 `next()`(或用 `for` 遍历、被 `sum` 等消费)时,函数体才开始/继续执行,一直运行到遇到 `yield` 表达式:此时函数**暂停**,把 `yield` 后面的值**产出**给调用方,并**完整保存当前的执行状态**(局部变量、指令位置);下次 `next()` 时从暂停处**恢复**继续执行,直到下一个 `yield` 或函数结束(结束时抛 `StopIteration`)。所以生成器是"可暂停/可恢复的函数",实现了**惰性求值**——值是"一次要一个、要时才算"。**省内存的原因**:普通做法(如返回一个 list)会**一次性把所有结果全部计算并存进内存**,N 个元素就占 N 份内存;而生成器**任意时刻只在内存中保留当前一个元素和少量状态**,边产出边被消费、用完即可丢弃,不需要同时持有全部数据。因此处理大文件(逐行 yield)、大数据流、或本质无限的序列(如 `count()`)时,生成器能把内存占用从 O(n) 降到 O(1)。代价是生成器只能单向遍历一次、不支持随机下标访问,且若需要多次使用结果则要重新生成或转 list。典型用法是把多个生成器串成惰性流水线,全程几乎不额外占内存。

</details>

4. 列表推导和生成器表达式有什么区别?什么时候用哪个?

<details><summary>参考答案</summary>

**列表推导 `[expr for x in it]`** 会**立即执行、一次性构建出完整的 list** 并放在内存里,得到一个真正的列表对象(可下标访问、可多次遍历、有 len)。**生成器表达式 `(expr for x in it)`** 返回一个**生成器(惰性迭代器)**,**不立即计算**,只有在被遍历/消费时才逐个产出元素,任意时刻只在内存里保留当前一个,几乎不占额外内存,但只能遍历一次、不支持下标和 len。**选择原则**:①当结果**只需要遍历一次**、尤其是直接喂给聚合/消费函数(`sum`、`any`、`all`、`max`、`min`、`"".join`、`for` 等)时,**优先用生成器表达式**,省内存且往往支持短路提前结束(如 `any(x>0 for x in big)` 找到一个就停)——例如 `sum(x*x for x in range(10**7))` 不会先建一个千万元素的 list;②当需要**多次遍历**结果、**随机下标访问**、需要 `len()`、或要把结果传给会多次迭代它的代码时,用**列表推导**得到实体 list;③数据量很大或可能无限时必须用生成器表达式(列表推导会爆内存或无法完成);④注意生成器只能消费一次,消费完再用会得到空。一个细节:当生成器表达式是某函数调用的**唯一**实参时,可以省略外层括号,如 `sum(x for x in nums)`。总之:一次性消费、省内存选生成器表达式;要复用、要索引选列表推导。

</details>

5. `itertools` 有什么用?举几个常用的例子。

<details><summary>参考答案</summary>

`itertools` 是标准库提供的一组**高效、惰性的迭代器构造与组合工具**,它们都返回迭代器(惰性产出、内存友好),用于以"流式"的方式处理序列而无需构建中间大列表,常用来写简洁高效的数据处理管道。常用函数:①**无限迭代器**——`count(start, step)`(无限计数,如 `count(0)` 产出 0,1,2,...)、`cycle(iterable)`(无限循环某序列)、`repeat(x, n)`(重复 x);②**截断/切片**——`islice(iterable, stop)` 或 `islice(it, start, stop, step)`(对迭代器做惰性切片,常配合无限迭代器使用,如 `islice(count(), 5)` 取前 5 个);③**组合多个序列**——`chain(*iterables)`(把多个可迭代对象首尾相连成一个,如 `chain([1,2],[3,4])`)、`chain.from_iterable`(展开嵌套);④**分组**——`groupby(iterable, key)`(按 key 连续分组,注意需先按 key 排序);⑤**笛卡尔积/排列组合**——`product`、`permutations`、`combinations`(替代多重循环);⑥**复制迭代器**——`tee(it, n)`(把一个迭代器分成 n 个可独立遍历的,但内部会缓存);⑦**其他**——`accumulate`(累积/前缀和)、`takewhile`/`dropwhile`/`filterfalse`、`starmap`、`zip_longest`。优势:这些都是 C 实现、惰性、可组合,处理大数据流时几乎不占额外内存且性能好;例如逐行读大日志、过滤、取前 N 条的管道全程惰性。

</details>

6. 迭代器"一次性"会带来什么坑?如何应对?

<details><summary>参考答案</summary>

迭代器(包括生成器)是**有状态、只能消费一次**的:它内部记录遍历进度,遍历到末尾(抛出 StopIteration)后就**耗尽**了,再次遍历只会得到空、不会自动从头开始(对迭代器调用 `iter()` 返回的还是它自己,不重置)。由此产生的坑:①**"数据莫名为空"**——把一个生成器先遍历一次(如先 `for` 统计一遍),再遍历第二次(如再 `for` 处理),第二次拿到的是空,逻辑出错;同理把生成器传给会遍历它两遍的函数也会出问题;②**`list(gen)` 之后 gen 仍是空的**——转换会消费掉它;③对 `zip`/`map`(它们返回的也是一次性迭代器)同样适用。**应对**:①如果需要**多次遍历**,就把数据**物化成 list/tuple**(`data = list(gen)`),之后随便遍历多少次——代价是失去惰性、占内存;②如果数据量大不能全装内存但确实要遍历多次,要么**每次重新创建生成器**(重新调用生成器函数),要么用 `itertools.tee(it, n)` 复制成多个(但 tee 会缓存已产出元素,若两个分支进度差很大反而占内存);③在函数接口设计上,明确参数是"可迭代对象(可重复遍历)"还是"迭代器(一次性)",必要时在函数内部 `data = list(data)` 防御;④注意不要在遍历生成器的同时又依赖它"还能再遍历"。一句话:迭代器用完即弃,需要复用就先物化或重建。

</details>
