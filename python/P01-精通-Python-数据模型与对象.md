>

## 一、一切皆对象

Python 里**一切皆对象**——整数、字符串、函数、类、模块,统统是对象。每个对象有三个不变属性:

- **身份(identity)**: 对象在内存中的唯一标识,用 `id(obj)` 取(CPython 里就是内存地址)。一经创建不变。
- **类型(type)**: `type(obj)`,决定对象支持哪些操作。类型本身也是对象(类型的类型是 `type`,见 [P12 元类](./P12-精通-Python-元类与类创建.md))。
- **值(value)**: 对象持有的数据。

```python
x = 42
print(id(x), type(x))      # 某地址, <class 'int'>
print(type(int), type(type))  # <class 'type'> <class 'type'>——type 是自己的类型
```

连函数和类都是"一等对象":可赋值给变量、作参数传递、作返回值、存进容器。这是装饰器([P06](./P06-精通-Python-装饰器与上下文管理器.md))和高阶函数的基础。

---

## 二、变量是"名字",赋值是"绑定"

这是 Python 区别于 C/Java 的核心:**变量不是装值的盒子,而是贴在对象上的标签**。`x = 42` 的含义是"让名字 `x` 指向那个值为 42 的对象",不是"把 42 拷进 x"。

```python
a = [1, 2, 3]
b = a            # 不是拷贝!b 和 a 是同一个列表对象的两个名字
b.append(4)
print(a)         # [1, 2, 3, 4]——通过 b 改了,a 也"变了"(其实是同一对象)
print(a is b)    # True
```

赋值**从不复制对象**,只是多绑一个名字。理解这点,函数传参([P04](./P04-精通-Python-函数参数与作用域.md))、容器别名、默认参数陷阱就都通了。

## 三、`is` vs `==`

- **`==`** 比较**值**是否相等,调用 `__eq__`。
- **`is`** 比较**身份**(是不是同一个对象),即 `id(a) == id(b)`,不可重载。

```python
a = [1, 2]; b = [1, 2]
print(a == b)   # True ——值相等
print(a is b)   # False——两个不同对象
```

**准则**:比较值用 `==`;只有判断"是不是同一个对象"或和单例比较时才用 `is`。和 `None`/`True`/`False` 比较**必须用 `is`**(它们是单例):`if x is None`,不要写 `if x == None`。

⚠️ **小整数缓存 / 字符串 intern 的迷惑**:

```python
a = 256; b = 256; print(a is b)   # True ——CPython 缓存 -5~256 的小整数
a = 257; b = 257; print(a is b)   # 可能 False ——超出缓存范围,是不同对象
```

这只是 CPython 的优化(见 [P18](./P18-精通-Python-对象内存优化.md)),**绝不能依赖 `is` 比较数值/字符串相等**——结果随实现和上下文变化。

## 四、可变 vs 不可变

| 不可变(immutable) | 可变(mutable) |
|---|---|
| `int` `float` `bool` `str` `bytes` `tuple` `frozenset` `None` | `list` `dict` `set` `bytearray` 及大多数自定义对象 |

- **不可变对象**一经创建值不能改。"修改"其实是创建新对象、重新绑定名字:
  ```python
  s = "abc"; print(id(s))
  s += "d"; print(id(s))   # 地址变了——生成了新字符串,不是原地改
  ```
- **可变对象**可原地修改,身份不变(`list.append`、`dict[k]=v`)。

影响深远:
- **只有不可变(可哈希)对象能做 dict 的键 / set 的元素**(见 [P02](./P02-精通-Python-内置容器底层.md))。`list` 不可哈希,不能当键;`tuple`(元素都不可变时)可以。
- **可变默认参数是经典陷阱**(见 [P04](./P04-精通-Python-函数参数与作用域.md))。
- 不可变对象天然线程安全、可安全共享(呼应 [P20 并发](./P20-精通-Python-多线程threading.md))。

可哈希性:`hash(obj)` 可调用即可哈希。默认对象按身份哈希;不可变内置类型按值哈希。**重写 `__eq__` 会使对象变得不可哈希**(除非也定义 `__hash__`),因为"相等的对象必须有相等的哈希"这一契约需要你维护。

## 五、数据模型:`__dunder__` 协议

Python 的"数据模型"是一套**双下划线特殊方法(dunder, magic methods)**协议:你在自定义类里实现它们,对象就能融入语言的内置语法(运算符、`len()`、`for`、`with`、`[]`…)。这是 Python "可扩展但语法统一"的精髓——**用协议而非继承**。

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):                      # repr():开发者友好,应可还原对象
        return f"Vector({self.x}, {self.y})"
    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)
    def __hash__(self):                      # 配合 __eq__,让对象可哈希
        return hash((self.x, self.y))
    def __add__(self, other):                # 支持 v1 + v2
        return Vector(self.x + other.x, self.y + other.y)
    def __len__(self):                       # 支持 len(v)
        return 2
```

常用协议:`__init__`(初始化)、`__new__`(创建,见 [P12](./P12-精通-Python-元类与类创建.md))、`__repr__`/`__str__`、`__eq__`/`__hash__`、`__len__`/`__getitem__`/`__iter__`([P05](./P05-精通-Python-迭代器与生成器.md))、`__enter__`/`__exit__`([P06](./P06-精通-Python-装饰器与上下文管理器.md))、`__call__`、算术与比较运算符等。

`__repr__` vs `__str__`:`repr()`/交互式回显/容器内显示用 `__repr__`(面向开发者,信息完整);`str()`/`print()` 用 `__str__`(面向用户,可读)。只定义一个就定义 `__repr__`(`__str__` 默认回退到它)。

## 六、深拷贝与浅拷贝

因为赋值不复制,需要副本时用 `copy`:

```python
import copy
a = [[1, 2], [3, 4]]
b = a.copy()              # 浅拷贝(等价 a[:]、list(a)、copy.copy(a))
b.append([5, 6])          # 顶层独立:不影响 a
b[0].append(99)           # 但内层是共享引用!
print(a)                  # [[1, 2, 99], [3, 4]] ——a 的内层也变了

c = copy.deepcopy(a)      # 深拷贝:递归复制所有层级,完全独立
```

- **浅拷贝**:新建外层容器,但元素仍是**原对象的引用**(共享内层)。
- **深拷贝**:递归复制每一层,得到完全独立的对象(能正确处理循环引用)。

可变嵌套结构要"真正独立的副本"时用 `deepcopy`;深拷贝有性能成本,不可变结构无需拷贝。

## 陷阱清单

- **用 `is` 比较值**:`x is 257`、`s is "abc"` 结果靠 CPython 缓存,不可靠。值比较一律 `==`,只有 `None`/单例用 `is`。
- **以为赋值会拷贝**:`b = a` 后改 `b` 影响 `a`(同一对象)。需要副本用 `copy`/`deepcopy` 或切片。
- **浅拷贝以为是深拷贝**:嵌套结构 `a.copy()` 只复制外层,内层仍共享。
- **重写 `__eq__` 忘了 `__hash__`**:对象变得不可哈希(不能进 set/做 dict 键),或哈希契约被破坏。
- **拿可变对象做 dict 键**:`list` 不可哈希直接报错;需用 `tuple`。
- **`==` 与 `is` 混淆导致的 bug**:尤其 `if x == None` 在自定义 `__eq__` 下可能行为异常,用 `is None`。
- **可变对象作为类属性被所有实例共享**:类体里的 `data = []` 是类属性,所有实例共用(类似默认参数坑,见 [P09](./P09-精通-Python-类与属性查找.md))。

## 2026 现状

- **数据模型是 Python 的"协议优先"哲学的体现**:鸭子类型([P13](./P13-精通-Python-鸭子类型与协议.md))靠的就是"实现了协议方法即可",而非继承某基类。
- **`@dataclass`(3.7+)与 Pydantic(v2)** 自动生成 `__init__/__repr__/__eq__` 等样板,现代代码大量用它们定义数据类(类比 Java record,见 [J29](../java/J29-精通-Java版本特性演进.md)):`@dataclass(frozen=True)` 得到不可变值对象。
- **`match` 语句(3.10+ 结构化模式匹配)** 配合 `__match_args__` 可解构对象,现代写法。
- **不可变 + 类型注解([P14](./P14-精通-Python-类型注解与typing.md))** 成为编写可靠数据模型的主流范式。

## 练习题

1. `is` 和 `==` 有什么区别?为什么 `256 is 256` 是 True 而 `257 is 257` 可能是 False?

<details><summary>参考答案</summary>

`==` 比较两个对象的**值**是否相等,会调用对象的 `__eq__` 方法(可重载);`is` 比较两个名字是否指向**同一个对象**(身份),等价于 `id(a) == id(b)`,不可重载。日常比较值用 `==`;只有判断"是否同一对象"或与单例(`None`/`True`/`False`)比较时用 `is`(如 `if x is None`)。`256 is 256` 为 True、`257 is 257` 可能为 False 的原因是 **CPython 的小整数缓存优化**:解释器在启动时预先创建并缓存了 -5 到 256 之间的整数对象,这个范围内的整数字面量总是复用同一个缓存对象,所以 `is` 为 True;而 257 超出缓存范围,每次出现都(可能)创建新的 int 对象,两个 257 是不同对象,`is` 为 False(实际结果还受是否在同一编译单元/常量折叠影响)。这正说明**不能用 `is` 比较数值或字符串是否相等**——它依赖 CPython 的实现细节(缓存、intern),结果不可靠且不可移植,值相等必须用 `==`。

</details>

2. Python 里"变量赋值"到底发生了什么?`b = a` 之后修改 `b` 为什么可能影响 `a`?

<details><summary>参考答案</summary>

Python 的变量不是"装值的盒子",而是**绑定到对象的名字(引用)**。`x = 42` 的本质是:创建(或复用)一个值为 42 的对象,然后让名字 `x` 指向它。赋值操作**从不复制对象**,只是建立"名字→对象"的绑定。因此 `b = a` 让 `b` 和 `a` 成为**同一个对象的两个名字**(`a is b` 为 True),它们指向同一块数据。如果该对象是**可变的**(如 list、dict),通过任一名字原地修改它(`b.append(...)`、`b[0]=...`),另一名字看到的也是被修改后的同一对象,于是"改 b 影响了 a"。若对象是**不可变的**(如 int、str、tuple),则不存在原地修改——`b += 1` 会创建新对象并把 `b` 重新绑定到新对象,`a` 仍指向旧对象、不受影响。要得到真正独立的副本,需显式拷贝:浅拷贝(`a.copy()`、`a[:]`、`list(a)`、`copy.copy`)只复制外层容器、内层元素仍共享引用;深拷贝(`copy.deepcopy`)递归复制所有层级、完全独立。

</details>

3. 哪些内置类型是不可变的?可变/不可变的区分带来哪些实际影响?

<details><summary>参考答案</summary>

**不可变类型**:`int`、`float`、`complex`、`bool`、`str`、`bytes`、`tuple`、`frozenset`、`None`。**可变类型**:`list`、`dict`、`set`、`bytearray`,以及大多数自定义类的实例。区别在于对象创建后值能否原地改变:不可变对象的"修改"实际是创建新对象并重新绑定名字(如 `s += "x"` 后 `id(s)` 变了),可变对象可原地修改而身份不变。实际影响:①**可哈希性与作为键**——只有可哈希(通常即不可变)的对象才能作 `dict` 的键或 `set` 的元素,`list` 不可哈希会报 `TypeError`,需用 `tuple`(且其元素也须不可变);②**默认参数陷阱**——函数默认值在定义时只创建一次,可变默认值(如 `def f(x, lst=[])`)会在多次调用间被共享累积,应改用 `None` 哨兵(见 P04);③**别名副作用**——多个名字指向同一可变对象时,一处修改处处可见,需注意拷贝;④**类属性共享**——可变对象作类属性会被所有实例共享;⑤**线程安全**——不可变对象天然线程安全、可自由共享,可变对象跨线程需同步(见 P20);⑥**函数传参**——传可变对象时函数内修改会影响外部。理解可变性是避免一大类隐蔽 bug 的关键。

</details>

4. 什么是 Python 的"数据模型"/dunder 方法?举例说明它如何让自定义对象融入语言语法。

<details><summary>参考答案</summary>

Python 的"数据模型"是一套**特殊方法(special methods,即双下划线包裹的 dunder/magic methods)协议**:你在自定义类里实现这些方法,解释器在执行相应的内置语法/函数时就会自动调用它们,从而让自定义对象"表现得像内置类型"。这体现了 Python "协议优先于继承"的设计——对象支持某操作,靠的是实现对应协议方法,而非继承特定基类。例子:实现 `__len__` 后 `len(obj)` 可用;实现 `__getitem__` 后 `obj[i]` 和(配合)`for x in obj` 可用;实现 `__iter__`/`__next__` 让对象可迭代(见 P05);实现 `__eq__`(并配 `__hash__`)定义相等与可哈希;实现 `__add__`/`__lt__` 等支持 `+`/`<` 运算符;实现 `__enter__`/`__exit__` 支持 `with`(见 P06);实现 `__call__` 让实例可像函数一样调用;`__repr__`(开发者友好、信息完整,交互回显与容器内显示用)和 `__str__`(用户友好,`print` 用,默认回退到 `__repr__`)控制对象的字符串表示。比如定义了 `__add__` 和 `__repr__` 的 `Vector` 类就能写 `v1 + v2` 并被友好打印。`@dataclass` 和 Pydantic 正是自动为你生成这些 dunder(`__init__/__repr__/__eq__` 等)以减少样板。

</details>

5. 浅拷贝和深拷贝有什么区别?各在什么场景用?

<details><summary>参考答案</summary>

**浅拷贝(shallow copy)**:创建一个新的外层容器对象,但新容器里的元素仍然是**原容器中元素的引用**(不递归复制内层对象)。得到方式:`list(a)`、`a[:]`、`a.copy()`、`copy.copy(a)`。效果是外层独立(对新容器增删元素不影响原容器),但若元素是可变对象,通过任一容器修改某个内层元素,另一容器也会看到变化(因为共享同一内层对象)。**深拷贝(deep copy)**:`copy.deepcopy(a)`,递归地复制对象及其所有层级的子对象,得到一棵与原对象完全独立的对象树,修改副本的任何层级都不影响原对象;它还能正确处理**循环引用**(内部用 memo 字典记录已复制对象,避免无限递归)。**场景**:①当数据结构是**扁平的或元素不可变**时,浅拷贝就够了(且更快),比如复制一个 `list[int]`;②当需要修改副本的**嵌套可变内容**而绝不能影响原对象时(如复制 `list[list]`、嵌套 dict 配置),必须用深拷贝;③深拷贝有明显性能和内存开销,不应滥用——对不可变对象无需拷贝(它们可安全共享),只在确有"独立可变副本"需求时才深拷贝。

</details>

6. 重写 `__eq__` 时为什么往往需要同时定义 `__hash__`?

<details><summary>参考答案</summary>

因为 Python 有一条核心契约:**相等的对象必须有相等的哈希值**(`a == b` 为真 ⇒ `hash(a) == hash(b)`)。哈希用于 `dict`/`set` 的快速定位:它们先用 `hash()` 找到桶,再用 `==` 在桶内确认。如果两个相等的对象哈希不同,就可能被分到不同桶,导致 set 里出现"重复"、dict 查找失败等错误。默认情况下,对象的 `__hash__` 基于其**身份(id)**、`__eq__` 也基于身份,二者一致。但一旦你重写 `__eq__` 让相等基于**值**(如两个字段相同即相等),默认的基于 id 的 `__hash__` 就与新的相等语义不匹配了。为防止你无意中破坏契约,**Python 规定:一个类只要定义了 `__eq__`,其 `__hash__` 就会被自动设为 `None`,从而该类实例变得不可哈希**(放进 set/做 dict 键会报 `TypeError: unhashable type`)。所以:①如果希望对象按值可哈希(能进 set/做键),重写 `__eq__` 后必须同时定义 `__hash__`,且哈希应基于参与相等比较的那些(不可变)字段,如 `return hash((self.x, self.y))`;②如果对象本就该是可变、不应作为键,那保持不可哈希是合理的;③`@dataclass(frozen=True, eq=True)` 会自动正确生成配套的 `__eq__` 和 `__hash__`,省去手写。

</details>
