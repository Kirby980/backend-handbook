# 精通 Python 类与属性查找

> 类与对象人人会写,但"属性到底从哪找来的"很多人说不清:实例属性、类属性、`__dict__`、`__slots__`、`__getattr__`。面试常问:"类属性和实例属性区别?""`__slots__` 干嘛的?"本篇讲透属性查找机制,为 [P11 描述符](./P11-精通-Python-描述符与property.md)、[P10 MRO](./P10-精通-Python-继承与MRO.md)打底。
>
> **📅 基准:2026 年 6 月,Python 3.13 / 3.14。**

---

## 一、实例属性 vs 类属性

```python
class Dog:
    species = "犬"             # 类属性:所有实例共享,存在 Dog.__dict__
    def __init__(self, name):
        self.name = name       # 实例属性:每个实例独有,存在 self.__dict__

a, b = Dog("旺财"), Dog("来福")
print(a.species, b.species)    # 都是 "犬" —— 共享类属性
a.name                         # 实例属性,各自不同
```

- **类属性**:定义在类体里,存在**类的 `__dict__`**,被所有实例共享。
- **实例属性**:通常在 `__init__` 里 `self.x = ...` 创建,存在**实例自己的 `__dict__`**。

`obj.__dict__` 是一个字典,存放该实例的属性。`type(obj).__dict__` 存放类的属性/方法。

---

## 二、属性查找顺序

读 `obj.attr` 时,Python 大致按此顺序找(完整含描述符的版本见 [P11](./P11-精通-Python-描述符与property.md)):

1. **类型(及其 MRO)中的数据描述符**(如 `property`)——优先级最高
2. **实例的 `__dict__`**——实例属性
3. **类型(及 MRO,见 [P10](./P10-精通-Python-继承与MRO.md))中的类属性 / 非数据描述符**(普通方法、函数)
4. 都没有 → 调 **`__getattr__`** 兜底,否则抛 `AttributeError`

```python
class C:
    x = "类属性"
c = C()
print(c.x)        # "类属性"(实例没有 x,落到类)
c.x = "实例属性"  # 在实例 __dict__ 里新建 x,遮蔽类属性
print(c.x)        # "实例属性"
print(C.x)        # "类属性"(类的没变)
del c.x
print(c.x)        # "类属性"(实例的删了,又看到类的)
```

赋值 `c.x = ...` 默认**只写实例的 `__dict__`**(遮蔽,不改类属性)。理解这条线能解释一大类"属性行为诡异"的问题。

## 三、可变类属性的共享坑

类属性被所有实例共享——如果它是**可变对象**,所有实例会共用同一个(类似默认可变参数坑,见 [P04](./P04-精通-Python-函数参数与作用域.md)):

```python
class Team:
    members = []               # ❌ 可变类属性,所有实例共享!
    def add(self, m):
        self.members.append(m) # 改的是共享的那一个 list

t1, t2 = Team(), Team()
t1.add("Alice")
print(t2.members)              # ['Alice'] —— t2 也"有"了!
```

修复:可变状态应放**实例属性**(在 `__init__` 里 `self.members = []`)。类属性适合放**不可变的常量/默认值/所有实例共享的配置**。

注意区别:`self.members.append(x)` 是**原地修改共享对象**(影响所有);`self.members = [x]` 是在实例 `__dict__` 里**新建**(只影响自己)。

## 四、`__slots__`:省内存、限属性

默认每个实例有个 `__dict__`(dict 开销不小)。`__slots__` 声明固定的属性名,让实例**不再有 `__dict__`**,改用紧凑的定长存储:

```python
class Point:
    __slots__ = ("x", "y")     # 只允许 x、y 两个属性
    def __init__(self, x, y):
        self.x, self.y = x, y

p = Point(1, 2)
# p.z = 3                      # AttributeError!不在 __slots__ 中
```

- **省内存**:海量小对象(几十万个 Point)能省可观内存(见 [P18](./P18-精通-Python-对象内存优化.md))。
- **代价**:不能动态加属性、不能有 `__dict__`(除非把 `"__dict__"` 也写进 slots);多继承有限制;`__slots__` 不被子类自动继承(子类要自己声明,否则又有 `__dict__`)。
- 适合**字段固定、数量巨大**的数据类;`@dataclass(slots=True)`(3.10+)可自动加。

## 五、拦截属性访问

三个钩子让你定制属性访问(慎用,易出错):

- **`__getattr__(self, name)`**:**仅当常规查找失败**(实例和类都没找到)时调用——做动态属性/兜底/懒加载/代理。
- **`__getattribute__(self, name)`**:**每次**属性访问都先调它(无条件)——极强大也极危险,容易无限递归(内部要用 `super().__getattribute__(name)` 而非 `self.name`)。
- **`__setattr__(self, name, value)`**:拦截所有 `self.x = v` 赋值(同样要小心递归,用 `super().__setattr__` 或 `self.__dict__[name]=v`)。

```python
class LazyConfig:
    def __getattr__(self, name):           # 只在找不到时触发
        value = load_from_disk(name)
        setattr(self, name, value)         # 缓存到实例
        return value
```

`__getattr__` 是实现 ORM 字段、代理对象、惰性加载的常用手段。

## 六、方法也是属性

方法本质上是类里的**函数属性**;`obj.method` 取到的是**绑定方法(bound method)**——它把 `obj` 绑为第一个参数 `self`(这背后是描述符,见 [P11](./P11-精通-Python-描述符与property.md))。

```python
class C:
    def greet(self): return "hi"
c = C()
print(c.greet)            # <bound method C.greet of ...>
print(C.greet)            # <function C.greet ...>(未绑定,普通函数)
print(c.greet())          # "hi";等价 C.greet(c)
```

`@staticmethod`(不接收 self)、`@classmethod`(接收 cls)、`@property`(像属性一样访问)都是通过描述符机制改变方法的绑定行为(见 [P11](./P11-精通-Python-描述符与property.md))。

## 陷阱清单

- **可变类属性被所有实例共享**:`members = []` 当类属性,一个实例改、全体变。可变状态放 `__init__` 的实例属性。
- **以为 `obj.x = v` 会改类属性**:它只在实例 `__dict__` 新建/遮蔽,类属性不变。
- **`__slots__` 不被继承**:子类不声明 `__slots__` 就又有 `__dict__`,省内存失效。
- **`__slots__` 与需要动态属性/弱引用冲突**:需要 `__dict__`/`__weakref__` 要显式加进 slots。
- **`__getattribute__` 内用 `self.x`**:无限递归;用 `super().__getattribute__`。
- **`__getattr__` 与 `__getattribute__` 混淆**:前者只在查找失败时调,后者每次都调。
- **在 `__init__` 外随意加实例属性**:属性散落各处,可读性差;集中在 `__init__` 或用 dataclass。

---

## 2026 现状

- **`@dataclass`(3.7+)是定义数据类的主流**:自动 `__init__/__repr__/__eq__`,`slots=True` 省内存,`frozen=True` 不可变(见 [P01](./P01-精通-Python-数据模型与对象.md));比手写类省大量样板。
- **Pydantic v2** 在需要校验/序列化的数据模型(API 出入参)中流行,底层 Rust 提速。
- **`__slots__`** 仍是性能敏感、海量实例场景的省内存利器(见 [P18](./P18-精通-Python-对象内存优化.md))。
- 与 Java 对照:Python 实例属性存在 `__dict__`(动态、可随时加),Java 字段在编译期固定;`__slots__` 让 Python 实例"像 Java 一样"字段固定+省内存。

## 练习题

1. 类属性和实例属性有什么区别?分别存在哪里?

<details><summary>参考答案</summary>

**类属性**是定义在类体里(`class` 语句块中、方法之外)的属性,它存储在**类对象的 `__dict__`**(即 `ClassName.__dict__`)中,**被该类的所有实例共享**——所有实例看到的是同一个类属性。**实例属性**通常在方法里(尤其 `__init__`)通过 `self.x = ...` 创建,存储在**实例自己的 `__dict__`**(即 `obj.__dict__`)中,**每个实例独有**、互不影响。访问 `obj.attr` 时,Python 先查实例的 `__dict__`,没有再查类(及其基类 MRO)的 `__dict__`,所以实例属性会"遮蔽"同名类属性。关键点:①**赋值 `obj.x = v` 默认只在实例 `__dict__` 里创建/修改 x**,不会改动类属性(即使类有同名属性,也只是在实例层面新建一个遮蔽它);要修改类属性得用 `ClassName.x = v`;②因此类属性适合放**所有实例共享的常量、默认值、配置**;实例属性适合放**每个对象各自的状态**;③一个重要陷阱:如果类属性是**可变对象**(如 `[]`、`{}`),由于被所有实例共享,任一实例对它的**原地修改**(append 等)会影响所有实例,所以可变状态必须放实例属性(在 `__init__` 里新建)。可用 `obj.__dict__` 和 `type(obj).__dict__` 分别查看实例和类的属性字典来验证。

</details>

2. 描述一下 Python 读取 `obj.attr` 时的属性查找顺序。

<details><summary>参考答案</summary>

(简化但准确的)查找顺序如下——Python 在求值 `obj.attr` 时,实际调用 `type(obj).__getattribute__(obj, 'attr')`,其默认逻辑为:①先在 **`type(obj)` 及其 MRO(继承链,见 P10)中查找名为 attr 的类属性**,看它是否是一个**数据描述符**(定义了 `__set__` 或 `__delete__` 的对象,如 `property`,见 P11)——如果是,**数据描述符优先级最高**,直接调用其 `__get__` 返回结果;②否则,查找**实例自身的 `__dict__`**(`obj.__dict__`),如果 attr 在其中,返回该实例属性;③否则,回到第①步找到的类属性:如果它是**非数据描述符**(只有 `__get__`,如普通函数/方法)或普通类属性,则返回它(对非数据描述符调用 `__get__`,这正是方法绑定 self 的机制);④如果以上都没找到,调用 **`__getattr__`**(如果类定义了的话)作为兜底,否则抛出 **`AttributeError`**。记忆优先级:**数据描述符 > 实例 `__dict__` > 非数据描述符/类属性 > `__getattr__`**。这条规则解释了很多现象:为什么 `property`(数据描述符)能"压过"同名实例属性、为什么实例属性能遮蔽普通类属性、为什么方法能自动绑定 self、`__slots__` 和 `cached_property` 的行为等。注意 `__getattribute__` 是每次访问都会调用的总入口(可重写但极易递归),而 `__getattr__` 只在常规查找失败后才调用。

</details>

3. 为什么把可变对象(如列表)作为类属性是个坑?

<details><summary>参考答案</summary>

因为**类属性被该类的所有实例共享**——所有实例访问到的是**同一个**类属性对象。如果这个类属性是**可变对象**(list、dict、set 等),那么任何一个实例对它进行**原地修改**(如 `self.members.append(x)`、`self.cache[k]=v`),修改的都是这个被共享的同一个对象,于是**所有实例都会看到这个改动**,造成"我只往一个实例里加了数据,怎么别的实例也有了"的诡异 bug。例如 `class Team: members = []`,然后 `t1.add("Alice")` 后 `t2.members` 也变成 `['Alice']`,因为 `t1.members` 和 `t2.members` 是同一个 list。这与"默认可变参数"陷阱(P04)同源:都是"本应每个独立、却共享了同一个可变对象"。**正确做法**:把每个实例各自的可变状态放到**实例属性**——在 `__init__` 里 `self.members = []`,这样每个实例创建时都新建一个独立的 list,互不影响。**辨析一个关键点**:`self.members.append(x)` 是对(共享的)对象**原地修改**,会影响所有实例;而 `self.members = [x]` 是在**实例自己的 `__dict__` 里新建**一个 members 属性遮蔽类属性,只影响该实例(但这通常意味着你本就该用实例属性)。所以原则是:**类属性只放不可变的常量/默认值/共享配置;凡是每个对象各自的、会被修改的状态,一律放实例属性**。

</details>

4. `__slots__` 是什么?用它有什么好处和代价?

<details><summary>参考答案</summary>

默认情况下,Python 每个实例都有一个 `__dict__`(一个字典)来存储其实例属性,这让对象可以**动态地添加任意属性**,但字典本身有不小的内存开销。**`__slots__`** 是在类里定义的一个特殊类属性(一个字符串序列,如 `__slots__ = ("x", "y")`),它声明"这个类的实例**只允许拥有这些固定的属性**"。这样做的效果是:CPython 不再给实例创建 `__dict__`,而是用一种**紧凑的、类似 C 结构体的定长存储**(在类型对象上为每个 slot 预留固定位置、用描述符访问)来存这些属性。**好处**:①**显著省内存**——对于需要创建**大量小对象**的场景(如几十万、上百万个只有几个字段的实例),去掉每实例的 dict 能节省可观内存(见 P18);②**属性访问略快**;③**防止误加属性**——拼写错属性名(`self.naem = ...`)会直接报 `AttributeError` 而非悄悄新建一个属性。**代价/限制**:①**不能再动态添加未声明的属性**(`obj.new_attr = 1` 会 `AttributeError`),牺牲灵活性;②实例**不再有 `__dict__`**(除非把 `"__dict__"` 也加进 slots,但那就失去省内存意义),一些依赖 `__dict__` 的代码(如某些序列化、`vars(obj)`)会受影响;③默认也没有 `__weakref__`(不能被弱引用),需要弱引用要显式把 `"__weakref__"` 加进 slots;④**继承问题**——`__slots__` 不会被子类自动继承,如果子类没有定义自己的 `__slots__`,子类实例又会获得 `__dict__`,省内存效果消失;多继承时多个非空 `__slots__` 基类会冲突;⑤与 `@cached_property` 等需要写实例 dict 的特性可能冲突。**适用场景**:字段固定、数量巨大、对内存敏感的数据类。现代可用 `@dataclass(slots=True)`(3.10+)自动生成带 slots 的数据类。

</details>

5. `__getattr__` 和 `__getattribute__` 有什么区别?各用在什么场景?

<details><summary>参考答案</summary>

二者都用于自定义属性访问,但触发时机和用途完全不同。**`__getattribute__(self, name)`** 是属性访问的**总入口**:**每一次** `obj.attr` 访问都会**无条件**先调用它(它内部实现了前面说的标准查找逻辑——查描述符、实例 dict、类等)。重写它意味着拦截**所有**属性读取,威力极大但也极危险:①性能影响大(每次访问都过你的代码);②**极易无限递归**——如果在 `__getattribute__` 里写 `self.x` 去读属性,又会触发 `__getattribute__`,无限循环;正确做法是调用 `super().__getattribute__(name)` 来完成实际查找。它适合需要对所有属性访问做统一拦截的高级场景(如全代理、访问审计、ORM 的某些实现),但一般应避免重写。**`__getattr__(self, name)`** 则是**兜底钩子**:它**只在常规属性查找失败时**(即实例 `__dict__`、类及其 MRO 中都没找到该属性)才被调用。它不会拦截已存在的属性,所以更安全、更常用,典型场景:①**动态/惰性属性**——按需计算或加载某个属性(如从磁盘/网络懒加载配置,首次访问时加载并 `setattr` 缓存到实例,下次就走正常查找不再触发);②**代理/包装对象**——把找不到的属性转发给内部被包装对象(`return getattr(self._wrapped, name)`);③**ORM/灵活对象**——把任意字段名映射成数据访问。配套的还有 `__setattr__`(拦截所有赋值 `self.x = v`,同样要小心递归,内部用 `super().__setattr__` 或直接操作 `self.__dict__`)和 `__delattr__`。一句话:**要"找不到时再处理"用 `__getattr__`(安全常用);要"拦截每一次访问"才用 `__getattribute__`(强大危险,注意用 super 避免递归)**。

</details>

6. `c.greet` 和 `C.greet` 有什么区别?什么是绑定方法?

<details><summary>参考答案</summary>

`C.greet`(通过**类**访问方法)得到的是一个**普通函数(function)**对象——它就是定义在类里的那个函数本身,调用它需要显式传入实例作为第一个参数:`C.greet(c)`。而 `c.greet`(通过**实例**访问方法)得到的是一个**绑定方法(bound method)**对象——它把实例 `c` "绑定"为该函数的第一个参数 `self`,所以调用时不需要再手动传 self:`c.greet()` 等价于 `C.greet(c)`。这就是为什么我们调用方法 `obj.method(args)` 时不用自己传 self——`obj.method` 已经是绑定了 obj 的方法。**这背后的机制是描述符(见 P11)**:函数对象实现了 `__get__`(是一个**非数据描述符**),当你通过实例访问一个函数属性 `c.greet` 时,属性查找机制会调用这个函数的 `__get__(c, C)`,它返回一个绑定方法对象(把 c 记为 self);而通过类访问 `C.greet` 时 `__get__(None, C)` 返回函数本身。绑定方法对象内部通过 `__self__`(绑定的实例)和 `__func__`(原函数)记录这层关系。延伸:`@staticmethod` 装饰的方法的描述符 `__get__` 返回原函数(不绑定任何东西,所以不接收 self/cls);`@classmethod` 的描述符 `__get__` 返回绑定到**类**的方法(第一个参数是 cls 而非实例);`@property` 是数据描述符,让方法表现得像属性(访问时自动调用)。所以"方法"本质就是"类里的函数 + 描述符协议带来的自动绑定",理解这点是理解 P11 描述符的钥匙。

</details>
